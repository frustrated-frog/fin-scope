# PRD：事件与证据工作台重构

## 1. 背景与问题

FinScope 的事件页已经拥有事件队列、时间线、归并依据、证据、学习任务、内容选题和人工治理等完整能力，但现有双栏比例让事件队列过窄，详情中的不同信息又被等权卡片切碎。

证据页目前只是一个全局表格：`Event / Tier / Type / Claim / 原文 / Confidence`。它能查到材料，却不能帮助用户判断“当前能确认什么、推断到什么程度、还缺哪些证据”。

## 2. 目标

1. 保留事件页已有数据与治理能力，仅重构空间分配和阅读顺序。
2. 将证据页升级为论点—证据工作台，明确区分已证实事实、部分支持的推断和待补证据。
3. 每个论点和证据都可回溯至文章原文与所属事件。
4. 不让前端根据置信度臆测结论状态；论点、状态和缺口由后端持久化。

## 3. 非目标

1. 不改造事件聚类算法、事件人工治理接口或文章抓取流程。
2. 不引入新的大模型调用；论点使用确定性初始规则生成，后续可由研究流程丰富。
3. 不做跨事件的自动因果图谱。

## 4. 用户故事

- 作为个人研究者，我进入证据页时首先看到某个事件当前哪些判断可靠，而不是一张无上下文的证据表。
- 我能展开一个判断，查看支持它的原始主张、来源层级、置信度、日期和原文链接。
- 我能发现一个判断缺少的是监管文件、公司公告还是量化数据，从而知道下一步该补什么。
- 我仍能从全局证据页按事件、来源层级、证据类型和最低置信度筛选材料。
- 我在事件页中能完整看清事件队列，并快速判断事件发展、归并理由和当前证据状态。

## 5. 体验与信息架构

### 5.1 事件页

- 桌面端布局由窄队列 + 宽详情调整为 `38% / 62%`；队列最小宽度 350px，详情不小于 0。
- 左栏仍包含标题、主题/状态/新意筛选、事件卡、分页；卡片内容不删减。
- 右栏依次为：事件摘要与指标 → 事件如何发展（时间线）/ 为什么归并（主内容） → 当前证据状态（代表性证据 + 跳转证据页） → 学习任务与选题 → 人工治理。
- 完整证据列表不再在事件页重复渲染，只显示最高质量的两条代表项和状态入口。

### 5.2 证据页

证据页包含四个层次：

1. **筛选与上下文**：事件、来源层级、证据类型、最低置信度；选择单个事件时显示事件标题和主题。
2. **证据健康度**：已证实论点数、部分支持论点数、待补缺口数、一手来源占比。
3. **论点与证据**：每个论点显示状态、类别、表述、解释、支持它的证据列表；证据显示层级、类型、主张、置信度、文章出处、日期、原文链接。
4. **证据缺口与来源构成**：明确列出下一步需要的证据，不用低质量材料伪造完整性；右栏展示来源层级分布和研究轨迹。

空状态必须提示“尚未形成论点；先从事件详情补充文章或证据”，而不是只显示空表格。

## 6. 数据与规则

新增持久化对象 `EventEvidenceThesis`：属于一个事件，包含 `statement`、`kind`（FACT / IMPACT）、`status`（CONFIRMED / PARTIALLY_SUPPORTED / OPEN）、`rationale`、`evidenceGap`、创建/更新时间。它与 Research 页面已有的长期研究问题 `ResearchThesis` 完全隔离。

新增关联表 `research_thesis_evidence`：关联论点与 `EvidenceItem`。一个论点可由多条证据支撑；同一证据可支撑多个论点。

首次获得事件证据时，系统为尚无论点的事件按证据类型确定性生成：

- `FACT / TIMELINE` → `FACT + CONFIRMED`，直接复用最高可信证据的 claim。
- `DATA` → `IMPACT + PARTIALLY_SUPPORTED`，说明数据本身不等价于影响结论。
- 证据不足时不生成虚假论点。

每个 PARTIALLY_SUPPORTED 论点默认写入明确的证据缺口：需要同一变量的独立一手来源或可比数据。该缺口可由后续研究流程编辑。

## 7. 验收标准

1. 证据页不再使用 `Table` 呈现核心内容，论点和证据关系可在一屏内阅读。
2. 后端可按 event/source tier/type/min confidence 返回论点工作台，且每条证据保持原文可追溯。
3. 新建证据能为对应事件建立或复用确定性论点；重复捕获不重复建立关系。
4. 事件页左侧队列在 1280px 宽度下至少 350px，事件详情按主次排布，治理操作仍可用。
5. 现有前端测试、后端针对性测试、前端构建通过。
