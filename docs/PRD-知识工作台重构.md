# PRD：FinScope 知识工作台重构

## 1. 文档信息

- 日期：2026-07-13
- 状态：待评审
- 范围：合并现有 `Topics` 与 `Learning` 两个一级 Tab，建设统一的 `Knowledge / 知识库` 工作台
- 目标用户：使用 FinScope 做个人投研、长期学习、秋招项目展示和内容素材积累的单人用户

## 2. 背景与问题

FinScope 的产品定位不是资讯浏览器，也不是任务管理器，而是把短期信息加工成长期判断力的本地优先投研工作台。当前知识区域没有完成这一定位：

1. `Topics` 主要展示 SQLite 字段和 Vault 路径，更像数据库列表，不像长期研究档案。
2. `Learning` 同时承载事件学习任务、Topic 重复列表和个人笔记表单，页面缺少单一主线。
3. `LearningTask` 与 `Topic` 在后端没有正式关联，前端通过概念字符串包含关系猜测归属。
4. 自动生成的任务直接进入待办池。当前活跃数据中只有 3 个 Topic，却有 341 条 LearningTask，338 条处于 `TODO`，自动化输出已经淹没真实行动。
5. 修改任务状态不要求产出答案，追加 Topic 笔记也不知道在回答哪个问题，学习结果不可审计。
6. 学习任务已在 Events 详情中展示，Learning 又重复管理；Topic Reader 与 Learning 之间来回跳转，阅读和记录被拆断。
7. 页面混用中英文、原始状态码、路径、渐变卡片和高饱和操作按钮，信息层级弱，用户进入页面后不知道先看什么、下一步做什么。

## 3. 产品定义

将 `Topics` 与 `Learning` 合并为一个一级工作区：

> 知识工作台是 FinScope 中把事件、证据、文章、简报和学习问题转化为个人结论，并安排后续复习与输出的地方。

统一后的知识生命周期为：

```text
外部信息
  -> Event / Evidence / Article / Brief
  -> Agent 学习建议
  -> 用户接受并归入 Topic
  -> 回答问题并引用证据
  -> 形成 Knowledge Entry
  -> Topic 掌握度提升或进入复习
  -> 成熟后进入 Content Studio
```

## 4. 产品目标

### 4.1 进入页面后，十秒内知道下一步

首页优先展示最多 3 个明确行动，每个行动必须包含：

- 为什么现在应该做；
- 关联哪个 Topic；
- 从哪里产生；
- 点击后会进入哪个操作界面。

不使用只有数字、没有行动含义的仪表盘指标作为首屏核心。

### 4.2 知识资料完整但不重复

每个 Topic 形成统一研究档案，聚合：

- 当前摘要和掌握阶段；
- 相关事件与新增变量；
- 代表证据；
- 关联文章和简报；
- 已接受和待处理的学习问题；
- 用户自己的回答、结论、复习记录；
- 最近更新时间、下次复习时间和可输出状态。

同一内容不在 Hero、侧栏和 Markdown 正文中重复展示。

### 4.3 学习完成必须产生知识成果

- Agent 生成内容默认为“建议”，不能直接成为用户义务。
- 用户接受建议后，它才进入待学习队列。
- 学习任务标记完成时，必须同时保存一条非空知识记录。
- 知识记录必须关联 Topic，可选择引用 Evidence。
- 系统保留问题快照、回答、引用和时间，便于后续复盘。

### 4.4 结构清晰且可长期扩展

页面与后端共同区分：

- Topic 生命周期；
- Topic 掌握度；
- LearningTask 工作状态；
- KnowledgeEntry 类型；
- Review 调度。

不再用一个 `status` 字段表达多种业务含义。

## 5. 成功标准

### 5.1 用户体验

1. 用户进入知识工作台后，无需阅读说明即可找到首要行动。
2. 从首页进入任意 Topic 不超过 2 次点击。
3. 从学习任务进入回答编辑器不超过 1 次点击。
4. Topic 页面内可以完成阅读资料、回答问题、追加结论和安排复习，不需要跳转到另一个一级 Tab。
5. 主界面不展示 Vault 原始绝对路径、英文数据库状态码或技术 trace。
6. 390px、768px、1280px 和 1512px 宽度下不存在横向溢出，主要操作不会被长列表推到页面底部。

### 5.2 数据与业务

1. 100% 新流程完成的学习任务至少关联一条最终 KnowledgeEntry；迁移前已完成但没有成果记录的任务明确标记为历史兼容数据，不计入该指标。
2. 100% KnowledgeEntry 关联一个有效 Topic。
3. 自动生成但未接受的建议不计入“待学习”数量。
4. 不再使用前端字符串包含规则推断任务与 Topic 的正式归属。
5. 现有 Topic、文章、简报、任务和 Vault 内容不丢失。
6. 当前 341 条历史任务保留，但未开始的自动任务迁移为“建议”，不再污染待办。

### 5.3 工程质量

1. 领域状态转换集中在 Service/Domain policy，不由 Controller 或前端自由拼接。
2. 多表写入使用事务，任务完成与知识记录创建要么同时成功，要么同时回滚。
3. 重要更新使用 `revision` 乐观锁，冲突返回明确的 `409 Conflict`。
4. 列表 API 分页，Overview 使用聚合查询，不把全部任务加载到前端再过滤。
5. 关键状态机、数据迁移、事务回滚、API 契约和前端主流程均有自动化测试。

## 6. 信息架构

侧边栏将原来的 `Topics` 和 `Learning` 合并为一个 `Knowledge / 知识库` 入口。进入后提供四个内部视图：

### 6.1 今日工作台

回答“我现在应该做什么”。包含：

- 下一步行动，最多 3 条；
- 正在研究的 Topic；
- 到期复习；
- 最近新增的知识记录；
- Agent 建议摘要，但不与用户待办混在一起。

### 6.2 主题档案

回答“我已经积累了什么”。包含：

- 搜索；
- 按掌握阶段、更新时间、是否待复习筛选；
- Topic 列表；
- 新建主题；
- Topic 工作台入口。

新建主题使用弹窗或侧边抽屉，不永久占据列表首屏。

### 6.3 待学习

回答“有哪些问题需要我真正处理”。分为：

- 进行中；
- 已接受待开始；
- Agent 建议；
- 已完成；
- 已忽略。

默认只展示进行中与已接受任务。Agent 建议单独呈现，支持接受、归入 Topic、忽略，不制造虚假紧迫感。

### 6.4 待复习

回答“哪些已有判断需要重新验证”。包含：

- 到期 Topic；
- 上次结论；
- 上次复习以来新增的事件和证据；
- 结论仍有效、需要修正或已经失效；
- 下一次复习时间。

## 7. 核心用户流程

### 7.1 首次进入

1. 用户进入知识工作台。
2. 系统显示“今天从这里继续”。
3. 如果有进行中的学习任务，优先继续任务。
4. 如果有到期复习，优先展示复习。
5. 如果没有用户行动，只显示“查看 Agent 建议”或“创建第一个 Topic”，不伪造任务。

### 7.2 接受 Agent 建议

1. 用户打开“Agent 建议”。
2. 查看问题、为什么值得学、来源事件和代表证据。
3. 选择已有 Topic 或创建新 Topic。
4. 点击“加入学习计划”。
5. 建议转换为 `TODO`，出现在待学习队列。

### 7.3 完成学习任务

1. 用户打开任务。
2. 页面展示问题、来源事件、Evidence、已有 Topic 内容和上次相关结论。
3. 用户填写回答、当前判断、仍待验证点，并选择引用证据。
4. 可以保存草稿；点击“完成并沉淀”时创建 KnowledgeEntry。
5. 同一事务中将任务更新为 `DONE`。
6. Topic 时间线立即出现该记录，Overview 重新计算下一步行动。

### 7.4 Topic 复习

1. 到期 Topic 出现在待复习列表。
2. 用户查看上次结论和新增证据。
3. 选择“仍有效”“需要修正”或“已失效”，并填写理由。
4. 系统创建 `REVIEW` 类型 KnowledgeEntry。
5. 更新掌握度与下一次复习时间。

### 7.5 从 Topic 进入内容输出

当 Topic 达到 `MATURE` 且至少有一条结论记录时，显示“生成选题”入口。该入口将 Topic 摘要、关键证据和个人结论传给现有 Content Studio，但本期不重做 Content Studio。

## 8. 状态定义

### 8.1 Topic 生命周期

- `ACTIVE`：正常维护。
- `PAUSED`：暂不推进，但保留资料。
- `ARCHIVED`：不再主动展示。

### 8.2 Topic 掌握度

- `EXPLORING`：刚建立，资料和问题仍不完整。
- `BUILDING`：正在形成理解。
- `REVIEWING`：已有结论，等待验证或复习。
- `MATURE`：结论相对稳定，可以输出。

### 8.3 LearningTask 状态

- `SUGGESTED`：Agent 自动生成，尚未被用户接受。
- `TODO`：用户已接受。
- `IN_PROGRESS`：正在回答。
- `DONE`：已产生 KnowledgeEntry。
- `DISMISSED`：用户明确忽略。

复习不属于 LearningTask 状态，避免继续混用 `REVIEWING`。

### 8.4 KnowledgeEntry 类型

- `ANSWER`：对学习问题的回答。
- `INSIGHT`：用户主动记录的理解。
- `CONCLUSION`：当前阶段结论。
- `REVIEW`：复习和结论修订记录。

## 9. 页面内容与文案原则

1. 面向用户显示中文业务含义，不直接显示 `LEARNING`、`MATURE` 等状态码。
2. 路径和内部 ID 只在调试信息或详情菜单中出现。
3. 每张卡片只有一个主要动作；删除、归档等低频动作进入更多菜单。
4. 空状态说明下一步，例如“还没有已接受的学习任务，去查看 Agent 建议”。
5. 操作名称与结果提示一致，例如“完成并沉淀”对应“已完成并写入主题档案”。
6. 不使用收益涨跌、霓虹渐变等交易终端视觉暗示，知识区域强调证据、问题和判断演进。

## 10. 数据迁移要求

1. 迁移前不删除任何现有记录或 Vault 文件。
2. 现有 Topic：
   - `LEARNING` -> 生命周期 `ACTIVE`、掌握度 `BUILDING`；
   - `REVIEWING` -> 生命周期 `ACTIVE`、掌握度 `REVIEWING`；
   - `MATURE` -> 生命周期 `ACTIVE`、掌握度 `MATURE`。
3. 现有 LearningTask：
   - `TODO` -> `SUGGESTED`，因为历史记录没有用户接受证据；
   - `LEARNING` -> `IN_PROGRESS`；
   - `REVIEWING` -> `IN_PROGRESS`，等待用户补充成果后完成；
   - `DONE` 保留 `DONE`，并把 completion mode 标记为 `LEGACY`，不伪造 KnowledgeEntry。
4. 不用当前前端的字符串匹配结果自动写入正式 Topic 关联。
5. 迁移后提供“未归类建议”队列，允许批量忽略或逐条归档。

## 11. 边界与非目标

本期不做：

- 投资建议、买卖信号或自动交易；
- 多用户协作、权限和云同步；
- 富文本协同编辑器；
- 向量数据库或语义检索；
- 复杂知识图谱与任意层级 Topic 树；
- 自动判定用户是否真正掌握；
- 全站所有页面的视觉重构；
- 重写 Content Studio、Events 或 Evidence，只提供清晰跳转与数据关联。

## 12. 分阶段交付

### 阶段一：领域与数据闭环

- 新状态模型与迁移；
- LearningTask 与 Topic 正式关联；
- KnowledgeEntry；
- 完成任务必须沉淀记录；
- 分页和乐观锁。

### 阶段二：统一知识工作台

- 合并导航；
- 今日工作台；
- 主题档案；
- 待学习工作区；
- Topic 详情内完成记录。

### 阶段三：复习与资料完整性

- ReviewState；
- 待复习页面；
- Topic 事件与证据聚合；
- 新增证据提示；
- 成熟 Topic 进入 Content Studio。

## 13. 验收场景

1. 进入 `Knowledge`，首屏显示最多 3 个带原因和动作的下一步。
2. 341 条历史任务迁移后，不再全部出现在待办数量中。
3. 接受一条建议并关联 Topic 后，它进入 `TODO`。
4. 未填写回答时，任务不能完成。
5. 完成任务后，任务变为 `DONE`，Topic 同时新增 `ANSWER` 记录。
6. 任一环节写入失败时，任务状态和 KnowledgeEntry 均不发生半成功。
7. 打开 Topic 可以查看事件、证据、文章、简报、任务和个人记录。
8. 到期 Topic 出现在复习队列，提交复习后更新下一次复习时间。
9. 两个浏览器窗口同时编辑同一任务时，后提交者收到冲突提示，不覆盖先提交内容。
10. 原有 `/api/topics` 读取和现有 Vault 内容在迁移期间保持可用。
