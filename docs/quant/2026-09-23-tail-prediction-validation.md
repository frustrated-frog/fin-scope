# 尾盘定时留档与次日真实验收

## 使用入口

Strategy → Quant → 尾盘与盘后 → **预测验证台**。

1. 在“自动观察名单”中填写最多 10 只沪深股票，支持六位代码或带市场后缀的代码。
2. 填写买卖成本及滑点合计的研究假设（默认 20 基点），启用并保存计划。
3. 保持 Python 行情服务运行。交易日上海时间 14:30、14:45 开始采集；刷新页面可查看最近窗口及每只股票的结果。
4. 次日自动轮换获取到期行情，页面按固定退出时点展示全历史验收。

默认不启用、没有预置股票。保存计划后只处理后续完整窗口；修改计划不改变已有窗口的名单、费用或预测。原有手动 14:30/14:50 和盘后真实持仓入口保留，手动新增 14:45。

更新后需在 IDEA 重启 Java 和 Python 服务，前端刷新即可。无需模型 API。

## 留档协议

- Python 进程生命周期内每 20 秒检查窗口，上海时间与已覆盖交易日历共同决定是否运行。
- 截止后 5 分钟以内开始并完成的尾盘结果标记 `FORWARD`；超时完成只列 `RETROSPECTIVE`。
- 同一日期、时点通过 SQLite 唯一键抢占，重复检查不重新执行；异常、行情缺失、历史不足也留痕，不伪造概率。
- 计划存储在独立 `overnight-research.db`，包括观察名单、费用、启用时间；重启后将启用期间错过的窗口登记为 `MISSED`。停用期间不算漏跑。
- 已开始却没有完成的窗口显示中断；不在事后补造实时预测。
- 预测、原始分钟输入、输入指纹、数据截止、模型版本及基准随第一次结果冻结。有效手动研究仍沿用原有冻结身份。
- 新版 `overnight-local-v2` 在每个退出目标上冻结历史盈利比例和历史平均净收益。旧版保留，不补造缺失基准。

## 结算与验收

分钟档案全量遍历，不再只处理最近 50 份。后台每 5 分钟轮换至多 3 只未完成结算的股票；前端“更新到期结果”也使用该流程。列表仍只显示最近 50 份，验收覆盖全部已存档案。

- 尾盘收益入场代理：决策后 5 分钟的价格，按区间结束时间标记的分钟 K 线取开盘价。例如 14:45 决策使用 14:55 K 线开盘价，约对应 14:50。
- 盘后持仓收益基准：信号日收盘价；真实账本成本继续单独显示。
- 退出：次日开盘、10:00、14:30、收盘；不使用最高价事后择时。
- 扣除预测时冻结的成本和滑点假设。入场一字区间及新版退出一字区间不作为可验证成交；缺失行情不替换为其他交易日。
- 分组：场景、模型版本、时点、费用、实时/历史回顾。每个指标先在目标交易日内平均，再对交易日等权。
- 概率基准：只在有冻结基准的相同记录上比较模型 Brier 与基准 Brier；旧记录显示缺失。
- 参与基准：同一可核验观察名单、同日期和费用下，比较全部参与与固定 `概率 >= 50%` 参与规则；后者当天全部不参与记零收益。未完成核验的记录不会被计为亏损或零收益，并单独展示状态/缺失原因。
- 概率分组显示平均预测与实际盈利比例，并同时显示记录数和独立交易日数。

原有“次日收盘预测 → 真实预测效果验收”也迁到 Java 后端全历史计算，通过每批 500 条主键游标读取冻结账本。按版本、股票和目标日保留最早生成的记录，再检查结果；明细仍最多展示 100 条。该口径不扣费，也没有新增事后基准。

## 边界

这些统计仍是价格代理研究，不是实际成交记录。分钟成交额和一字区间过滤不能证明排队成交；当前原始价格没有公司行为校正。观察名单由用户设置，不代表全市场，无成交或缺失样本排除仍可能导致选择偏差。60 个交易日提示仅用于提醒样本规模，不是优势认证门槛。

交易日历当前仅覆盖 2026 年；未知年份不推断交易窗口。服务未启动时无法采集，重启只能登记错过的窗口。首次分钟源可能只返回有限历史，少于 60 个成熟样本时保留数据并显示不足，不用日线或大模型补齐。当前每个窗口只发起一次有界并发采集，供应商发布延迟也可能造成该窗口数据不足。

## 验证

- Python：全量 471 项通过，包括跨日漏跑、幂等、计划持久化、失败留档、固定基准、分组隔离、等权统计以及超过显示窗口的结算。
- Java：18 项专项测试通过，覆盖模块编译、Spring 上下文以及隔夜 RPC/服务、次日账本分页与汇总。
- 前端：14 项专项测试通过，覆盖隔夜计划保存、空态、场景/证据隔离、全历史接口失败及既有次日预测/股票发现；生产构建通过。
- 浏览器使用独立测试端口和临时数据，验证计划保存和页面布局（含合成到期样本、390px 窄屏无整页横向溢出），不修改 IDEA 服务的数据。
