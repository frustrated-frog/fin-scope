# 验证刷新与模型训练隔离

## 问题

真实运行中，训练从 21:27 持续到 21:38 仍未结束，验证统计的 computedAt 停留在 21:27。原因是五类统计与耗时训练共享 OvernightJointWorker.tick，所谓五分钟刷新只能在下一轮训练循环检查。

## 修复

- 新建 OvernightValidationWorker，通过应用 lifespan 独立启动与停止。训练 worker 仅处理样本准备、训练、发布和训练任务恢复。
- 验证使用独立、单线程、有名的 executor，不与 asyncio.to_thread 的共享线程池争用执行槽位。每轮等待结束后再提交下一轮；同一实例的并发 tick 通过非阻塞锁跳过，不积压重复计算。
- errorAudit、marketForward、jointForward、closeDirectionForward、contextDirectionForward 分别按自身 computedAt 判断五分钟间隔。轮询间隔 20 秒，实际刷新时间还包括计算和数据库访问耗时。
- 验证不受 13:00–18:00 训练避让窗口限制；自动化关闭时也停止验证。
- 单项异常保留原结果，记录异常类型并继续其他项；失败项在后续轮询重试。无效或未来时间戳触发重算。重启复用已有统计时间，避免重复刷新尚未到期的指标。
- 状态接口增加 validationWorker 心跳、最近完成时间、当前状态、错误项、刷新项。前端沿用模型研究折叠区展示最近完成时间与异常状态，不把尝试时间当成成功时间。

本次不更改模型、预测概率或验收门槛。

## 验证

- 独立 worker 专项 10 项通过：盘中更新、五分钟边界、重启、单项缺失、异常保留与恢复、禁用、异常时间戳、并发防重。
- 并发测试令真实训练 worker 的拟合步骤阻塞，并将共享 executor 限制为一个线程。验证 worker 使用自己的线程完成两轮更新，覆盖全部五类统计；随后正常停止两个任务。
- 前端相关 10 项测试及生产构建通过；既有大包提示仍在。
- Python 全量 693 项通过；对照项目规范检查，无新增 Java 注入、外部依赖或模型协议变更。
