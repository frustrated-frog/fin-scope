# 量化训练、补数与前瞻准入补修

本次接续《2026-11-12-candidate-rolling-repair.md》的复查，修复六处尚未闭环的问题。代码和故障路径已验证；没有证据可以宣称次日预测准确率已经提高。

## 六项闭环

| 复查发现 | 修复与边界 |
| --- | --- |
| 同日新增分钟数据不会改变训练任务键 | 分钟实际变更、公司行为核验、研究池、指数及冻结候选名单进入输入版本；同一时点的新版本训练至少间隔 30 分钟。同版本失败沿用任务租约有限重试，仍避开 13:00—18:00 |
| 子模型失败仍把整个任务记为成功 | 各部分独立保存结果，任务记为失败并保留非服务用途的检查点；重试复用成功部分。只有完整版本可以用于预测，期间继续使用上次完整版本；每个任务最多尝试三次 |
| 基础方向训练绕过公司行为过滤，最终重拟合又混入已排除选择段记录 | 在基础方向面板注入核验标记；初次训练、最终重拟合和后续研究学习均遵守训练资格。已知除权影响窗口只从拟合中排除，验证标签和原始预测不删除、不改写 |
| 较老候选的样本缺口没有进入补数队列 | 按冻结名单的判断行情、次日结果和过去特征缺口优先补数，不要求仍在最新两轮名单或公共池内。研究读取可用完整归档修补部分实盘日，需通过重叠行情核对；实盘输入视图及冻结报告不变 |
| 错误分析、候选验证和周报采用不同校验，且周报缺少 ADAPTIVE | 复用严格时序、参考价、结果日与模型一致性校验；每个方案独立与主判断做完整名单配对，指数缺失不再阻断其他方案。ADAPTIVE 进入周报 |
| 新方案永远处于研究状态，没有启用和退化回退通路 | 预先限定 ROLLING、ADAPTIVE 两个方案。新增独立生产准入监测，合格后才允许自动前瞻预测采用；不以训练完成、历史回放或周报的单个高分替代准入 |

研究补数不能重建当时真实发行的新预测。新增的 `overnight_data_revision` 单行表由现有 SQLite 初始化流程建立；这是本轮相对上一轮“没有数据库迁移”的变化。未增加依赖、Java Bean、外部付费服务，也未改交易费率。

## 启用规则

- 仅累计新训练策略 `action-aware-data-refresh-v1` 实际发行的自动前瞻预测；旧档案不追认。
- 每个模式、判断时点与方案独立固定首批 60 个完整交易日验收，计划日期完整覆盖至少 90%。同一日多股只算一天。
- 方向命中和概率误差须同时优于当时原判断与历史比例基准，使用现有按日期分块的不确定性检验及比较组数修正；上涨、未上涨识别率各不低于 35%。
- ROLLING 另外要求固定前三名和匹配看涨名额均优于原判断、当日涨幅排序及同池平均，看涨日期覆盖至少一半、看涨命中超过 50%。
- 首批验收结果固定保存；失败后不会滚动挑选一个更好的 60 日窗口覆盖失败。未来变更需要新的预声明策略版本与独立证据。
- 首批通过后持续检查最近 20 个计划交易日；缺失保留分母，覆盖至少 90%，方向和概率仍需有优势。
- 真正发行预测时再次检查监测在判断前生成且未超过一天、标签已经到期、模型和参考价匹配、当前为有效模型估计而非 PRIOR。满足条件才采用；同一预测保留原判断与回退值。
- 当前版固定优先采用合格 ROLLING，其次 ADAPTIVE。其他研究组保持各自对照，不通过比较多个事后分数临时挑选方案。

“达到启用条件”不等于“某条预测已经采用”。页面在研究详情展示准入进度，在单条预测标明实际采用、验证过期或未满足本次条件。主页面不增加操作按钮，历史档案继续保持冻结。
