# 资金行为历史评价实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 Market Intel 资金行为页建立严格时点的事件研究评价，让当前信号能够携带可复现的 1/3/5 日历史统计证据进入页面和 Agent，同时在样本不足时明确拒绝展示百分比。

**Architecture:** 评价服务只读取已保存 `CapitalBehaviorSnapshot` 中的日线事实，按交易日前缀重新运行现有因子与信号引擎，未来价格只用于标签，避免未来资金数据进入事件判定。结果以版本化评价快照持久化，通过独立 `evaluationRef` 进入 Agent 证据包和输出门禁；页面展示样本数、覆盖率、收益、MFE、MAE 和稳定性状态。评价失败不影响行情快照刷新主链路。

**Tech Stack:** Java 8、Spring、Jackson、SQLite/JdbcTemplate、JUnit 5、React、TypeScript、Vitest、Testing Library。

---

## File structure

- `finscope-domain/.../CapitalBehaviorEvaluation.java`：一次可复现评价快照的聚合根。
- `finscope-domain/.../CapitalSignalEvaluation.java`：单一信号、单一前向周期的统计证据。
- `finscope-dao/.../CapitalBehaviorEvaluationRepository.java`：按源快照幂等保存和读取评价 JSON。
- `finscope-service/.../CapitalFactorEvaluationService.java`：严格前缀回放、标签计算和样本门禁。
- `CapitalAgentEvidencePacket/Assembler/Gate/Agent`：将合格评价作为受控引用送入模型并校验输出。
- `MarketIntelCapitalView/Service/RefreshCoordinator`：刷新后生成评价并暴露给页面。
- `CapitalHistoricalEvaluationCard.tsx`：独立展示历史统计，不把模型文本作为统计来源。

- [ ] **Step 3: 实现最小事件研究算法**

算法固定为：

```text
按 observedAt 去重并升序排列 DAY_1
for eventIndex in daily points:
  prefix = points[0..eventIndex]
  signals = CapitalBehaviorSignalService.detect(prefix)
  for horizon in [1, 3, 5]:
    entry = close[eventIndex]
    exit = close[eventIndex + horizon]
    return = exit / entry - 1
    MFE = max(close[eventIndex + 1 .. eventIndex + horizon] / entry - 1)
    MAE = min(close[eventIndex + 1 .. eventIndex + horizon] / entry - 1)
```

输入指纹包含排序后的日线 `id/observedAt/price/mainNetInflow/amount/calculationVersion/payloadHash` 以及 factor/signal/evaluation 版本。稳定性使用按事件时间前后半段平均收益方向是否一致，样本不足 10 时为 `INSUFFICIENT_SAMPLE`。
