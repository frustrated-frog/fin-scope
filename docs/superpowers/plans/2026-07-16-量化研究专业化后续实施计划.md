# 量化研究专业化后续实施计划

> 日期：2026-07-16
> 分支：`codex/quant-research-professionalization`
> 输入：`docs/产品需求-策略研究中枢第三期.md`、`docs/superpowers/specs/2026-07-16-量化因子说明书与研究闭环设计.md`

## 目标

在不伪造市场数据、不增加一级页面复杂度的前提下，补齐资金行为到量化研究的真实操作闭环，将单一 IC 诊断升级为多周期、分阶段、换手与成本敏感性证据，并让受控 Agent 能读取这些确定性结果和历史运行记忆。

## Task 1：真实研究数据集向导

**修改：**

- `frontend/src/features/strategy/QuantWorkspace.tsx`
- `frontend/src/features/strategy/quantTypes.ts`
- `frontend/src/features/strategy/QuantWorkspace.test.tsx`
- `frontend/src/styles.css`

**行为：**

1. 在“研究样本”内新增“建立真实研究集”入口，不把学习样本包装成真实数据。
2. 真实研究集按四步显示：创建容器、导入日线行情、导入 point-in-time 股票池、冻结资金分区。
3. 日线与股票池通过本地 JSON 文件导入现有受控 API；前端先做结构、大小与日期范围校验。
4. 冻结请求显式填写起止日与信息截止时间，调用 `/api/factor-research/datasets/{id}/capital-flow-freeze`。
5. 每步完成后重新读取服务端数据集与质量报告；阻断状态展示服务端事实，不自动降级或补零。

## Task 2：多周期专业评价报告

**新增/修改：**

- `backend/finscope-domain/src/main/java/com/finscope/domain/quant/factor/FactorHorizonAnalysis.java`
- `backend/finscope-domain/src/main/java/com/finscope/domain/quant/factor/FactorRobustnessReport.java`
- `backend/finscope-domain/src/main/java/com/finscope/domain/quant/factor/FactorAnalysis.java`
- `backend/finscope-service/src/main/java/com/finscope/service/quant/factor/DatasetFactorAnalysisService.java`
- `backend/finscope-service/src/main/java/com/finscope/service/quant/factor/FactorAnalysisService.java`
- `backend/finscope-service/src/main/java/com/finscope/service/factorresearch/FactorEvidenceAssessmentService.java`
- 对应 service 单元测试

**行为：**

1. 对 1/3/5/10/20 日未来 close-to-close 收益分别计算 Rank IC、方向调整 IC、置信区间、分位差与单调性。
2. 默认 1 日仍作为兼容主指标；API 增加 `horizons`，不破坏旧调用方。
3. 将样本按时间顺序切为前 70% 与后 30%，输出样本内/样本外方向一致性；样本不足时明确标记不可评估。
4. 计算因子排名的日间变化作为换手代理，按 10/30 bps 输出成本压力提示，不冒充真实成交成本。
5. 评价门禁仍使用版本化政策；样本外方向冲突时结论降级为 `INCONCLUSIVE`。

**行为：**

1. 默认摘要只回答结论、样本外是否同向、成本/换手风险和下一步。
2. 多持有期证据用紧凑表格展示，不制造更多孤立卡片。
3. 专业详情折叠展示 IC、区间、分位差、覆盖率、样本内外和成本敏感性。
4. 学习数据始终显示“流程验证、不是市场证据”；所有结论只使用支持、反驳、证据不足。

## Task 4：Agent 稳健性与研究记忆

**修改：**

- `backend/finscope-dao/src/main/java/com/finscope/dao/factorresearch/FactorResearchAgentRunRepository.java`
- `backend/finscope-service/src/main/java/com/finscope/service/factorresearch/FactorResearchAgentService.java`
- `backend/finscope-service/src/test/java/com/finscope/service/factorresearch/FactorResearchAgentServiceTest.java`
- `frontend/src/features/strategy/FactorResearchAgentPanel.tsx`
- `frontend/src/features/strategy/quantTypes.ts`

**行为：**

1. 计划依据是否来自资金草稿、数据性质和是否存在历史运行动态生成，不执行任意脚本。
2. Agent 将多周期、样本外、换手和成本压力作为强制反证节点。
3. 只读取同因子已完成历史运行的结论、证据哈希、数据集指纹，形成对比记忆；不把历史结论复制为当前结论。
4. 数字继续全部来自确定性工具；扩大数据范围、创建实验或升级生命周期仍需人工授权。

## Task 5：验收与收口

2. 前端全量 Vitest、TypeScript 构建。
3. 浏览器验证真实研究集向导、因子观测站、Agent 计划与响应式布局。
4. `git diff --check`、敏感边界复核与最终提交。

## 明确延期

- 行业内相对资金强度：缺少 point-in-time 行业归属历史，不接入。
- 容量模型与真实冲击成本：缺少盘口和真实可成交量，只输出换手代理与成本敏感性。
- 自动交易与自动生命周期升级：不在产品授权边界内。
