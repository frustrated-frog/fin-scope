# 量化策略工作台第一期设计

## 目标与边界

为个人长期投资学习建立一个新的一级工作区 `策略`。第一期提供完整、可操作的前后端体验：用户可以在页面内建立场外基金与股票条目、给资产设定角色和目标权重、选择策略模板、维护股票研究卡，并在同一处看到待完成的投资动作。

第一期不接入券商账户、历史净值回测、交易执行或自动下单。所有初始内容均为空状态或示例引导；用户后续在界面中自行添加基金和股票。组合、策略状态、股票研究与复盘必须持久化至后端 SQLite 数据库，不能以浏览器本地状态作为事实来源。

用户为正在通过场外基金开始真实投资、计划逐步研究股票的个人投资者。页面的单一职责是：把“今天该看什么、该记录什么、哪些想法正在验证”呈现为可行动的长期投资地图。

## 交付范围

### 一级入口与内部导航

- 在现有左侧工作区导航新增 `Strategy / 策略` 一级入口。
- 进入后默认展示 `组合`；内部切换为：`组合`、`策略库`、`股票孵化`、`复盘`。
- 一级入口仅承载策略工作台，不改动现有自选、归因、研究、事件页面与 API。

### 组合

- 初始为空时，展示面向场外基金的引导：建立组合、定义目标、记录第一笔研究动作。
- 支持在前端添加基金或股票：代码、名称、资产类型、组合角色、目标权重、当前权重、备注。
- 场外基金支持的角色为：核心、卫星、防守、观察；股票角色为：观察、模拟、真实验证。
- 添加后展示资产卡、目标权重汇总、角色分布、资产表；可删除条目、调整角色和权重。
- 资产由后端保存，刷新、重启服务后仍保留；没有任何预置持仓或虚构收益数据。

### 策略库

- 给出三张基金策略模板：长期定投、目标权重再平衡、研究驱动的卫星仓。
- 给出两张股票策略模板：质量成长观察、事件研究观察。
- 选中策略后显示：策略要解决的问题、输入项、执行节奏、风险边界、当前状态；用户可将其标记为“使用中”或“研究中”。
- 策略卡不展示虚构回测收益；未有真实回测能力时以“尚未回测”明确标注。

### 股票孵化

- 支持添加股票研究卡：代码、名称、投资逻辑、买入条件、失效条件、观察重点、阶段。
- 阶段固定为：研究池、观察池、模拟组合、小仓位验证，且卡片可在阶段之间推进。
- 每张卡突出“为什么值得观察”与“什么发生时应放弃”，避免仅显示名称和涨跌。
- 数据由后端保存；不产生真实交易建议或下单动作。

### 复盘

- 汇总组合条目数、使用中策略数、股票研究进度和本周期待完成动作。
- 允许记录一则复盘：事实、推理、下一步行动；将条目按时间显示。
- 无数据时提供清晰的第一步行动，而不是空白页面。

## 信息架构与交互流

```text
策略
 ├─ 组合：建立资产地图与角色
 │     └─ 添加基金/股票 → 设定角色与权重 → 形成组合结构
 ├─ 策略库：选择正在训练的纪律
 │     └─ 选模板 → 查看规则与边界 → 标记为研究中/使用中
 ├─ 股票孵化：训练股票研究方法
 │     └─ 写逻辑与失效条件 → 推进研究阶段 → 进入模拟观察
 └─ 复盘：连接事实、推理与行动
       └─ 记录复盘 → 回到组合/策略调整
```

新增、编辑、删除与阶段推进均在页面内完成，使用抽屉或轻量弹层，操作成功后给出明确反馈。键盘可聚焦所有控件；减少动态效果偏好下不播放装饰动画。

## 视觉设计

### 设计方向

采用“投资作战室”而不是传统金融行情屏。这个页面处理的是数年尺度的判断与复利，不是盘中交易，所以以沉静、纸本研究感和精确的数据标记为主。

### Token

- `深墨 / Ink`：`#101923`，页面主背景与长期专注氛围。
- `石板 / Slate`：`#1B2835`，层级表面与内容分区。
- `雾蓝 / Mist`：`#A9C0D0`，辅助信息与说明文字。
- `潮汐青 / Tide`：`#36C5B2`，正向进度、主操作和聚焦状态。
- `琥珀 / Amber`：`#E7B65A`，长期、目标权重和需要注意的偏离。
- `珊瑚 / Coral`：`#F07D6A`，失效条件与风险提醒。

字体延续系统中文字体以保证加载稳定；数字和代码使用等宽字体。展示标题只在工作台标题与“长期策略”信号带中使用较大字重，正文克制紧凑。

### 布局与标志性元素

页面顶部不是常见 KPI 大数字，而是一条可交互的“复利轨道”：核心、卫星、防守、观察四段对应组合目标权重，未配置时显示待建立的空轨道；配置后用真实用户权重填充，并标出偏离。它既是第一页的视觉记忆点，也是组合策略的核心控制器。

```text
策略 / 长期投资地图                         + 添加资产
核心 ━━━━━━━━━━━━  卫星 ━━━━━  防守 ━━━  观察 ━

[ 组合 ] [ 策略库 ] [ 股票孵化 ] [ 复盘 ]

左：资产与角色卡片        右：本周期行动 / 策略状态
```

其余界面保持平静的卡片和细线分隔；悬停时只抬升可操作的卡片，策略状态和阶段转换用短暂的颜色过渡表达，不使用持续闪烁或无意义图表。

### 自我审查

已避免套用通用的“黑底 + 大收益数字 + 霓虹涨跌图”金融仪表盘。深色并非炫技，而是与既有 FinScope 主题保持连贯；独特性来自将资产配置本身做成“复利轨道”，并让它成为添加资产、理解角色和发现偏离的直接交互入口，而不是背景装饰。

## 后端结构

策略领域独立于 `watchlist_item`，但复用现有 `instrument` 标的主数据。自选表示“我关注什么”，策略持仓表示“它在我的组合中承担什么角色”；同一标的可同时存在于两处，不能因删除自选而删除策略记录。

后端是本期的领域核心，不是前端的临时数据代理。实现必须保持清晰的聚合边界：组合持仓、策略采用状态、股票研究命题和复盘分别建模；控制器仅处理 HTTP，服务层承载业务规则与事务，Repository 只负责 SQL 映射。不得以一个泛化 JSON 字段或一个超大 `StrategyService` 混合所有职责。

### 数据模型

- `strategy_holding`：组合条目，引用 `instrument_id`，保存资产角色、目标权重、当前权重、备注、排序与创建/更新时间。基金角色为核心/卫星/防守/观察；股票角色为观察/模拟/真实验证。
- `strategy_playbook`：用户已采用的策略模板，保存固定模板代码、状态（研究中/使用中/暂停）、可选备注与更新时间。模板的文字定义由服务端策略目录提供，不将 UI 文案存入数据库。
- `strategy_stock_thesis`：股票研究卡，引用股票 `instrument_id`，保存阶段、投资逻辑、买入条件、失效条件、观察重点、备注和更新时间。
- `strategy_review`：复盘记录，保存复盘日期、事实、推理、下一步行动与创建时间。

所有表由 `DatabaseInitializer` 使用 `CREATE TABLE IF NOT EXISTS` 建立，并为持仓标的、策略状态、股票研究阶段和复盘日期建立查询索引。业务对象、DAO、服务、控制器分别位于既有 `domain`、`dao`、`service`、`web` 模块，遵循当前 JDBC Repository 与响应 DTO 模式。

### 领域不变量与演进规则

- 策略持仓只允许 `FUND` 与 `STOCK`；基金和股票的角色集合不同，服务层必须拒绝不匹配的组合。
- 单条目标权重与当前权重均为 `0..100`；组合目标权重总和不能超过 `100`。更新在事务内校验，避免并发/连续编辑产生超配。
- 一个组合内同一 `instrument_id` 只允许一个持仓记录；股票研究卡与组合持仓可以并存，但同一股票只能有一个未归档研究卡。
- 股票阶段只能按“研究池 → 观察池 → 模拟组合 → 小仓位验证”前进，允许退回前序阶段；跳跃、无效枚举和已删除标的均返回明确的业务错误。
- 所有写入维护 `created_at`、`updated_at` 与乐观锁 `revision`。更新请求必须携带当前 `revision`，陈旧写入返回冲突而不是静默覆盖。
- 建表和扩列一律为向前兼容的幂等迁移；不修改或重建现有 `instrument`、`watchlist_item` 数据，策略表上的外键删除策略记录时级联，删除标的时受限保护。

枚举和约束既在数据库 `CHECK` 中表达，也在服务层进行领域校验；数据库保护事实完整性，服务层负责可理解的中文错误。若当前 SQLite 环境未开启外键，初始化器必须显式开启并由集成测试验证。

### API

- `GET /api/strategy/overview`：一次返回组合条目、角色权重汇总、本周期行动摘要与最新复盘；组合条目可附带当前行情快照，但行情失败不能影响策略记录读取。
- `POST/PATCH/DELETE /api/strategy/holdings`：新增、更新、删除策略组合条目。新增时先解析/创建 `instrument`，只允许 `FUND` 或 `STOCK`。
- `GET /api/strategy/playbooks` 与 `PUT /api/strategy/playbooks/{code}/status`：读取模板目录并更新用户采用状态。
- `GET/POST/PATCH/DELETE /api/strategy/stock-theses`：管理股票研究卡及阶段推进。
- `GET/POST/DELETE /api/strategy/reviews`：读取、记录、删除复盘。

服务层负责输入校验、`instrument` 解析、领域边界和中文错误信息；控制器不直接编排 SQL。第一期不在接口中承诺回测指标或真实交易收益，以避免空数据被误读为可用策略结论。

## 工程质量门槛

1. **契约先行**：先为请求/响应、错误码与状态迁移写控制器测试，再实现 Web 层；前端只依赖响应 DTO，不接触数据库字段或内部实体。
2. **持久化可证**：DAO 使用真实 SQLite 集成测试，覆盖唯一约束、索引查询、级联/受限删除、迁移幂等和 `revision` 冲突。
3. **事务可证**：对“新增标的并新增持仓”“更新权重”“更新阶段”等多步操作写服务层事务测试，任何一步失败不得留下半成品。
4. **错误可用**：所有预期失败返回稳定的中文业务语义；行情/名称解析失败只能降级为标的名称或行情缺失，不能阻断用户保存研究记录。
5. **可维护**：不把模板目录、SQL、验证规则和视图组装堆在同一个类；每个新增领域类保持单一职责，日志沿用中文消息和结构化关键字段。
6. **验证顺序**：Repository/Service/Web 测试 → 前端 API 测试 → TypeScript 构建 → 真实页面走查。任何一层失败不得被后续手工走查掩盖。

## 前端结构

- 新增 `frontend/src/features/strategy/StrategyView.tsx`，封装工作台加载、内部页面切换、表单与 API 操作。
- 新增 `frontend/src/features/strategy/StrategyView.test.tsx`，覆盖默认空状态、添加资产、切换策略状态、添加股票研究卡、添加复盘和 API 刷新。

- 在 `frontend/src/styles.css` 添加以 `strategy-` 为前缀的样式，并包含宽屏、平板和窄屏断点。

## 后端测试

1. DAO 测试：验证建表后持仓、策略状态、股票研究卡和复盘的读写/删除，以及策略记录与自选记录相互独立。
2. 服务测试：验证标的类型限制、重复持仓规则、权重范围、阶段合法迁移与错误信息。
3. Controller 测试：验证各 API 的成功响应、非法请求与行情源不可用时仍可读取已保存组合。

## 测试与验收

1. 后端模块测试：策略 DAO、服务和 Web API 测试通过。
2. `npm test`：新增策略测试与现有前端测试全部通过。
3. `npm run build`：TypeScript 与 Vite 构建通过。
4. 手动检查：从左侧打开策略，四个内部区域可切换；基金和股票可添加、删除、刷新后仍由 API 返回；策略可切换状态；股票研究卡可推进阶段；复盘可新增。
5. 响应式检查：复利轨道与操作按钮在窄屏不溢出，桌面双栏在中小屏收为单栏。

## 后续演进

第二期接入现有自选、基金净值、行情与研究/归因数据。第三期再增加基金穿透、数据快照、日频回测、策略版本、模拟组合与因子研究。真实交易或自动下单不在当前路线内。
