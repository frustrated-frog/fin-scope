# 量化策略平台第二期技术设计

## 1. 设计结论

第二期新增独立 `quant` 领域，交付 A 股日频多因子策略从数据到实验解读的完整闭环。现有 `strategy` 领域继续承载长期投资纪律，不承担数据计算、因子分析或回测职责。

系统采用“Agent 控制面 + 确定性执行面”：Agent 把自然语言翻译为受限策略 DSL，并解读服务端已计算结果；数据校验、因子计算、组合构建、交易撮合和指标计算全部由可测试的 Java 服务完成。

## 2. 参考原则

参考 BigQuant 因子分析与多因子实践中的可复现原则：截面预处理、因子分层、Rank IC、信号与收益错位、股票池过滤、基准对比、交易成本和年度拆解。平台不复制 BigQuant 的 Python/SQL 编辑器，而是将这些原则固化为后端不变量。

参考资料：

- [因子分析框架详解（AlphaMiner）](https://bigquant.com/wiki/doc/kkC3XIaMup)
- [基于 ICIR 动态加权的多因子行业中性选股](https://bigquant.com/wiki/doc/pwbrtZP3tE)
- [弹性网络选股：机器学习多因子模型搭建](https://bigquant.com/wiki/doc/qjl2v0tXah)

## 3. 模块边界

```text
finscope-web
  QuantDatasetController / QuantFactorController
  QuantStrategyController / QuantExperimentController
            │
finscope-service
  dataset   数据集编排、质量门禁、指纹
  factor    因子目录、计算、诊断
  strategy  DSL 校验、版本管理、Agent 草案
  backtest  时间轴、选股、撮合、账本、指标
  experiment 实验状态、快照、结果与 Agent 解读
            │
finscope-dao
  quant 数据仓储；只负责 SQL 与行映射
            │
finscope-domain
  不可变配置、领域枚举、数据记录和结果模型
            │
finscope-rpc
  QuantMarketDataProvider / LlmChatClient
```

`QuantBacktestEngine` 不依赖 Spring、HTTP、SQLite 或 LLM，只接收不可变输入并返回结果，保证可以用内存夹具进行确定性测试。实验服务负责从仓储装配输入和持久化输出。

## 4. 数据模型

### 4.1 数据集

- `quant_dataset`：名称、市场、股票池类型、来源类型、数据性质、起止日期、状态、指纹、质量摘要、revision。
- `quant_universe_member`：dataset_id、trade_date、instrument_code、member、source_kind。
- `quant_daily_bar`：dataset_id、trade_date、instrument_code、OHLC、adjusted_close、volume、amount、trade_status、ST、limit flags。
- `quant_fundamental_snapshot`：dataset_id、instrument_code、report_period、disclosed_at、估值/质量/成长/规模字段。
- `quant_dataset_issue`：严重度、代码、日期/标的、说明和计数。

主键或唯一键必须包含 `dataset_id`，避免不同来源相互污染。金额和价格使用 `BigDecimal` 持久化；计算核心使用 `double` 并在边界检查非有限值。日期使用 ISO `yyyy-MM-dd`。

数据指纹按规范化记录排序后计算 SHA-256，包含数据集元数据、股票池、行情和财务快照。修改数据后生成新指纹并使旧草案的验证状态失效。

### 4.2 因子与策略

- 因子目录是代码内版本化注册表，不把公式作为任意表达式保存到数据库。
- `quant_strategy_draft`：prompt、Agent 原始响应、规范化 DSL、校验状态和校验问题。
- `quant_strategy`：逻辑策略身份与名称。
- `quant_strategy_version`：不可变 DSL JSON、策略指纹、创建来源、引擎兼容版本。

DSL 只允许白名单字段：

```json
{
  "name": "质量价值与中期动量",
  "datasetId": 1,
  "benchmark": "000300.SH",
  "factors": [
    {"code": "ROE", "weight": 0.3, "direction": "HIGH"},
    {"code": "EP", "weight": 0.3, "direction": "HIGH"},
    {"code": "MOMENTUM_60D", "weight": 0.4, "direction": "HIGH"}
  ],
  "portfolio": {"topN": 20, "rebalanceEvery": 20, "weighting": "EQUAL"},
  "filters": {"excludeSt": true, "minTradingDays": 252, "minAmount": 5000000},
  "execution": {"signalPrice": "CLOSE", "fillPrice": "NEXT_OPEN", "slippageBps": 10},
  "cost": {"buyCommission": 0.0003, "sellCommission": 0.0003, "stampDuty": 0.001, "minimumCommission": 5}
}
```

不得保存任意 JavaScript、SQL、SpEL 或可执行代码。

### 4.3 实验

- `quant_experiment`：strategy_version_id、dataset_fingerprint、engine_version、状态、请求时间、开始/完成时间、错误摘要。
- `quant_experiment_metric`：指标代码、数值、单位。
- `quant_equity_point`：交易日、组合净值、基准净值、现金、总资产、回撤。
- `quant_trade`：信号日、执行日、代码、方向、数量、成交价、名义金额、费用和原因。
- `quant_position_snapshot`：实验、交易日、代码、数量、市值和权重。
- `quant_experiment_year`：年度收益、基准、超额、波动、回撤。
- `quant_experiment_interpretation`：结构化观察、风险、建议和模型信息。

结果表只允许在实验从 `RUNNING` 转为 `SUCCEEDED` 的事务中写入。失败实验保存错误和输入快照，不保存半套指标。

## 5. 因子计算

`FactorDefinition` 声明代码、类别、方向、依赖字段、最短窗口和计算器。`FactorRegistry` 是唯一目录入口。首批计算器按交易日、标的分组，生成 `(signalDate, instrument, value)`。

量价因子从 `quant_daily_bar` 计算；基本面因子对每个信号日选择 `disclosed_at <= signalDate` 的最新快照。预处理顺序固定为：

1. 形成当日可见股票池；不根据未来标签删样本。
2. 排除非有限值并记录缺失率。
3. 按截面 2.5%/97.5% 分位去极值。
4. Z-Score 标准化；标准差为零的因子记为不可用。
5. 按方向转换并形成加权总分。

二期不实现行业/市值中性化；字段和处理阶段预留，页面明确显示“未中性化”，避免产生虚假精度。

## 6. 回测引擎

### 6.1 时间轴

- T 日收盘后读取截至 T 日可见的数据并形成目标组合。
- T+1 使用下一可交易日开盘价加减滑点撮合。
- 因子诊断的持有期收益同样从 T+1 开始。
- 数据末端缺少完整持有期时不生成标签，且不得影响 T 日截面统计。

### 6.2 组合与撮合

回测按交易日推进：先执行上一个信号日的订单，再按收盘价估值，最后在调仓日生成下一交易日订单。卖出先于买入；买入金额受现金和最低佣金约束。停牌、涨停买入、跌停卖出或缺少价格时拒绝成交并生成告警。

Top-N 按总分降序、代码升序确定稳定顺序，等权目标基于可投资资产净值计算。默认初始资金 1,000,000 元，仅为回测计价基数，不表达用户真实资金。

### 6.3 指标

收益使用复利净值而非日收益简单相加。年化交易日常量为 242。指标计算覆盖累计收益、CAGR、年化波动、最大回撤、夏普、卡玛、日胜率、换手、交易次数、基准收益和超额收益。无风险利率进入实验快照，默认 2%。

## 7. Agent 边界

`QuantStrategyAgent` 向 LLM 提供：可用因子目录、数据集摘要、DSL Schema、参数范围和禁止事项。响应经过 JSON 提取、字段白名单、枚举、范围、权重总和、数据覆盖和时间语义校验。

只有 `VALIDATED` 草案可被用户确认。确认操作创建不可变版本；运行操作只接收版本 ID。解读 Agent 接收服务端生成的指标、年度表现、告警和因子摘要，不接收原始全量价格；响应中的数字引用再次与服务端摘要校验，无法校验的数字降级为定性描述。

## 9. 前端

将现有 `StrategyView` 拆为路由壳与子页面，避免继续形成超大组件：

- `QuantLabView`：实验流水线和策略草案。
- `QuantDatasetView`：数据卡、质量报告和学习数据创建。
- `QuantFactorView`：因子目录与诊断。
- `QuantExperimentView`：实验列表和详情。
- `LongTermStrategyView`：承接一期四个区域。

前端状态按页面局部管理，不引入新的全局状态库。API 类型集中在 `shared/types/quant.ts`，调用封装在 `features/quant/quantApi.ts`。图表使用轻量 SVG 组件并提供表格/文本回退。

## 10. 失败处理与可观测性

- 导入失败：保留错误清单，事务回滚，不改变旧指纹。
- Agent 失败：保存失败草案和模型摘要，不生成策略版本。
- 回测失败：实验进入 `FAILED`，记录稳定错误码、中文消息和 traceId。
- 数据质量不足：使用门禁错误阻止运行，不自动降级到其他数据。
- 异步实验使用专用有界线程池；重复提交通过请求指纹幂等。
- 日志使用中文消息并保留 datasetId、draftId、strategyVersionId、experimentId、durationMs 等结构化键。

## 11. 安全与性能

- DSL 不包含可执行表达式，从根源避免代码注入。
- 导入限制大小、记录数、日期范围和数值范围。
- LLM 提示中不包含 API Key、原始配置或不必要的用户数据。
- SQLite 写入串行、批量事务化；行情读取按 dataset/date/code 建联合索引。
- 因子矩阵按实验局部缓存，不使用无界进程缓存。
- 二期面向个人低用量，优先正确性和可复现性，不做分布式计算。

## 12. 测试策略

1. 数据仓储：唯一键、幂等导入、披露日查询、指纹稳定性、事务回滚。
2. 因子：固定小样本验证每个公式、去极值、标准化、缺失和时间对齐。
3. DSL：合法草案、未知因子、权重错误、参数越界、数据覆盖不足和非法字段。
4. 回测：T/T+1 对齐、停牌/涨跌停、费用、现金约束、稳定排序、财务可见性和确定性。
5. 指标：复利收益、回撤、年化、基准和零波动边界。
6. Web：导入、Agent 草案、确认、运行、查询和失败响应。
7. 前端：学习数据空状态、生成草案、确认回测、查看结果和失败恢复。

## 13. 设计自审

- 无占位项和未决策参数。
- `strategy` 与 `quant` 边界明确，Agent 与回测执行隔离。
- 真实数据和学习数据具有持久化标识与 UI 水印。
- 基本面使用披露日而非报告期，回测执行从下一交易日开始。
- 第二期只实现受限多因子 Top-N；基金、多资产、代码策略和自动实验不混入本期。
