# 现有市场数据高可用刷新设计

## 背景

FinScope 当前页面已经展示了足够的数据。本次改造不增加新的行情栏目、研究页面或数据类型，只提高现有页面刷新链路的成功率、可恢复性和状态透明度。

现状存在三类可靠性缺口：

- `QuoteService` 只选择第一个支持标的类型的 `QuoteAdapter`，上游失败后不会继续尝试其他来源。
- 行情抓取失败生成的无效 `Quote` 也会进入 30 秒缓存，短时间内重复刷新仍可能得到同一失败结果。
- 行情与板块最后成功数据主要保存在进程内，应用重启后失去兜底；用户也无法统一识别主源成功、备源成功、部分更新和旧快照。

## 目标

1. 用户每次点击刷新后，系统优先返回新鲜数据；所有在线来源失败时返回最后成功快照。
2. 已经产生过至少一次成功快照后，“刷新后仍有可用数据显示”的目标成功率不低于 99.9%。
3. 新鲜数据成功率和可用数据显示成功率分开统计，旧快照不能伪装成实时数据。
4. 数据源切换、部分更新、旧快照和完全不可用都必须有持续、明确的页面提醒。
5. 保持现有页面结构和主要 REST 路径，不为了接入更多来源新增展示模块。
6. 建立可扩展的数据源契约，后续增加来源时不修改业务页面和领域计算。

## 非目标

- 不新增市场数据页面、行情字段或专题数据入口。
- 不接入券商交易、自动下单或付费数据订阅。
- 不把 Python 或 Node 数据服务引入正式运行链路。
- 不在本次改造中扩充量化因子。量化因子与成交量因子作为后续独立设计，复用本次形成的数据质量元数据。
- 不用语义不同的数据静默替代现有数据。例如新浪日级资金流不能冒充东方财富 5 分钟资金流。

## 开源项目借鉴结论

### tickflow-stock-panel

借鉴：

- 通过 `ProviderCapabilities` 声明来源支持的 instrument、daily、minute、realtime、financial 等能力。
- Provider 输出统一结构，使存储和计算不依赖来源实现。
- 数据集级来源配置、连接测试和 Schema 映射校验。
- 持久化最后抓取时间与最后成功数据。
- 能力探测遇到瞬时网络错误时保留上次确认的能力，避免错误降级。
- 行情热路径与慢 Webhook、批量计算等任务隔离。

不照搬：

- 它对每类数据选择一个来源；自定义实时来源抓取异常后会结束当次处理，不形成完整的主动多源故障转移。
- 单纯保留旧缓存但不返回统一质量状态，不能满足 FinScope 的明确提醒要求。

### a-stock-data

借鉴：

- 腾讯、新浪、通达信、同花顺、巨潮、交易所官方等不同故障域的端点目录。
- 东财请求限频、IP 级风控识别和官方来源兜底经验。
- 对失效接口、错误参数、字段索引和返回结构漂移的实测记录。
- “主源与备源必须属于不同域名和不同风控面”的原则。

不照搬：

- 该仓库主要是数据获取说明和代码片段，不是具备运行时路由、健康检查和审计能力的数据服务。
- 多处异常后返回空列表，无法区分合法无数据、Schema 漂移和来源故障。
- 东财不同子域名仍可能共享 IP 级风控，不能因为 URL 不同就算作独立备源。

本项目只借鉴架构、端点知识和故障经验。Provider 使用 Java 重新实现并配套固定响应测试，不直接复制未经验证的代码片段。

## 总体架构

采用 FinScope 原生的能力路由架构：

```text
页面刷新
  -> 现有 Controller / Service
  -> MarketDataRouter
       -> ProviderRegistry
       -> ProviderHealthRegistry
       -> QualityValidator
       -> Primary / Backup Providers
       -> LastGoodSnapshotRepository
  -> 现有响应字段 + DataQuality 元数据
  -> 页面常驻提醒与卡片状态
```

业务服务请求的是能力，不直接指定外部厂商。例如股票与指数请求 `REALTIME_QUOTE`，板块排行请求 `SECTOR_CATALOG`，资金行为刷新请求 `CAPITAL_FLOW_5M`。

### 能力枚举

首期只注册现有页面实际使用的能力：

- `REALTIME_STOCK_QUOTE`
- `REALTIME_INDEX_QUOTE`
- `REALTIME_FUND_ESTIMATE`
- `REALTIME_SECTOR_QUOTE`
- `SECTOR_CATALOG`
- `CAPITAL_FLOW_5M`

能力定义同时约束数据语义。`CAPITAL_FLOW_1D` 与 `CAPITAL_FLOW_5M` 是两个不同能力，不能互相冒充。

### Provider 契约

每个 Provider 公开以下元数据和操作：

- `providerCode`：具体来源代码。
- `providerFamily`：共享风控面的来源家族，例如 `EASTMONEY`、`SINA`、`TENCENT`。
- `capabilities`：支持的能力集合。
- `priority`：同一能力下的默认优先级。
- `batchLimit`、`minimumInterval`、`timeout`：调用约束。
- `fetch(request)`：返回统一的 `ProviderResult<T>`。

`ProviderResult` 必须包含数据、来源、上游数据时点、获取时点、覆盖范围、警告和原始载荷摘要。Provider 不得通过空列表表达网络失败；网络错误、权限错误、限流、Schema 漂移、合法空数据分别使用明确错误类型。

## 首期来源路由

| 现有能力 | 主源 | 备源 | 最终兜底 |
|---|---|---|---|
| 股票实时行情 | 腾讯 | 新浪 | 持久化最后成功行情 |
| 指数实时行情 | 腾讯 | 新浪 | 持久化最后成功行情 |
| 基金盘中估值 | 天天基金估值 | 暂不伪造独立备源 | 最后成功估值和已确认净值 |
| 已关注板块行情 | 东方财富 | 暂无等价在线备源 | 与板块目录共享的已验证快照及持久化最后成功行情 |
| 行业/概念板块目录 | 东方财富 | 暂无语义完全一致且代码映射稳定的独立来源 | 持久化最后成功目录 |
| 5 分钟资金流 | 东方财富 | 不使用新浪日级资金流冒充 | 已持久化的最后成功资金快照 |

腾讯行情适配器是首期新增的主要在线备援能力。新浪现有股票与指数适配器保留，并从“唯一来源”变成路由中的备选来源。

本期不为了表面上的“来源数量”接入语义不一致或未经验证的接口。TDX、交易所官方行情和 TickFlow 可在统一 Provider 契约稳定后作为后续来源加入；接入时业务层和页面合同不变。

## 刷新数据流

### 1. 请求合并

同一个能力和同一组标的在短时间内并发刷新时使用 single-flight。后续请求等待同一刷新任务，避免连续点击对上游造成重复压力。

### 2. 主备竞速

1. 路由器根据能力、熔断状态、最近成功率和优先级选择主源。
2. 启动主源请求。
3. 主源在 hedge delay 内没有返回时启动备源；默认延迟为 800 毫秒，可按来源配置。
4. 任一结果只有通过质量校验后才能胜出。
5. 已胜出的请求不再等待其他来源；无法取消的阻塞调用在独立、限界线程池中自然结束，不占用 Web 请求线程。
6. 单次点击刷新总预算默认 10 秒。预算耗尽后立即进入最后成功快照兜底。

### 3. 逐标的补洞

批量行情不是全有或全无：

- 主源返回的有效标的立即进入结果集。
- 缺失、错误或不合格的标的交给备源继续请求。
- 每个标的独立记录实际来源和数据质量。
- 聚合结果根据覆盖率产生 `FRESH_PRIMARY`、`FRESH_FALLBACK` 或 `PARTIAL_FRESH`。

### 4. 最后成功快照

只有通过质量校验的数据才能写入内存缓存和持久化快照。错误结果、空返回和无效 Quote 不再写入 30 秒缓存。

当所有在线来源失败时：

- 有最后成功快照：返回 `STALE_FALLBACK`，保留原始 `asOf`，同时返回本次失败原因。
- 没有最后成功快照：返回 `UNAVAILABLE`。

为了满足“始终能看到数据”的目标，最后成功快照不设置统一硬过期时间；页面按年龄提高警告等级。跨交易日行情仍可展示，但必须显示红色旧数据警告，不能参与“新鲜成功率”。Schema 版本不兼容或载荷损坏的快照不可使用。

## 数据质量门禁

### 通用校验

- 响应不是 HTML、登录页或反爬错误页。
- 必要字段存在，数值可解析，百分比和金额单位符合 Provider 契约。
- `retrievedAt`、`asOf` 不得晚于当前时间 2 分钟以上。
- 请求标的与返回标的可一一匹配，重复项按明确规则去重。
- 响应载荷 Hash 和 Schema 版本可记录。

### 行情校验

- 价格大于零，或者来源明确给出停牌状态。
- `high >= max(open, price, low)`，`low <= min(open, price, high)`；缺少某字段时只校验已有字段。
- 涨跌额、涨跌幅与昨收的差异在舍入容差内。
- 只有请求标的 100% 通过校验时才能把整批标记为主源完全成功；缺失项必须进入逐标的备源补洞。

### 板块目录校验

- 响应必须是预期数组结构，不能把错误对象当作空列表。
- 板块代码符合 `BK` 加四位数字，名称非空。
- 目录规模低于最后成功快照的 70% 时拒绝覆盖旧快照，并记录 `SUSPICIOUS_COVERAGE_DROP`。

### 资金流校验

- 时间粒度、交易日和标的代码必须与请求一致。
- 时间序列单调、有合理覆盖，金额单位统一。
- 5 分钟能力只接受 5 分钟语义的数据；日级来源只能用于独立能力或交叉校验。

## 健康检查、限频与熔断

现有 `ProviderRequestGuard` 演进为非全局串行的健康注册表。任何线程不得在持有全局锁时限频休眠。

健康状态分两层：

- Endpoint 层：`providerCode + capability`。某个东财板块接口失败，不直接判定东财所有接口失效。
- Family 层：`providerFamily`。连接拒绝、429、403 风控和大面积超时会提高整个 `EASTMONEY` 家族的失败分，避免对同一风控面反复撞击。

状态为 `CLOSED`、`OPEN`、`HALF_OPEN`：

- 连续 3 次可重试失败后打开 Endpoint 熔断 60 秒。
- 同一家族至少两个不同能力在 30 秒内出现可重试失败时打开 Family 熔断，初始 60 秒，最高退避到 5 分钟。
- 熔断到期只允许一个半开探测请求。
- 权限或参数错误不重试；超时、连接错误、429 和 5xx 最多重试 2 次，并使用抖动退避。
- 能力探测发生瞬时失败时保留最后确认能力；明确 401/403 或配置删除时才降级能力。

## 持久化模型

新增通用最后成功快照表 `market_data_snapshot`：

- `capability`
- `scope_key`，例如 `STOCK:600519`、`INDEX:000001`、`SECTOR_CATALOG:INDUSTRY`
- `provider_code`
- `provider_family`
- `as_of`
- `retrieved_at`
- `payload_json`
- `payload_hash`
- `schema_version`
- `updated_at`

唯一键为 `(capability, scope_key)`。成功写入使用事务内 upsert；载荷先完成反序列化和质量校验，再替换旧快照。

新增轻量刷新审计表 `market_data_refresh_run`：

- `id`、`capability`、`scope_summary`、`trigger_type`
- `started_at`、`finished_at`、`status`
- `requested_count`、`fresh_count`、`stale_count`、`failed_count`
- `selected_sources`、`warning_message`

详细 Provider 尝试记录以结构化日志输出，刷新表只保存用户可见结果和聚合统计，避免逐标的审计表无限增长。刷新记录保留 30 天并在每日维护任务中清理，最后成功快照不清理。

## API 兼容与质量元数据

保留现有业务字段和主要路径，在响应中增加以下兼容字段：

- `qualityStatus`
- `sourceCode`
- `asOf`
- `retrievedAt`
- `staleAgeSeconds`
- `warning`
- `refreshId`

质量状态统一为：

- `FRESH_PRIMARY`
- `FRESH_FALLBACK`
- `PARTIAL_FRESH`
- `STALE_FALLBACK`
- `UNAVAILABLE`

列表响应同时提供聚合质量状态；单个行情项目保留自己的来源和质量状态。这样主源成功 18 只、备源补齐 2 只时，页面能显示整体 `FRESH_FALLBACK`，同时保留逐标的溯源。

聚合规则固定为：全部标的来自主源且新鲜为 `FRESH_PRIMARY`；全部标的新鲜但至少一项来自备源为 `FRESH_FALLBACK`；至少一项只能使用旧快照而其余项新鲜为 `PARTIAL_FRESH`；全部项目只能使用旧快照为 `STALE_FALLBACK`；不存在任何可显示数据为 `UNAVAILABLE`。

资金行为现有 `health` 和 `refresh run` 合同不另起一套平行模型，而是映射到上述统一状态和来源元数据。

## 页面提醒

不新增页面，只在现有刷新入口和卡片中补充状态：

| 状态 | 展示规则 | 示例文案 |
|---|---|---|
| `FRESH_PRIMARY` | 刷新时间轻提示，不显示告警横幅 | `行情已更新 · 14:32:08` |
| `FRESH_FALLBACK` | 黄色常驻提示，下一次主源恢复后消失 | `腾讯行情暂不可用，已自动切换至新浪。` |
| `PARTIAL_FRESH` | 黄色常驻提示并显示数量 | `本次更新 18/20 只标的，2 只仍显示上次行情。` |
| `STALE_FALLBACK` | 橙色或红色常驻横幅；相关卡片显示“旧数据” | `当前行情源均不可用，正在显示 27 分钟前的数据，请勿视为实时行情。` |
| `UNAVAILABLE` | 红色常驻错误，不渲染伪造的零值 | `行情暂不可用，系统没有可用历史快照。` |

提醒不能只使用会消失的 Toast。`STALE_FALLBACK` 必须同时显示在页面顶部资源状态区和受影响卡片上；跨交易日旧数据使用红色而不是黄色。

## 现有模块改造边界

### 自选行情和市场指数

- `QuoteService` 从“找第一个 Adapter”改为调用 `MarketDataRouter`。
- 新增腾讯股票/指数 Provider，新浪成为在线备源。
- 30 秒缓存只保存有效数据，并增加持久化最后成功快照。
- `/api/watchlist` 和 `/api/market-indices` 增加质量元数据，不改变现有行情字段。

### 板块行情中心

- 保留现有排行、搜索、关注和 single-flight 设计。
- `SectorMarketService` 使用通用 Provider 健康状态和持久化快照，不再只依赖进程内 15 分钟兜底。
- 目录异常骤降、错误对象和空数组经过质量门禁后不得覆盖上一版数据。
- 页面现有 `最近可用数据` 提示升级为统一的来源、快照年龄和失败原因提示。

### 资金行为页面

- 保留现有持久化资金快照和异步刷新记录。
- `MarketIntelRefreshCoordinator` 不再使用 `findFirst()` 固定选择首个 Provider，而是通过能力路由器选择来源。
- 当前只有东方财富提供已验证的 5 分钟资金流时，失败返回已有快照并明确标为 `STALE_FALLBACK`；不把日级资金流混入 5 分钟规则计算。

## 可观测性

每次刷新至少记录：

- `refreshId`、能力、触发方式和请求规模。
- 每个来源的开始时间、耗时、结果类型、重试次数和熔断状态。
- 主源成功率、备源接管率、部分覆盖率、旧快照兜底率和完全不可用率。
- 快照年龄分布和来源返回覆盖率。

日志不得记录 API Key、完整敏感响应或用户隐私数据。用户界面只展示可理解的来源、时间和原因，不暴露堆栈或内部异常类名。

## 测试策略

### Provider 契约测试

- 使用固定响应 Fixture 验证腾讯、新浪、东方财富的字段、编码、单位和停牌语义。
- HTML 错误页、空对象、空数组、字段漂移、超时、429、403、5xx 都有独立用例。
- Provider 实现必须通过统一契约测试套件。

### 路由测试

- 主源成功时不启动不必要的备源。
- 主源超时或质量失败时备源接管。
- 主源只返回部分标的时按标的补洞并保持输入顺序。
- 所有在线来源失败时返回持久化快照。
- 没有快照时返回 `UNAVAILABLE`。
- 无效结果不进入新鲜缓存和最后成功快照。
- Endpoint 与 Family 熔断互不混淆，半开状态只放行一个探测。
- 并发点击只产生一个上游刷新任务。

### 持久化与重启测试

- 进程重启后仍能读取最后成功行情和板块目录。
- Schema 版本不兼容、Hash 不匹配和损坏 JSON 不可作为兜底。
- 新快照写入失败时旧快照保持完整。

### Web 与前端测试

- 现有响应字段保持兼容。
- 五类质量状态映射到正确文案、颜色和可访问性角色。
- `STALE_FALLBACK` 不会因为 Toast 消失而失去提醒。
- 部分更新显示准确数量，并只给受影响卡片增加旧数据标记。
- 一个页面资源失败不阻断其他资源刷新。

### 可靠性模拟

使用内存 Fixture Provider 执行至少 1000 次确定性故障组合，包括超时、部分返回、Schema 漂移和进程重启。验收“已有最后成功快照后每次刷新都有可用结果”，同时验证旧数据均被标记为非新鲜状态。真实外部接口只做可选冒烟检查，不作为自动化测试通过条件。

## 验收标准

1. 股票或指数主源失败时，页面能自动使用备源并明确显示切源信息。
2. 主备源都失败且存在历史快照时，页面继续显示数据，并持续显示来源、快照时间和旧数据警告。
3. 应用重启后仍可使用最后成功行情和板块目录兜底。
4. 主源部分返回时只补取缺失标的，返回顺序和页面现有展示不变。
5. 空数组、错误对象、字段漂移和异常覆盖率不会覆盖最后成功快照。
6. 基金、板块和资金流没有独立等价备源时不伪造多源，统一使用最后成功快照并明确提醒。
7. 连续点击刷新不会形成重复上游风暴，某一来源熔断不会阻断其他故障域。
8. 当前自选、市场指数、板块中心和资金行为页面不增加新的数据区块，原有核心交互保持不变。
9. 新增 Provider、路由、持久化、Web 合同和前端提醒均有自动化测试。

## 后续边界

完成本设计后，量化因子改造单独进入下一份设计。届时以统一 `asOf`、来源、质量状态和快照版本作为因子输入审计信息，重点补充量比、量价相关性、量价背离、OBV、成交量冲击、放量突破和缩量回撤等因子，不与本次数据刷新改造混在一个实施计划中。
