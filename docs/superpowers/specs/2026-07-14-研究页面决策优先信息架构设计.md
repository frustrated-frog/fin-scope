# 研究页面“决策优先”信息架构设计

## 1. PRD

### 1.1 背景

当前研究页直接展示命题状态、全部发现、产物数量、计划来源和 Agent 运行记录。信息虽然完整，但缺少主次：用户需要先理解“现在能得出什么判断、依据是什么、下一步看什么”，页面却优先暴露系统内部对象和执行明细，造成首屏空、卡片碎、文字密、页面过长。

### 1.2 产品目标

把研究页从“系统运行看板”重构为“研究决策工作台”：

1. 用户进入页面后，优先看到当前判断、置信度和下一验证点。
2. 支持、反证和未知项只展示足以形成判断的摘要，默认不铺开全部文本。
3. 运行产物、来源和 Agent 轨迹退居诊断层，需要时再展开。
4. 不删除已有数据和能力，不新增后端接口。

### 1.3 用户任务优先级

1. **判断命题进展**：当前是待验证、证据初步形成，还是已经形成结论。
2. **理解证据平衡**：支持与反证是否失衡，仍缺什么关键变量。
3. **决定下一步动作**：下一验证窗口是什么，是否需要再次运行研究。
4. **审计研究过程**：仅在需要排查或追溯时查看来源、步骤和 Agent 记录。

### 1.4 页面结构

#### A. 命题选择区

- 左侧继续保留命题创建表单。
- 右侧命题卡改为紧凑选择卡，展示研究对象、问题、产品化阶段标签。
- 阶段标签由已有字段推导：
  - `CONCLUDED`：已形成结论；
  - 存在结论但未结束：持续验证；
  - 存在发现但无结论：证据积累中；
  - 无发现：待验证。
- 选中态不再依赖大面积空白表达，而通过边框、阶段标签和简洁元数据表达。

#### B. 决策摘要区

- 取代原来的四列等权卡片。
- 主区展示：阶段标签、当前判断、置信度、下一验证点。
- 次区展示三条证据轨道：支持、反证、未知。
- 每条轨道默认最多展示 2 条发现，超过部分显示“另有 N 条”，不在首屏继续铺陈。
- 没有发现时显示方向性空状态，不显示模糊的“暂无”。
- 底部使用弱化元数据行展示“运行次数 · 关联产物数 · 最近研究日期”，不再使用独立大卡片。

#### C. 研究执行区

- 保留运行日期、来源预算和启动按钮。
- 不改变当前研究执行逻辑。

#### D. 运行详情区

- 默认展示运行进度、运行结果和报告入口。
- 执行步骤、计划来源、Agent 记录合并为一个“研究过程与来源”折叠区。
- 折叠标题展示摘要：已获取来源数量、计划来源数量、处理节点数量。
- 展开后：
  - 来源默认展示前 4 个；其余仅显示数量；
  - 执行步骤和 Agent 记录保持现有诊断能力；
  - 原始 JSON 继续放在二级“诊断信息”中。

### 1.5 内容与视觉原则

- 结论使用完整句，指标使用短标签，系统枚举不直接暴露给用户。
- 主结论只允许一个视觉焦点；证据轨道是辅助层，不与主结论争夺权重。
- 来源属于审计信息，不属于默认阅读路径。
- 桌面端决策摘要为主区 + 三轨证据布局；窄屏自动变成单列。
- 默认状态下，命题详情与运行详情均不得因为来源或发现数量线性增长页面高度。

### 1.6 验收标准

1. 选中命题后能看到产品化阶段、当前判断、置信度和下一验证点。
2. 支持、反证、未知各最多默认展示 2 条。
3. “本次研究产物”独立卡片消失，统计信息移动到摘要底部。
4. 默认页面不再逐条展示全部计划来源。
5. 来源与诊断折叠区能够展开，并最多直接展示 4 个来源。
6. 没有结论或发现时仍提供清晰下一步，不出现空白大卡片。
7. 桌面和移动布局均不产生横向溢出。

## 2. 技术方案

### 2.1 改动边界

本次仅修改前端展示与派生逻辑：

- `frontend/src/features/research/ResearchView.tsx`
- `frontend/src/features/research/researchPresentation.ts`
- `frontend/src/features/research/ResearchView.test.tsx`
- `frontend/src/features/research/researchPresentation.test.ts`
- `frontend/src/styles.css`

后端 `ResearchThesisDetail` 和 `ResearchRunDetail` 已包含所需字段，无需调整接口或数据库。

### 2.2 展示模型

在 `researchPresentation.ts` 中新增纯函数，避免 JSX 内继续堆积业务判断：

- `presentThesisStage(thesis, findingCount)`：生成阶段中文、语气和说明。
- `presentConfidence(confidence)`：将 `HIGH/MEDIUM/LOW` 转为用户语言。
- `groupThesisFindings(findings, limit)`：按 SUPPORT/COUNTER/UNKNOWN 分组、截断并返回剩余数量。
- `summarizeResearchDiagnostics(detail)`：生成来源与处理节点摘要。

所有函数只依赖输入数据，使用单元测试覆盖边界。

### 2.3 组件结构

`ResearchView` 内拆分为文件内小组件，控制主组件复杂度：

- `ThesisDecisionSummary`：主结论、置信度、下一验证点、证据轨道和弱化统计。
- `FindingLane`：单个证据轨道，统一限制 2 条。
- `ResearchDiagnostics`：合并步骤、来源和 Agent 记录的折叠区。

这些组件不自行请求数据，只接收当前 `thesisDetail` 或 `detail`，保持现有数据流不变。

### 2.4 状态与异常

- 命题详情请求失败：沿用当前清空详情行为，不阻断命题创建和研究运行。
- 命题尚无结论：展示“尚未形成稳定结论”，并使用下一验证点引导继续研究。
- 命题无发现：三轨显示各自的方向性空状态。
- 运行无来源快照：折叠摘要显示“暂无来源快照”，展开后给出空状态。

### 2.5 测试策略

- 展示函数单元测试：阶段推导、置信度中文化、每轨截断、剩余数量、诊断摘要。
- 组件测试：主结论优先、产物大卡消失、每轨最多 2 条、来源默认折叠、展开后最多 4 个来源。
- 构建验证：`npm run build`。
- 差异检查：`git diff --check`。
