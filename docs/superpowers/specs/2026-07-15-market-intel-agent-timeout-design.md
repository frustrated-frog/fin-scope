# 资金行为 Agent 超时与等待反馈设计

## 目标

让 GLM-5 有足够时间完成资金行为解读，同时让用户在等待期间持续知道系统仍在工作、当前处于什么阶段，以及超时后会如何处理。

## 方案

- 资金行为 Agent 主请求超时由 15 秒提高到 60 秒。
- 模型返回不可解析内容时允许一次修复请求，修复请求最多等待 30 秒。
- 前端轮询窗口提高到约 120 秒，覆盖主请求、一次修复和异步调度开销。
- Agent 按钮在运行时显示已等待秒数并保持禁用，防止重复提交。
- 等待提示分为三个阶段：
  - 0～9 秒：正在整理因子与资金证据。
  - 10～29 秒：模型正在分析资金行为。
  - 30 秒及以上：模型响应较慢但仍在运行，并明确说明超时后会自动展示规则解读。
- 服务端最终超时时仍返回规则兜底结果，保持页面可用。

## 边界

- 本次不引入 SSE、WebSocket 或新的进度接口；阶段提示基于客户端等待时间，不伪装为服务端真实执行进度。
- 不修改全局模型超时，只调整资金行为 Agent 自身的调用预算。
- 不允许用户在同一页面重复提交尚未完成的 Agent 任务。

## 测试

- 后端测试验证主请求使用 60 秒、修复请求使用 30 秒。
- 前端测试验证各等待阶段文案、实时秒数和按钮禁用状态。
- 运行资金行为相关测试后，再执行前端全量测试与构建、后端全量 Maven 测试。
