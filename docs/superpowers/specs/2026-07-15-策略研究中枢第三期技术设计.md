# 策略研究中枢第三期技术设计

> 状态：待评审
> 日期：2026-07-15
> 对应 PRD：`docs/产品需求-策略研究中枢第三期.md`
> 决策：以独立 `factor-research` 领域桥接资金行为与量化，不合并现有注册表；按 A → C → B 分期交付。

## 1. 设计目标

本方案将资金行为、因子研究、量化实验和 Agent 研究组织为同一条可复现证据链，同时保持现有领域边界。重点解决以下技术问题：

1. 线上资金行为数据如何安全、按时点冻结为量化研究输入；
2. 因子如何从简单代码枚举升级为带定义、来源、版本、质量和生命周期的研究对象；
3. 个股事件研究与横截面因子研究如何共存而不互相冒充；
4. Agent 如何在不执行任意代码、不伪造数字、不越权发布的前提下参与研究；
5. 如何让后端输出既满足统计复核，又能支持前端的渐进式解释。

## 2. 当前基线与缺口

### 2.1 量化域

当前 `FactorDefinition` 只包含编码、名称、分类、方向、描述、回看期和 point-in-time 标记；`FactorRegistry` 以内置方式注册少量价格量、估值和财务因子；`FactorPreprocessor` 只做有限值过滤、分位截断和标准化；`DatasetFactorAnalysisService` 主要计算下一日 Rank IC；`QuantBacktestEngine` 直接构造注册表和计算器。

这些实现足以支持学习型回测，但无法表达数据来源、可获得时间、缺失策略、中性化、固定版本、外部依据、失效条件、样本外证据和正式准入状态，也难以接入新的资金行为 provider。

### 2.2 资金行为域

当前资金行为已具备稳定历史样本质量门禁、严格前缀重放和 1/3/5 日事件评价，能够计算信号样本收益、无条件基线、超额、稳定性、衰减、MFE/MAE 等。

该评价本质是单标的事件研究，不能替代横截面 IC 和分组组合评价。其线上表仍会刷新，也不能被历史量化实验直接读取。

### 2.3 Agent

现有量化 Agent 主要是单次生成策略 JSON 或对已保存指标做一次解释，缺少研究计划、白名单工具、多步状态机、预算、反证复核、结构化记忆和完整追踪。

## 3. 架构决策

### 3.1 新增中立领域，不合并原注册表

新增逻辑模块 `factor-research`，它不拥有行情采集，也不拥有组合交易规则，而是拥有跨域研究契约：

```text
marketintel ──候选指标/事件证据──▶ factor-research ◀──数据集/实验── quant
                                             │
                                             ▼
                                      agent-research
                              计划/工具/复核/记忆/审计
```

边界如下：

- `marketintel`：采集、当前状态解释、资金行为候选指标、单股票事件评价；
- `factor-research`：因子定义、版本、生命周期、评价协议、统计结果、研究发现；
- `quant`：冻结数据集、横截面因子矩阵、组合构建、回测、策略版本；
- `agent-research`：研究计划、白名单工具编排、稳健性复核、研究记忆和运行预算。

这样可以保留资金页面对实时观察的职责，也避免量化回测依赖可变的线上表。

### 3.2 两条评价通道

`EvaluationMode` 必须显式取值：

- `SINGLE_INSTRUMENT_EVENT_STUDY`：按单标的严格前缀重放信号，比较信号后 1/3/5 日收益与自身无条件基线；
- `CROSS_SECTIONAL_FACTOR_STUDY`：按交易日构造股票截面，评价因子值排序与未来收益排序、分位组合及可交易性。

两类结果共享证据接口，但使用不同结果模型和验证政策。任何 API、Agent 工具或前端卡片都不得省略 `evaluationMode`。

### 3.3 确定性计算与 LLM 解读分离

所有数字由版本化 Java 服务或受控统计引擎计算。LLM 输入只接收结构化结果和证据引用；输出使用受约束 schema，包含事实、解释、限制、反证和下一步，不允许新增输入中不存在的数值。

## 4. 领域模型

### 4.1 因子定义

新增 `ResearchFactorDefinition` 聚合：

```java
record ResearchFactorDefinition(
    FactorIdentity identity,
    FactorSemantics semantics,
    FactorDataContract dataContract,
    FactorCalculationSpec calculation,
    FactorProvenance provenance,
    FactorEvaluationPolicyRef evaluationPolicy,
    FactorLifecycle lifecycle
) {}
```

主要值对象：

| 对象 | 核心字段 |
|---|---|
| `FactorIdentity` | namespace, code, version, name, category, frequency, valueType, expectedDirection |
| `FactorSemantics` | plainMeaning, hypothesis, economicRationale, expectedMechanism, riskExposures, failureRegimes, interpretationBoundary |
| `FactorDataContract` | requiredFields, availableAtRule, lookback, unit, missingPolicy, adjustmentPolicy, pointInTime |
| `FactorCalculationSpec` | expression/calculatorKey, operatorVersion, winsorization, normalization, neutralization, calculationFingerprint |
| `FactorProvenance` | sourceType, immutableUrl/doi, sourceVersion, adaptationNote, license |
| `FactorEvaluationPolicyRef` | policyCode, policyVersion, defaultHorizons, allowedDatasetLevels |
| `FactorLifecycle` | status, changedAt, changedBy, reason, previousStatus |

身份键使用 `(namespace, code, version)`。已进入实验的数据定义不可原地修改；任何公式、输入字段、可获得时间或预处理变化都生成新版本。

### 4.2 因子生命周期

```text
CANDIDATE
  → DEFINITION_REVIEWED
  → IMPLEMENTED
  → CALCULATION_VERIFIED
  → EXPLORATORY
  → VALIDATED
  → PRODUCTION_ELIGIBLE
  → INVALIDATED / RETIRED
```

状态迁移由 `FactorLifecycleService` 执行，并读取版本化 `FactorValidationPolicy`。Agent 可以建议迁移，但 `VALIDATED` 与 `PRODUCTION_ELIGIBLE` 必须由人工批准。学习数据、质量门禁失败、只完成样本内评价或缺少复现证据时禁止迁移。

### 4.3 因子观测

```java
record FactorObservation(
    String datasetId,
    String instrumentCode,
    LocalDate tradeDate,
    Instant availableAt,
    FactorIdentity factor,
    BigDecimal rawValue,
    BigDecimal processedValue,
    ObservationQuality quality,
    String sourceFingerprint,
    String calculationFingerprint
) {}
```

`availableAt` 是防止未来数据泄漏的核心字段。若输入字段在组合形成时间尚不可获得，该观测必须拒绝或延迟到实际可用日期，不能只依赖 `tradeDate`。

### 4.4 研究对象

研究 Agent 和前端共同使用以下聚合：

- `ResearchQuestion`：用户问题、范围和创建来源；
- `ResearchHypothesis`：预期方向、经济机制、评价指标和预注册失败条件；
- `ResearchPlan`：数据、因子、工具步骤、对照实验、预算和审批状态；
- `ResearchRun`：状态机、当前步骤、预算消耗、开始/结束/停止原因；
- `ResearchExperiment`：不可变参数、输入指纹、输出指标和日志；
- `ResearchFinding`：事实、解释、证据、反证、适用范围和置信等级；
- `ResearchConclusion`：`SUPPORTED`、`REFUTED` 或 `INCONCLUSIVE`；
- `InvalidationCondition`：何种数据、市场状态或后续证据会使结论失效。

## 5. 数据存储设计

### 5.1 冻结资金行为表

在量化数据集域新增：

```sql
CREATE TABLE quant_capital_flow_daily (
    dataset_id                 VARCHAR(64) NOT NULL,
    trade_date                 DATE NOT NULL,
    instrument_code            VARCHAR(32) NOT NULL,
    available_at               TIMESTAMP NOT NULL,
    main_net_inflow            DECIMAL(24, 6),
    main_flow_share            DECIMAL(18, 10),
    super_large_net_inflow     DECIMAL(24, 6),
    large_net_inflow           DECIMAL(24, 6),
    medium_net_inflow          DECIMAL(24, 6),
    small_net_inflow           DECIMAL(24, 6),
    turnover_rate              DECIMAL(18, 10),
    amount                     DECIMAL(24, 6),
    provider_code              VARCHAR(64) NOT NULL,
    quality_status             VARCHAR(32) NOT NULL,
    source_fingerprint         VARCHAR(128) NOT NULL,
    calculation_version        VARCHAR(64) NOT NULL,
    PRIMARY KEY (dataset_id, trade_date, instrument_code)
);
```

冻结服务从通过 `CapitalHistoryQualityGate` 的历史快照读取数据，并按研究截止时间过滤 `available_at`。冻结过程与行情数据处于同一数据集事务或两阶段状态机中：只有所有必需分区成功并完成总指纹后，数据集才从 `BUILDING` 变为 `READY`。

### 5.2 数据集级别与清单

`QuantDataset` 增加：

- `level`: `LEARNING` / `RESEARCH`；
- `asOfTime`：研究时点；
- `universeDefinition`：股票池版本；
- `partitions`：行情、基本面、资金行为等分区清单；
- `qualityReportId`；
- `datasetFingerprintVersion`。

总指纹按稳定字段序列化后计算：

```text
SHA-256(
  schemaVersion
  + asOfTime
  + universeDefinitionVersion
  + sorted(partitionType, rowCount, minDate, maxDate, partitionFingerprint)
)
```

数据集一旦 `READY` 即不可修改。刷新生成新数据集，不复用旧标识。

### 5.3 研究与审计表

建议新增：

- `research_factor_definition`
- `research_factor_lifecycle_event`
- `research_factor_evaluation`
- `research_factor_metric`
- `research_plan`
- `research_run`
- `research_tool_call`
- `research_experiment_link`
- `research_finding`
- `research_conclusion`
- `research_approval`

大体量时间序列结果仍写入专用结果表或对象化 JSON，但关键检索字段必须结构化存储。所有记录包含 `created_at`、`schema_version` 和逻辑主体标识；审计与审批记录只追加、不覆盖。

## 6. 因子计算架构

### 6.1 Provider 扩展点

将 `QuantBacktestEngine` 对具体注册表的直接构造改为依赖注入：

```java
interface FactorProvider {
    boolean supports(FactorIdentity factor);
    FactorObservation calculate(FactorCalculationContext context,
                                ResearchFactorDefinition definition);
    FactorProviderMetadata metadata();
}
```

首批 provider：

- `PriceVolumeFactorProvider`
- `FundamentalFactorProvider`
- `CapitalFlowFactorProvider`
- `DerivedFactorProvider`

`FactorProviderRegistry` 只负责路由和重复声明校验，不拥有领域定义。回测、评价和 Agent 工具都通过同一 `FactorCalculationService` 获取观测，防止各自重复计算。

### 6.2 受控表达式 DSL

简单因子使用类型安全 AST，不接受任意脚本。首批运算符：

```text
REF, DELTA, RETURN, MEAN, SUM, STD, MAX, MIN,
TS_RANK, CS_RANK, CORR, COV, ZSCORE, PERCENTILE,
ABS, SIGN, LOG, DIVIDE_SAFE, NEUTRALIZE
```

每个运算符定义输入类型、窗口要求、缺失传播、零除行为、最小样本和 `operatorVersion`。复杂因子使用经过注册和测试的 `FactorCalculator` 类，并以 `calculatorKey + version` 进入计算指纹。

### 6.3 预处理流水线

处理顺序显式配置并写入结果：

1. point-in-time 与股票池过滤；
2. 缺失策略；
3. 异常值诊断；
4. 去极值；
5. 行业/规模/波动率/流动性中性化；
6. 标准化或截面排名；
7. 覆盖率与质量标记。

顺序变化视为新计算版本。默认禁止静默填充；任何填充值都必须有来源、范围和质量标记。

### 6.4 首批资金行为公式

设当日主力净流入为 `main_flow`、成交额为 `amount`：

- `MAIN_FLOW_SHARE = DIVIDE_SAFE(main_flow, amount)`
- `MAIN_FLOW_ZSCORE_20D = ZSCORE(MAIN_FLOW_SHARE, 20)`
- `NORMALIZED_MAIN_FLOW_SUM_5D = SUM(MAIN_FLOW_SHARE, 5)`
- `NORMALIZED_MAIN_FLOW_SLOPE_5D`：对最近 5 日 `MAIN_FLOW_SHARE` 做固定版本线性斜率计算
- `SUPER_LARGE_CONTRIBUTION = DIVIDE_SAFE(super_large_net_inflow, amount)`
- `FLOW_PERSISTENCE_5D = MEAN(SIGN(MAIN_FLOW_SHARE), 5)`
- `PRICE_FLOW_DIVERGENCE`：固定窗口价格收益方向与资金强度趋势的背离值
- `SECTOR_RELATIVE_FLOW_STRENGTH = NEUTRALIZE(MAIN_FLOW_SHARE, industry)`

上述均先以 `CANDIDATE` 建档，公式只是待验证假设，不暗示有效。

## 7. 评价引擎

### 7.1 评价输入

`FactorEvaluationRequest` 必须包含：

- 因子身份与计算版本；
- 数据集标识、指纹和级别；
- 股票池版本与过滤规则；
- 组合形成时间与未来收益口径；
- 1/3/5/10/20 等持有期；
- 预处理方案；
- 分组数量、权重和再平衡规则；
- 费用、冲击和不可交易处理；
- 样本内/样本外切分；
- 验证政策版本。

### 7.2 横截面评价步骤

1. 审计数据质量和 point-in-time；
2. 生成每日因子截面和未来收益标签；
3. 输出覆盖率、分布、异常和截面样本量；
4. 计算 Pearson IC、Spearman Rank IC 及时间序列；
5. 汇总 IC 均值、标准差、ICIR、正 IC 比例、置信区间与 HAC/Newey-West 修正统计；
6. 计算分位数组合收益、最高减最低、单调性和持有期衰减；
7. 计算换手、排名自相关、调仓频率敏感性和交易成本后表现；
8. 分析行业、规模、beta、波动率和流动性暴露；
9. 运行中性化评价、因子相关性和增量 IC；
10. 运行样本外、walk-forward、市场阶段、参数扰动、股票池与数据源变化；
11. 运行 bootstrap、多重检验修正；策略层结果可补充 Deflated Sharpe Ratio；
12. 由验证政策根据结构化结果给出门禁事实，人工决定正式状态。

### 7.3 标签与重叠

未来收益必须明确价格字段和成交假设，例如 `t+1 open → t+h close`。当持有期大于调仓间隔时，统计显著性必须处理重叠收益的序列相关，不能把每个观察视为独立样本。

标签生成器读取 `availableAt`，确保因子形成时间早于可交易时点。停牌、涨跌停、退市和缺失未来价格使用版本化策略处理，并同时报告排除比例。

### 7.4 验证政策

阈值集中在版本化 `FactorValidationPolicy`，不得散落为 magic number。政策至少描述：

- 最小截面日数、每日最小标的数和覆盖率；
- 样本外占比和最少市场阶段；
- IC、分组单调性、成本后差值和稳定性要求；
- 最大换手、暴露和相关性风险；
- 必需的参数扰动与反证实验；
- 多重检验方法和允许的研究次数；
- 不同数据集级别允许达到的最高状态。

门禁输出逐项 `PASS/FAIL/NOT_APPLICABLE` 及证据，不只输出一个总分。

## 8. Agent 研究架构

### 8.1 一个编排器，四类职责

采用一个逻辑 `ResearchOrchestrator`，内部拆分职责而非制造多个自由聊天 Agent：

- `ResearchPlanner`：把用户问题转为假设、实验计划、失败条件和预算；
- `DeterministicToolLayer`：执行白名单研究工具；
- `RobustnessReviewer`：主动检查泄漏、过拟合、成本、暴露和反证；
- `ResearchMemoryService`：持久化可检索、带版本和证据的研究记录。

编排器使用持久化状态机，服务重启后从已完成工具的幂等结果恢复，不依赖对话上下文重放。

### 8.2 运行状态机

```text
DRAFT
  → AWAITING_APPROVAL
  → APPROVED
  → RUNNING
  → ROBUSTNESS_REVIEW
  → AWAITING_DECISION
  → COMPLETED

任意运行态 → PAUSED / CANCELLED / FAILED / BUDGET_EXHAUSTED
```

`ResearchPlanScope` 固定以下边界：数据集、股票池、因子集合、参数范围、工具白名单、最大调用数、最大实验数、最长运行时间和费用预算。每次工具调用前由 `ResearchPolicyGuard` 重新校验。

### 8.3 白名单工具

首批工具：

| 工具 | 用途 | 是否可改变正式状态 |
|---|---|---|
| `inspect_dataset` | 查看范围、质量、指纹 | 否 |
| `audit_point_in_time` | 检查未来数据泄漏 | 否 |
| `inspect_factor_definition` | 查看定义、版本、来源 | 否 |
| `calculate_factor_coverage` | 计算覆盖率和缺失 | 否 |
| `run_factor_diagnostics` | 分布、异常、暴露诊断 | 否 |
| `run_quantile_analysis` | 分位收益和单调性 | 否 |
| `run_factor_correlation` | 因子相关性 | 否 |
| `run_neutralized_analysis` | 中性化前后对比 | 否 |
| `run_single_factor_backtest` | 单因子组合回测 | 否 |
| `run_walk_forward` | 滚动样本外评价 | 否 |
| `run_cost_stress` | 交易成本压力测试 | 否 |
| `run_parameter_sensitivity` | 参数扰动 | 否 |
| `compare_experiments` | 同口径实验比较 | 否 |
| `retrieve_capital_evidence` | 获取资金事件证据 | 否 |
| `read_research_memory` | 检索历史结论 | 否 |
| `write_research_finding` | 保存有证据的发现 | 仅新增研究记录 |

每个工具具备 JSON Schema、权限、数据范围、超时、幂等键、预算权重、输入/输出指纹和错误码。工具只接受业务参数，不接受代码、SQL、文件路径或网络地址。

### 8.4 数值信任边界

LLM 输出中的每个指标引用 `evidenceRef`。服务端执行以下校验：

- 引用必须存在且属于当前研究运行；
- 展示数值必须能从工具结构化结果按字段路径读取；
- 单位、精度、周期和样本范围由渲染层补充，不由 LLM 自由生成；
- 缺少引用的句子只能标记为解释或假设，不能标记为事实；
- Robustness Reviewer 找到的关键反证不可被最终摘要删除。

### 8.5 自动与人工边界

用户批准计划后，Agent 可在参数范围内选择下一项已批准工具、跳过已由证据证明无意义的后续步骤，并在低风险诊断间迭代。以下操作由硬门禁阻止并要求新审批：

- 扩大股票池、日期、数据源或预算；
- 新增未批准因子或改变假设方向；
- 更改正式策略版本；
- 将因子升级为 `VALIDATED/PRODUCTION_ELIGIBLE`；
- 执行任意代码、外部网络访问或交易操作。

## 9. API 设计

### 9.1 资金行为桥接

```text
POST /api/research-drafts/from-capital-signal
GET  /api/capital-behavior/{code}/factor-candidates
GET  /api/factor-research/factors/{namespace}/{code}/versions/{version}/capital-evidence
```

创建请求包含 `instrumentCode`、`observationDate`、`signalCode`、候选因子版本和来源证据标识。响应为草稿，不触发评价。

### 9.2 因子与评价

```text
GET  /api/factor-research/factors
GET  /api/factor-research/factors/{namespace}/{code}/versions/{version}
POST /api/factor-research/evaluations
GET  /api/factor-research/evaluations/{evaluationId}
GET  /api/factor-research/evaluations/{evaluationId}/explanation
POST /api/factor-research/factors/{id}/lifecycle-transitions
```

评价创建使用幂等键；重复请求返回原任务。生命周期迁移单独鉴权，不复用评价接口。

### 9.3 Agent 研究


## 10. 面向前端的解释契约

后端不只返回指标，还返回统一的解释模型：

```json
{
  "verdict": "INCONCLUSIVE",
  "plainSummary": "高资金流入强度在当前样本中表现更好，但样本外没有保持稳定。",
  "reasons": [
    {"text": "样本内排序关系为正", "evidenceRef": "metric:rank_ic:is"},
    {"text": "样本外排序关系接近零", "evidenceRef": "metric:rank_ic:oos"}
  ],
  "risks": [
    {"code": "OOS_DECAY", "plainText": "换到未参与调参的数据后，效果明显减弱。"}
  ],
  "nextActions": [
    {"action": "RUN_NEUTRALIZED_ANALYSIS", "reason": "检查结果是否主要来自小盘股暴露。"}
  ],
  "professionalDetailsRef": "factor-evaluation:eval-123"
}
```

前端按三层展示：

1. 默认：结论、证据状态、风险、下一步；
2. “为什么”：证据解释、对照和术语说明；
3. “专业详情”：公式、时间序列、统计检验、来源、指纹和工具输出。

术语服务返回“它回答什么问题”“当前结果如何理解”“常见误区”，不只返回抽象定义。

## 11. 可观测性、错误与安全

### 11.1 可观测性

统一追踪字段：`researchRunId`、`planId`、`toolCallId`、`experimentId`、`datasetFingerprint`、`factorVersion`、`strategyVersion`、`calculationVersion`。

监控至少覆盖：

- 数据冻结成功率、质量门禁失败原因和指纹冲突；
- 评价队列时长、各阶段耗时、超时与恢复次数；
- Agent 工具成功率、预算消耗、越权拦截和证据引用校验失败；
- 同输入非确定性结果、未来数据审计失败和状态迁移拒绝。

### 11.2 错误模型

错误码按领域分类：

- `DATASET_NOT_READY`
- `DATA_QUALITY_GATE_FAILED`
- `POINT_IN_TIME_VIOLATION`
- `FACTOR_VERSION_MISMATCH`
- `INSUFFICIENT_CROSS_SECTION`
- `EVALUATION_NOT_COMPARABLE`
- `TOOL_SCOPE_VIOLATION`
- `RESEARCH_BUDGET_EXHAUSTED`
- `EVIDENCE_REFERENCE_INVALID`
- `LIFECYCLE_TRANSITION_FORBIDDEN`

错误响应同时包含面向用户的解释、可恢复动作和专业诊断标识。

### 11.3 安全边界

- Agent 工具使用服务端注册表，不从模型输出解析类名或 endpoint；
- 数据访问按批准的数据集和用户权限过滤；
- 禁止工具参数包含 SQL、脚本、文件路径或任意 URL；
- 审批、状态迁移和策略版本写入均要求防重放令牌与审计记录；
- 外部来源只由独立摄入流程引入，Agent 研究运行不临时抓取数据；
- 所有展示包含“研究工具，不构成投资建议”的固定风险说明。

## 12. 性能与运行约束

- 因子矩阵按 `dataset + factorVersion + preprocessingVersion` 缓存，缓存内容不可跨指纹复用；
- 评价任务按股票池和日期分区并行，但汇总顺序固定以保证确定性；
- 大型 IC 序列和净值序列分页读取，默认摘要不返回全量点位；
- Agent 同一计划默认顺序运行有依赖的工具，无依赖诊断可受控并行；
- 工具超时后写入明确终态，重试沿用幂等键；
- 数据冻结和计算结果使用 `BigDecimal` 或明确精度策略，指纹序列化固定时区、排序和小数格式。

## 13. 兼容与迁移

### 13.1 现有因子迁移

现有 `FactorRegistry` 中的因子先自动映射为 `legacy` namespace 的定义草稿，状态不高于 `IMPLEMENTED`。补齐来源、计算核验和评价证据后再进入后续状态。旧 API 在过渡期由适配层读取新定义，但不立即删除。

### 13.2 现有实验

历史实验继续可读，标记为 `LEGACY_EVIDENCE_LEVEL`。缺少资金数据分区、完整指纹或评价协议版本的实验不能与新正式实验直接比较，也不能作为因子验证依据。

### 13.3 资金事件评价

保留现有 `CapitalFactorEvaluationService` 和 `capital-evaluation-v2` 结果。新增统一证据适配器，只转换元数据和链接，不把事件统计字段伪装为 IC 指标。

## 14. 测试策略

### 14.1 因子计算

- 黄金向量：对每个运算符和首批资金因子验证固定输入输出；
- 性质测试：排名单调性、标准化均值/方差、缩放不变性、安全除法；
- 变形测试：未来日期数据变化不得影响过去因子值；
- 缺失、零成交额、停牌、极值和行业缺失边界；
- 相同输入的值、指纹和序列化完全一致。

### 14.2 评价正确性

- 随机因子不应被稳定地判为有效；
- 植入已知横截面信号时能恢复方向、衰减和分位单调性；
- 标签重叠时使用正确的统计修正；
- 中性化后移除人为植入的行业或规模暴露；
- 成本上升时成本后收益不得反向增加；
- 样本内过拟合因子在样本外门禁被拒绝；
- 多候选搜索触发多重检验和研究次数记录。

### 14.3 Agent 信任边界

- Agent 无法调用未注册工具或扩大已批准范围；
- Agent 无法写入 `VALIDATED` 和 `PRODUCTION_ELIGIBLE`；
- 虚构 `evidenceRef`、篡改数字或删除关键反证时校验失败；
- 工具超时、服务重启、重复回调和预算耗尽均可恢复到明确状态；
- 同一批准计划重复提交不会创建重复实验。

### 14.4 端到端验收

1. 从资金行为信号创建研究草稿；
2. 冻结包含资金分区的研究数据集；
3. 运行资金因子覆盖、IC、分组收益、中性化、样本外和成本压力评价；
4. Agent 引用工具结果生成支持/反驳/证据不足结论；
5. 页面默认层用自然语言展示，专业层可回溯公式、指纹和实验；
6. 未经人工审批不能发布因子或修改正式策略。

## 15. 分期实施

### Phase A1：研究模型与资金数据桥

- 建立 `factor-research` 模块和数据库迁移；
- 实现因子定义、版本和生命周期；
- 实现资金行为分区冻结、point-in-time 审计和总指纹；
- 引入 `FactorProvider`，保留旧实现适配器；
- 完成研究草稿和统一解释契约。

### Phase A2：评价与门禁

- 实现多持有期 IC、分位组合、换手、衰减和暴露；
- 实现中性化、样本外、walk-forward、参数与成本压力；
- 实现版本化验证政策和学习/研究数据集级别；
- 让首批资金候选因子达到 `EXPLORATORY`，不预设验证结果。

### Phase C：受控研究 Agent

- 实现计划、审批、状态机、白名单工具和预算守卫；
- 实现 Robustness Reviewer 和证据引用校验；
- 实现结构化研究记忆、实验比较和失败恢复；
- 完成越权、幻觉数值和反证保留测试。

### Phase B：扩展因子库

- 先补行业、规模、beta、波动率和流动性控制因子；
- 再补可解释的价格量、基本面与资金行为因子；
- 最后通过 DSL 接入经审查的 Qlib/经典表达式候选；
- 每个候选仍执行定义评审、计算核验、探索、稳健性和人工发布。

## 16. 关键决策记录

| 决策 | 选择 | 原因 |
|---|---|---|
| 跨域方式 | 新增中立 `factor-research` | 避免实时观察、研究协议和回测执行职责混杂 |
| 资金数据接入 | 冻结到量化数据集 | 保证复现，不让历史回测读取可变线上表 |
| 因子扩展 | Provider + 受控 DSL | 可扩展、可审计，禁止任意代码 |
| 评价模型 | 事件研究与横截面研究并存 | 两者回答不同问题，不能相互替代 |
| Agent 自主性 | 计划审批后的有限自主 | 提高研究效率，同时保留数据、预算和发布控制 |
| 专业呈现 | 三层解释 | 默认易懂，细节可复核，不增加默认页面复杂度 |
| 正式准入 | 版本化门禁 + 人工审批 | 防止阈值漂移和 Agent 自我背书 |
