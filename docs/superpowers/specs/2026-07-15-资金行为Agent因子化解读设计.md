# 资金行为 Agent 因子化解读设计

- 日期：2026-07-15
- 状态：设计调整已确认，待书面规格复核
- 适用页面：`Market Intel · 资金行为`
- 目标版本：`capital-interpret-v2`

## 1. 背景

当前资金行为页已经保存分钟级和日线资金事实，并展示成交量、成交额、换手率、量比、主力净流向等指标，但 Agent 解读仍然接近“对少量原始数字做语言改写”。主要原因不是模型能力不足，而是 Agent 输入、确定性计算和输出验收之间缺少一层稳定的资金行为认知模型。

现有 `CapitalInterpretationAgent` 只向模型传递时间、价格、成交额和主力净额，没有传递成交量、换手率、量比、超大单、大单、中单、小单等已有字段；`CapitalBehaviorSignalService` 也只有少量固定规则。模型因此无法稳定解释量能、换手、订单结构、日内节奏和多周期资金趋势。

本设计吸收以下原则：

1. 数字和标签由代码计算，LLM 只负责综合与表达。
2. 先形成可复算因子，再形成状态标签，最后生成自然语言解读。
3. 所有结论必须引用因子或原始指标，不能产生证据包之外的数字。
4. 解读目标是识别当前盘面状态和后续验证条件，不预测涨跌，不提供买卖建议。
5. 第一阶段优先利用现有数据，不以增加页面字段或扩大数据源为前提。

## 2. 目标与非目标

### 2.1 目标

1. 建立资金行为专用的确定性因子注册、计算和版本管理能力。
2. 将分钟级与日线资金事实加工为量能、换手、资金强度、订单结构和日内节奏因子。
3. 在因子之上生成可复算、带阈值和证据引用的资金行为信号。
4. 通过不可变 `AgentEvidencePacket` 向模型提供完整、受控的分析上下文。
5. 升级 Agent 输出协议，明确区分事实、观察、假设、反证、观察条件和数据缺口。
6. 对模型输出执行 Schema、引用、数字和置信度门禁。
7. 页面明确展示模型成功、规则兜底和数据不足状态，不把 fallback 伪装成模型成功。
8. 为后续资金因子历史评价和外部证据扩展保留边界。
9. 建立外部因子研究来源、适配类型、准入状态和评价状态的可审计目录。

### 2.2 非目标

本版本不建设以下能力：

- 不做多 Agent 辩论或开放式自主委派。
- 不做聊天式股票问答。
- 不输出买卖、仓位、目标价或涨跌预测。
- 不引入 LangGraph、Qlib、向量数据库或新的 Python 运行时。
- 不让在线请求链路依赖 Qlib、RD-Agent、外部因子仓库或公式 RAG。
- 不在在线服务中执行任意公式字符串或 Agent 生成的代码。
- 不批量照搬 Alpha158、Alpha360 或 101 Formulaic Alphas。
- 不在第一阶段批量接入龙虎榜、新闻、公告、融资融券等新数据。
- 不把未经历史检验的盘面标签描述为有效预测因子。
- 不允许模型自行计算或补全缺失数字。

## 3. 方案决策

采用“确定性资金因子引擎 + 单一综合 Agent + 证据门禁”的方案。

不采用只扩写 Prompt 的方案，因为它无法保证计算口径、证据引用和输出稳定性；也不在当前阶段采用多 Agent，因为多个角色读取同一份薄数据只会产生重复文本，不能形成真正独立的分析证据。

总体链路如下：

```text
CapitalFlowPoint 分钟/日线事实
  -> CapitalFactorEngine
  -> CapitalSignalEngine
  -> CapitalAgentEvidenceAssembler
  -> CapitalInterpretationAgent v2
  -> CapitalInterpretationGate
  -> CapitalAgentInterpretationPanel
```

模型始终位于确定性计算之后、输出验收之前。

## 4. 领域边界

### 4.1 资金行为因子与量化策略因子分离

新建 `CapitalFactorRegistry`，不直接扩展现有 `FactorRegistry`。

两类因子虽然共享注册、版本、计算和评价思想，但业务语义不同：

- 量化策略因子用于全市场截面排序、组合构建和历史回测。
- 资金行为因子用于单个标的的时间序列状态识别、日内结构和解释。

二者可以复用设计模式和统计工具，但不得共用含义模糊的因子编码或数据模型。

### 4.2 LLM 不直接访问仓储和数据源

`CapitalInterpretationAgent` 只接收已经组装好的不可变证据包，不读取 Repository、不请求外部 HTTP、不自行选择数据源，也不修改资金事实、因子结果或信号。

### 4.3 继续复用 Agent Harness

Agent 调用继续进入现有 `AgentHarness`、fingerprint、预算、Trace 和 fallback 体系。新设计只增强资金领域输入和输出，不引入第二套工作流运行时。

### 4.4 研究来源与运行依赖分离

Qlib、101 Formulaic Alphas、Alphalens、RD-Agent 以及其他开源项目只作为研发阶段的因子发现和工程方法来源。FinScope 运行时不克隆、不查询也不加载这些项目，而是把通过评审的思想重新实现为本地、确定、可测试的 Java 代码。

每个外部启发因子必须记录原始来源、规范公式、字段要求、适配说明和解释边界。Agent 只接收本地注册表中的正式定义及其计算结果，不检索外部项目文档来决定因子含义。

第一批研究来源为：

- [Qlib Alpha158/Alpha360](https://github.com/microsoft/qlib/blob/d5379c520f66a39953bad76234a7019a72796fd0/qlib/contrib/data/loader.py)：借鉴窗口化特征族、算子组合和特征/标签分离。
- [101 Formulaic Alphas](https://arxiv.org/abs/1601.00991)：借鉴排名、差分、相关性、衰减和价量组合范式，不默认接受原始参数和有效性。
- [Alphalens](https://github.com/quantopian/alphalens/blob/77084f1e4c2c0be407e032d444fb19e4be4b0f37/alphalens/performance.py)：借鉴前向收益、IC、分位收益、换手和衰减评价。
- [RD-Agent](https://github.com/microsoft/RD-Agent/blob/4f9ecb005881cddc08df0124a2e894c018007679/rdagent/components/workflow/rd_loop.py)：借鉴假设、实验、实现、运行、反馈和 Trace 闭环，不接入其运行时。

## 5. 确定性资金因子模型

### 5.1 因子定义

`CapitalFactorDefinition` 至少包含：

```text
code
name
category
description
expressionKind
canonicalFormula
calculationKey
requiredFields
window
minimumSamples
sourceType
sourceRef
adaptationType
calculationVersion
evaluationStatus
interpretationBoundary
```

`interpretationBoundary` 用于描述允许的解释边界，例如“仅表示公开资金口径下大单与小单方向不同，不能确认机构与散户真实身份”。

字段约束：

- `expressionKind` 只能是 `DECLARATIVE` 或 `CALCULATOR`。简单窗口计算使用声明式定义，复杂订单结构和日内节奏使用显式 Calculator。
- `canonicalFormula` 使用人类可审阅的规范公式，用于展示、审计和 fingerprint，不通过 `eval` 或脚本解释执行。
- `calculationKey` 指向代码中已注册的类型安全计算计划或 Calculator。声明式计划通过 Java 表达式节点构建，规范公式由同一计划渲染，避免展示公式与实际计算漂移。
- `sourceType` 第一版支持 `INTERNAL`、`QLIB`、`FORMULAIC_ALPHA_101`、`PAPER` 和 `OSS_PROJECT`。
- `adaptationType` 只能是 `ORIGINAL`、`ADAPTED` 或 `PROXY`。代理实现必须在 `interpretationBoundary` 中说明损失的信息。
- `evaluationStatus` 只能是 `UNTESTED`、`EXPLORATORY`、`VALIDATED` 或 `INVALIDATED`。准入拒绝使用独立的 `REJECTED` 状态，不能混用。
- 定义在应用启动时注册为不可变目录，第一版不提供页面动态修改公式的能力。

### 5.2 因子观测

`CapitalFactorObservation` 至少包含：

```text
factorCode
observedAt
window
value
baseline
percentile
zScore
state
sampleCount
metricRefs
qualityStatus
calculationVersion
```

未满足最小样本数时不输出伪造的分位数或 Z-score，而是生成明确的数据缺口。

### 5.3 轻量因子算子模型

不建设 Qlib 完整表达式引擎，而是采用“类型安全算子库 + 声明式定义 + 复杂 Calculator”的混合方案。

底层时间序列算子为无市场语义的纯 Java 函数，可由量化因子和资金行为因子复用；两类业务仍保留各自独立的 Definition、Registry 和评价边界。第一版支持：

```text
REF
DELTA
MEAN
SUM
STD
ZSCORE
TS_RANK
QUANTILE
SLOPE
RSQUARE
CORR
MIN
MAX
POSITIVE_SHARE
```

约束：

1. `TS_RANK` 表示单标的历史窗口排名，不能与全市场横截面 `CS_RANK` 混用。当前资金行为页不实现 `CS_RANK`。
2. 所有算子统一处理排序、最小样本、空值、非有限数、零分母和精度。
3. 声明式因子只能组合白名单算子和已注册字段，不执行任意字符串。
4. 订单结构背离、日内反转、尾盘占比等具有领域语义的计算继续使用独立 Calculator。
5. 同一输入、算子版本、因子定义和窗口必须产生相同结果。

### 5.4 第一批因子

#### 量能与交易活跃度

| 因子编码 | 含义 |
|---|---|
| `AMOUNT_RATIO_5D` | 当前成交额相对近5日平均成交额 |
| `AMOUNT_RATIO_20D` | 当前成交额相对近20日平均成交额 |
| `AMOUNT_ZSCORE_20D` | 当前成交额在近20日的标准化异常程度 |
| `TURNOVER_PERCENTILE` | 换手率在当前可用20/60日窗口中的分位 |
| `VOLUME_RATIO_LATEST` | 最新有效量比 |

#### 资金强度与连续性

| 因子编码 | 含义 |
|---|---|
| `MAIN_FLOW_SHARE` | 主力净额占同周期成交额比例 |
| `MAIN_FLOW_SUM_5D` | 近5日累计主力净额 |
| `MAIN_FLOW_SUM_10D` | 近10日累计主力净额 |
| `MAIN_FLOW_SUM_20D` | 近20日累计主力净额 |
| `MAIN_FLOW_STREAK` | 当前连续净流入或净流出周期数 |
| `MAIN_FLOW_SLOPE_5D` | 近5日主力净额变化方向和强度 |
| `MAIN_FLOW_ZSCORE_20D` | 当前主力净额的历史异常程度 |

#### 订单结构代理

| 因子编码 | 含义 |
|---|---|
| `BIG_ORDER_NET` | 超大单与大单净额合计 |
| `SMALL_MID_ORDER_NET` | 中单与小单净额合计 |
| `BIG_SMALL_DIVERGENCE` | 大单方向与中小单方向是否背离 |
| `SUPER_LARGE_CONTRIBUTION` | 超大单对主力净额的贡献比例 |

上述因子只能解释为公开口径下的订单结构代理，不能直接声称机构吸筹、散户接盘或主力出货。

#### 价格、量能与资金关系

| 因子编码 | 含义 |
|---|---|
| `PRICE_FLOW_ALIGNMENT` | 价格方向与主力净流向是否一致 |
| `PRICE_VOLUME_ALIGNMENT` | 价格变化与量能变化是否一致 |
| `PRICE_VOLUME_FLOW_REGIME` | 价格、量能、资金三维组合状态 |

#### 日内节奏

| 因子编码 | 含义 |
|---|---|
| `INTRADAY_FLOW_REVERSALS` | 当日资金方向有效反转次数 |
| `INTRADAY_FLOW_ACCELERATION` | 最近几个周期资金流入/流出是否加速 |
| `LATE_SESSION_FLOW_SHARE` | 尾盘资金净额占全天主力净额或绝对流量比例 |
| `PEAK_INFLOW_BUCKET` | 最大净流入时间区间 |
| `PEAK_OUTFLOW_BUCKET` | 最大净流出时间区间 |

### 5.5 因子候选与准入

外部项目或论文中的公式先进入候选目录，不直接进入 `CapitalFactorRegistry`。准入状态按以下顺序推进：

```text
CANDIDATE
  -> FEASIBILITY_PASSED
  -> IMPLEMENTED
  -> TESTED
  -> PUBLISHED
```

任何阶段都可以进入 `REJECTED`，并保留拒绝原因。准入检查至少包括：

1. 当前数据是否具备全部必需字段。
2. 原公式是单标的时间序列还是全市场横截面，避免语义误配。
3. 是否需要行业中性化、逐笔成交、Level-2 或其他当前缺失数据。
4. 适配后属于原始实现、参数调整还是代理实现。
5. 单元测试是否覆盖公式样例、边界值和排序无关性。
6. 是否与已有因子重复或高度同义。

只有 `PUBLISHED` 因子可以进入信号引擎和 Agent 证据包。`UNTESTED` 表示尚未验证预测能力，不妨碍其用于描述当前盘面，但 Agent 必须受到解释边界约束。

## 6. 资金行为信号

`CapitalSignalEngine` 只消费因子观测，不重复读取和解释原始事实。第一版支持以下信号：

- 放量净流入
- 放量净流出
- 缩量净流入
- 缩量净流出
- 高换手分歧
- 价格上涨但资金流出
- 价格下跌但资金流入
- 大单与中小单方向背离
- 超大单主导流入
- 超大单主导流出
- 资金连续增强
- 资金连续衰减
- 日内资金加速流入
- 日内资金加速流出
- 日内资金方向反转
- 尾盘流入增强
- 尾盘流出增强

每条信号必须保存：

```text
code
label
window
actualValues
thresholds
factorRefs
metricRefs
qualityStatus
ruleVersion
```

阈值优先使用历史分位和 Z-score。固定金额不能作为跨标的通用阈值。所有规则进入版本化策略，第一版标记为 `capital-signal-v2`。

## 7. Agent 证据包

`CapitalAgentEvidencePacket` 是 Agent 唯一输入，结构如下：

```json
{
  "snapshot": {},
  "quality": {},
  "factorObservations": [],
  "signals": [],
  "rawMetrics": [],
  "allowedHypotheses": [],
  "watchConditions": [],
  "dataGaps": []
}
```

约束：

1. `rawMetrics` 只保留必要事实和可引用 ID，不将全部原始时间序列无差别塞入 Prompt。
2. `factorObservations` 包含值、基线、分位、样本数和解释边界。
3. `signals` 是规则引擎已经确认的状态，不由模型重算。
4. `watchConditions` 的指标与阈值由服务端生成，模型只能选择和解释。
5. `dataGaps` 必须包含数据质量、缺失字段、样本不足和 Level-2 边界。
6. 证据包参与 fingerprint；事实、因子版本或规则版本变化后必须生成新的解读缓存键。

## 8. Agent v2 输出协议

模型输出严格 JSON，协议版本为 `capital-interpret-v2`：

```json
{
  "marketState": "",
  "executiveSummary": "",
  "observations": [
    {
      "dimension": "VOLUME|TURNOVER|FLOW|ORDER_STRUCTURE|INTRADAY|MULTI_PERIOD",
      "claim": "",
      "factorRefs": [],
      "metricRefs": []
    }
  ],
  "hypotheses": [],
  "counterEvidence": [],
  "watchConditionRefs": [],
  "dataGaps": [],
  "confidence": "LOW|MID"
}
```

规则：

- 不允许输出 `HIGH`，直到历史评价和独立证据轨道达到后续版本门槛。
- `marketState` 只能从服务端状态目录中选择。
- `observations` 必须至少覆盖一个有数据的维度，且所有引用必须存在。
- 模型不能在文本中出现证据包之外的数字。
- `hypotheses` 继续使用受控类型目录；吸筹、出货、拆单、隐藏资金在无 Level-2 时只能低置信度。
- `watchConditionRefs` 只能引用服务端生成的观察条件。
- 输出解析支持 Markdown 代码块和附加文本中的 JSON 提取。
- 首次结构校验失败时允许进行一次结构修复；修复提示只包含协议、校验错误和原始响应，不增加新事实。

## 9. 输出门禁

新增 `CapitalInterpretationGate`，负责：

1. 校验输出字段和枚举白名单。
2. 校验所有 `factorRefs`、`metricRefs` 和 `watchConditionRefs`。
3. 拒绝无引用观察和证据包之外的数字。
4. 将模型置信度限制在规则和数据质量允许的上限内。
5. 对缺少 Level-2 的行为归因补充固定反证和数据缺口。
6. 删除无法通过引用校验的单条观察；如果剩余观察为空，则整体进入规则兜底。
7. 保存被拒绝字段数量和原因到 Agent Trace，不在用户界面暴露原始模型正文。

现有 `CapitalHypothesisGate` 的引用和置信度封顶规则迁入或委托给该门禁，避免出现两套不一致规则。

## 10. 失败、降级和明确提醒

页面和接口必须区分以下状态：

| 状态 | 用户提示 | 行为 |
|---|---|---|
| `SUCCEEDED` | 模型解读 | 展示通过门禁的结构化结果 |
| `FALLBACK` | 规则兜底 | 明确展示降级原因和规则解释 |
| `INSUFFICIENT_DATA` | 数据不足 | 展示缺失字段和最低样本要求 |
| `FAILED` | Agent 解读失败 | 展示可理解错误，不伪造结果 |

降级原因至少区分：

- `LLM_NOT_CONFIGURED`
- `LLM_TIMEOUT`
- `INVALID_MODEL_OUTPUT`
- `OUTPUT_REJECTED_BY_GATE`
- `INSUFFICIENT_FACTOR_COVERAGE`
- `PARTIAL_MARKET_DATA`

页面不得只展示 `plainSummary` 而隐藏执行状态。规则兜底结果不能使用“Agent 深度解读成功”的视觉文案。

## 11. 页面信息架构

Agent 区域保持一键运行，不改造成聊天框。展示结构如下：

1. 顶部运行状态：模型解读、规则兜底、数据不足或失败。
2. 一句话资金状态和整体置信度。
3. 维度卡片：量能、换手、资金强度、订单结构、日内节奏、多周期趋势。
4. 支持证据：使用人类可读标签，不直接展示裸 `flow:102:mainNetInflow`。
5. 假设与反证：明确区分已确认状态和待验证行为假设。
6. 后续观察：展示由服务端生成的指标条件和阈值。
7. 数据缺口与风险边界。
8. 折叠元信息：模型、Prompt、因子版本、规则版本、快照时间和数据质量。

证据标签保留底层引用，点击后定位并高亮资金证据带或日线资金趋势中的对应记录。

## 12. 与现有能力的复用

### 12.1 直接复用

- `CapitalFlowPoint` 及其 `metricRef`。
- `CapitalBehaviorSnapshot` 和 snapshot fingerprint。
- `CapitalBehaviorMetricsService` 的最新指标和连续性语义。
- `AgentHarness`、Trace、预算和错误分类。
- `LlmChatClient`。
- 量化模块的 Registry、计算器、数据指纹和因子分析设计模式。
- `QuantExperimentAgent` 的 JSON 提取、严格 Schema 和字段白名单模式。

### 12.2 不直接复用

- 不将 `CapitalFactorDefinition` 塞入现有量化 `FactorRegistry`。
- 不使用量化策略的截面 IC 结果替代单标的资金行为评价。
- 不允许 Market Intel Agent 自动发起量化实验或修改策略。

## 13. 历史评价与研究自动化边界

### 13.1 资金行为因子与信号评价

因子解释能力完成后，再增加 `CapitalFactorEvaluationService`。它必须使用严格时点数据，并输出：

- 样本数量
- 标签出现频率
- 后续1/3/5个交易日收益分布
- 正收益占比
- 平均最大有利变化和最大不利变化
- 不同市场阶段的稳定性
- 训练、验证和测试时间段
- 数据覆盖率和缺失损失率

这些结果只能称为“历史统计参考”，不能称为预测概率，除非样本、时间切分和验证方法达到独立产品标准。样本不足时不展示百分比。

资金行为页是单标的时间序列解释，优先使用事件研究：统计信号发生后的1/3/5日收益、最大有利变化、最大不利变化和样本稳定性，不用单只股票的时间序列结果冒充横截面 IC。

### 13.2 量化因子评价

现有量化模块继续使用横截面评价，并逐步补齐 Alphalens 风格指标：

- Spearman IC、Rank IC 均值、标准差、ICIR 和正 IC 比例。
- 因子分位组前向收益和顶底组收益差。
- 分位收益单调性。
- 分位组换手率和因子排名自相关。
- 1/3/5/10日因子衰减。
- 行业调整和市场阶段拆分。

量化因子评价结果不能直接替代资金行为事件评价，但二者共享 `UNTESTED/EXPLORATORY/VALIDATED/INVALIDATED` 状态语义。

### 13.3 自动因子研究

RD-Agent 式“提出假设 -> 生成实验 -> 实现 -> 运行 -> 反馈 -> 迭代”属于独立后续项目，不进入本次 P0～P2。未来建设时必须满足：

- 只在隔离的离线研究环境运行生成代码。
- 每次实验保存输入数据指纹、代码、参数、结果和反馈 Trace。
- 对无穷值、缺失值、索引、样本覆盖、重复因子和参考结果进行确定性门禁。
- Agent 不能自行发布因子，必须经过人工确认后才能进入正式 Registry。
- 在线 Market Intel 请求不能触发实验或执行研究代码。

## 14. 外部数据扩展顺序

第一阶段不依赖新数据。完成现有数据因子化后，按以下顺序扩展 Agent 后台证据：

1. 近120日资金流，用于更稳定的分位和异常检测。
2. 行业相对表现，用于区分个股独立行为和板块共振。
3. 龙虎榜和机构席位，用于补充公开机构行为证据。
4. 融资融券，用于补充杠杆资金变化。
5. 大宗交易和股东户数，用于补充中低频筹码变化。

这些证据不默认堆叠到主页面，只进入证据包和可展开详情。每类外部数据继续通过市场数据网关统一管理来源、fallback、质量状态和明确提醒。

## 15. 版本和迁移

- Prompt：`capital-interpret-v1` 升级为 `capital-interpret-v2`。
- 因子：`capital-factor-v1`。
- 信号：`capital-signal-v2`。
- 规则解释：`capital-rules-v2`。
- 旧解释记录保持可读，不原地改写。
- 新旧解释根据 `promptVersion` 和 `ruleVersion` 选择展示适配器。
- 解读缓存键包含 snapshot fingerprint、factor version、signal version、rule version 和 prompt version。

## 16. 测试策略

### 16.1 因子测试

- 每个基础算子覆盖正常、空值、非有限数、零分母、窗口不足和无序输入。
- `TS_RANK` 与 `CS_RANK` 的语义通过类型和测试隔离。
- 声明式定义只能引用白名单算子与已注册字段。
- 每个因子至少覆盖正常、空值、零分母和样本不足。
- 覆盖日线升序、降序和无序输入，计算结果保持一致。
- 覆盖午间休市和分钟桶相邻关系。
- 覆盖正负净流向、大单小单背离和尾盘占比。
- 候选因子未达到 `PUBLISHED` 时不能进入信号和证据包。

### 16.2 信号测试

- 每条信号覆盖触发和不触发边界。
- 实际值、阈值、因子引用和指标引用可复算。
- 固定金额不得被用作跨标的通用异常阈值。

### 16.3 Agent 契约测试

- 纯 JSON、Markdown 代码块和附加文本 JSON 都能解析。
- 非法枚举、未知引用、外部数字和高置信度被拒绝或降级。
- 第一次失败只允许一次结构修复。
- LLM 未配置、超时和非法输出均产生明确状态。

### 16.4 页面测试

- 模型成功和规则兜底拥有不同提示。
- 数据不足展示缺失原因。
- 人类可读证据标签能定位原始资金记录。
- 不展示裸引用作为主要用户文案。
- 日线与分钟级数据排序不影响因子计算和最新状态。

## 17. 实施阶段

### P0：Agent 可靠性与诚实状态

- JSON 提取和一次结构修复。
- 明确 `SUCCEEDED/FALLBACK/INSUFFICIENT_DATA/FAILED`。
- 页面展示 fallback 原因、模型和版本。

### P1：资金因子与信号引擎

- 建立类型安全时间序列算子库。
- 建立带公式、字段要求、来源、适配类型和评价状态的因子定义。
- 建立因子观测、Calculator 和计算服务。
- 建立候选因子准入状态，正式 Registry 只暴露 `PUBLISHED` 因子。
- 完成第一批五类资金因子。
- 扩展 `capital-signal-v2`。
- 生成数据缺口和服务端观察条件。

### P2：证据包、Agent v2 与页面

- 建立不可变证据包。
- 上线 `capital-interpret-v2`。
- 新增输出门禁。
- 改造 Agent 解读展示和证据定位。

### P3：历史评价

- 建立严格时点的资金行为事件评价。
- 展示样本数、数据覆盖、后续分布、MFE、MAE 和稳定性。
- 为量化模块补充分位收益、换手、排名自相关和衰减评价。
- 不与第一版 Agent 上线相互阻塞。

### P4：外部证据扩展

- 按近120日资金、行业、龙虎榜、两融、筹码顺序接入。
- 继续复用市场数据网关和数据质量提醒。

## 18. 验收标准

1. Agent 使用现有资金事实生成至少三个有引用的分析维度；数据不足时明确说明，不能凑数。
2. 任何展示数字均可追溯到因子观测或原始指标。
3. 模型不能输出不存在的指标引用，门禁后不存在无证据观察。
4. 模型未配置或输出非法时，页面明确显示规则兜底及原因。
5. 量能、换手、资金强度、订单结构、日内节奏和多周期趋势均有确定性计算入口。
6. 同一快照和同一版本产生稳定的证据包 fingerprint 和可缓存解读。
7. 因子和信号规则具备独立单元测试，Agent 契约具备成功、修复和降级测试。
8. 本版本不产生买卖建议、涨跌预测或未经验证的机构意图结论。
9. 外部来源因子具备来源、规范公式、字段要求、适配类型和解释边界。
10. 未发布因子、任意公式字符串和 Agent 生成代码不能进入在线计算链路。
11. FinScope 在线运行不依赖 Qlib、RD-Agent、外部因子仓库或公式 RAG。

## 19. 最终产品定义

资金行为 Agent 的职责是：

> 基于可复算的资金行为因子，解释当前盘面属于什么状态，列出支持证据和反证，并说明后续哪些可观测条件会验证或推翻当前判断。

它不是股票预测器，也不是交易决策器。其技术价值来自确定性计算、证据引用、置信度封顶、数据质量提示和可验证的历史演进路径。
