# 量化因子说明书与研究闭环设计

> 日期：2026-07-16
> 对应 PRD：`docs/产品需求-策略研究中枢第三期.md`
> 路线：A（研究专业化）→ C（受控研究 Agent）→ B（因子扩展）
> 核心体验：页面更易懂，研究契约更严格；不以增加卡片制造专业感。

## 1. 用户问题与设计目标

当前量化工作台把 13 个因子平铺成卡片。用户能看到名称和 IC，但无法快速回答：它衡量什么、为什么可能有效、何时会误导、数据是否可用、当前证据能说明到哪一步。资金行为页虽然已有主力资金证据，也没有进入横截面量化研究的明确入口。

本次改造需要形成一条可追溯路径：

```text
资金行为观察 → 研究草稿 → 冻结数据集 → 因子说明书 → 确定性评价
            → Agent 受控复核 → 结论/反证/失效条件 → 策略实验
```

首屏必须让量化初学者看懂，专业详情必须让研究者能够复核。两者使用同一份后端定义和计算证据，避免前端文案与实现口径漂移。

## 2. 信息架构

保留量化工作台现有三个页签，不增加一级菜单：

- **策略实验室**：从研究假设生成受限策略草稿，明确需要人工确认。
- **因子观测站**：改造成“因子目录 + 单因子说明书”，承载理解、可用性和单因子诊断。
- **实验档案**：保留策略结果，后续加入稳健性与 Agent 研究记录。

因子观测站采用已经确认的 B 方案：

```text
┌──────────────┬────────────────────────────────────┐
│ 搜索与分类目录 │ 单因子说明书                         │
│              │ 1. 它衡量什么                       │
│ 动量         │ 2. 为什么可能有效                   │
│ 价值         │ 3. 最容易误读的地方                 │
│ 质量         │ 4. 当前数据是否支持诊断             │
│ 资金行为     │ 5. 主动运行诊断后的自然语言解释      │
│              │ 6. 公式、字段、时点、缺失与版本详情  │
└──────────────┴────────────────────────────────────┘
```

默认只展开用户决策所需的信息；公式、字段和计算版本放入“专业详情”。不显示因子排行榜，不把探索性指标标成“有效”，不以颜色代替证据。

## 3. 统一因子契约

### 3.1 后端是专业文案的唯一事实源

`ResearchFactorCatalog` 纳入现有 13 个量化因子和 `MAIN_FLOW_SHARE`。每个定义必须与实际 `FactorCalculator` 计算保持一致，并包含：

- 稳定身份：namespace、code、version；
- 初学者解释：plainMeaning；
- 可证伪假设：hypothesis；
- 机制解释：economicRationale；
- 误读与失效边界：interpretationBoundary；
- 输入字段、可获得时间、缺失策略；
- 计算公式、实现版本、来源与评价协议；
- 生命周期状态。

现有因子即使实现和单元测试完备，也只标记为 `CALCULATION_VERIFIED` 或 `EXPLORATORY`；没有样本外、稳健性和人工准入证据时，禁止使用 `VALIDATED`。

### 3.2 目录与可计算能力分离

专业目录回答“这个研究对象是什么”；数据集质量与 Provider 回答“它现在能不能算”。前端用稳定 code 合并两份信息，但不得以目录存在推断数据可用。

资金行为因子即使进入目录，也必须在数据集资金分区未冻结或质量门禁未通过时显示阻断原因，不能降级为零值或偷偷改用线上快照。

## 4. 三层解释

### 4.1 第一层：一分钟看懂

固定回答四件事：

1. 它衡量什么；
2. 为什么有人研究它；
3. 最容易误读什么；
4. 当前处于定义、计算、探索还是验证阶段。

### 4.2 第二层：当前样本怎么说

用户主动点击“运行诊断”后才展示。系统先生成确定性文字摘要，再展示 IC 指标：

- 明确评价是“同日股票池的横截面排序”，不是个股涨跌预测；
- 同时看方向、一致性、样本数量和数据性质；
- 学习数据固定提示“只验证流程，不能证明真实市场有效性”；
- 证据不足时直接说明不足，不输出模糊的积极措辞。

### 4.3 第三层：专业详情

以可折叠区域展示公式、字段、时点规则、缺失策略、来源、计算版本、评价协议和数据集指纹。

## 5. 资金行为桥接

资金行为页新增“创建量化研究草稿”，但不自动运行任何回测。草稿带入：

- 标的与观察时间；
- 候选因子 `capital:MAIN_FLOW_SHARE:1.0.0`；
- 当前客观异常标签与资金证据引用；
- 建议的评价模式 `CROSS_SECTIONAL_FACTOR_STUDY`；
- 明确的待补条件：冻结横截面资金数据、选择股票池、预注册持有期。

创建成功后进入量化工作台的因子说明书并选中对应因子。草稿持久化，刷新页面后仍可追溯；创建行为不升级因子状态、不修改策略。

## 6. A2 评价门禁

单因子评价从“一个 Rank IC 数字”升级为版本化评价报告：

- 数据门禁：覆盖率、缺失、截面数量、可获得时间、学习/研究数据标签；
- 核心统计：多持有期 Rank IC、IC 均值/波动/ICIR、正 IC 比例与置信区间；
- 组合证据：分位组收益、首尾组差、单调性；
- 可交易性：换手、费用压力、涨跌停约束；
- 稳健性：样本内/外、滚动窗口、市场阶段、参数扰动；
- 结论门禁：只允许 `SUPPORTED`、`REFUTED`、`INCONCLUSIVE`，且必须绑定证据和限制。

先完成协议与门禁，再允许 Agent 或人工提议生命周期迁移。

## 7. C：受控研究 Agent

Agent 不是自由执行脚本的聊天机器人，而是白名单研究编排器：

1. 根据研究草稿生成带假设、失败条件、数据范围、工具步骤和预算的计划；
2. 用户已授权的范围内调用确定性工具；
3. 保存每次工具输入摘要、输出证据、失败状态和预算消耗；
4. 主动寻找反证并形成 `SUPPORTED / REFUTED / INCONCLUSIVE` 结论；
5. 需要扩大范围、引入数据、修改策略或升级状态时停止并要求新授权。

本轮用户已经授权按既定方案连续实现与测试，但产品运行时仍保留人工审批边界。

## 8. B：因子扩展准入

只有在 A2 门禁和 C 的证据追踪可用后才增加候选因子。资金行为首批依次为：

1. 主力净流入占成交额；
2. 20 日资金流强度 Z 分数；
3. 5 日归一化主力流入累计；
4. 5 日资金流持续性；
5. 超大单贡献度；
6. 价格—资金背离；
7. 行业内相对资金强度。

每个候选必须满足：定义完整、公式测试、PIT 测试、缺失/零除测试、冻结数据可复现、目录可解释、评价报告可生成。数量不作为交付成功指标。

## 9. 错误、可访问性与响应式要求

- 目录加载失败时保留旧量化因子兼容展示，并明确专业说明暂不可用；
- 数据不可用和计算失败分别展示，不把单工具失败解释为整体研究失败；
- 搜索、目录选择、详情折叠和运行诊断均支持键盘操作与可读标签；
- 窄屏下目录变为顶部横向/下拉选择，说明书保持内容顺序；
- 尊重 `prefers-reduced-motion`，不加入无意义动画；
- 所有核心结论不只依赖红绿颜色。

## 10. 验收标准

- 现有 13 个因子与首个资金因子均有与代码一致的专业说明书；
- 用户不理解 IC 也能从默认层理解因子含义、假设与误读边界；
- 诊断只在数据集 READY 且因子可用时启用，阻断原因可见；
- 资金行为可以创建持久化研究草稿并定位到对应说明书，不自动运行实验；
- A2 报告不把学习样本或单次样本内结果称为已验证；
- Agent 数字全部来自白名单确定性工具，工具调用和反证可追溯；
- 新资金因子通过统一 Provider、版本、PIT 和评价门禁接入；
- 前后端测试、类型检查、构建、关键浏览器流程和响应式检查通过。
