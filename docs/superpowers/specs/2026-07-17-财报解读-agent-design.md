# 财报解读 Agent 设计规格

> 日期：2026-07-17；状态：待用户确认；产品范围：公司财报分析工作台第二阶段

## 1. 设计结论

在第一阶段结构化财报工作台之上增加一个“受证据约束的单 Agent”。系统先用确定性代码完成指标、趋势、规则和质量判断，再把不可变证据快照交给模型组织成固定结构的财报解读。

本期不做自由聊天、多 Agent、PDF 语义抽取、Strategy 对照、行业排名和投资建议。这样可以先把“结论是否可核查、是否会编造数字、失败后是否可用”这三个基础问题解决好。

完整需求见：

- `docs/产品需求-财报解读Agent.md`
- `docs/技术方案-财报解读Agent.md`

## 2. 用户体验

用户在财报分析页选择一份报告后，可以：

1. 查看三张表、指标和规则发现。
2. 点击“生成 Agent 解读”。
3. 在生成状态结束后阅读经营状态、执行摘要、六维分析、积极信号、风险、拐点和观察清单。
4. 点击任意证据标签，回到指标、报表科目、规则、趋势或数据缺口。
5. 查看历史解读或明确发起重新生成。

新生成失败时继续展示上一份成功解读。模型不可用或输出不合规时展示确定性降级解读，不出现空白卡片。

## 3. 不可变约束

- 模型只能消费服务端生成的证据包，不能访问数据库或原始 PDF。
- 模型不计算指标，不允许引入证据包外的精确数字。
- 每条实质性判断必须至少有一个当前快照内的合法引用。
- 年度、累计和单季度数据不得混入同一趋势。
- 数据质量决定置信度上限，模型只能降级不能升级。
- 模型输出只有通过结构、引用、数字和禁止表达门禁后才可保存为成功结果。
- 首次不合规最多修复一次，之后立即确定性降级。
- 结果与快照、算法版本、提示词版本和输入指纹绑定，历史追加保存。
- 不输出买卖动作、目标价、收益承诺或自动修改用户投资命题。

## 4. 核心数据流

```text
三张表和可比报告
  -> 确定性指标 / 规则 / 同口径趋势 / 数据缺口
  -> 不可变分析快照 + SHA-256 输入指纹
  -> 带稳定证据 ID 的最小证据包
  -> 单个财报解读 Agent
  -> 类型化 JSON 候选结果
  -> Parser + Trust Gate
  -> 成功结果 / 一次修复 / 确定性降级
  -> 追加式历史记录 + Agent Trace
  -> 页面解读区 + 证据抽屉
```

## 5. 输出模型

固定六个维度：

1. 成长性。
2. 盈利能力。
3. 盈利质量。
4. 现金质量。
5. 资产质量。
6. 偿债与资本纪律。

此外必须输出经营状态、置信度、执行摘要、积极信号、风险与反证、可能的拐点、后续观察项、数据限制和免责声明。事实、推断与观察项使用不同类型标识。

## 6. 失败设计

| 故障 | 处理 |
| --- | --- |
| 核心数据不足 | 不调用模型，直接输出缺口和确定性结果 |
| 模型超时或不可用 | 保存降级解读，保留旧成功版本 |
| JSON 或 Schema 非法 | 反馈精简错误并修复一次 |
| 非法引用或凭空数字 | 门禁拒绝并进入修复/降级 |
| 服务重启导致任务中断 | 启动时标记中断，允许重新生成 |
| 快照已经变化 | 旧结果仍可读，页面提示基于旧快照 |

## 7. 复用与隔离

复用项目现有的 LLM 客户端、Agent Harness、Trace 和通用异步设施。财报模块独立定义证据包、提示词、输出 DTO、Parser、Gate、仓储和错误码，不复用资金行为 Agent 的领域枚举或输出类型。

这种边界既保留基础设施一致性，也避免两个分析领域因字段或规则变化互相影响。

## 8. 实施顺序

1. 用测试锁定指标公式、趋势口径和快照指纹。
2. 实现迁移 302、快照仓储与证据 ID。
3. 用恶意/非法样本驱动 Parser 和 Trust Gate。
4. 实现确定性降级，再接入 Agent 和一次修复流程。
5. 实现异步 API、幂等和历史记录。
6. 实现前端结果区、证据抽屉、历史和状态体验。
7. 运行后端、前端和真实样本回归，修复后提交。

## 9. 验证重点

- 同一输入在不同运行中生成相同快照指纹和证据 ID。
- 任意不存在的引用都无法通过门禁。
- 任意证据包外的精确数字都无法通过门禁。
- 缺少现金流量表或比较期时不会出现高置信度现金结论。
- 同一生成键不会因重复点击产生多个并发任务。
- 新任务失败不会覆盖上一份成功结果。
- LLM 完全不可用时，用户仍能得到有证据的规则解读。
