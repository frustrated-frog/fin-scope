# 单一数据库与策略迁移设计

> 日期：2026-07-18；状态：已确认

## 1. 目标

FinScope 运行时只使用 `/Users/machengqian.1/code/MyProject/data/finance.db` 作为当前主数据库，不再因 Java 工作目录变化连接或创建其他 SQLite 文件。同时把误生成数据库 `fin-scope/data/finance.db` 中独有的“质量—趋势—量价中长线策略”及其 17 条规则迁入主数据库。

## 2. 根因

当前配置同时使用 `jdbc:sqlite:../data/finance.db` 和 `finscope.data-root=../data`。相对路径基于进程工作目录解析：从 `fin-scope/` 启动时指向主库，从 `fin-scope/backend/` 启动时指向项目内空库。SQLite 对不存在的文件会自动建库，因此错误不会在启动时暴露。

## 3. 路径方案

新增运行时数据目录引导器，数据库与 Vault 只从同一个绝对 `dataRoot` 派生：

1. 显式配置 `FINSCOPE_DATA_ROOT` 时优先使用，并规范化为绝对路径。
2. 本地源码运行且未显式配置时，从当前目录向上定位同时包含 `backend/pom.xml` 与 `frontend/package.json` 的项目根目录，再使用其父目录下的 `data`，即当前主数据目录。
3. 无法定位项目、数据目录不存在或 `finance.db` 不存在时拒绝启动，不允许静默创建新库。
4. `spring.datasource.url` 由解析后的 `dataRoot/finance.db` 生成；若外部同时给出不同数据库 URL，则拒绝启动，避免再次分叉。
5. 启动日志输出最终数据库绝对路径，不输出密钥或业务内容。

测试覆盖从项目根目录、`backend/` 目录启动得到同一主库，以及缺库、冲突配置和显式覆盖场景。

## 4. 迁移方案

迁移前使用 SQLite 在线备份分别保存主库和误生成库。迁移以策略 `code=STOCK_QUALITY_TREND_CHEN_XIAO_2020` 为业务键，在单个事务中执行：

1. 校验源策略存在且恰好一条，源规则为 17 条。
2. 主库不存在该 `code` 时复制策略字段并取得新的主库 ID。
3. 复制规则时使用新的主库策略 ID，不复制源数据库自增 ID。
4. 主库已存在且内容一致时视为已完成；存在同 code 但内容冲突时中止，不覆盖。
5. 提交后校验主库策略一条、规则 17 条，并通过业务查询接口验证卡片可见。

迁移不删除误生成数据库，待用户确认长期运行稳定后再单独归档或清理。

## 5. 验收标准

- 从 `fin-scope/` 和 `fin-scope/backend/` 启动均解析到同一主库。
- 主库缺失时应用给出明确错误并拒绝启动。
- 主库继续返回 21 条自选记录。
- 主库包含目标策略一条及其 17 条规则。
- 错误库保持原样；迁移前备份可用。
- Java 全量测试和应用构建通过。
