# 研报手动发现与按需导入设计

## 目标

将研报分析页从“进入即抓取并自动导入”改为用户完全可控的三阶段流程：进入页面只读取本地数据；用户点击后才检查公开目录；用户明确选择某篇后才下载 PDF、入库并生成详细解读。

## 产品规则

1. 进入或切换公司、财报期间时，只请求本地研报列表和选中研报详情，不访问外部研报来源。
2. 页面初始显示“检查最新研报”操作，并明确说明检查只查询公开目录，不下载 PDF、不调用 Agent。
3. 用户点击“检查最新研报”后调用只读候选接口，显示最新检查时间、已导入数量和可导入候选。
4. 候选研报只有在用户点击“导入并详细解读”后才下载 PDF、写入数据库并调用 Agent。
5. 已入库研报始终优先展示；目录检查失败不影响本地研报阅读和 PDF 上传。
6. 切换公司时清空上一家公司的候选目录，并丢弃已发出但迟到的旧请求结果。

## API 边界

- `GET /api/financials/instruments/{id}/research-reports`：读取本地研报。
- `GET /api/financials/instruments/{id}/research-reports/candidates`：用户触发的公开目录检查，仅返回元数据。
- `POST /api/financials/instruments/{id}/research-reports/import`：用户选择后下载并解读单篇研报。
- 移除具有隐式自动导入语义的 `POST .../research-reports/sync`，从后端消除误调用风险。

## 页面状态

- 未检查：显示本地研报和“尚未检查公开目录”。
- 检查中：按钮显示“检查中…”，不遮挡已入库研报详情。
- 检查完成：展示候选研报及最近检查时间；不出现“自动导入”文案。
- 检查失败：同步区展示非阻断错误，本地阅读及上传入口保持可用。
- 导入中：只锁定被选择的候选项，完成后加入本地研报列表并立即展示解读。

## 验收标准

- 打开研报 Tab、切换公司或切换财报期间时，不请求候选目录和同步接口。
- 只有点击“检查最新研报”才访问外部目录，且该动作不会下载或生成解读。
- 只有点击某一候选的“导入并详细解读”才产生 PDF 下载、数据库写入和 Agent 调用。
- 原有本地研报阅读、重新解析、上传和财报联动能力不受影响。
