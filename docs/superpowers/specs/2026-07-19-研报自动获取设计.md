# 研报自动获取设计

> **状态：已废弃。** 本文记录最初的“进入即自动同步并导入”方案。现行行为以 `2026-07-19-研报手动发现与按需导入设计.md` 为准：进入页面只读取本地数据，用户点击后才检查公开目录，选择具体研报后才下载并解读。

## 1. 目标与边界

公司财报分析页的“研报分析”以自动获取为主、手动上传为补充。用户进入某家公司后，系统自动同步公开可访问的个股研报目录，并将最新且有公开 PDF 原文的研报导入现有详细解读与财报联动管线。

系统只访问无需登录、无需付费且无需绕过访问控制的公开页面与文件；来源不可用时保留已有数据并展示明确状态，不影响财报页面其他功能。

## 2. 产品行为

1. 首次进入研报页时自动同步最近 365 天、最多 20 篇研报目录。
2. 自动下载并解读目录中最新 1 篇尚未导入且存在公开 PDF 的研报。
3. 其余目录项保留为“待导入”，用户点击后再下载并详细解读。
4. 页面提供“同步最新研报”按钮，可主动重新同步；同一公司同时只执行一个同步任务。
5. 自动导入的研报与上传研报共用同一详情页、原文展示、证据引用和财报事实验证。
6. 自动同步失败不会删除或隐藏已入库研报；页面展示来源、同步时间、成功/跳过/失败数量及错误摘要。
7. 手动上传入口继续保留，适用于公开来源未覆盖或用户自行合法取得的 PDF。

## 3. 来源策略

采用 BrokerResearchSource 接口隔离外部来源。第一期实现 EastmoneyBrokerResearchSource：

- 目录：东方财富公开个股研报接口，按六位 A 股代码查询。
- 原文：目录返回的公开报告标识对应的 PDF 地址。
- 元数据：标题、股票代码、机构、分析师、发布日期、评级、报告类型、页数和原文 URL。
- 请求约束：固定超时、响应大小上限、明确 User-Agent/Referer、串行下载、单次同步数量上限。

业务层不依赖东方财富字段。后续新增来源只需实现目录查询和原文下载，不改变存储、解析、前端或财报联动代码。

## 4. 数据模型

### 4.1 远程目录项

BrokerResearchCandidate 表示尚未必已入库的公开研报，包含：

- sourceCode、externalId、sourceUrl
- title、institution、analyst、publishedDate
- rating、reportType、pageCount
- importedReportId、availability

目录项不单独永久落库。每次同步返回实时目录，并通过 source_type + source_url 与本地研报匹配导入状态。

### 4.2 同步结果

BrokerResearchSyncResult 返回：同步状态、候选列表、自动导入的研报、成功/跳过/失败数量、错误列表和完成时间。

现有 broker_research_report 继续作为唯一研报事实表：

- 自动来源写入 source_type=EASTMONEY 与稳定 source_url。
- 文件内容仍以 SHA-256 去重。
- 数据库迁移 304 为 (source_type, source_url) 增加唯一索引，防止重复同步。

## 5. 后端组件与数据流

    GET/POST sync API
      -> BrokerResearchSyncService（并发合并、数量限制、结果聚合）
      -> BrokerResearchSourceRegistry
      -> EastmoneyBrokerResearchSource（目录 + PDF）
      -> BrokerResearchService.importRemote（验证、去重、存储）
      -> BrokerResearchDocumentParser
      -> BrokerResearchAnalyzer
      -> BrokerResearchFinancialLinker

BrokerResearchService 提取上传与远程导入共用的 storeUnique 管线。远程导入必须验证：股票代码匹配、HTTPS 主机白名单、PDF 签名、30MB 大小上限和响应 Content-Type。重定向后的最终地址也必须属于白名单。

## 6. API

- POST /api/financials/instruments/{instrumentId}/research-reports/sync?financialReportId={id}：同步目录并自动导入最新 1 篇。
- GET /api/financials/instruments/{instrumentId}/research-reports/candidates：只刷新目录，不自动下载。
- POST /api/financials/instruments/{instrumentId}/research-reports/import：按来源和外部 ID 导入单篇待导入研报。

同步接口保持同步 HTTP 语义，但设置单篇和整批超时；前端显示逐步状态。并发请求复用同一个进行中的 CompletableFuture，避免重复抓取与重复 LLM 调用。

## 7. 前端

研报 Tab 顶部新增自动同步区：

- 初次打开自动触发一次同步。
- 展示“已自动获取 N 篇”“还有 N 篇可导入”“最后同步时间”。
- 展示候选研报卡片；已导入可直接阅读，待导入可点击“导入并详细解读”。
- 同步期间禁用重复操作；切换公司时使用请求序列号丢弃旧响应。
- 自动同步失败时展示非阻断提示，并保留上传入口。

## 8. 失败处理与可观测性

- 目录失败：返回 PARTIAL 或 FAILED，不修改本地研报。
- 单篇失败：继续处理下一篇，结果中记录标题和简短原因。
- PDF 不合法或过大：跳过该篇，不进入分析器。
- LLM 失败：沿用确定性降级解读，仍保存原文与证据。
- 日志只记录来源、外部 ID、耗时和结果，不记录研报全文。

## 9. 测试与验收

- 来源适配器使用假 HTTP 客户端验证参数、字段映射、超时、状态码、PDF 限制和主机白名单。
- 同步服务验证自动导入上限、去重、并发合并、部分失败和跨公司校验。
- Controller 验证三个新接口与参数传递。
- 前端验证首次自动同步、候选导入、失败回退、公司切换竞态和上传入口保留。
- 验收标准：进入已知有公开研报的 A 股公司页面后，无需上传即可看到自动导入的详细研报解读，并能查看原文证据及与当前财报的验证结果。
