# 研报解读可读性与 Agent 稳定性修复设计

## 1. 背景与根因

当前公开研报能够完成 PDF 入库、文本提取和规则解析，但真实样本暴露出三个问题：

1. PDF 首页的多栏排版被串行为普通文本，页眉、分析师联系方式、执业编号、目录和免责声明混入结论。
2. 降级解析直接复制最长 500 字的原文段落，页面又同时展开观点和原文摘录，导致重复、冗长且难以扫读。
3. 研报 Agent 调用硬编码 45 秒超时，覆盖了全局 300 秒配置。主数据库中现有两篇研报均因 `Read timed out` 进入 `DETERMINISTIC_FALLBACK`。

六维分析区固定使用两列等宽网格，长短内容不均时会形成明显的列高失衡。

## 2. 目标

- 让核心结论和六维分析以适合长文学习的层级呈现。
- 在进入 LLM 前净化 PDF 文本，避免版式噪声污染提示词和规则降级结果。
- 将模型超时提升到符合长研报生成时长的范围，并对非法 JSON 执行一次结构修复。
- 降级时仍输出可阅读的结构化内容，并明确展示失败原因。
- 临时模型失败不得覆盖已存在的成功 Agent 解读。

## 3. 文本处理设计

新增 `BrokerResearchTextCleaner`，职责仅限将 PDFBox 输出转换为适合分析的文本：

- 删除分析师电话、邮箱、SAC 编号、风险等级、末页声明等非正文行。
- 删除目录点线、单独页码和重复的报告标题页眉。
- 识别 ``、`投资建议`、`风险提示` 等段落边界。
- 合并中文自然换行，但保留标题、项目符号和句号后的语义边界。
- 输出净化文本供 LLM 与规则解析使用，原始提取文本仍保留在数据库用于原文查看和证据定位。

规则降级只从净化文本中选择有语义的句子，每条最多约 180 字；优先提取投资要点、投资建议、业务、行业与风险内容，不再把整页文本作为单条结论。

## 4. Agent 稳定性设计

- 主调用超时改为 120 秒，仍受全局客户端最大超时限制。
- 首次响应无法解析或缺少核心章节时，使用精简修复提示词再调用一次，修复超时为 60 秒。
- 修复输入只包含原响应、字段契约和少量证据上下文，避免再次发送完整研报。
- 失败原因分为未配置、超时、无效 JSON、无核心章节和服务错误，并写入 `error_message`。
- `reanalyze` 若得到降级结果且数据库中已有 `LLM` 结果，则保留原成功内容，只更新可观测错误信息。

## 5. 页面结构设计

页面采用单列长文学习流：

```text
研报身份与解读状态
降级原因提示（仅失败时）
核心结论（全宽）
投资逻辑（全宽）
业务分析（全宽）
行业格局（全宽）
关键假设（全宽）
催化因素（全宽）
风险与反证（全宽）
盈利预测 × 财报事实（全宽）
观点 × 财报事实（全宽）
学习笔记 | 术语卡片（仅短内容双列）
```

每条观点显示简洁正文；原文证据改为可展开的 `details`，默认收起。条目使用稳定编号、最大阅读宽度和更紧凑的段间距，避免同一文本重复占据页面。

## 6. 错误与状态呈现

- `LLM`：展示“Agent 详细解读”。
- `DETERMINISTIC_FALLBACK`：展示“规则解析”及顶部原因提示，并提供“重新详细解析”。
- 原因提示使用面向用户的中文分类，不直接暴露异常堆栈。
- OCR 不足仍标记“证据有限”，不虚构可阅读内容。

## 7. 测试与验收

- 文本净化测试覆盖多栏首页、联系方式、目录点线、页眉页脚和中文断行。
- Analyzer 测试覆盖 120 秒主调用、一次修复、超时降级和短句规则解析。
- Service 测试覆盖临时失败不覆盖历史 LLM 结果。
- 前端测试覆盖单列阅读流、折叠证据和降级原因提示。
- 全量 Maven、Vitest、Vite 构建通过，并在真实研报页面进行桌面宽度视觉验证。
