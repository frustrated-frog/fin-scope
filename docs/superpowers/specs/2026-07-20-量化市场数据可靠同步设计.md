# 量化市场数据可靠同步设计

## 背景与决策

FinScope 已具备实时行情主备路由、资金流降级和最后成功快照，但量化研究的真实数据集仍需人工导入 JSON。这导致“页面可以看行情”与“量化实验拥有可持续数据”之间存在断层。

本期不建设重型数据平台，也不仅增加重试次数。采用“可靠同步垂直切片”：复用 Python 市场数据服务的多源路由，由 Java 量化服务编排逐标的增量同步，通过现有质量门禁后写入真实数据集。

## 目标

1. 真实量化数据集可以从已导入的 PIT 股票池自动获取日线，不再要求用户整理 K 线 JSON。
2. 同步是增量、幂等且可重试的：已入库交易日不重复写入，单个标的失败不破坏其他标的成果。
3. 每次运行可审计：记录请求标的数、成功数、失败数、写入行数、起止日期、真实上游来源、质量状态和错误摘要。
4. 日线数据的 `asOf` 必须是最后交易日，不能用 HTTP 获取时间伪装数据新鲜度。
5. Python 服务提供就绪检查，区分“进程存活”与“快照库可用且有数据提供者”。
6. Java 侧保留 Python 返回的真实上游 `sourceCode/sourceFamily`，不把 Python 进程误当作独立数据故障域。

## 范围

### 本期交付

- Python 日线信封新鲜度修正和 `/ready` 就绪检查。
- Java 侧 Python 日线客户端，把稳定 JSON 契约映射为 `QuantDailyBar`。
- 数据集级市场数据同步服务和 REST 触发入口。
- 同步运行持久化、运行查询和定时增量刷新。
- 前端数据集向导中的“自动同步行情”动作、进度摘要和降级提示。
- 配置和文档中的 Python 服务地址统一，密钥仅从环境变量读取。

### 非目标

- 不承诺付费数据商级 SLA，不把单一互联网数据源宣传为绝对高可用。
- 不在本期自动构造历史 PIT 股票池；同步只使用用户已导入的 PIT 成分。
- 不在本期全量建设财务、复权因子和公司行为管道。
- 不让定时任务修改已冻结的 `READY` 数据集。

## 架构与边界

```text
QuantDatasetController
  -> QuantMarketDataSyncService
       -> QuantDatasetRepository / QuantMarketDataRepository
       -> QuantDailyBarSource (service 端口)
            -> PythonMarketDataDailyBarClient (rpc 适配器)
                 -> market-data-service ProviderRouter
                      -> AkShare / Eastmoney / snapshot fallback
       -> QuantDataQualityService
       -> QuantDataSyncRunRepository
```

`QuantDailyBarSource` 是业务端口，使量化服务不依赖 Python/HTTP 细节。返回值同时包含 bars 和 provenance，入库前必须经过现有 `QuantDataQualityService`。

## 同步数据流

1. 读取数据集，拒绝学习样本、已冻结数据集和没有 PIT 股票池的请求。
2. 从股票池得到去重标的；每标的以已入库最后交易日作为增量水位。
3. 在有界并发度下逐标的请求 Python 服务。每个标的保持自己的来源和质量信息。
4. 只保留水位之后且不晚于请求截止日的数据，执行代码、OHLCV、重复键和日期校验。
5. 每个标的使用独立短事务写入，一个标的失败不回滚已成功标的。
6. 运行结束后重算数据集指纹与质量摘要，并写入 `SUCCESS` / `PARTIAL` / `FAILED`。
7. 重跑会从新水位继续，不依赖上次运行的内存状态。

## 定时策略

- 默认交易日 18:30（`Asia/Shanghai`）触发，时间可配置。
- 只处理 `REAL + BUILDING` 且已存在 PIT 股票池的数据集。
- 同一数据集只允许一个同步运行；重叠触发返回冲突，不重复压迫上游。
- 节假日运行可以成功且写入 0 行，但不能伪造新的 `asOf`。

## 质量与错误语义

- Python 返回 `UNAVAILABLE` 或无 `data` 时该标的失败。
- `STALE_FALLBACK` 可以用于补齐历史缺口，但运行必须标记降级；若快照没有水位之后的新行，则写入 0 行。
- 任何不合法 OHLCV、标的不匹配、未来日期或重复 `(datasetId, instrumentCode, tradeDate)` 在写入前拒绝。
- 只有全部标的请求与质量校验都成功才标记 `SUCCESS`；部分失败为 `PARTIAL`。
- API 返回人可读摘要，不返回上游原始响应或敏感配置。

## 就绪与来源语义

- `/health` 仅表示 Web 进程存活。
- `/ready` 检查 SQLite 快照库可读写，以及至少存在一个已配置 Provider。不在就绪检查内调用外部网络，避免检查本身放大上游故障。
- 信封中 `sourceCode/sourceFamily` 始终是实际产生数据的 Provider；Python 服务只是传输边界。
- 信封中 `retrievedAt` 是本次获取时间，`asOf` 是数据最后事实时点，两者不可混用。

## 前端交互

在真实数据集向导的日线步骤提供“从市场数据同步”，只在已导入 PIT 股票池时可用。页面显示：

- 运行状态和结束时间。
- 标的成功/失败数、新增行数、数据最后交易日。
- 实际上游来源。
- 部分成功或使用旧快照时的明确提示。

页面不暴露 Provider 选择器、重试参数或调度表达式。

## 验收标准

1. Python 日线信封的 `asOf` 等于最后一根 bar 的交易日，节假日重试不变。
2. `/ready` 在快照库不可写或没有 Provider 时返回 503，正常时返回 200。
3. 对同一数据集连续同步两次，第二次不产生重复 bar。
4. 两个标的中一个上游失败时，成功标的仍入库，运行标记 `PARTIAL`。
5. 已冻结数据集、当前截面股票池和学习样本均不会被自动同步。
6. 所有新增行为有单元/集成测试，Python 全量测试、Java 相关模块测试、前端测试和构建通过。
