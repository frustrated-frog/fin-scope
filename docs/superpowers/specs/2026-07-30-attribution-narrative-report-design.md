# 归因报告通俗叙事与历史即时刷新设计

> 日期：2026-07-30  
> 状态：已确认  
> 范围：自选股、基金与板块的归因报告生成和阅读页

## 1. 背景

现有归因页已经具备一句话归因、首要驱动、4–6 条驱动因素、传导链、反证、观察窗口和证据列表，但内容仍偏向“研究结果字段的直接陈列”。用户需要自行把新闻、产业链位置、市场预期和价格反应拼成完整故事，因此不容易快速回答三个实际问题：今天发生了什么、为什么影响这个标的、为什么今天反应这么大。

同时，新归因任务通过 `taskId` 进入阅读页时，历史列表请求会被跳过。任务完成后 `taskId` 仍然存在，右侧历史归因保持空白；返回自选再进入时不再携带 `taskId`，历史才会正常加载。

## 2. 目标

1. 新归因完成后立即刷新右侧历史列表，并显示刚生成的报告。
2. 把归因报告从“驱动因素清单”升级为一条普通用户 30 秒内可以理解的涨跌故事线。
3. 保留证据、置信度、反证和观察窗口等专业信息，采用分层阅读而不是删减研究深度。
4. 股票、基金和板块使用同一报告契约，但输出符合各自的价格传导路径。
5. 模型不可用或旧报告缺少新字段时，页面仍使用现有字段完整展示，不阻断归因流程。

## 3. 方法映射

借鉴 Serenity 的核心组织方式，但不复制其主题选股输出。Serenity 的分析链条是：

```text
市场叙事 → 系统变化 → 必需环节 → 产业链层级 → 稀缺约束
→ 相关公司 → 证据 → 市场可能忽略的部分 → 证伪条件
```

每日归因将其转换为：

```text
今日异动 → 直接触发 → 预期变化 → 标的暴露/产业链位置
→ 板块与资金放大或缓冲 → 价格反应 → 后续验证
```

这里的重点不是增加篇幅，而是让每个结论都回答“发生了什么、与我有什么关系、如何传导到价格”。

## 4. 产品结构

### 4.1 第一层：30 秒看懂

报告首屏按以下顺序展示：

1. **核心结论**：2–3 句白话，先说主因，再说放大因素和结论边界。
2. **原因故事线**：4–6 个短节点，按时间与因果顺序呈现。
3. **为什么是它**：说明股票的产业链位置、基金的持仓暴露或板块的共同驱动。
4. **为什么是今天**：区分直接触发事件、此前积累的预期和当日行情条件。
5. **涨跌放大器与缓冲器**：展示前期涨跌幅、板块联动、资金拥挤、市场风险偏好等次级力量。

首屏不重复呈现同一结论。`summary` 是最终判断，故事线负责解释判断，驱动卡片负责提供依据。

### 4.2 第二层：把原因讲透

驱动因素不再仅按序号平铺，而是增加角色：

- `TRIGGER`：直接触发今日行情的事件；
- `AMPLIFIER`：放大涨跌幅的行情、资金或预期因素；
- `BACKGROUND`：此前已经存在、帮助理解但不是今日直接触发的背景；
- `COUNTER`：相反解释、缓冲因素或对主因的挑战。

每条驱动统一回答：

1. 发生了什么；
2. 为什么与该标的有关；
3. 如何传导到价格；
4. 哪些证据支持、还缺少什么确认。

### 4.3 第三层：证据与验证

保留证据来源等级、链接、反证、不确定性与观察窗口。证据通过 URL 与驱动关联；历史背景继续标记为背景，不计作当日直接证据。

## 5. 报告契约

在现有 `AttributionReport` 中增加一个可选的叙事对象 `narrative`，避免继续向报告根对象堆积松散字段：

```text
AttributionNarrative
  plainSummary        通俗核心结论
  event               今天发生了什么
  instrumentLink      为什么影响该标的
  whyToday            为什么在今天集中反应
  causalSteps[]       按顺序排列的因果节点
  amplifiers[]        放大跌幅或涨幅的因素
  dampeners[]         缓冲因素或相反力量
```

在 `AttributionDriver` 增加：

```text
role                 TRIGGER | AMPLIFIER | BACKGROUND | COUNTER
plainExplanation     面向普通用户的白话解释
```

字段均为可选。旧报告反序列化时保持兼容；如果 `narrative` 不存在，前端根据 `summary`、`primaryDriver` 和 `transmissionPath` 使用旧版结构。

持久化采用 `attribution_report.narrative_json`。数据库初始化以 `ensureColumn` 幂等增加字段，不修改现有数据。

## 6. 不同标的的解释路径

### 6.1 股票

```text
事件/数据 → 盈利或风险预期变化 → 公司产业链暴露
→ 板块与资金行为 → 股价反应
```

### 6.2 基金

```text
行业或核心持仓变化 → 对组合暴露的影响
→ 净值/交易价格反应
```

报告不得把基金本身描述为制造产品或发布经营公告的主体。

### 6.3 板块

```text
政策/需求/行业事件 → 龙头股反应 → 成分股扩散与市场广度
→ 板块涨跌
```

## 7. 生成约束

模型输出继续使用严格 JSON。提示词增加以下要求：

1. 先生成完整因果链，再生成驱动列表；
2. 使用普通中文，专业术语出现时在同一句中解释；
3. 明确区分直接触发、放大因素和背景信息；
4. `whyToday` 必须结合证据时间、当日板块表现或资金/估值背景，不得只复述事件；
5. `instrumentLink` 必须具体说明标的暴露，不得使用“受到市场关注”等空泛话术；
6. 故事线节点保持短句，前后必须能连成因果；
7. 不能把历史背景伪装成当日触发因素。

确定性回退根据首要驱动和现有传导链生成最小叙事对象；没有足够信息时宁可省略可选模块，也不能生成与证据无关的套话。

## 8. 历史归因刷新

历史加载不再以 `taskId` 是否存在作为永久条件：

1. 打开已持久化报告时立即加载历史；
2. 新归因进行中可以暂不加载，避免把 `GENERATING` 快照当成历史收据；
3. 当前报告第一次变为 `COMPLETED` 时请求历史接口；
4. 请求成功后确保当前报告存在于列表中，并按报告日期、创建时间和 ID 排序；
5. 历史请求失败不清空已经展示的数据，页面保留当前报告并允许其他内容正常阅读。

## 9. 错误处理与兼容

- 新叙事 JSON 解析失败时记录日志并返回空叙事对象，旧字段照常展示。
- 模型遗漏某个叙事字段时只隐藏对应 UI 模块。
- 历史加载错误不得覆盖报告读取错误，也不得清空已成功加载的历史。
- 切换历史版本后，标题中的日期和涨跌幅以所选报告为准；本期不改变历史报告内容。

## 10. 测试

### 前端

- 带 `taskId` 的新报告完成后发起历史请求，并显示刚完成的历史收据；
- 历史请求失败时不清空已有历史；
- 完整叙事对象按“核心结论、原因故事线、为什么是它、为什么是今天、放大器/缓冲器”展示；
- 旧报告不包含 `narrative` 时仍展示现有报告；
- 驱动角色和白话解释正确显示。

### 后端

- 模型 JSON 能解析叙事对象和驱动角色；
- 新字段正确写入并从 SQLite 读回；
- 旧行缺少叙事数据时正常读取；
- 回退生成器不会把历史证据写成当日触发；
- 股票、基金和板块的提示词包含各自的传导要求。

## 11. 验收标准

1. 新归因完成后无需返回页面，右侧历史列表在一次历史请求后出现当前报告。
2. 用户在首屏可以直接读出“触发因素、标的关联、今日集中反应原因、放大或缓冲因素”。
3. 每条详细驱动都能回答事件、关联、传导和证据四个问题。
4. 旧报告与模型降级路径保持可读，Inbox 和归因任务不因新字段失败。
5. 前后端相关测试、前端生产构建和后端 Maven 测试通过。

## 12. 非目标

- 不增加新的付费行情、Level-2 或持仓数据源；
- 不引入新的 Agent 框架；
- 不展示模型原始思维链；
- 不提供买卖建议或收益预测；
- 不重做归因研究运行进度页。
