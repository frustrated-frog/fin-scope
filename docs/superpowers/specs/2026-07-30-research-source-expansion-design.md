# 研究 Agent 信息来源扩展设计

## 目标

让研究 Agent 在不重复建设行情基础设施的前提下，直接获取并引用公告、公司互动问答、券商研报和财经快讯；同时借鉴 Serenity 的研究方法，将固定的正反新闻搜索升级为“研究地图—一级资料—交叉验证—反方检验—缺口收敛”的任务图。

## 产品原则

- 用户只定义研究命题，不配置“每主题来源数”或是否包含停用来源。
- 系统自动纳入所有启用且符合主题约束的配置来源。
- 来源广度由资料类型覆盖、来源独立性和证据增量决定，不由固定数量决定。
- 公告与公司正式回复优先于媒体和研报；新闻用于发现线索，重要事实需要一级资料核验。
- 内部保留请求预算、限流、熔断和连续无进展停止条件。

## 可复用 Provider 基础设施

抽取 `ExternalDataProvider` 作为行情与研究资料 Provider 的公共元数据合同，包含 providerCode、providerFamily、优先级、批量上限、最小间隔、超时和终端兜底标志。

现有 `MarketDataProvider` 继承该合同，保持行情接口和业务 DTO 不变。`ProviderRequestGuard` 增加字符串能力编码入口，使行情能力和研究资料能力共享同一套限流、超时、重试、端点熔断与厂商级熔断。行情快照与研究证据仍由各自领域管理，不共享错误的缓存语义。

## 研究资料模型

新增以下研究资料能力：

- `ANNOUNCEMENT`：公司公告，T1。
- `INTERACTION`：公司互动回复，回复为 T1，未回复问题不进入事实证据。
- `BROKER_REPORT`：个股券商研报，T2，复用现有东财研报来源。
- `NEWS_FLASH`：财经快讯，T2，用于发现与时效补充。

所有资料标准化为 `ResearchMaterial`：资料类型、标题、正文、原文地址、发布时间、provider、来源层级、股票代码和稳定外部标识。

## 第一批 Provider

### 巨潮

- 公告：动态获取股票真实 orgId，再查询公告列表。
- 互动问答：先解析公司 orgId，再查询公司问题与回复。
- 请求必须校验允许域名、响应结构、股票代码和空结果。

### 财联社

- 使用公开快讯端点和本地签名。
- 只保存与研究对象或查询词匹配的快讯。
- 财联社失败时不阻塞其他资料通道，由公开搜索继续补充。

### 东财研报

- 复用现有 `EastmoneyBrokerResearchSource`，不创建第二个客户端。
- 将研报目录元数据转成研究资料；正文仍通过已有 PDF 摄取链路获取。

## 研究 Agent 工具

新增 `research_material_search`，严格参数为：

- `stockCode`：六位 A 股代码。
- `materialType`：`ANNOUNCEMENT|INTERACTION|BROKER_REPORT|NEWS_FLASH`。
- `query`：自然语言主题词。

工具通过 `ResearchMaterialGateway` 路由 Provider，将标准化资料写入运行级研究证据表，并返回新增证据、独立来源和失败通道摘要。单一 Provider 失败不应终止整次研究。

## 研究规划

任务图最多八项：

1. 基线来源扫描。
2. 系统变化与产业链研究地图。
3. 公告、财报或公司回复等一级资料。
4. 行业、研报和财经资讯补充。
5. 客户、供应商或竞争对手交叉验证。
6. 不同解释与反向事实。
7. 证据缺口判断。
8. 报告合成。

对于没有六位 A 股代码的命题，规划器不得调用结构化 A 股资料工具，而应使用公开搜索完成对应任务。

## 来源规划参数

前端和创建研究请求删除 `maxSourcesPerTheme` 与 `includeDisabled`。`SourcePlanner` 自动选择所有启用、主题匹配或层级匹配且未被禁止的来源，并按可信度排序、按来源 ID 去重。

## 健壮性

- 所有外部请求有域名白名单、响应大小、连接/读取超时与总截止时间。
- Provider 共享厂商级限流，东财至少一秒间隔。
- 结构化响应缺字段、股票不匹配或无公司回复时不得形成事实证据。
- 证据以原始 URL 或 provider + 外部 ID 去重。
- 工具错误转成 Observation；除所有通道均失败外，不终止研究循环。

## 验证

- 公共 Provider 合同兼容现有行情测试。
- 巨潮、财联社和研报适配器使用固定响应样例做契约测试。
- 研究工具验证参数、去重、部分失败和证据落库。
- 规划器验证有代码与无代码两种任务图。
- 前端验证启动请求不再包含来源数量和停用来源参数。
- 运行后端全仓测试、前端全量测试和生产构建。
