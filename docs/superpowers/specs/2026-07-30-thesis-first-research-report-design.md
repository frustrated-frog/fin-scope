# 命题优先研究报告设计

## 目标

研究报告直接回答用户命题，通过完整事实段落和紧随其后的 AI 解读形成认识。报告不再向读者解释系统使用了多少支持或反对证据、如何执行研究、如何计算相关性；这些机制继续在内部运行，用于保证报告安全和可靠。

## 读者可见结构

报告统一采用以下结构：

1. **核心结论**：直接回答命题，说明结论成立的条件和边界，不展示支持/反对数量。
2. **关键事实与 AI 解读**：每条关键事实采用固定的“事实—AI 解读”对。
   - **事实**：完整展示本次报告选中的事实段落，并附 `[E1]` 引用。
   - **AI 解读**：解释该事实与命题的关系、传导机制、能说明什么以及不能单独证明什么；不得引入未被引用支持的新事实。
3. **命题拆解与综合判断**：围绕用户真正关心的子问题逐项回答，把多个事实合并为判断，不介绍研究过程。
4. **影响机制**：解释事实如何影响估值、经营、行业、交易或其他与命题相关的关键变量。
5. **不同解释与不确定性**：呈现可能改变当前认识的替代解释和未知项，不使用“支持/反对证据数量”或“最强反方”式系统术语。
6. **情景推演**：给出基准、上行、下行情景及各自触发条件。
7. **结论更新条件**：列出哪些后续事实会强化、削弱或推翻当前结论。
8. **资料来源**：保留证据编号、标题、来源、日期和原文链接，便于追溯。

不再展示以下内容：

- “执行摘要”章节。
- 支持、反向、中性证据数量及比例。
- 证据立场、相关性分数、来源层级等内部评分。
- “本次运行如何研究”“如何阅读报告”等过程说明。
- 任意省略号、`（已截断）` 或在句子中间截断的事实。

## 完整事实段落

系统从搜索摘要或正文中选取与命题直接相关的完整句子，使用句号、问号、叹号或英文句点作为边界。长度控制发生在事实选择阶段，而不是在 Markdown 生成后硬切字符串：

- 优先保留能够独立表达事实的完整句群。
- 在提示词预算内选择最多约 900 个字符的完整段落。
- 如果候选文本超过预算，只在完整句子边界停止，不添加省略号。
- 报告生成后不得再次截断事实段落或整份 Markdown。
- 新闻全文不复制到报告；读者通过文末原文链接查看全文。

## AI 解读约束

AI 解读必须：

- 紧跟对应事实，不能集中放入独立的通用“AI 解读”章节。
- 明确关联研究命题和关键变量。
- 区分事实与推理，不把推理伪装成已发生事实。
- 对数字、日期和外部事实继续使用引用。
- 不新增证据档案之外的公司、数字、事件或来源。
- 说明事实的解释边界，避免从单条新闻直接推出长期结论。
- 不给出买卖指令。

## 内部安全机制

以下能力保留但不直接展示：

- 证据支持/反向/中性分类。
- 证据充分性和独立来源评估。
- 不同解释和反方覆盖校验。
- 引用合法性、事实声明和数字冲突审计。
- 模型输出修复及不合格报告回退。

模型报告与确定性回退报告使用同一读者可见结构。模型草稿若缺少引用、完整事实—解读对或不同解释，将被质量校验拒绝；回退报告仍需为每条事实提供安全、对象特定的研究解读，不恢复旧的执行摘要模板。

## 数据流

```text
运行内证据
  -> 完整句子事实选取
  -> 内部论证蓝图（含不同方向与未知项）
  -> AI 生成逐事实解读和命题综合判断
  -> 事实声明与引用审计
  -> 命题优先 Markdown
  -> 报告阅读器
```

## 验收标准

- 报告不存在“执行摘要”章节。
- 正文不存在支持/反对数量、比例、立场分数或运行过程说明。
- 每条关键事实后紧跟 `**AI 解读：**`。
- 关键事实和解读保留可点击引用。
- 报告不存在 `…`、`...`、`（已截断）` 等截断标记。
- 核心结论、事实与 AI 解读、不同解释、更新条件均通过引用与质量校验。
- 模型路径和确定性回退路径生成相同的章节结构。
- 文末资料来源保留标题、来源、日期和原文链接。

## 测试策略

- 事实选择测试：长文本只在句末停止，无省略号且保留完整语义。
- 确定性报告测试：新章节齐全，旧元叙事不存在，每条事实后有 AI 解读，引用有效。
- 结构化报告测试：模型蓝图和叙事组装为事实—AI 解读对。
- 质量校验测试：拒绝缺失 AI 解读、出现旧章节或截断标记的报告。
- 声明审计测试：AI 解读不得绕过数字与事实引用校验。
- 前端测试：新章节正常进入目录，引用跳转和资料来源显示正常。
