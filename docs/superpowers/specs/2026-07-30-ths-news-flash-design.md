# 同花顺快讯接入设计

## 目标

将同花顺 7×24 实时快讯和要闻精华接入现有研究资料来源体系，为研究 Agent 增加独立资讯来源，并为后续资讯订阅页面保留可复用的数据边界。

## 方案

- 继续使用 `ResearchMaterialProvider`、`ResearchMaterialGateway` 和 `ProviderRequestGuard`，不新增第二套 HTTP、限流、熔断或来源路由逻辑。
- 分别实现 `THS_NEWS_FLASH` 与 `THS_NEWS_DIGEST` 两个 Provider。两者共享同一个同花顺 JS 数据解析基类，但拥有独立的健康状态和失败隔离。
- 直接读取同花顺页面使用的 `realtimenews.js` 与 `ywjh.js` 数据文件，不解析页面 DOM，也不复制第三方仓库代码。
- 将有效条目标准化为 `ResearchMaterialType.NEWS_FLASH`，保留新闻序列号、标题、完整正文、原文地址、发布时间和同花顺来源标记。
- 使用现有关键词析取匹配和请求条数上限；同一研究动作会与财联社等其他来源共同执行，由网关统一去重。

## 数据契约与健壮性

- 响应必须符合 `var thsRss = {...}` 结构，根节点必须包含 `item` 数组；结构漂移时抛出不可重试的 `INVALID_RESPONSE`，交由现有熔断逻辑处理。
- 允许 JavaScript 对象的未加引号字段名，但不执行任何脚本。
- 忽略 `isvalid != 1`、标题和正文同时为空、发布时间非法的坏条目；单条坏数据不破坏整批结果。
- 优先使用条目 `seq` 作为外部编号，缺失时使用内容哈希；地址统一升级为 HTTPS。
- 根据数据集 `pubDate` 产生新鲜度告警，但不因休市或周末没有更新而丢弃仍可引用的历史快讯。
- HTTP 调用继续受统一响应大小、超时、最小调用间隔和 Provider 总时间预算约束。

## 验证

- 契约测试覆盖未加引号字段、中文完整正文、关键词过滤、无效条目、数量上限、URL 标准化和元数据。
- 错误测试覆盖非法脚本包装、缺少 `item`、单条非法时间以及陈旧数据告警。
- 运行 RPC 模块测试、后端全量测试，并对两个公开数据端点执行只读验活。

## 范围边界

本次实现数据源及其研究 Agent 接入，不同时建设资讯 Tab、持久化订阅或 SSE 页面通道；这些能力后续直接消费同一标准化来源，避免当前改动扩散为未经验证的完整新页面。
