# Agent 驱动的实时资讯分类设计

## 1. 目标

在现有 News Wire 页面中增加动态分类标签，让用户可以在“全部、公司动态、行业产业、政策宏观、全球市场、市场异动”等分类之间切换。所有分类复用当前的实时快讯、要闻精华、来源筛选、搜索、手动刷新和降级提示 UI；当前选中的分类继续使用现有 45 秒轮询刷新。

分类归属由 Agent 根据可配置分类目录判断，而不是由 Java 关键词规则或前端常量硬编码。分类失败不得阻断资讯展示，未完成分类的资讯仍可在“全部”中看到。

## 2. 已确认的交互

1. 页面顶部展示由后端返回的分类标签，默认进入“全部”。
2. 用户点击分类后立即请求该分类的资讯，页面结构不变，只改变数据范围。
3. 页面始终只有一个轮询任务；它每 45 秒刷新当前选中的分类。
4. 切换分类后，后续轮询自动跟随新分类，旧请求不得覆盖新分类内容。
5. 自动轮询发现新资讯时不直接打断阅读，而是在列表顶部显示“发现 N 条新资讯”。用户点击提示后再合并到当前列表。
6. 手动点击“立即刷新”时直接替换当前列表并保留现有成功或失败 Toast。
7. 来源筛选和文本搜索只作用于当前分类。

## 3. 分类目录

分类目录存储在 SQLite 中，字段包括稳定编码、展示名称、Agent 分类指导、启用状态和展示顺序。初始目录为：

| 编码 | 名称 | 分类指导 |
| --- | --- | --- |
| `COMPANY` | 公司动态 | 单一或多家公司的公告、业绩、订单、产品、并购、治理和经营变化 |
| `INDUSTRY` | 行业产业 | 行业供需、产业链、技术路线、产能、价格和竞争格局变化 |
| `MACRO_POLICY` | 政策宏观 | 监管政策、财政货币政策和重要宏观经济数据 |
| `GLOBAL` | 全球市场 | 海外市场、地缘政治、汇率及国际大宗商品事件 |
| `MARKET_MOVE` | 市场异动 | 指数、板块、个股、成交、资金或波动异常 |

“全部”是查询维度而不是 Agent 分类，前端在分类目录首位补充固定的 `ALL` 标签。后续可以通过数据库调整分类名称、指导和顺序；Agent 只能从当前启用目录中选择，不能自行创造一级分类。

## 4. Agent 分类契约

`NewsClassificationAgent` 接收一批尚未分类的资讯和当前分类目录。为控制模型成本，每条资讯只发送标题、来源、发布时间和截断后的正文。Agent 返回 JSON 数组：

```json
[
  {
    "itemId": "CLS_NEWS_FLASH:12345",
    "categoryCode": "COMPANY",
    "confidence": 0.91,
    "reason": "内容描述上市公司的重大订单及经营影响"
  }
]
```

服务端必须验证 `itemId`、分类编码和置信度。未知编码、缺失条目或无法解析的输出均视为失败，不使用关键词规则猜测分类。成功或失败结果写入 `agent_run`，节点名称为 `news-classification`。

## 5. 持久化与异步执行

新增两张表：

- `news_category`：动态分类目录。
- `news_item_classification`：按稳定资讯 ID 保存分类状态、分类编码、置信度、理由、模型和更新时间。

资讯接口仍通过 `ResearchMaterialGateway` 获取最新资讯。服务端对完成去重和映射后的条目批量查询已有分类，并原子认领尚未分类的条目，然后交给独立的 `newsClassificationExecutor` 异步调用 Agent。这样页面请求不等待模型，同时轮询不会重复提交同一条资讯。

状态包括：

- `PENDING`：已认领，等待或正在分类。
- `CLASSIFIED`：分类完成，可出现在对应分类中。
- `FAILED`：本次分类失败；超过重试间隔后允许再次认领。

`ALL` 返回所有已抓取资讯，包括尚未分类和分类失败的条目。具体分类只返回状态为 `CLASSIFIED` 且编码匹配的条目。Agent 不可用时资讯流仍正常工作，只是具体分类暂时不会新增内容，并通过现有 warnings 告知用户。

## 6. API

### 分类目录

```http
GET /api/news/categories
```

返回当前启用分类，按 `displayOrder` 排序。前端在首位加入“全部”。

### 分类资讯

```http
GET /api/news?category=COMPANY&limit=100
```

`category` 缺省或为 `ALL` 时返回全部资讯；未知或停用分类返回参数错误。`NewsFeedItem` 增加可空的分类编码、分类名称、分类置信度和分类理由，便于后续展示 Agent 判断依据。

## 7. 前端状态与竞态处理

`NewsView` 维护：

- 当前分类 `selectedCategory`；
- 当前已展示快照 `snapshot`；
- 自动轮询暂存的快照 `pendingSnapshot`；
- 当前请求序号，用于忽略切换分类前发出的迟到响应。

首次进入、切换分类和手动刷新会立即应用响应。自动轮询若发现当前列表中不存在的新 ID，则保存为 `pendingSnapshot` 并显示“发现 N 条新资讯”；没有新增条目时可以直接更新刷新时间和告警。点击提示后应用暂存快照。

切换分类时清空旧分类的暂存结果、搜索词和来源选择，立即加载新分类。轮询定时器不因切换而重复创建，它每次读取最新的分类引用。

## 8. 错误与降级

- 分类目录加载失败：仍展示“全部”，保留基础资讯流。
- Agent 未配置或调用失败：记录失败，不阻断 `ALL`，并允许稍后重试。
- 某个资讯来源失败：沿用当前部分来源不可用提示。
- 分类切换请求失败：保留当前页面已有内容并展示错误，不用空页面覆盖。
- 自动轮询失败：保留当前内容，不弹出持续打扰用户的 Toast。

## 9. 测试与验收

后端测试覆盖分类目录初始化与排序、分类认领幂等、失败重试、Agent 输出校验、按分类过滤、`ALL` 降级以及 Controller 参数传递。前端测试覆盖动态标签、切换后立即请求、轮询跟随当前分类、迟到响应隔离、新资讯提示、点击合并和现有手动刷新行为。

验收标准：

1. 分类标签来自后端，前端没有业务分类常量。
2. 分类判断由 LLM Agent 完成，服务端没有关键词分类规则。
3. 所有分类复用同一套 UI 和单一 45 秒轮询。
4. 切换分类后立即显示对应资讯，旧响应不会串入。
5. 自动刷新新增内容先显示数量提示，用户确认后插入。
6. Agent 故障不影响“全部”资讯浏览和手动刷新。

## 10. 本期边界

本期不实现 SSE、WebSocket、事件聚类、持仓相关性排序、外部通知和自动研究任务。分类持久化和动态导航是后续事件雷达的第一层数据基础。
