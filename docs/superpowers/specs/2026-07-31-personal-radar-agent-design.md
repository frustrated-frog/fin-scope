# 个人研究雷达 Agent 增强设计

## 1. 目标

在现有个人研究雷达的确定性基线上增加受控 Agent 能力，使系统能够处理规则聚类的灰区、生成稳定事件标题、按事件自动补充多源证据，并向个人投资初学者解释“发生了什么、为什么值得关注、还缺什么”。

本设计借鉴 `jdt-data-hotspot` 的混合编排方式，但不复制策略管理、Prompt 编辑、模型选择、运营投放或 Skill 生成后台。用户不需要配置任何策略。

## 2. 核心原则

- 确定性代码继续负责采集、快速排除、图聚类、优先级和失败回退。
- LLM 只进入语义灰区、规范标题和证据综合三个高价值位置。
- 所有模型输出必须是严格 JSON，并经过字段、长度、置信度和输入集合校验。
- Agent 不可用时保持现有雷达结果可用，不阻断实时资讯。
- 单次刷新只处理有变化的灰区新闻对；相同输入复用持久化缓存。
- 每个 Agent 节点写入 `agent_run`，使用 `subject_type=RADAR_EVENT` 或 `RADAR_CLUSTER`，不展示隐式思维链和完整敏感 Prompt。
- 外部检索使用固定个人版工具白名单和预算，不提供前端策略配置。

## 3. 分期范围

### 3.1 第一批：语义聚类闭环

新增 `RadarEventMatchAgent`，接收两条灰区信号并返回：

```json
{
  "sameEvent": true,
  "confidence": 0.91,
  "reason": "同一行业板块在同一交易时段因相同驱动上涨"
}
```

聚类顺序为：

1. 标题规范化、主体冲突和相似度规则先给出 `SAME/DIFFERENT/AMBIGUOUS`；
2. 仅 `AMBIGUOUS` 进入判断缓存；
3. 缓存未命中且模型可用时调用 Agent；
4. 模型失败、超时或输出非法时保守拆分；
5. 所有确认相同的新闻对构成无向图；
6. 使用 BFS 连通分量生成事件组；
7. 每条事件关系保留规则或 Agent 的匹配原因。

缓存键由排序后的信号语义指纹组成，指纹覆盖标题、正文摘要和分类。内容变化后自动形成新键，避免复用过期判断。

新增 `RadarCanonicalTitleAgent`，只对包含多条信号且没有可复用历史标题的事件生成规范标题。输出标题必须非空、不超过 48 个字符、不包含 Markdown；失败时使用确定性代表标题。

### 3.2 第二批：事件理解与检索计划

新增 `RadarEvidencePlanAgent`。它从事件及其信号中提取事件类型、主体、股票代码、检索词和所需工具。允许的工具仅包括：

- `research_material_search`：公告、互动问答、研报、财经快讯；
- `public_news_search`：公开新闻补充；
- 后续已存在可靠 Adapter 时再开放行情、板块和资金快照。

每个事件最多两个外部工具动作。没有股票代码时不得调用要求股票代码的工具；低优先级和单条普通快讯默认不自动检索。

### 3.3 第三批：证据综合与页面轨迹

检索结果先写入现有研究证据域或雷达证据引用，再由 `RadarEvidenceSynthesisAgent` 生成结构化结论：

- 事实摘要；
- 主要驱动；
- 自选关联；
- 独立来源确认情况；
- 证据冲突和缺口；
- 下一步观察项；
- 引用的数据引用 ID。

雷达详情增加折叠的 Agent 轨迹，只显示节点、状态、耗时、工具名称、召回数量、回退原因和可审计摘要，不显示模型隐式思维链。

## 4. 模块与接口

- `RadarPairDecisionRepository`：保存和读取灰区新闻对判定缓存。
- `RadarEventMatchAgent`：把两条信号转换为严格、可验证的同事件判定。
- `RadarCanonicalTitleAgent`：为一个聚类生成稳定规范标题。
- `RadarClusteringService`：组合规则判定、缓存、Agent 判断和 BFS；其公共接口仍是 `cluster(signals)`。
- `RadarAgentTraceRecorder`：统一向 `agent_run` 写 Radar 节点记录。
- `RadarEvidenceOrchestrator`：后续负责固定预算下的计划、工具执行和综合。

`RadarClusteringService` 是主流程使用的深模块。缓存、LLM、图实现和降级均为内部实现细节，调用者不需要理解它们。

## 5. 错误处理

- 模型未配置：灰区判定保守拆分，标题使用代表信号。
- 模型超时或异常：记录失败和回退原因，不向上抛出阻断刷新。
- JSON 非法或字段越界：视为无效输出并回退。
- 缓存读写失败：继续执行；缓存不能成为雷达可用性的单点。
- 图聚类必须只消费已经验证的布尔判定，不直接消费模型原文。
- 证据工具失败：保留其他来源，详情显示降级原因。

## 6. 测试与验收

- 灰区同事件能够被 Agent 合并；
- 灰区不同事件保持拆分；
- 模型不可用、异常和非法 JSON 均保守拆分；
- 相同新闻对第二次聚类命中缓存，不重复调用模型；
- A-B、B-C 相同但 A-C 未直接确认时，BFS 仍形成一个事件组；
- 主体冲突不会调用 Agent；
- 规范标题通过校验后使用，失败时回退代表标题；
- Agent 判断、缓存命中、标题生成和回退均可在 `agent_run` 查询；
- 现有 `/api/news`、实时资讯默认页和确定性雷达测试保持通过；
- 关闭 LLM 后雷达仍能刷新并展示事件。

## 7. 明确不做

- 不增加策略管理页面；
- 不允许用户编辑 Prompt、权重、推理模式或工具组合；
- 不自动生成买卖、仓位和目标价建议；
- 不展示隐式思维链；
- 不把所有雷达快讯自动写入长期知识库；
- 不让模型直接接管全量聚类或优先级排序。
