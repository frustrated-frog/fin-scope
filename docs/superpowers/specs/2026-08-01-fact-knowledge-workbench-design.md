# 事实与知识工作台效果版设计

## 目标

将现有 Events、Evidence、Knowledge 三个并列入口收敛为唯一的 Knowledge 入口，在不修改数据库和后端接口的前提下，让用户通过“事实核验”视图理解事件、证据与知识之间的关系。

## 范围

- 移除侧边栏中的 Events 和 Evidence 入口，只保留 Knowledge。
- Knowledge 内新增“事实核验”区域。
- 现有 `event_cluster` 在前端映射为事实候选，现有 `evidence_item` 映射为支持材料。
- 根据证据类型、来源层级和置信度计算只读的展示状态、来源覆盖和待补缺口。
- 保留旧 Events/Evidence 组件和后端接口，不删除数据，不修改 Schema，不新增写操作。

明确不修改 Research、Radar、News、Inbox、Article、Strategy、Watchlist、Financials、Market Intel、Agent Runtime 及其数据流。

## 页面结构

Knowledge 继续作为唯一一级入口，内部主导航只保留：工作台、事实核验、知识库。学习队列和到期复习继续作为工作台行动或知识库上下文页面存在，不再占据并列主入口。

“事实核验”采用主从布局：左侧是事实候选列表，支持搜索和核验状态筛选；右侧是事实详情，展示摘要、核验状态、材料数量、一手来源数量、直接事实材料、证据缺口和按质量排序的证据列表。

默认工作队列只显示已有证据材料的候选，并按“待交叉验证、已有材料但待核验、证据较充分”的处理优先级排列；无材料事件通过独立开关按需显示，避免淹没可执行任务。

## 展示规则

- 证据类型为 `FACT` 或 `TIMELINE` 时，视为直接事实材料。
- 来源层级为 `REGULATOR`、`OFFICIAL` 或 `COMPANY` 时，视为一手来源。
- 同时存在直接事实材料与一手来源时，显示“较充分”。
- 只存在其中一种时，显示“待交叉验证”。
- 两者都不存在时，显示“待核验”。
- 这些状态只用于界面预览，不持久化，也不宣称完成事实认证。

## 兼容性

旧的 Events、Evidence 和 Event Detail 视图代码暂时保留，避免破坏内部跳转；它们不再出现在侧边栏。后续是否删除或迁移，等用户体验验证后再决定。
