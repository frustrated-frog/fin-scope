# 纯投资数据认识 Agent 设计

## 目标

把“投资认识”从文章主题库改造成一个可持续检验的投资判断系统。Agent 只消费结构化的投资与财富数据，先形成可复核的观察事实，再提出带有反证条件的投资命题。文章、简报和抓取内容继续作为独立知识库存在，但不再进入认识工作台，也不作为 Agent 的检索、引用或证明材料。

## 产品边界

### 纳入范围

- 股票、基金、ETF、指数、行业及宏观财富变量
- 自选标的及其行情、涨跌幅、成交、波动、估值等结构化数据
- 资金流、财务报表、公司公告、交易所与监管披露、官方宏观数据
- 财经快讯仅作为“为何现在值得检查”的触发器
- Agent 候选认识、待补证据、正式认识和失效记录
- 用户手动新建投资问题的入口

### 明确排除

- 文章、简报、RSS 正文、手动抓取内容进入投资认识
- Agent 搜索、召回、总结或引用文章库
- 仅有新闻叙事、技术概念或泛行业观点，无法对应可投资对象或财富变量的内容
- 删除、迁移或重写现有数据库记录

## 核心原则

1. **先事实，后判断**：价格、成交、资金、财务和官方披露先形成确定性观察；LLM 不负责发明事实。
2. **快讯只触发，不证明**：快讯可提高检查优先级，但不能单独成为支持证据。
3. **对象必须可投资**：每条候选必须绑定股票、基金、ETF、指数、行业或宏观财富变量。
4. **结论必须可失效**：没有验证指标、时间窗口和失效条件的内容不能升级为正式认识。
5. **Agent 只提案，人来确认**：Agent 生成候选或标记缺证据；用户确认后才沉淀为正式认识。
6. **旧数据只隐藏**：历史上由文章形成的主题不删除、不迁移，只从新的认识入口中隐藏。

## 信息架构

投资认识页面收敛为四个工作状态：

| 状态 | 含义 | 主要动作 |
| --- | --- | --- |
| Agent 候选 | 数据已足以形成可检验命题 | 查看依据、接受、转待补证据、忽略 |
| 正式认识 | 已由用户确认，进入长期跟踪 | 查看版本、复核、修正、判定失效 |
| 待补证据 | 有投资意义，但当前数据不足 | 查看缺口、补数据、重新运行 Agent |
| 已失效 | 触发失效条件或被用户否定 | 查看原因、保留历史、必要时重开 |

页面首屏回答三个问题：今天 Agent 检查了什么、发现了哪些值得判断的变化、哪些命题需要用户处理。手动新建保留为次级入口，不再与 Agent 主流程争夺视觉重心。

## Agent 数据链路

```text
自选与投资对象
  -> 行情/成交/估值/资金/财务/官方披露
  -> 确定性观察器（变化、异常、缺失和数据时间）
  -> 快讯触发器（可选，只调整检查优先级）
  -> 投资命题生成器
  -> 反证审查器
  -> Agent 候选 / 待补证据
  -> 用户确认
  -> 正式投资认识
```

### 数据来源优先级

1. 自选清单与可投资对象元数据
2. 行情与量价：价格、涨跌幅、成交额、换手、波动、行业广度、基金净值
3. 资金与交易结构：主力/北向/ETF/融资融券/龙虎榜等可用结构化数据
4. 基本面与官方数据：财报、公告、交易所/监管披露、官方宏观指标
5. 财经快讯：只提供触发原因和时间，不进入支持证据列表

### 生成门槛

候选命题至少包含：

- 可投资对象类型、代码与名称
- 已观察到的结构化变化及数据时间
- 从变化到盈利、估值或风险的作用机制
- 支持数据和反向数据
- 未来验证指标及检查窗口
- 明确失效条件
- 置信度与当前证据完整度

若对象不明确、只有快讯、缺少结构化支持数据，或无法给出失效条件，Agent 只能输出“待补证据”，不能输出正式候选。

## 数据模型

新增独立的 `investment_recognition_candidate` 表，不修改既有 Topic、文章或简报记录。核心字段：

- `subject_type/code/name`：投资对象
- `status`：`CANDIDATE`、`NEEDS_EVIDENCE`、`ACCEPTED`、`DISMISSED`、`INVALIDATED`
- `thesis`、`observed_change`、`mechanism`
- `supporting_data_json`、`counter_data_json`
- `validation_metrics_json`、`invalidation_conditions`
- `horizon`、`confidence`、`evidence_completeness`
- `trigger_summary`：可记录快讯触发原因，但不得进入证据字段
- `agent_run_id`、`topic_id`、`generated_at`、`updated_at`、`revision`

接受候选时创建或关联正式 Topic，并将候选状态改为 `ACCEPTED`。该操作只新增认识数据，不改动历史文章主题。

## 文章库隔离

- 移除文章详情和简报中的“沉淀主题”按钮。
- 前端停止调用 `/api/topics/from-article/*` 和 `/api/topics/from-brief/*`。
- 投资认识页移除“待提炼材料”分类，只展示符合认识准入规则的档案。
- 旧接口暂时保留兼容，避免扩大本次改动；新工作台不会调用它们。
- Article Agent 可以继续服务文章阅读，但其输出不进入投资认识 Agent 的输入载荷。

## 失败与降级

- 行情不可用：不生成凭空判断，记录为数据不足。
- LLM 不可用：确定性观察仍可完成，候选降级为待补证据，不阻断页面。
- 输出无法解析：保存 Agent Run 错误，不创建候选。
- 数据过期：页面显式展示数据时间和过期状态，不把旧数据伪装成今日变化。
- 重复运行：以对象、命题指纹和观察窗口去重，更新候选版本而非无限新增。

## 验收标准

- 文章新增、抓取、简报生成后不会出现在投资认识任何 Tab。
- 前端没有文章/简报沉淀认识入口，也不再请求对应接口。
- Agent 请求载荷不含文章 ID、正文、摘要、文章引用或检索结果。
- 每条 Agent 候选都对应投资对象，并展示支持、反证、验证和失效条件。
- 仅有快讯时进入待补证据，而不是形成正式候选。
- 不删除、不迁移现有数据库数据；历史文章主题仅在新入口中不可见。
