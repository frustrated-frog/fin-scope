# 投资命题核验队列设计

## 目标

把现有“事实与变化”从全量文章事件档案收缩为投资认识链路中的质量门：只核验会保持、修正或推翻某条投资认识的具体命题。文章仅作为命题的来源材料，不再直接充当事实。

本轮仅修改事实—认识工作台前端投影和界面，不修改数据库、Schema、后端接口或其他业务页面。

## 现状问题

当前页面以 `EventCluster` 为核验对象，并把同一事件下的全部 `EvidenceItem` 展示为支持材料。真实数据中存在以下问题：

- 事件标题本质上经常是文章标题，而非可证伪命题。
- 同一事件关联了主题无关的论文和新闻材料。
- 来源等级存在误标，例如 arXiv 被标成监管来源。
- 重复文章会被重复展示，材料数量被误解为事实可信度。
- 与任何投资认识无关的生活新闻、教程和论文也进入核验列表。

因此，现有页面验证的是“系统是否收集了材料”，而不是“投资命题是否成立”。

## 方案选择

### 方案 A：继续使用全量事件，增加关键词过滤

改动小，但无法可靠判断事件是否影响投资认识，也无法解决文章标题冒充命题的问题。不采用。

### 方案 B：把所有材料改名为待核验线索

文案更诚实，但依然会形成庞大的信息仓库，不能回答“为什么值得核验”。不采用。

### 方案 C：从已形成认识的关联材料反向生成核验任务

只读取被分类为“已形成认识”的 Topic Workspace，以认识—事件—证据的已有关系建立核验队列。它天然回答“影响哪条认识”，也能让没有认识关联的文章退出核验页。采用此方案。

## 核验对象

核验对象是原子命题，而不是事件或文章。命题必须同时满足：

1. 来自已形成投资认识档案所关联的证据。
2. 证据类型为 `FACT` 或 `TIMELINE`。
3. 是简短陈述句，不是问题、Markdown 链接、论文 Abstract 或整段文章摘要。
4. 能追溯到具体来源 URL。

同一认识下的相同命题按规范化文本合并；文章标题、URL 和来源等级只作为命题下方的材料属性。

## 状态模型

前端只做只读投影，不写入核验结论：

- `NEEDS_PRIMARY`：只有媒体、研究或来源不明材料，需要寻找公告、监管或公司一手来源。
- `RECORDED`：命题已存在可识别的一手来源，可归档为已记录事实，不占用待核验队列。

当前数据没有可靠的支持/反驳关系字段，因此本轮不虚构“已支持”或“已反驳”状态。未来只有在后端持久化命题结论后才能增加这两个状态。

## 一手来源识别

不再只信任 `sourceTier`。来源必须同时满足等级和 URL 主机校验：

- 监管来源：政府、监管、交易所等明确域名。
- 官方/公司来源：等级为 `OFFICIAL` 或 `COMPANY`，且 URL 不是新闻聚合、媒体、社交平台或 arXiv。

来源 URL 缺失时不能判定为一手材料。

## 页面结构

导航名称改为“核验队列 / 影响判断”。页面主体保持克制的研究台账结构：

```text
核验队列说明                 待核验数量 / 已记录数量
筛选：待找一手 | 已记录
┌ 命题索引 ─────────┬ 命题卷宗 ─────────────────┐
│ 状态、命题、认识   │ 待核验命题                 │
│                    │ 为什么值得核验 / 影响的认识 │
│                    │ 缺口                        │
│                    │ 来源材料                    │
└────────────────────┴─────────────────────────────┘
```

默认只显示待找一手的命题。没有符合条件的命题时，明确说明：当前文章材料没有形成值得核验的投资命题，并引导用户先建立投资认识或从今日变化中提出具体命题。

## 数据流

```text
active topics
  -> classifyKnowledgeTopic
  -> recognition topics only
  -> knowledgeApi.topicWorkspace(topicId)
  -> related events + evidence
  -> atomic proposition filter and deduplication
  -> source-host validation
  -> verification queue (read-only)
```

## 失败与边界

- 某个认识档案加载失败时，不用其他文章补位；页面按现有全局错误机制提示加载失败。
- 没有已形成认识时，不请求 Topic Workspace，直接展示空队列。
- 命题没有 URL、过长或形态像文章内容时直接排除，不降低准入标准。
- 本轮不增加“确认”“反驳”“忽略”等写操作，避免在没有后端语义支持时制造伪状态。

## 验收标准

- 全量事件和全量证据不再作为核验页数据源。
- 文章标题、Markdown 链接、论文 Abstract 不会成为核验命题。
- 核验项必须显示其影响的投资认识。
- arXiv 等研究站点不会因 `REGULATOR` 误标而被当成一手监管来源。
- 默认队列只展示仍需寻找一手来源的命题。
- 当前没有已形成认识时，页面诚实显示空队列。
- 前端单元测试、全量测试和生产构建通过。
