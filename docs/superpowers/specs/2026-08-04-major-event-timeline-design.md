# 大事记设计

## 目标

让用户在新闻资讯或雷达页发现重要信息时，一键保留一条可长期回看的投资大事记录；数月后能够按事件发生时间回顾某月发生的重要事件及当时的判断。

## 范围

首期新增独立的「大事记」工作区。它接收来自实时资讯、Article 和 RadarEvent 的记录，按事件发生日期组织为时间线，并可按时间范围、主题分类和来源类型筛选。

不复用 Inbox 候选项的 `SAVED_FOR_LATER` 状态：候选项代表待处理流程；大事记代表已经识别为重要的长期历史记录。

## 方案选择

采用“带来源引用的历史快照”。保存时复制标题、摘要、来源、分类、事件日期和可选个人判断到独立记录，同时保存来源标识。Article 和 RadarEvent 保存稳定的数据库关联；实时资讯保存其供应商 `itemId` 作为来源标识。

这避免了纯引用收藏在来源被更新、过期或删除时失去历史语境；也避免独立手工录入需要重复填写新闻信息。源文章或雷达事件的后续更新不会覆盖快照，但用户可以通过来源链接查看最新内容。

## 用户流程

1. 用户在实时资讯、文章卡片或雷达事件卡片上点击“记入大事记”。
2. 系统打开轻量确认框，预填标题、摘要、分类和事件发生日期。
   - Article 默认使用 `publishedAt` 的日期，无发布时间时使用当前日期。
   - RadarEvent 默认使用 `firstSeenAt` 的日期。
3. 用户可调整事件日期并输入一段可选的“当时判断 / 为什么重要”。确认后创建快照。
4. 用户进入侧边栏「大事记」，按月份倒序回看记录；可按日期范围、主题分类及来源类型筛选。
5. 用户可编辑事件日期或个人判断、删除记录，或跳转查看原文章/雷达事件。

## 界面

- 新增顶级导航项：`Timeline`，中文提示为「大事记」。
- 文章和雷达事件卡片提供同一语义的操作入口「记入大事记」。
- 大事记默认按 `occurredDate DESC, createdAt DESC` 排列，按“YYYY 年 M 月”分组。
- 每张时间线卡片显示：事件日期、标题、摘要、分类、来源标识、个人判断与来源跳转。
- 空状态说明这是用于沉淀和回看市场大事的时间线。

## 数据与接口

新增 `major_event` 表及对应领域模型，字段包括：

- `id`、`origin_type`（`NEWS_ITEM`、`ARTICLE` 或 `RADAR_EVENT`）、`origin_key`
- `title`、`summary`、`source_name`、`source_url`、`category_code`
- `occurred_date`、`note`、`created_at`、`updated_at`

每一行都是不可被来源同步任务覆盖的历史快照。后端提供创建、查询、更新和删除接口；Article 和 RadarEvent 的创建接口按来源类型与 ID 读取当前对象生成默认快照，实时资讯由前端提交当前可见内容的快照。接口拒绝不存在的持久化来源和重复保存同一来源的请求。

## 边界与错误处理

- 同一个实时资讯、Article 或 RadarEvent 只能被记入一次，重复操作返回明确的冲突结果；前端把已记录项显示为已加入。
- 删除只删除大事记记录，不影响文章、雷达事件、证据或简报。
- 空筛选结果不报错，显示空状态。
- 来源记录后续不存在时，大事记快照仍可正常浏览；来源跳转操作不可用。

- Web 层覆盖参数校验和来源不存在的响应。
- 前端覆盖：从文章/雷达触发记录、确认提交、时间线分月显示、筛选、编辑与删除。
