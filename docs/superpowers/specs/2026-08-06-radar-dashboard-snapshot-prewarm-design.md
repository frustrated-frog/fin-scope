# 雷达与首页热点快照预热设计

## 目标

资讯抓取、雷达聚合、评分和 Agent 增强继续在既有后台链路中执行。雷达生产批次完成后，直接将本轮已生成的热点结果物化为 Redis 快照；首页榜单和雷达页只读这些快照，不再让页面请求承担 SQLite 查询与 DTO 组装成本。

## 范围

- 预热首页金融、科技、政治三类热点榜单。
- 预热雷达默认视图：`category=ALL`、`watchlistOnly=false`、`limit=20`、`state=ALL`。
- SQLite 保留在生产链路中，用于生成事件 ID、保存事件详情、观察记录、研究关联和历史追溯；它不参与首页榜单和雷达列表的正常读取，也不会被预热服务回读。
- Redis 读取失败、缓存损坏或首轮生产尚未完成时，两个列表接口返回明确的空快照与生产状态，不触发 SQLite 回查。

不在本次范围内：将每一种雷达筛选组合全部写入 Redis、改变热点计算/分类口径、改动抓取频率或 Agent 行为、移除 SQLite 中已有的详情与历史模型。

## 架构与数据流

1. 定时抓取触发既有资讯刷新、雷达生产及 Agent 增强链路。
2. 雷达生产得到本轮完整事件结果后，快照物化服务从内存结果构造雷达默认页及金融、科技、政治三类榜单，序列化并写入 Redis 的下一版本。
3. 所有快照写入成功后，原子切换 `radar` 与 `dashboard` 的 revision，并通过既有 SSE 通知在线页面刷新；旧 revision 的键由 TTL 自动回收。
4. SQLite 继续在生产链路中完成事件与关系的持久化，以支持 Agent 的事件 ID、详情和历史；快照物化不再从 SQLite 回读这些结果。
5. 首页调用独立的热点榜单接口；雷达页调用既有雷达读取接口。两个接口只读取 Redis；无可用快照时返回空结果与当前生产状态。

## 接口

- 新增 `GET /api/dashboard/hotspots`：返回三个首页热点榜单；只读 Redis 快照，不再依赖首页汇总接口中的 `hotspotRankings` 字段。
- `GET /api/dashboard` 继续返回首页其它概览数据，不负责热点榜单。
- `GET /api/research-radar` 保持当前默认参数与响应契约。非默认筛选参数仅针对已物化的分类快照返回；未物化组合返回空事件列表与说明，不会回查 SQLite。

前端首页并行请求首页概览和热点榜单，以免排行榜的更新或暂不可用影响其它首页信息的返回。

## 错误处理与一致性

- 预热中的单项失败不会发布新 revision；记录日志，页面继续展示最近一次完成的快照。
- Redis 写入失败不影响 SQLite 的生产持久化；列表页面继续读取最近一次完整 Redis revision，或返回空快照。
- 雷达生产失败时不发布新版本，继续展示最近一次完成的快照。
- 写入与读取复用既有 JSON 序列化和版本化 key，避免增加第二套缓存协议。

## 测试

- 快照预热服务会将默认雷达视图和三个榜单写入下一 revision，并在全部写入后发布版本更新。
- 首页热点接口只读取已预热快照；缓存未命中时返回空榜单。
- 雷达默认视图可由预热快照直接返回；未物化筛选组合不会触发 SQLite 查询。
- Redis 仓储异常时，两个接口不调用 SQLite 列表查询，并返回最近成功快照或明确的空状态。
