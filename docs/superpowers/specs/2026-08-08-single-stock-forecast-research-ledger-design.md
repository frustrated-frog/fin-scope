# 单股预测研究台账与完整评估报告设计

## 1. 目标

把当前“一次性概率预测”升级为可复查、可解释、可比较的单股研究运行：

- 每次点击预测都保存一条不可变记录，包括当时的数据、模型、指标、结论和个人持仓快照。
- 默认比较基准固定为同一只股票同期买入并持有，不使用沪深 300。
- Python 负责特征、训练、滚动验证、虚拟交易、绩效统计、市场阶段和参数稳定性分析。
- Java 负责调用 Python、读取个人持仓、保存与查询研究记录。
- 前端既能运行新预测，也能浏览历史记录和阅读完整研究报告。

这仍然是研究支持工具，不自动交易，不把统计结果包装成确定性买卖建议。

## 2. 方案选择

### 方案 A：扩展单股预测为独立研究运行（采用）

新增专用 `single_stock_forecast_run` 表，每条记录保存索引字段、完整报告 JSON 和持仓快照 JSON。Python 返回完整报告，Java 原样映射并持久化。

优点：边界清楚、兼容当前架构、历史报告可精确重放、迭代字段时不需要大量关系表迁移。缺点：JSON 内的细粒度指标不适合复杂 SQL 聚合，但当前是个人单股研究，不需要跨市场统计。

### 方案 B：复用现有 `quant_experiment` 体系

把单股预测包装成策略版本和量化实验。

优点：可以复用收益曲线、交易、年度表现等关系表。缺点：现有实验面向数据集和组合策略，必须虚构 dataset、strategy version，语义混乱，并会重新引入 Java 回测职责。

### 方案 C：所有记录都由 Python SQLite 保存

优点：分析与持久化都在 Python。缺点：业务历史绕过 Java 服务层，持仓关联和统一 API 权限边界变差，也不符合项目的模块职责。

因此采用方案 A。

## 3. 研究规则

### 3.1 预测对象

- 一次只研究一只 A 股。
- 使用最多 5000 根服务端缓存的 QFQ 日线。
- 当前核心预测周期仍为未来 20 个交易日。
- T 日收盘产生信号，T+1 开盘模拟成交，避免未来数据泄漏。

### 3.2 虚拟策略

为了让“策略收益、交易次数、换手率、持仓占比”具有确定含义，固定研究策略如下：

- 当滚动样本外上涨概率大于等于 60% 时，下一交易日开盘全仓买入。
- 每笔持有 20 个交易日，在第 20 个交易日收盘卖出。
- 持仓期间忽略新信号，不加仓、不重叠持仓、不使用杠杆。
- 空仓资金收益按 0 计算。
- 每次完整买卖默认总成本 15 bps；报告单独展示累计交易成本。
- 规则参数写入报告，不根据某只股票的结果自动调优。

该策略只是把概率变成可审计的历史实验，不影响当前概率本身，也不对应用户真实仓位。

### 3.3 默认基准

- 基准代码与预测股票完全相同。
- 在样本外评估窗口首个可交易日开盘买入，最后一个交易日收盘卖出。
- 基准应用相同的单次完整买卖成本。
- 页面统一称为“同股买入并持有”，禁止默认显示沪深 300。

### 3.4 样本内与样本外

- 时间顺序前 60% 的成熟样本作为初始训练段。
- 样本内报告描述模型对初始训练段的拟合，只用于诊断，不作为有效性证据。
- 后 40% 使用扩展窗口 walk-forward：每个预测点只使用当时已经产生且标签已成熟的样本。
- 额外每 20 个交易日抽取一个非重叠锚点，作为独立样本指标。
- 最终结论以样本外、尤其是独立样本为主，样本内结果不能把结论升级。

## 4. Python 报告结构

### 4.1 概率结论

保留当前字段：上涨概率、相近历史信号收益 P20/均值/P80、Brier、命中率、历史基础上涨率和最近样本外观察。

最终状态收敛为四类：

- `ROBUST`：样本外相对买入持有有正超额收益，风险调整后指标改善，独立样本充分，且相邻参数方向一致。
- `CONDITIONAL`：只在部分阶段或部分相邻参数下有效，适合作为条件性观察。
- `NO_CLEAR_EDGE`：概率或收益看似积极，但样本外没有稳定优于同股买入持有。
- `INSUFFICIENT_DATA`：历史、独立样本、交易次数或阶段覆盖不足，拒绝稳健性判断。

结论规则确定化并版本化，不调用 LLM 决定评级。

### 4.2 因子知识与解释

七个现有因子逐一输出：

- 因子代码、中文名称、类别和公式。
- 使用窗口和所需行情字段。
- 当前值、在该股历史中的百分位。
- 模型标准化系数、当前 logit 贡献和方向。
- 经济含义、适用条件和误判风险。

因子为 `MOMENTUM_5`、`MOMENTUM_20`、`MOMENTUM_60`、`PRICE_VS_MA20`、`PRICE_VS_MA60`、`VOLATILITY_20`、`AMOUNT_RATIO_20_60`。页面明确说明“贡献解释模型输出，不证明因果关系”。

### 4.3 绩效与风险

策略和同股买入持有分别计算：

- 总收益、年化收益、超额收益。
- 最大回撤、最大回撤开始日、谷底日、恢复日和持续交易日。
- Sharpe、年化波动率、日胜率。

策略额外计算：

- 完整交易次数、盈利交易胜率。
- 单边换手率和累计交易成本。
- 持仓交易日占比、平均持仓天数。

收益曲线按交易日输出策略净值、买入持有净值和策略回撤。前端进行抽样渲染，但持久化保存完整曲线。

### 4.4 年度与趋势阶段

- 分年度输出策略收益、买入持有收益、超额收益、最大回撤和交易次数。
- 阶段使用该股票自身、且只依赖当时数据的 120 日滚动收益分类：大于等于 10% 为上行阶段，小于等于 -10% 为下行阶段，其余为震荡阶段。
- 报告称其为“标的自身趋势阶段”，避免误解为全市场牛熊划分。
- 每个阶段输出样本天数、策略收益、基准收益、超额收益、Sharpe、最大回撤、交易次数和持仓占比。

### 4.5 相邻参数稳定性

不搜索最优参数，只计算预先固定的五个邻域方案：

- 基准：20 日持有、60% 入场阈值。
- 阈值邻域：55%、65%，持有期保持 20 日。
- 持有期邻域：15 日、25 日，阈值保持 60%。

每个方案输出样本外年化收益、相对同股买入持有超额收益、Sharpe、最大回撤和交易次数。稳定性摘要关注方向一致率、最差邻域超额收益和最差邻域 Sharpe；不根据结果挑选最好的一格作为主结论。

## 5. 预测记录

新增 SQLite 表 `single_stock_forecast_run`：

- `id`：自增主键。
- `instrument_code`、`as_of_date`：历史列表筛选字段。
- `status`、`up_probability`：摘要字段。
- `data_fingerprint`、`model_version`、`report_schema_version`：可复现性字段。
- `same_data_as_previous`：同一股票上一条记录是否使用相同数据指纹。
- `report_json`：Python 返回的完整不可变报告。
- `holding_snapshot_json`：运行时个人持仓快照。
- `created_at`：实际运行时间。

每次点击都插入新记录，不因相同股票或相同数据指纹去重。历史详情只读取保存内容，不重新抓行情、不重新跑模型。

API：

- `POST /api/quant/single-stock-forecasts`：运行、附加持仓快照、保存并返回详情。
- `GET /api/quant/single-stock-forecasts?code=&limit=`：按时间倒序查询摘要。
- `GET /api/quant/single-stock-forecasts/{id}`：读取不可变详情。

## 6. 真实持仓隔离

个人持仓不进入特征、训练、概率、回测或稳健性评级。

复用现有策略组合中的股票记录，并为股票持仓增加可选的 `quantity` 与 `average_cost`：

- 未填写时仍可只使用当前权重、目标权重、角色和备注。
- 已填写时用预测数据最后收盘价计算估算市值与未实现收益率。
- 运行时将持仓字段和估算结果冻结进 `holding_snapshot_json`，以后修改持仓不会改写旧报告。
- 个人化解释只输出持仓事实、与模型结论的关系、需要观察的条件和失效风险，不生成“买入/卖出/加仓”命令。

## 7. 前端信息架构

预测页面改为三层研究阅读器：

1. 顶部运行区：股票代码、运行按钮、数据规则和最近一次状态。
2. 左侧或顶部历史轨：按股票和运行时间显示记录，标记相同数据、结论和概率；点击后直接打开旧报告。
3. 报告正文：
   - 决策摘要与四级结论。
   - 策略与同股买入持有双曲线。
   - 收益、风险、交易和持仓占比指标矩阵。
   - 因子解释卡片与当前贡献。
   - 样本内/样本外对比。
   - 相邻参数稳定性矩阵。
   - 分年度和标的自身趋势阶段表格。
   - 最近预测观察和交易摘要。
   - 个人持仓上下文。
   - 数据来源、模型版本、指纹、成本与局限。

视觉上延续现有深色研究终端，但降低装饰密度：结论优先、证据次之、方法细节可展开。颜色只表达状态和正负，不用高概率制造“强烈买入”的视觉暗示。

## 8. 错误与兼容

- 少于 750 根有效 QFQ 日线时仍保存 `INSUFFICIENT_DATA` 记录，并解释缺失项。
- Python 返回结构或数值非法时 Java 拒绝保存，防止污染历史。
- 保存失败时本次 POST 返回失败，不出现“页面有结果但历史没有记录”的半成功状态。
- 旧前端字段继续保留，新字段增量扩展。
- 历史 JSON 带 schema version；读取旧版本时只展示已有区块。
- 同股基准、成本、阈值、周期、模型版本全部进入报告和指纹。

## 9. 测试与验收

- Python 单元测试覆盖无未来数据、同股基准、交易成本、回撤持续时间、年度与阶段切分、参数邻域和四级结论。
- Python API 测试覆盖完整 JSON、数据不足和旧缓存刷新。
- Java DAO 测试覆盖每次运行都插入、相同数据标记、列表筛选、详情原样恢复。
- Java service/controller 测试覆盖持仓隔离、保存失败和三个 API。
- 前端测试覆盖运行后入历史、打开旧报告不重算、完整指标、因子知识、同股基准文案和持仓区块。
- 真实验收至少使用一只有 1500 根以上日线的股票，核对 Python API、Java API、SQLite 记录和页面历史回看结果一致。

## 10. 非目标

- 不做全市场选股。
- 不读取券商账户，不自动同步真实成交。
- 不实时盯仓，不自动调仓，不执行交易。
- 不自动搜索最优参数。
- 不承诺未来收益，不用单次概率替代稳健性结论。
