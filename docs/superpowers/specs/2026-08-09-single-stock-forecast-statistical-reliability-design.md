# 单股预测统计可靠性第一批增强设计

日期：2026-08-09  
状态：待用户确认  
适用范围：策略工作台的单只 A 股、未来 20 个交易日净收益为正概率研究

## 1. 背景与目标

现有单股预测已经具备前复权日线校验、只使用已成熟标签的扩展窗口验证、同股买入持有基准、交易成本、完整绩效、参数邻域稳定性、因子解释和不可变研究记录。第一批增强不增加全市场选股，也不实时计算持仓，目标是提高结论的统计可信度和可复现性：

1. 明确隔离训练、概率校准和最终检验，减少反复观察同一批样本造成的乐观偏差。
2. 将模型输出的原始分数校准为更接近真实频率的概率。
3. 为概率质量和策略表现给出区间，而不只给单点结果。
4. 固化一次研究的模型、数据、参数与随机过程，使历史结论可以重放和比较。
5. 把这些证据直接呈现在策略工作台，校准失败或样本不足时明确降级，不伪造精确度。

“预测准确”在本设计中指：对从未参与拟合和校准的数据，方向判断、Brier、Log Loss、概率可靠性以及经济结果可以被重复检验。系统不承诺某只股票必然上涨，也不以样本内命中率作为准确性证明。

## 2. 第一批范围

### 2.1 本批实现

- 带标签成熟约束的前向训练与三段式资格检验。
- Platt 概率校准及无泄漏回退规则。
- Brier、基准 Brier、Brier Skill Score、Log Loss、ECE 和可靠性分箱。
- 确定性移动区块 bootstrap 置信区间。
- 当前校准概率的有限不确定性区间。
- 模型资格检验与实验身份写入现有预测历史记录。
- 策略工作台新增“预测可信度”与“概率校准”展示。
- 自动化测试覆盖时间泄漏、切分隔离、校准、bootstrap、序列化和前端状态。

### 2.2 本批不实现

- 全市场截面选股、Qlib 全量接入和 101 Alphas 批量导入。
- 自动搜索最优因子、模型、持有期或交易阈值。
- 深度学习、新闻文本因子、财务因子与行业横截面中性化。
- 自动下单、仓位优化和实时持仓联动。
- 宣称未来收益确定发生。

这些能力留在后续批次，避免在单只股票有限样本下先引入高自由度模型和数据挖掘偏差。

## 3. 工程原则与代码边界

本设计遵循根目录《项目开发规范与代码评审清单》从三个生产工程提炼出的原则：明确边界、固定主干、开放稳定变化点、集中处理失败与审计。

```text
前端策略工作台
    ↓ 展示与交互
Java Web / Service
    ↓ 参数校验、Python 契约适配、不可变记录持久化
Python forecast pipeline
    ├── 时间切分与标签成熟检查
    ├── 基础模型训练
    ├── 概率校准
    ├── 锁定测试评估
    ├── bootstrap 区间
    └── 全历史生产重拟合与因子解释
```

- 统计计算留在 `market-data-service`，Java 不复制公式。
- Java Controller 保持薄，只调用现有单股预测服务；Python 调用继续通过 `finscope-rpc`。
- SQLite 仍是预测历史的事实来源；新增资格检验随报告 JSON 一起不可变保存，不新建第二套实验数据库。
- 算法变化点只在确实存在替换需求时抽象：切分、校准和区间估计使用业务内明确组件，不建立通用框架或无意义 `Impl`。
- 不引入 scikit-learn。当前模型和 Platt 校准都是低维逻辑回归，使用现有 NumPy 能减少依赖、保持确定性，并可通过专门测试验证数值行为。

## 4. 数据与标签契约

### 4.1 输入

- 单只股票、按交易日升序、字段完整的 QFQ 日线。
- 每根日线必须通过现有代码、日期唯一性、OHLC、成交量和成交额校验。
- 特征只能读取信号日及以前数据。
- 标签保持现有口径：信号日收盘计算，下一交易日开盘进入，第 20 个交易日收盘退出，扣除 0.15% 往返成本后净收益是否大于零。

### 4.2 标签成熟与 purge

对任一待预测日 `T`，训练样本必须满足：

```text
sample.exit_date < T
```

这会排除所有结果区间仍覆盖 `T` 的样本，是单向扩展窗口下真正需要的 purge。当前实现已经具备这一核心约束，本批把它提升为显式切分审计数据和不变量测试。

纯前向训练不会使用验证区之后的样本回头训练过去，因此不机械添加对称式 embargo。embargo 主要用于训练集合可能同时位于验证区前后的交叉验证；在本项目的严格单向时间轴中，额外删掉验证区之后的数据没有对象。若后续加入双向 purged K-fold 或参数搜索，再增加与 20 日标签周期一致的 embargo。

### 4.3 数据最低门槛

- 保持不少于 750 根合格日线的入口门槛。
- 分割后开发训练样本不少于 300。
- 校准集独立锚点不少于 15；锁定测试集独立锚点不少于 15。
- 任一区间正负标签均至少 5 个，否则该区间不能支持校准或概率质量结论。
- 门槛不足时仍保存 `INSUFFICIENT_DATA` 研究记录，并列出具体缺失数量，不返回伪概率。

## 5. 四段证据链

样本按信号日期排序，以完整标签样本的时间跨度切分：

1. **开发训练区：前 60%**。只用于扩展窗口训练和基础模型形成。
2. **校准区：接下来的 20%**。基础模型参数固定，生成原始概率；仅用这些原始概率和真实标签拟合 Platt 校准器。
3. **锁定测试区：最后 20%**。基础模型选择、模型参数和校准器都不得读取该区标签；只在全部冻结后评估一次。
4. **生产重拟合：资格检验完成后**。为了计算“截至今天”的概率，在所有已成熟历史标签上重新拟合相同基础模型，并应用资格阶段得到的校准映射。生产重拟合不能反向修改锁定测试指标。

切分边界采用日期并记录首尾日期、原始样本数、独立锚点数、purge 数和标签分布。经济绩效继续使用每个交易日的顺序样本外概率模拟；统计准确性使用每 20 个交易日一个锚点，降低重叠标签带来的伪样本量。

这里的“锁定”是代码路径隔离，不是假装数据对开发者永远不可见。系统会通过测试保证测试区标签不进入训练、校准和阈值选择；模型版本发生变化时会产生新的资格检验身份，不能把旧测试结论冒充新模型证据。

## 6. 概率校准

### 6.1 方法

默认使用 Platt scaling：

```text
calibrated_probability = sigmoid(a × logit(raw_probability) + b)
```

仅用校准区的独立锚点拟合 `a`、`b`，采用 L2 正则、概率裁剪和固定迭代规则。相比 isotonic，Platt 在本项目单股小样本下参数更少、外推更平滑。

### 6.2 回退

以下任一条件成立时，校准状态为 `NOT_FITTED`，生产概率退回原始概率：

- 校准独立锚点少于 15。
- 正类或负类少于 5。
- 数值迭代不收敛或输出非有限值。
- 校准区的 Log Loss 相比恒等映射明显恶化超过预设容忍值。

回退原因写入报告和 warnings，前端不得把未校准概率标成“校准概率”。

### 6.3 当前输出

- `rawProbability`：全历史生产模型的原始输出。
- `upProbability`：校准器可用时的校准输出，否则等于原始输出。
- `probabilityInterval`：只反映校准映射参数在小样本下的不确定性，不宣称覆盖全部模型风险。
- 因子贡献继续解释基础模型的 raw logit；页面明确说明校准器只改变概率尺度，不改变因子方向排序。

## 7. 资格检验指标

所有决定结论的概率指标默认来自锁定测试独立锚点：

- Accuracy：以 50% 为固定方向阈值，仅作直观辅助。
- Brier Score：概率平方误差，越低越好。
- Baseline Brier：用开发区已成熟标签的历史上涨率作为朴素概率，不能读取锁定测试整体上涨率。
- Brier Skill Score：`1 - model_brier / baseline_brier`，大于 0 才代表优于朴素概率。
- Log Loss：对自信但错误的预测施加更大惩罚。
- ECE：按预测概率分箱后，预测均值与实际频率差的加权平均。
- Reliability bins：每箱给出样本数、预测均值、实际上涨率和正负误差。

同时保留原始概率与校准概率在锁定测试上的 Brier、Log Loss、ECE，用户可以直接判断校准到底有没有改善，而不是只看到处理后的结果。

可靠性分箱使用固定边界 `[0, .2, .4, .6, .8, 1]`；空箱保留为空状态，不补零。固定边界使不同日期、不同预测记录可以直接比较。

## 8. Bootstrap 置信区间

### 8.1 方法与随机性

使用移动区块 bootstrap，默认：

- 统计资格指标：对锁定测试独立锚点重采样，区块长度 3，重复 1,000 次。
- 经济表现：对样本外日收益与同股基准日收益成对重采样，区块长度 20，重复 1,000 次。
- 当前概率区间：固定生产基础模型，对校准样本成对重采样并重拟合两参数校准器，重复 500 次。
- 区间使用 2.5% 和 97.5% 分位数。
- 随机种子由数据指纹、模型版本和用途经 SHA-256 派生，不依赖系统时间。

区块重采样保留部分时间相关性；策略和基准必须成对取相同区块，避免破坏市场路径对应关系。

### 8.2 输出区间

- 校准 Brier Skill Score。
- 校准 Log Loss。
- 方向 Accuracy。
- 策略相对同股买入持有的累计超额收益。
- 策略 Sharpe。
- 当前校准概率的有限区间。

当有效样本不足、全部重采样结果无效或指标分母为零时，区间返回明确的 `UNAVAILABLE`，不以 `[0, 0]` 代替。

## 9. 模型资格与最终结论

报告新增 `qualification`，包含：

- `status`: `QUALIFIED`、`CONDITIONAL`、`FAILED`、`INSUFFICIENT_DATA`。
- 切分与 purge 审计。
- 校准方法、状态、参数、校准样本规模和回退原因。
- 锁定测试原始/校准/基准指标。
- 可靠性分箱和置信区间。
- 试验身份和版本。

最终业务结论仍为 `ROBUST`、`CONDITIONAL`、`NO_CLEAR_EDGE`、`INSUFFICIENT_DATA`，但判断升级为：

- **ROBUST**：锁定测试 Brier Skill 为正，95% 区间下界不显著为负；校准 Log Loss 不劣于原始值；策略超额收益为正且区间不过度偏向负值；相邻参数方向一致；样本和交易数达标。
- **CONDITIONAL**：点估计有优势，但至少一个关键区间跨越无优势边界，或优势依赖市场阶段/相邻参数。
- **NO_CLEAR_EDGE**：锁定测试概率质量不优于朴素基准，或经济结果与概率结果同时缺乏优势。
- **INSUFFICIENT_DATA**：资格检验门槛不足。

结论阈值会集中定义，并写入 trial 配置快照；不会根据本次测试结果临时调参。

## 10. 实验身份与不可变记录

每次报告新增：

- `reportSchemaVersion = single-stock-research-v3`
- `modelVersion = logistic-platt-qualified-v3`
- `trialId`：模型版本、特征版本、标签版本、切分版本、数据指纹、成本和固定参数的 SHA-256 摘要。
- `featureVersion`、`labelVersion`、`splitVersion`、`calibrationVersion`、`bootstrapVersion`。
- `randomSeed`、重复次数、区块长度和固定阈值。
- 开始/结束日期、各区样本量和数据指纹。

同一数据与同一配置产生相同 trialId 和统计结果。现有 SQLite 预测记录继续保存完整 JSON，因此 v2 历史无需迁移；前端以可选字段兼容读取 v2，v3 才展示资格卡片。

## 11. API 契约草案

在现有 `SingleStockForecastResult` 上新增，不删除 v2 字段：

```text
rawProbability: number | null
probabilityInterval:
  status, lower, upper, confidenceLevel, method, limitation
qualification:
  status
  trial
  splitAudit
  calibration
  lockedTest
  confidenceIntervals
```

`lockedTest` 同时包含 `rawMetrics`、`calibratedMetrics`、`baselineMetrics` 和 `reliabilityBins`。所有数值必须为有限值；不可计算使用状态和 `null`，禁止 NaN、Infinity 或语义不明的零。

Java RPC 适配器继续对关键契约做 fail-fast 校验：版本、概率范围、区间顺序、样本数量、分箱数量合计、trialId 格式和资格状态必须一致。下游协议异常仍映射为现有 `ProviderContractException`，不把 Python 原始堆栈作为业务响应透传。

## 12. 前端呈现

策略工作台保留当前纸张式研究报告视觉，新增两个区块：

### 12.1 预测可信度卡

- 主数字显示校准后上涨概率。
- 紧邻显示 95% 有限区间和原始概率。
- 显示 `已通过资格检验 / 条件有效 / 未通过 / 数据不足` 状态。
- 明确提示“区间仅覆盖校准误差，不覆盖突发事件和结构变化”。

### 12.2 概率可靠性

- 小型可靠性图：横轴预测概率、纵轴实际上涨频率，45° 线为理想校准。
- 下方并列原始与校准的 Brier、Brier Skill、Log Loss、ECE。
- 展示锁定测试样本数、日期范围、purge 数和基准定义。
- 指标区间跨越无优势边界时使用中性提示，不用红绿制造确定性。

移动端改为纵向卡片和横向可滚动的分箱表；遵守现有减弱动画和可访问性样式。历史 v2 报告显示“该记录生成时尚未启用资格检验”，而不是渲染空图。

## 13. 失败、性能与可观测性

- 单股日线数据规模小，bootstrap 串行 NumPy 计算即可；首批不引入线程池和异步任务。
- 目标：1,600 根日线的完整预测在普通本机额外耗时不超过 2 秒，总接口时间不因 bootstrap 超过现有超时预算。实现后以基准测试验证；若超预算，优先减少重复拟合和向量化，不降低数据正确性。
- Python 对阶段耗时记录结构化日志：`trialId`、样本数、校准状态、bootstrap 有效次数、总耗时；不记录完整行情和敏感配置。
- 数值失败、样本不足和资格失败属于不同状态。数值异常应明确失败；证据不足返回可保存的研究结果；不得用上一次股票的模型或结果静默降级。
- 已保存的预测历史仍可查看，即使当前 Python 服务暂时不可用。

## 14. 测试与验收

### 14.1 Python 单元测试

- 特征不读取信号日以后数据。
- 每个训练样本 `exit_date < prediction_date`。
- 校准集和锁定测试集标签从不进入基础模型拟合。
- 锁定测试标签从不进入校准器和朴素基准概率。
- 人工失准数据经 Platt 后 Log Loss/Brier 改善。
- 小样本、单一类别、非收敛时按契约回退。
- 固定数据产生相同 trialId、seed、bootstrap 区间和报告 JSON。
- 区块重采样保持策略/基准日期配对。
- 置信区间顺序正确且无 NaN/Infinity。
- v3 完整报告与数据不足报告均可序列化。

### 14.2 Java 契约与持久化测试

- v3 Python 响应完整解析；非法概率、非法区间、样本合计不一致和未知状态被拒绝。
- v2 历史 JSON 保持可读取。
- 相同请求仍生成不可变记录，并正确标识相同数据指纹。
- Python 失败不写入伪成功记录；数据不足按现有规则保存。

### 14.3 前端测试

- v3 显示校准概率、原始概率、区间、资格状态和可靠性分箱。
- 校准回退、区间不可用、资格失败和数据不足均有明确文案。
- v2 历史报告兼容。
- 图表空数据不崩溃，数值格式与无障碍标签正确。

### 14.4 完成门禁

- Python 全量测试通过。
- 相关 Java 模块测试通过；全量测试中的既有无关失败单独列明，不掩盖新增失败。
- 前端全量测试和生产构建通过。
- 使用固定合成日线完成一次端到端报告并核对所有统计字段。
- 使用一只真实关注股票运行一次，只用于验证契约、性能和页面，不用单次结果反向修改模型。

## 15. 后续批次接口预留

第一批完成后，第二批可在不改资格检验主干的前提下增加：

- 因子定义卡与版本化因子注册表。
- 成交量价、波动率形态、回撤、趋势质量等 20～30 个低冗余单股因子。
- 因子消融、相关性聚类和稳定选择。
- 逻辑回归、树模型和朴素基准的预注册模型竞争。
- 多周期标签和结构化市场阶段资格检验。

任何新增模型或因子都必须生成新 trialId，并重新通过相同的校准区与锁定测试门禁，避免“多试几个总能找到好结果”。
