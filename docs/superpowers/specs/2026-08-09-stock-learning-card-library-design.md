# 股票学习卡库与六维详情设计

## 目标

股票学习卡页面从“输入代码后只显示本次结果”改为持久化的股票卡片库。用户重新进入页面时，首页自动展示数据库中已有的股票学习卡；点击某只股票后进入其最新一次运行的六维解读详情。

本期仍由用户主动选择股票并生成，不引入自选股绑定、搜索建议、运行历史切换或批量研究。

## 方案选择

采用独立学习卡列表 API，而不是从自选股反推或使用浏览器缓存：

- 数据源直接来自 `stock_learning_card` 及其 `latest_run_id`，只展示真正生成过学习卡的股票。
- 页面刷新、退出重进或更换浏览器后仍可恢复。
- 不要求股票先进入自选，也不把学习卡状态复制到前端本地存储。

## 页面结构

页面包含两层视图，但仍属于同一个“股票学习卡”入口。

### 股票卡片首页

- 顶部保留股票代码输入和“生成学习卡”操作。
- 主体按股票展示紧凑卡片，每只股票只出现一次。
- 卡片展示股票名称、代码、最新运行状态、摘要、完成时间和六维完成数量。
- `RUNNING` 卡片展示当前阶段并自动轮询列表。
- 点击卡片进入详情，不在首页铺开六维正文。
- 没有任何历史卡片时展示明确空状态，引导输入股票代码。

视觉继续沿用 FinScope 深色研究工作台，不引入新的全局字体或主题。卡片的识别特征是六段式维度进度轨道：六个短格对应固定六维，已完成、证据不足和失败使用现有状态色区分，结构本身表达研究完整度。

### 六维详情

- 顶部提供“返回全部股票”操作、股票名称和代码、运行状态与重新生成按钮。
- 中部沿用现有六维卡片，展示判断、依据、反方、未知项及公开来源。
- 底部保留后续观察事项。
- 详情数据继续使用现有 `GET /api/stock-learning-cards/{code}`，不复制新的详情契约。

## 后端契约

新增 `GET /api/stock-learning-cards`，返回按学习卡更新时间倒序排列的摘要列表。摘要字段为：

- `code`、`name`
- `status`、`stage`
- `summary`
- `completedDimensions`、`totalDimensions`
- `updatedAt`、`completedAt`

Repository 使用一次关联查询读取学习卡、股票和最新运行，并通过聚合子查询统计最新运行中 `READY` 的维度数。列表不加载证据正文、完整 claims 或 watch items，避免首页响应过重。

## 数据流与错误处理

1. 页面进入时请求学习卡摘要列表。
2. 点击股票卡片后按股票代码请求最新详情。
3. 新建运行成功后立即进入该股票详情并轮询；运行终止后刷新列表摘要。
4. 列表请求失败时保留已显示数据并提示“学习卡列表加载失败”。
5. 详情请求失败时停留在当前层级并显示可理解的错误，不展示数据库或主题概念。

## 数据清理边界

本次按用户要求，只清理 `stock_learning_card_run` 中 603618 最新运行之前的旧运行。保留 `stock_learning_card.latest_run_id` 指向的最新记录；关联的旧 claim、evidence 和 watch item 依赖外键级联删除。其他研究运行、主题、持仓和业务数据不受影响。
