# 基金持仓详情与盘中估算贡献设计

## 目标

在自选页保持现有股票卡片点击打开日 K 行情的行为，并为基金卡片增加独立的持仓详情弹层。用户打开基金后，可以看到最近一期公开披露的前十大直接股票持仓、每只股票的最新盘中行情，以及按披露权重计算的当日估算贡献。

本功能优先保证信息口径准确：公开披露持仓不是基金实时持仓；实时股票行情不可用或已降级为旧快照时，不展示该股票的估算贡献，也不以旧行情冒充实时数据。

## 产品边界

### 本期范围

- 点击 `FUND` 自选卡片打开基金持仓详情弹层；股票卡片继续打开现有 K 线弹层。
- 展示最近一期公开披露的前十大直接股票持仓。
- 展示披露日期、持仓占基金净值比例、最新价、当日涨跌幅、单股估算贡献。
- 汇总前十大披露权重与当前可计算股票的估算贡献。
- 打开弹层时主动刷新持仓与股票行情；支持弹层内手动刷新。
- 显示行情截至时间、实际行情源、数据质量提示与估算口径说明。
- 基金持仓事实可用但股票实时行情不可用时，仍展示持仓，行情与贡献位置显示不可用。

### 不在本期范围

- 不声称获得基金实时持仓或基金经理盘中调仓。
- 不展示半年报、年报才完整披露的全部持仓。
- 不把估算贡献等同于基金当日真实净值涨跌。
- 不做 ETF 联接基金的目标 ETF 穿透；这类基金必须提示“当前展示直接披露股票，不代表目标 ETF 的底层成分股”。
- 不新增基金买卖、持仓成本或收益记账能力。
- 不允许点击持仓股票后继续打开第二层 K 线，避免弹层嵌套；后续可改为同层视图切换。

## 数据口径

基金持仓取天天基金 F10 最近一期公开披露的 `股票投资明细`。每条持仓至少包含：股票代码、股票名称、占基金净值比例、持股数、持仓市值。披露日期从页面“截止至”字段解析，不使用抓取时间代替。

股票行情统一通过现有 `MarketDataGateway.fetchQuotes("STOCK", codes, true)` 批量刷新。只有以下条件同时满足时才计算贡献：

1. 行情记录 `valid=true`；
2. `changePct` 为有限数字；
3. 单条行情质量不是 `STALE_FALLBACK` 或 `UNAVAILABLE`；
4. 聚合行情质量不是 `STALE_FALLBACK` 或 `UNAVAILABLE`。

计算公式：

```text
单股估算贡献（百分点） = 披露持仓占基金净值比例（%） × 股票当日涨跌幅（%） ÷ 100
前十大合计估算贡献 = 所有可计算单股估算贡献之和
```

例如披露权重为 `8.00%`、股票当日上涨 `2.00%`，估算贡献为 `+0.16` 个百分点。汇总结果只代表已披露且行情有效的股票部分，不能反推出基金完整实时估值。

## 方案选择

### 采用：服务端聚合详情接口

服务端依次取得基金披露持仓和一批股票行情，在同一响应中完成代码匹配、质量判断和贡献计算。前端只消费一个稳定合同。

优势：

- 避免前端 N+1 请求与跨域解析；
- 十只股票共享同一刷新批次和质量口径；
- 贡献算法只有一个服务端实现，便于单元测试；
- 上游 HTML 结构变化只影响 RPC 适配器，不污染 Controller 和前端。

### 未采用方案

- 前端直连基金网页和行情：受跨域、上游格式漂移和错误处理限制。
- 后端只返回持仓、前端逐只请求行情：会产生 N+1 请求与不一致时间戳。

## 后端架构

### Domain

新增基金披露领域对象：

- `FundHoldingDisclosure`：基金代码、基金名称、披露日期、抓取时间、持仓列表；
- `FundStockHolding`：排名、股票代码、股票名称、披露权重、持股数、持仓市值。

领域对象不携带网页 HTML，不依赖东方财富字段名。

### RPC

新增 `FundHoldingProvider` 扩展点和 `EastmoneyFundHoldingProvider` 实现。适配器负责：

- 请求 `FundArchivesDatas.aspx?type=jjcc&code={code}&topline=10&year=&month=`；
- 使用现有 HTTP 传输策略设置 Referer、超时、状态码与响应体上限；
- 从 `var apidata={ content:"..." }` 中提取 HTML 内容并用 Jsoup 解析；
- 严格校验六位基金代码、披露日期、股票代码、百分比和数值字段；
- 结构缺失时抛出 Provider 合同异常，不返回伪造空列表。

持仓接口是基金事实源，不加入 `SourceAdapter`；它属于外部金融数据，按仓库约束放在 `finscope-rpc`。

### Service

新增 `FundHoldingDetailService`：

1. 校验该代码对应普通自选中的 `FUND` 标的；
2. 从 `FundHoldingProvider` 获取最近一期直接股票持仓；
3. 提取并去重股票代码；
4. 通过 `MarketDataGateway` 批量强制刷新股票行情；
5. 按代码合并，判断每条行情是否足够新鲜；
6. 计算单股和合计估算贡献；
7. 返回持仓事实、行情质量和用户提示。

第一版不持久化基金持仓，也不在外部接口失败时伪造旧数据。RPC 适配器可使用短时进程内缓存降低重复打开压力，但 `refresh=true` 必须绕过缓存。股票行情仍复用现有网关的多源、单飞、快照和质量审计能力；旧快照可用于解释失败，但不能参与贡献计算。

### Web API

新增：

```http
GET /api/watchlist/{code}/fund-holdings?refresh=true
```

响应核心结构：

```json

  "disclosureDate": "2026-06-30",

  "quoteAsOf": "2026-08-10T14:29:58",
  "quoteSource": "TENCENT_STOCK",

  "topHoldingsWeightPct": 0.96,
  "estimatedContributionPct": 0.01,
  "estimatedHoldingCount": 10,
  "totalHoldingCount": 10,
  "lookThrough": false,
  "note": "按最近披露的直接股票持仓估算，不代表基金实时持仓或实际净值涨跌。",
  "holdings": [
    {
      "rank": 1,
      "stockCode": "688012",
      "stockName": "中微公司",

```

`estimatedContributionPct` 的单位统一为百分点。无有效行情时字段为 `null`，不返回 `0`，以免把未知误写成零贡献。

错误语义：

- 基金不在普通自选或类型不是基金：返回明确业务错误；
- 上游未披露股票持仓：返回成功响应和空持仓说明，适配货币基金、债券基金等；
- 上游结构漂移或网络失败：接口失败，前端保留弹层并提供重试；
- 股票行情部分失败：接口仍成功，逐条标记行情不可用，合计只汇总有效条目并展示覆盖数量。

## 前端设计

### 卡片交互

- `STOCK` 卡片保持“点击看 K 线”；
- `FUND` 卡片增加“点击看持仓”；
- 点击卡片空白区域打开对应弹层；删除、分组、归因等按钮继续阻止卡片点击；
- 卡片本身增加键盘可聚焦与 Enter/Space 打开能力，保留清晰的 focus 样式和语义标签。

### 基金详情弹层

复用现有 K 线弹层的遮罩定位、滚动锁定、Esc 关闭、焦点恢复、响应式底部抽屉和标题区节奏，新增 `WatchlistFundHoldingsDrawer`，不把两种内容硬塞入同一个大型组件。

桌面端结构：

```text
基金名称 / 代码 / 最近披露期                行情截至 / 刷新 / 关闭
口径提示：公开披露，不是实时持仓

前十大披露权重       可计算覆盖       合计估算贡献
0.96%                10 / 10          +0.01 个百分点

排名  股票             披露权重   最新价   今日涨跌   估算贡献
01   中微公司 688012    0.32%     468.50   +1.25%    +0.004
...
```

移动端不强行横向滚动表格，每只持仓转为紧凑两列卡片：左侧股票身份，右侧涨跌；第二行展示披露权重和估算贡献。数值使用等宽数字，涨跌继续沿用项目的红涨绿跌语义。

状态设计：

- 首次加载：骨架/加载提示，避免空白弹层；
- 持仓失败：标题与关闭按钮仍可用，正文显示错误与重试；
- 空持仓：说明该基金最近披露期没有股票投资明细；
- 部分行情失败：持仓行保留，行情显示 `--`，行内给出简短原因；
- 行情陈旧：顶部显示质量提示，所有贡献隐藏；
- ETF 联接基金：根据基金名称包含 `ETF联接` 或 `ETF 联接` 展示直接持仓提示，不做不可靠的目标 ETF 推断。

### 前端请求与缓存

打开基金弹层时请求 `refresh=true`。同一个弹层生命周期内避免重复请求；手动刷新再次发送 `refresh=true`。关闭后再次打开会重新拉取，确保股票行情不会被前端长期缓存。

## 安全与可靠性

- 基金代码和股票代码都执行白名单格式校验，不允许拼接任意 URL。
- RPC 请求设置短超时、响应体上限、固定主机和 Referer。
- HTML 解析只读取指定表格列，忽略脚本和链接，不执行上游内容。
- 任何非有限数、负权重、异常日期或代码不匹配都拒绝参与计算。
- 日志记录基金代码、Provider、耗时和错误类型，不记录凭据或完整上游响应。

## 测试方案

### RPC

- 使用固定 F10 响应夹具解析基金名称、披露日期、十条持仓及数值；
- 覆盖空持仓、转义内容、列缺失、非法百分比、代码不匹配与上游失败；
- 验证请求 URL、超时、Referer 和响应体限制。

### Service

- 验证批量股票行情只调用一次；
- 验证贡献公式和合计精度；
- 验证旧行情、无效行情和部分失败不参与贡献；
- 验证返回可计算覆盖数量与质量说明；
- 验证非基金或非自选代码被拒绝；
- 验证 ETF 联接提示但不执行穿透。

### Web

- Controller 合同测试覆盖成功、空持仓、刷新参数和业务错误。

### Frontend

- 点击基金卡片打开持仓弹层，股票卡片仍打开 K 线；
- 操作按钮不会误触发弹层；
- 覆盖加载、成功、空持仓、失败重试、部分行情失败和刷新；
- 验证披露日期、行情时间、估算口径与覆盖数量可见；
- 验证 Esc、遮罩关闭、焦点管理、滚动锁定和移动端布局；
- 运行前端全量测试和生产构建。

## 验收标准

1. 点击任一基金自选卡片可打开基金持仓详情，股票 K 线行为不回归。
2. 最近披露期、直接持仓口径和行情截至时间清晰可见。
3. 十只股票通过一次批量行情调用刷新，实时有效时展示涨跌与贡献。
4. 旧行情或无效行情不参与贡献，页面不把未知显示为零。
5. ETF 联接基金不会被描述为已经穿透目标 ETF。
6. 桌面表格和移动端持仓卡片均无溢出、遮挡或难读的日期换行。
7. 后端全量测试、前端全量测试与生产构建通过。
