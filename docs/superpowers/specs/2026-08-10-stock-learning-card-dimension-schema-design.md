# 股票学习卡维度专属 Schema 设计

## 1. 目标

股票学习卡继续固定使用空间、盈利模式、竞争格局、治理结构、市场定价和反方验证六个一级维度，但不再要求六张卡共同回答“为什么、反方、未知”。每个维度拥有不同的研究任务、核心栏目和可选栏目；六张卡只统一证据引用、验证状态与置信度协议。

本次改造不改变学习卡的非交易边界，不生成买卖、仓位、目标价或收益承诺，也不改变用户只输入股票代码即可发起生成的流程。

## 2. 输出契约

`StockLearningCardClaim` 保留维度、运行状态、失败信息、置信度与排序，新增：

- `headline`：该维度的一句话判断；
- `ratingLabel`：维度专属评级名称，例如“成长空间”“盈利质量”；
- `ratingValue`：标准化评级值，限定为 `HIGH`、`MEDIUM_HIGH`、`MEDIUM`、`MEDIUM_LOW`、`LOW`、`UNKNOWN`；
- `sections`：按顺序排列的维度专属栏目。

每个 `section` 包含：

- `key`：服务端定义的稳定栏目代码；
- `title`：固定中文栏目名；
- `content`：事实、推断与未知边界清楚的分析文本；
- `evidenceRefs`：该栏目实际使用的证据编号；
- `verificationStatus`：`SUPPORTED`、`PARTIALLY_SUPPORTED`、`UNVERIFIED` 或 `CONTRADICTED`；
- `sortOrder`：显示顺序。

旧字段 `judgment`、`rationale`、`counterargument`、`unknowns` 不再出现在新 API 契约和新页面中。SQLite 迁移保留旧列以兼容历史数据库，但新结果只读写新字段和栏目表。

## 3. 六维栏目定义

| 维度 | 评级名称 | 核心栏目 | 可选栏目 |
| --- | --- | --- | --- |
| 空间 | 成长空间 | 当前业务版图、增量引擎、公司承接能力、兑现路径、增长约束 | 行业天花板 |
| 盈利模式 | 盈利质量 | 收入引擎、利润引擎、资本效率、现金质量、盈利弹性 | 单位经济性、盈利质量趋势 |
| 竞争格局 | 竞争位置 | 行业格局、公司位置、护城河、议价权、胜负手 | 核心对手、竞争趋势 |
| 治理结构 | 治理风险 | 控制权、利益绑定、资本配置、大股东风险、财务与披露、历史兑现 | 股东友好度 |
| 市场定价 | 市场预期 | 当前估值坐标、隐含预期、预期可实现性、预期差 | 历史位置、同行比较、关键催化剂 |
| 反方验证 | 证伪压力 | 核心投资假设、逐条反证、证伪条件、压力情景、领先风险指标、当前验证状态 | 无 |

核心栏目必须全部返回；证据不足时使用 `UNVERIFIED` 并明确说明缺口。可选栏目只有在输入证据能支撑有效内容时才返回。模型不得创造白名单之外的栏目，也不得改变标题和顺序。

## 4. Agent 编排

前五维继续相互隔离执行：分别使用维度专属搜索模板收集证据，再由合成 Agent 使用该维度的 Schema 生成栏目。

反方验证改为第二阶段执行。它除消费自身风险检索证据外，还读取前五维已经形成的 `headline`、评级和栏目内容，用于抽取核心假设、寻找跨维度矛盾并给出可观察的证伪条件。前五维局部失败不会阻断反方验证；缺失维度作为明确的证据缺口传入。

每个维度继续独立失败。栏目字段、栏目数量、顺序、证据编号、验证状态、评级值和交易语言均由服务端校验。任一校验失败时只降级当前维度。

## 5. 持久化与 API

`stock_learning_card_claim` 新增 `headline`、`rating_label`、`rating_value`。新增 `stock_learning_card_section`，通过 `claim_id` 关联栏目，并保存栏目代码、标题、内容、证据引用 JSON、验证状态和顺序。

Repository 在同一事务中保存运行、维度与栏目。读取运行时组装完整的 `claims[].sections[]`。前端共享类型同步到新契约，详情页按栏目列表渲染，不再硬编码“为什么、反方、未知”。

## 6. 错误与兼容策略

- 无模型或无证据时，生成包含全部核心栏目的保守结果；栏目状态均为 `UNVERIFIED`。
- 历史行若没有新栏目，Repository 将其映射为保守的空栏目结构，页面不会恢复旧三栏模板。
- 证据引用必须来自当前维度输入；无效编号使当前维度失败。
- 反方维度所引用的搜索证据仍来自自身证据集合；前五维内容作为推理上下文，不伪装成新证据。
- 数据库迁移只新增表和列，不删除旧列，避免破坏本地已有学习卡数据。

## 7. 验收标准

1. 六个一级维度及顺序保持不变。
2. 六张卡展示各自的专属栏目，不再出现统一“为什么、反方、未知”。
3. 核心栏目固定存在，可选栏目只在有支撑时出现。
4. 每个栏目展示自己的证据引用与验证状态。
5. 反方验证基于前五维结果和风险证据综合生成。
6. 单维失败、证据不足、模型不可用和交易语言门禁仍保持维度隔离。
7. DAO、Service、Web 与前端测试覆盖新契约和兼容读取。
