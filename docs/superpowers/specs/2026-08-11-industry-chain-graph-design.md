# 产业链图谱工作台设计

## 目标

新增独立的“产业链图谱”工作台，让用户从产业全景理解原材料、核心部件、制造、基础设施与终端应用之间的完整链路，并能从自选股票快速定位其产业位置、上下游依赖和影响传导路径。

本功能复用现有公开资料搜索、原文获取、LLM 结构化归纳、SQLite 持久化和股票产业链能力，但不把现有三段式股票结论直接扩张为大图。现有股票产业链是公司视角快照；新功能是产业视角、可版本化的关系图谱。

## 产品原则

1. 产业优先：主入口是产业链，而不是单只股票。
2. 双视角：同一图谱支持产业全景和股票聚焦，不保存两套互相冲突的数据。
3. 渐进披露：默认展示环节与产品，代表公司按需展开，避免节点爆炸。
4. 关系可解释：产业逻辑关系与真实企业供销关系严格区分。
5. 证据约束：每条关系均保留来源、可信度和推断类型；未披露关系不得伪装成确定事实。
6. 本地优先：SQLite 是事实来源，外部搜索或模型失败时保留最近一次可用版本。
7. 非投资建议：不输出买卖、仓位、目标价或确定性价格影响。

## 产品入口

- 主导航新增“产业链图谱”。
- 图谱首页展示已生成产业、最近查看和搜索入口。
- 用户可以输入产业名称创建图谱，例如 AI 算力、光伏、新能源汽车、人形机器人或半导体。
- 自选股票详情中的产业链页提供“在完整图谱中查看”，进入相关产业并聚焦该股票。
- 第一期不自动构建全市场图谱，只构建用户主动创建或查看的产业。

## 统一图谱模型

### 节点

- `INDUSTRY_CHAIN`：产业链主题。
- `STAGE`：有明确先后顺序的产业环节。
- `PRODUCT`：材料、零部件、设备、服务或终端产品。
- `COMPANY`：上市公司或重要非上市公司。

### 关系

- `CONTAINS_STAGE`：产业链包含环节。
- `FLOWS_TO`：环节向下一环节传递产品或价值。
- `BELONGS_TO_STAGE`：产品属于环节。
- `INPUT_TO`：产品是另一产品的投入。
- `PRODUCES`：公司生产或提供产品。
- `PARTICIPATES_IN`：公司参与某产业环节。
- `SUPPLIES_TO`：公司向另一公司供应产品；只允许公开材料明确披露时建立。

关系必须记录方向、说明、可信度、证据引用、关系性质和有效时间。关系性质只允许：

- `DISCLOSED`：公告、年报或权威资料明确披露。
- `INDUSTRY_LOGIC`：有资料支持的产业结构关系，不代表真实采购。
- `INFERRED`：模型归纳的待验证关系，使用虚线并降低视觉权重。

## 持久化

SQLite 新增：

- `industry_chain`：产业主题与当前发布版本。
- `industry_chain_revision`：每次生成或刷新的运行状态、版本和错误。
- `industry_chain_node`：版本内节点。
- `industry_chain_edge`：版本内有向关系。
- `industry_chain_evidence`：冻结的公开证据。

图谱按修订版本整体发布。新版本只有通过结构和证据校验后才能替换当前版本；失败修订不会修改旧版本。节点与边使用稳定业务键，便于后续比较新增、删除和可信度变化。

## 生成流程

```text
用户创建或刷新产业
  -> 规划产业边界与查询分支
  -> 搜索公开资料并读取重点原文
  -> 冻结证据包
  -> LLM 输出严格图谱 JSON
  -> 校验节点、边、方向、证据引用、重复和循环
  -> 生成分层布局顺序
  -> 原子发布新修订
```

第一期使用一次受控的产业图谱规划与归纳流程，不引入开放式无限 Agent 循环。每个产业使用固定的搜索和全文读取预算；任一搜索供应商失败时保留其他供应商结果，全部失败时修订明确失败。

严格校验包括：

- 节点和关系类型必须在白名单内。
- 每条边的起止节点必须存在且不能指向自身。
- 环节主干必须为有向无环图。
- 每条边至少引用一条当前证据。
- `SUPPLIES_TO` 必须为 `DISCLOSED`，不能由兼容性或行业逻辑推断。
- 至少覆盖三个产业阶段，并存在从上游到终端的可达路径。
- 禁止投资建议和虚构的客户、供应商、合同或营收占比。

## 服务边界

- `IndustryChainService`：创建、读取、刷新与并发保护。
- `IndustryChainRefreshExecutor`：异步生成和运行状态更新。
- `IndustryChainEvidenceCollector`：通过共享搜索网关生成冻结证据。
- `IndustryChainSynthesisAgent`：只消费证据并输出严格 JSON。
- `IndustryChainGraphValidator`：执行结构与证据验证。
- `IndustryChainRepository`：修订、节点、边和证据持久化。
- `IndustryChainProjectionService`：生成全景或股票聚焦响应，不修改事实图谱。

外部调用继续位于 `finscope-rpc`；Controller 不直接调用 Repository。

## API

- `GET /api/industry-chains`：列出产业链及当前状态。
- `POST /api/industry-chains`：创建产业链并启动首个修订。
- `GET /api/industry-chains/{id}`：读取当前图谱和最新修订。
- `POST /api/industry-chains/{id}/refresh`：启动异步刷新。
- `GET /api/industry-chains/{id}/revisions`：读取修订历史。
- `GET /api/industry-chains/{id}/focus?stockCode=...`：返回股票聚焦投影。

创建和刷新接口立即返回运行信息；前端轮询读取终态。并发刷新返回业务冲突，过期运行允许自动失效后重试。

## 前端信息架构

桌面端采用四区研究工作台：

```text
顶部：产业名称 / 搜索 / 全景与聚焦切换 / 更新时间 / 刷新
左侧：产业索引 / 最近查看 / 图层和可信度筛选
中央：分层有向图画布
右侧：选中节点或关系的研究详情
底部：图例 / 当前路径 / 图谱版本 / 节点与关系统计
```

中央图谱从左到右排列产业阶段。默认只显示阶段和产品；公司折叠为数量摘要，点击产品后展开。用户选择节点时，无关节点降低透明度，上下游两跳路径被点亮，右侧详情面板滑入。搜索支持产业、产品、公司名和股票代码，并自动定位节点。

股票聚焦模式高亮该公司、所在产品与上下游路径。传导路径模式允许选择起点和终点，只突出两者间可达路径，并明确标注披露关系、产业逻辑与推断关系。

移动端不缩放桌面大图，改为纵向阶段阅读器；每个阶段内横向浏览产品卡片，详情使用底部抽屉。

## 视觉方向

视觉采用“深色研究画布 + 编辑杂志式排版 + 克制科技感”：

- 使用深海军蓝画布、弱网格和局部径向光晕，不使用纯黑或高饱和霓虹背景。
- 上游使用冷青，核心部件使用蓝紫，制造使用琥珀金，基础设施使用橙色，终端应用使用珊瑚红。
- 当前聚焦股票使用亮金描边；低可信关系使用灰色虚线。
- 节点类型同时通过轮廓、标签和布局区分，不能只依赖颜色。
- 普通浏览不播放永久动画；仅在路径聚焦时显示一次短促的方向流动。
- 面板、节点展开和焦点切换控制在 180–260ms，并支持减少动态效果。

## 状态体验

- 无产业：提供示例产业和创建入口。
- 首次生成：展示规划、取证、归纳、校验、发布阶段。
- 有图谱刷新中：保留旧版本可读，并显示非阻塞刷新状态。
- 刷新失败：展示稳定错误信息和重试操作，旧版本不受影响。
- 证据不足：允许发布明确标注的部分图谱，但必须满足主干完整性门槛。
- 无股票映射：保持产业全景并提示该股票暂未映射，不创建虚假关系。

## 第一期范围

包含：

- 用户创建、刷新和查看产业图谱。
- 环节、产品、公司和有向关系。
- 产业全景、股票聚焦和路径高亮。
- 搜索定位、渐进展开、节点详情和关系依据。
- 修订历史与失败保旧。
- 自选股票跳转到完整图谱。
- 桌面分层图与移动端纵向阅读器。

不包含：

- 全市场自动预生成。
- 工厂、地址、港口、物流和全球贸易实体。
- 实时风险监控和自动价格影响计算。
- 多人协作审核后台。
- 图数据库迁移。
- 投资建议。

“完整”的验收口径是产业阶段和关键产品路径完整，不承诺穷尽所有公司供销关系。

## 测试与验收

- DAO：修订、节点、边、证据保存，成功发布和失败保旧。
- Validator：未知类型、孤立边、自环、主干循环、未知证据、非法供应关系和不完整路径被拒绝。
- Agent：严格 JSON、一次修复、禁止交易语言和证据引用边界。
- Service：首次创建、并发保护、异步刷新、过期运行恢复和投影读取。
- Controller：列表、创建、详情、刷新、修订和股票聚焦契约。
- 前端：创建、轮询、全景/聚焦切换、搜索定位、节点展开、详情抽屉、失败保旧和移动端阅读。
- 视觉：桌面主要视口无重叠节点，键盘可操作，颜色对比达标，减少动态效果有效。

成功标准：用户能在三十秒内识别产业主干、定位一只股票所在环节，并沿图谱说清它的主要上游依赖和下游需求。
