# 产业链图谱布局修复设计

## 背景

产业链图谱当前把所有关系都绘制为节点中心之间的贝塞尔曲线，同时分别为产品和公司维护全局行号。结果是跨列、同列和父子关系争用同一区域；展开公司时，公司节点也不会参与其父产品所在列的垂直排布，因而会覆盖后续产品。

## 目标

- 展开代表公司后，公司卡片占据真实布局空间，不覆盖任何产品或其他公司。
- 阶段主链、产品归属和公司关系使用不同的稳定通道，减少交叉、回折和节点覆盖。
- 保留现有节点卡片、颜色图例、选择、搜索、聚焦与移动端阅读体验。

## 方案

### 节点布局

每个产业阶段作为一列。列内先放阶段卡片，再按图谱原始顺序放产品。若产品被展开，则把其公司紧接在该产品和展开按钮之后纵向排列；该产品后面的所有节点自动下移。公司不再共享独立的全局起始行。

布局计算显式包含卡片高度、公司按钮高度和组间距，使渲染高度与几何布局一致。画布高度取所有列实际底部的最大值。

### 连线路由

- `FLOWS_TO`：从阶段卡片右侧到下一阶段左侧，保持水平主链。
- `BELONGS_TO_STAGE`、`CONTAINS_STAGE`：在各列左侧分配递增通道，使用正交折线路由到节点左侧，避免穿过卡片。
- 公司与产品关系：使用父产品与公司之间的短距离右侧通道，方向固定，不横跨其他产品。
- 其余跨列关系：使用源、目标外侧端点和独立中间通道，保持单调前进；同列关系走列右侧通道。

箭头端点停在卡片边界，并为 marker 预留距离。不同关系继续沿用现有颜色和虚线语义。

## 验证

- 单元测试覆盖展开公司后后续产品下移且不重叠。
- 单元测试覆盖主链水平、公司短链、同列关系不穿过节点区域。
- 运行产业链布局测试、前端全量测试和生产构建。
- 使用真实 `AI 算力` R4 数据打开页面，展开至少两个公司的产品，检查卡片无覆盖、箭头无穿透，并确认控制台无错误。

## 非目标

- 不引入 React Flow、Dagre 等新依赖。
- 不改变后端图谱协议或已有产业链数据。
- 不重做图谱整体视觉主题。
