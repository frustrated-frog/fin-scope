# 股票产业链证据图谱设计

## 目标

将自选股票的行情弹层升级为统一股票详情，在不改变默认 K 线体验的前提下增加“产业链”页签。产业链结果必须可追溯、可持久化、可刷新，并明确区分公开证据支持的关系与模型推断。

## 产品入口

- 自选股票卡片仍打开股票详情，默认页签为“行情走势”。
- 股票详情顶部提供“行情走势 / 产业链”两个页签。
- 基金持仓表中的股票名称可点击，进入同一个股票详情；关闭或点击返回按钮后恢复基金持仓弹层。
- 不在自选卡片和基金表格内直接展开产业链，避免破坏当前信息密度。

## 数据语义

产业链不是实时行情。页面显示快照生成时间、证据披露时间和可信等级，不使用“实时”措辞。

每个快照包含：

- 公司产业位置与一句话判断；
- 上游、公司自身、下游三层节点；
- 每个节点的关系类型、说明、可信等级和证据引用；
- 公开证据列表，包括标题、URL、来源域名、来源层级、披露日期和摘要；
- 仍需验证的限制说明。

可信等级只允许 `HIGH`、`MEDIUM`、`LOW`。模型只能引用本次证据包中的证据编号，不能创造客户、供应商、合同或来源。

## 持久化与刷新

SQLite 增加两张表：

- `stock_supply_chain_snapshot`：每只股票仅保留当前可用快照，节点和证据保存为版本化 JSON。
- `stock_supply_chain_refresh_run`：记录每次异步刷新状态、阶段、错误和时间。

读取永远优先返回已保存快照。刷新采用“搜索公开资料 → 获取重点正文 → 结构化模型归纳 → 严格校验 → 成功后原子替换快照”的流程。搜索、模型或校验失败时只将刷新运行标为失败，旧快照继续可用。

首次进入产业链页且没有快照时，前端自动创建刷新任务并轮询。已有快照时不自动联网；用户点击“更新证据”才刷新。

## 后端边界

- `StrategyInstrumentResolver` 负责解析或创建股票标的，因此基金重仓股不必先加入自选。
- `SearchEvidenceGateway` 和 `SearchEvidenceContentService` 负责外部资料获取，业务服务不直接发网络请求。
- `StockSupplyChainSynthesisAgent` 只消费冻结证据包并输出严格 JSON。
- `StockSupplyChainRepository` 只负责快照与运行持久化。
- `StockSupplyChainService` 负责编排、并发刷新保护和旧快照保留。

REST 接口：

- `GET /api/stocks/{code}/supply-chain`：读取快照及最新刷新状态。
- `POST /api/stocks/{code}/supply-chain/refresh`：创建异步刷新。

## UI 方向

沿用当前股票弹层的深蓝行情工作台风格，不再创建第二套弹窗。产业链页的标志性元素是一条三段式证据轨道：

```text
上游供给与约束  →  公司核心位置  →  下游客户与需求
```

桌面端三列横向阅读，移动端转为纵向并使用向下连接线。中心公司节点保持最强视觉权重；上游使用冷蓝标记，下游使用暖橙标记，但颜色只编码层级，不编码涨跌。节点点击或键盘聚焦后展示关联证据，证据链接在新窗口打开。

状态设计：

- 无快照：解释正在生成哪些内容，并显示明确进度。
- 有快照刷新中：保留旧图谱，在顶部显示非阻塞刷新状态。
- 刷新失败：保留旧图谱，显示失败原因和重试操作。
- 证据不足：允许返回少量低可信节点，同时明确列出待验证事项。

## 测试与验收

- DAO 测试证明 JSON 快照可保存、覆盖和读取，刷新失败不会删除快照。
- Agent 测试证明非法层级、非法可信度、未知证据引用和多余字段会被拒绝。
- Service 测试证明首次运行、并发保护、成功替换和失败保旧。
- Controller 测试固定 API 契约。
- 前端测试覆盖页签懒加载、首次自动生成、轮询、旧快照刷新、基金持仓跳转与返回。
- 响应式测试固定桌面三列和移动端单列轨道。
