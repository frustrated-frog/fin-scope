# 雷达热点质量 V2 设计

## 目标

在不引入 Elasticsearch、向量 API 和 Agent 主链路判断的前提下，提高热点的聚类准确性、转载识别能力、事件身份稳定性、时序热度质量和榜单可解释性。首页继续读取全局热度榜，雷达继续读取研究优先级榜；SQLite 保留事实、详情和历史快照，Redis 只承接完整版本的页面快照。

## 边界

- 本轮活跃窗口仍为 48 小时，最多处理 500 条信号，使用 Java 内存候选索引即可。
- 不增加 Elasticsearch 运行依赖，只预留候选召回边界；活跃信号超过 2 万、需要跨月检索或候选召回成为瓶颈后再接入。
- Agent 只保留榜单发布后的标题、证据和解读增强，不参与聚类、热度、可信度和排序。
- 不改变详情数据先写 SQLite、榜单完整写入 Redis 新版本后再激活的体验保障。

## 生产架构

```text
定时抓取
  -> 信号特征一次提取
  -> 来源归属与转载簇识别
  -> 候选倒排分桶
  -> 带事实冲突约束的图聚类
  -> 稳定事件签名
  -> 时序热度 / 可信度 / 相关性
  -> SQLite 事务持久化与评分快照
  -> Redis 完整版本发布
  -> 异步 Agent 增强
```

## 信号特征与转载识别

`RadarSignalFeatureExtractor` 为一轮生产中的每条信号只提取一次特征，包括规范化标题、分类、主体、证券代码、动作、变量、方向、数值和事件时间。词典从散落常量收敛为集中领域词典，支持公司别名和互斥动作。

`RadarSourceIndependenceService` 输出来源组、内容指纹、转载簇和有效独立来源。相同来源组只计一次；标题高度相似且事实槽位一致的信号归入同一转载簇；官方来源、原创来源和独立确认保留不同质量权重。V2 的传播速度、扩散和可信度均使用有效独立来源，不再使用原始资讯条数冒充扩散。

第一版来源组使用确定性规则：标准化 provider/source 后识别官方来源，并将同一标准来源归为一组。接口保持独立，未来可以由类型化配置或 ES 元数据替换。

## 事件图聚类

先按照证券代码、主体、分类加变量、标题词元生成候选桶，只比较至少共享一个强候选键且位于 36 小时时间窗内的信号。候选对的匹配分由标题事实相似度、主体/代码、动作变量、时间和分类组成；主体、方向、互斥动作或关键数值冲突时禁止合并。

强匹配边通过 Union-Find 形成连通分量。合并两个分量前校验簇间硬冲突，避免 `A≈B、B≈C、A≠C` 的链式误合并。灰区继续保守拆分并记录现有异步判定样本，但 Agent 结果不阻塞本轮榜单。

事件键使用 `主体/证券代码 + 事件类型 + 核心变量 + 事实日期` 的稳定签名；缺少结构化事实时才回退到规范化标题指纹。分类变化和标题改写不应产生新事件 ID。

## 多目标评分

### 全局热度

```text
Hotness =
  30% Burst
+ 22% IndependentConfirmation
+ 18% Freshness
+ 15% Authority
+ 10% RankTrend
+  5% Persistence
```

- `Burst`：比较最近 30 分钟和之前 90 分钟的有效独立来源到达率，使用平滑基线和饱和函数，降低批次周期变化的影响。
- `IndependentConfirmation`：不同来源组且不同转载簇的有效确认数，边际收益递减。
- `Freshness`：按事件类型选择半衰期的指数衰减，不再使用突变的分段线性规则。
- `Authority`：对有效独立来源做加权聚合，不取单一最高来源。
- `RankTrend`：消费已有 `sourceRank/previousSourceRank`，奖励排名上升，惩罚明显回落。
- `Persistence`：使用前一快照的有效来源数和热度判断持续性，不把重复采集当作持续扩散。

### 可信度

```text
Confidence = 官方性 + 独立确认 + 来源质量 + 事实完整度 - 转载集中度 - 事实冲突度
```

可信度与热度分开保存和解释。高热度、低可信事件仍可进入首页，但雷达研究优先级会受到约束，并展示“缺少独立确认”等不确定性。

### 研究优先级

```text
ResearchPriority = 45% Relevance + 35% Hotness + 20% Confidence
```

相关性优先使用证券代码、标准名和别名精确命中，避免短名称的子串误判。首页按热度排序；雷达按研究优先级排序。

## 生命周期

生命周期由独立的 `RadarLifecycleService` 决策：`DISCOVERED -> RISING -> PEAK -> STABLE -> COOLING -> QUIET`。迁移同时参考当前热度、热度变化、有效来源增量和最后有效新增时间，并使用不同的进入/退出阈值形成滞回。没有足够证据时保持原状态，避免每个生产批次来回跳动。

## 数据与兼容性

- `radar_event` 增加 `confidence_score`、`confidence_explanation`、`score_version`。
- `radar_event_snapshot` 增加独立来源相关时序特征、可信度和评分版本，用于回放与解释。
- 数据库初始化继续使用兼容式 `ensureColumn`，旧库不需要重建。
- 对外现有字段保持兼容；新增字段仅补充能力，不删除旧字段。
- 任一步骤失败都不激活新的 Redis revision，页面继续读取上一成功版本。

## 测试与验收

- 单元测试覆盖转载不重复计数、官方来源权重、排名趋势、指数衰减和生命周期合法迁移。
- 聚类评测覆盖顺序无关、传递合并、簇间冲突阻断、不同事件不误合并和稳定事件键。
- 历史回放输出聚类误合并率、重复卡片率、事件键稳定率、生命周期抖动、Top K 独立确认比例和发现延迟。
- 兼容测试覆盖 SQLite 旧表增量升级、Repository 映射、生产管线持久化和 Redis 投影。

第一版验收门槛：聚类评测误合并率不高于 2%，正样本召回不低于 85%，事件键跨标题改写保持稳定，转载信号不增加有效独立来源，雷达与首页排序职责保持分离。
