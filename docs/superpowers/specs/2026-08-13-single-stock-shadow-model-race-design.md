# 单股预测影子模型赛马设计

## 1. 目标与边界

本期在现有单股 1/5/20 日概率预测、锁定测试和真实到期健康门禁之上，建立可持续的模型挑战机制。目标不是增加一张静态模型对照表，而是让每个候选模型在预测当时冻结概率，在未来使用完全相同的真实收益结算，并据此判断挑战者是否具备晋升资格。

本期继续遵守以下边界：

- 只分析用户主动关注的单只股票，不做全市场扫描。
- 日线规模控制在 5,000 根以内，适配本地 Mac 的 CPU 与内存。
- Python 拥有特征、模型、校准和时序验证逻辑；Java 不重算量化指标。
- 当前冠军仍由严格的历史开发区竞赛选出；真实影子赛马只给出晋升资格，不自动替换线上模型。
- 锁定测试、真实到期结果不得回流参与当次训练或冠军选择。
- 模型没有可靠优势时继续弃权或输出证据不足，不承诺提高后的固定命中率。

## 2. 方案选择

### 方案 A：只扩充离线模型

实现成本最低，但只能说明历史上哪个模型更好，无法验证模型上线后的衰减，也无法避免用户反复查看同一份数据造成的样本重复。

### 方案 B：影子模型赛马与成对真实结算（采用）

每次预测同时保存所有候选的冻结概率和方向。到期后，各候选共享同一笔 T+1 开盘到 T+N+1 开盘的扣费后收益，形成严格成对比较。该方案直接复用现有预测记录、结算和健康门禁，新增边界清晰，能够回答“新模型在真实未来数据上是否持续优于当前冠军”。

### 方案 C：自动在线学习和自动换模

短期看起来更智能，但单只股票真实样本积累慢，自动换模容易追逐噪声。本期不采用；只有积累足够成对样本并经人工确认后，后续才考虑模型注册表和显式晋升操作。

## 3. Python 模型与验证

候选池包括：

1. `LOGISTIC`：正则化逻辑回归，作为稳定且可解释的统计基线。
2. `BOOSTED_STUMPS`：轻量梯度提升树桩，捕捉非线性和阈值关系。
3. `REGIME_LOGISTIC`：按市场动量和波动状态选择局部逻辑回归，并与全局模型收缩混合；状态样本不足时确定性回退到全局模型。
4. `RULE_BASELINE`：固定动量规则，防止复杂模型只是在拟合噪声。

开发区冠军选择由单一尾段验证改为开发区内部多折、扩展窗口、带 purge 的时序验证：

- 所有折都位于前 60% 开发区内。
- 每折训练样本的退出日必须早于该折验证起点。
- 验证锚点按预测周期步长抽取，降低重叠标签的伪样本量。
- 主排序指标为平均 Brier，其次为 Log Loss，并对折间 Brier 波动加入稳定性惩罚。
- 后 20% 校准区只拟合 Platt 映射，最后 20% 锁定测试只评估，不参与冠军选择。

每个候选都返回并冻结：当前原始概率、校准概率、影子方向、资格状态、锁定测试样本量、Brier、Log Loss、命中率、Brier Skill。现有因子解释仍只解释正式冠军；非逻辑模型继续明确标注代理解释边界。

## 4. 持久化与真实结算

新增 `single_stock_forecast_candidate_run` 表，每条记录归属于一次 `single_stock_forecast_run`，唯一键为 `forecast_run_id + model_code`。保存内容包括：

- 股票、信号日、周期、数据指纹。
- 候选代码、名称、版本、当次角色。
- 原始概率、校准概率、影子方向和资格状态。
- 当次锁定测试指标。
- 到期状态、实际净收益、实际方向、方向是否命中和结算时间。

主预测结算成功后，在同一业务用例中把相同真实结果传播给该运行的所有候选；结算使用条件更新，重复触发保持幂等。候选没有输出影子方向时仍保留概率评分，但方向命中为空。

真实赛马查询按“股票 × 周期”聚合最近 20 个不同数据指纹的已到期运行，避免重复点击相同缓存行情扩大样本。每个候选计算：

- Brier、Log Loss、Brier Skill。
- 方向覆盖率和覆盖后命中率。
- 成对样本数量、首次与末次信号日。
- 相对当前冠军的 Brier 和 Log Loss 差异。

晋升资格必须同时满足：至少 12 个成对真实样本、挑战者 Brier 至少优于冠军 0.01、Log Loss 不差于冠军、覆盖率不低于 40%，且覆盖后命中率不低于冠军。资格只表示“值得人工审查”，不触发自动换模。少样本、不同候选领先不同指标或没有稳定优势时返回对应的保守状态。

## 5. 接口与前端

现有预测详情响应新增 `modelRace`，并新增只读接口：

`GET /api/quant/single-stock-forecasts/race?code=600519&horizonDays=5`

前端把原有离线模型表升级为两层赛马场：

- “历史资格赛”：展示开发区多折结果、稳定性、当前冻结概率、锁定测试指标和冠军/挑战者角色。
- “真实影子赛”：展示到期成对样本、Brier、Log Loss、覆盖率、覆盖后命中以及晋升资格。

页面明确区分历史锁定证据和预测后的真实证据；证据不足时显示积累进度，不以空值或零值制造优势。

## 6. 异常、兼容与性能

- 旧版 v5 预测响应继续可读取；新字段只在 v6 契约中强校验。
- 候选记录保存失败视为本次预测留痕失败，避免出现正式预测存在但影子证据永久缺失的半成品。
- 真实结算继续采用现有 best-effort 外层策略；远端行情失败不会阻断用户读取旧报告。
- 单次预测最多训练 4 个轻量模型，开发区 3 折，数据上限 5,000 根；不引入深度学习、Qlib 运行时或后台全市场任务。
- 数据库查询使用股票、周期、到期状态和数据指纹组合索引；前端不下载逐日训练矩阵。

## 7. 测试与验收

- Python 单元测试验证多折切分无泄漏、四模型确定性、状态模型回退、候选冻结概率和 v6 契约。
- DAO 测试验证候选唯一保存、幂等结算和数据指纹去重查询。
- Service 测试验证预测保存所有候选、赛马指标、晋升门槛和证据不足状态。
- RPC 契约测试拒绝越界概率、无效候选角色、冠军标记不一致和锁定指标缺失。
- 前端测试验证历史资格赛、真实影子赛、证据积累与晋升候选四类呈现。
- 完成后运行 Python 全量测试、Maven 全量测试、前端全量测试与生产构建。
