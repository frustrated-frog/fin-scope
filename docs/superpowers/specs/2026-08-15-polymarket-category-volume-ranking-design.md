# Polymarket 五分类成交量榜设计

## 目标

全球预期页不再从一个大市场池中依赖关键词挑选少量命题，而是使用 Polymarket 官方标签体系，稳定覆盖政治、财务、地缘冲突、科技、经济五个分类。每个分类独立抓取当前仍活跃的市场，并按 24 小时成交量降序保留前 10 条。

## 数据口径

- 分类来源：Polymarket Gamma API 的官方 tag slug，分别为 `politics`、`finance`、`geopolitics`、`tech`、`economy`。
- 排名指标：`volume24hr`，对应官网分类页默认的 24 小时成交量口径。
- 排名范围：每个分类独立 Top 10，总观察池最多 50 条。
- 市场范围：仅 `active=true`、`closed=false` 的市场。
- 中文标题：请求继续携带 `locale=zh`，无中文翻译时沿用官方返回标题。
- 重叠市场：同一市场若属于多个官方分类，可在各分类榜单中分别出现；“全部”视图按市场 ID 去重，避免重复卡片。

## 架构

`GlobalExpectationsCatalog` 只维护五个稳定分类的中文名、官方 slug 与研究提示，不再做关键词匹配。`PolymarketPublicClient` 通过 `/tags/slug/{slug}` 解析 tag ID，再调用 `/markets` 按 `volume24hr` 降序请求该分类前 10 条，并解析累计成交量与 24 小时成交量。tag ID 在进程内缓存，避免每分钟重复解析。

`GlobalExpectationsService` 逐分类获取榜单并保留分类归属，不再对五类数据做全局二次截断。价格历史最多涉及 50 个 token，RPC 客户端按每批 20 个拆分请求并合并结果，继续写入 Redis 历史缓存与视图缓存。

前端筛选固定显示“全部、政治、财务、地缘冲突、科技、经济”。卡片把排名依据明确标为“24h 成交”，避免用户误把累计成交量当作榜单口径。

## 失败与降级

- 任一分类请求失败时，本轮刷新整体进入现有 Redis 快照降级，避免把不完整榜单覆盖完整缓存。
- tag slug 无法解析、响应无有效 ID 或分类没有有效概率市场时，视为刷新失败。
- 历史价格批次失败仍沿用现有逐市场 Redis 历史降级，榜单本身可以继续展示并标记为部分数据。

## 测试

- RPC 测试验证 tag slug 解析、`volume24hr` 排序参数、limit 10、中文 locale 和 24 小时成交量解析。
- RPC 测试验证 50 个 token 会拆成三批历史请求并正确合并。
- Service 测试验证五个分类各保留 10 条、分类独立排序，且榜单不再依赖标题关键词。
- 前端测试验证五个筛选项、分类切换和“24h 成交”展示。
