# 自动策略学院设计

## 1. 目标

将现有策略素材库升级为面向量化初学者的自动策略学院。系统从公开且可溯源的策略候选出发，在用户选定的真实 A 股研究数据集上自动生成受限策略版本、启动确定性回测，并把来源、验证结果、风险与学习解释聚合为少量策略卡。

本期只提供研究、学习和影子验证能力，不生成真实账户调仓指令，不连接券商，也不把历史回测表述为实盘证明。

## 2. 产品原则

- 策略来源以公开经典研究为主，Agent 只负责在现有因子和 DSL 边界内完成本地适配。
- 硬门槛保持严格：真实研究数据集、数据质量通过、策略协议通过、结果可复现、成交成本已进入引擎。
- 收益、Sharpe、回撤、年度一致性等使用综合评分，不因单项不理想而删除学习卡。
- 策略卡永不伪装证据等级。公开来源、本地历史实验和未来前向观察分别展示。
- 学习书架可以包含未通过应用候选门槛的卡；应用候选书架只显示证据相对充分的卡。

## 3. 用户流程

1. 用户进入 Quant 的策略学院，选择一个状态为 `READY` 且 `dataKind=REAL` 的数据集。
2. 用户点击“自动构建本期学院”。
3. 服务端选择最多 6 个未归档且 `ADAPTABLE` 的公开策略候选。
4. 对尚无本地版本的候选调用既有候选转草案链；草案通过协议后自动确认版本并启动实验。
5. 已有版本或运行中实验保持幂等，不重复创建。
6. 页面轮询学院卡。实验完成后，卡片从“正在验证”更新为“历史验证”或“学习案例”。
7. 用户先阅读通俗解释，再展开来源、因子、指标、年度表现和限制。

## 4. 证据等级

| 等级 | 条件 | 页面语义 |
|---|---|---|
| `RESEARCH_REPLICATION` | 有公开来源且可本地适配，尚无成功实验 | 公开研究复现，等待本地验证 |
| `HISTORICAL_EVIDENCE` | 真实数据集上的确定性实验成功且无硬阻断 | 已有本地历史证据，可进入影子观察 |
| `FORWARD_OBSERVING` | 预留等级；未来固定规则后累计真实时间样本 | 正在前向观察，不等同实盘 |
| `LEARNING_CASE` | 实验失败或综合证据偏弱，但不存在数据造假式错误 | 适合学习失败原因，不作为应用候选 |

本期不产生 `FORWARD_OBSERVING`，但接口和 UI 明确展示它是下一阶段。

## 5. 综合评分

成功实验按 100 分评估：

- 样本覆盖 20 分：至少 3 个年度、至少 20 笔成交。
- 基准比较 25 分：超额收益为正、策略年化收益高于零。
- 风险控制 20 分：最大回撤不超过 35%，Calmar 为正。
- 稳定性 20 分：多数年度超额收益为正，结果不完全依赖单一年份。
- 可执行性 15 分：换手率处于可解释范围，实验无严重警告。

评分不作收益承诺：

- 70 分及以上：进入“应用候选”，证据等级为 `HISTORICAL_EVIDENCE`。
- 55–69 分：进入“当前观察”，仍为 `HISTORICAL_EVIDENCE`。
- 55 分以下：进入“学习案例”，保留指标与不足。

## 6. 后端设计

### 6.1 领域对象

新增 `QuantStrategyAcademyCard`，聚合候选身份、来源、因子、本地版本、实验状态、证据等级、书架、综合分、评分维度、关键指标、学习解释与限制。对象位于 `finscope-domain` 的 `quant/academy` 包。

新增 `QuantStrategyAcademyBuildResult`，返回本次扫描、创建草案、确认版本、启动实验、复用和失败数量，以及逐候选的非敏感消息。

### 6.2 服务

`QuantStrategyAcademyService` 负责：

- 校验数据集必须为 READY 的真实研究数据。
- 有界选择最多 6 个 `ADAPTABLE` 候选。
- 幂等复用已关联版本与运行中/成功实验。
- 调用既有 `QuantStrategyCandidateDraftService`、`QuantStrategyService` 和 `QuantExperimentService`。
- 聚合策略卡，不直接写 SQL。

`QuantStrategyEvidenceScorer` 是无状态确定性评分组件。它只消费候选、数据集与实验结果，不调用模型。

### 6.3 Repository 扩展

- `QuantStrategyCatalogRepository` 增加候选最近版本查询。
- `QuantExperimentRepository` 增加策略版本最近实验查询。
- 不新增数据库表；继续复用来源、草案、版本、实验、指标、年度表现和成交表。

### 6.4 API

- `GET /api/quant/academy/cards`：返回全部未归档可适配候选的学院卡。
- `POST /api/quant/academy/build`：请求体 `{ "datasetId": 1 }`，有界生成并启动实验。

## 7. 前端设计

策略素材库页签改名为“策略学院”，保留公开目录同步入口，但弱化 GitHub 工具语义。

视觉主题是“研究档案馆 + 证据阶梯”：

- 页面顶端用一条横向证据阶梯展示公开复现、历史验证、前向观察三层关系。
- 主操作区明确选择真实数据集并自动构建，不要求用户理解因子参数。
- 三个书架分别展示“应用候选”“当前观察”“学习案例”。
- 卡片的主视觉是证据分而不是收益率；收益率、Sharpe 和回撤作为第二层信息。
- 选中卡后展示五个初学者问题：赚什么钱、为什么可能有效、何时适用、如何失效、当前证据是什么。
- 来源链接和本地适配差异保留在证据抽屉中。

配色沿用 FinScope 深墨背景和潮汐青，增加用于证据成熟度的矿物蓝与克制琥珀；不引入新的全局字体。标志性元素是由虚线轨道连接的三段证据阶梯，节点状态来自真实后端状态。

## 8. 失败与恢复

- 单个候选生成或实验入队失败不阻断其他候选。
- 构建结果返回逐候选摘要，不返回模型原文、密钥或内部堆栈。
- 目录尚未同步时展示引导，不隐式访问任意外部 URL。
- LLM 不可用时沿用既有草案失败语义；已有卡片与实验结果继续可读。
- 页面保留最近成功卡片，局部接口失败显示可重试提示。

## 9. 测试与验收

- 评分单元测试覆盖 70+、55–69、低分、实验中和实验失败。
- 编排测试覆盖最多 6 个、复用已有版本、草案失败隔离、只允许真实 READY 数据集。
- Repository 测试覆盖最近版本与最近实验查询。
- Controller 测试覆盖列表、构建和非法数据集。
- 前端测试覆盖证据阶梯、三书架、自动构建、指标与失败恢复。
- 验证执行相关 Maven 测试、前端测试、生产构建，并在桌面与窄屏截图中检查布局。
