# 量化真实验证闭环设计

## 1. 目标

本期增强单股预测与股票发现共用的量化基座，但不承诺通过增加模型数量直接提高收益。系统必须先把每次股票发现的候选、概率、排名、模型版本和数据指纹冻结下来，在未来行情到期后自动结算，再用真实未知样本判断概率、排序和模型是否有效。

第一版以股票发现默认 5 个交易日周期为主，1 日预测继续保留为单股影子能力，不替换 5 日正式输出。

## 2. 范围

### 2.1 本期实现

- 股票发现全部合格候选的不可变结果账本，不只保存最终前五。
- T+1 开盘进入、T+N+1 开盘退出、扣除双边成本的自动结算。
- 深度候选中冠军、挑战者和规则基线的影子概率保存与同步结算。
- Python 计算 30/90/180 日概率质量、Top-1/3/5、合格池对照、板块表现、可靠性分箱和真实模型赛马。
- 股票发现补齐沪深 300 历史上下文，使其与单股预测使用相同的市场状态特征。
- 当日点时正确的截面增强因子：市场宽度、行业宽度、行业相对强弱、行业资金排名质量和成交活跃度排名。
- 股票发现页面增加预测能力仪表盘；证据不足时明确显示“积累中”，不伪造百分比。

### 2.2 本期不实现

- 不回填历史同花顺热榜；无法证明当时可见的榜单不能用于历史选股回测。
- 不接入新闻情绪或 LLM 预测因子。
- 不自动晋升模型；达到门槛只进入人工复核状态。
- 不以实时持仓或真实交易账户作为训练输入。
- 不增加 Qlib 常驻依赖，不引入 GPU 或分布式训练。

## 3. 数据流

```text
同花顺热榜 + 完整成分 + QFQ 日线
  -> Python 点时因子与深度预测
  -> Java 原子保存批次、候选、模型影子概率
  -> 定时扫描 PENDING 候选
  -> 行情 RPC 获取最新 QFQ 日线
  -> Java 条件更新候选和模型到期结果
  -> Python 无状态评测 API
  -> Java REST API
  -> 股票发现预测能力仪表盘
```

外部行情调用不进入数据库事务。候选结算与其模型影子结果在一个短事务内更新，通过 `WHERE maturity_status='PENDING'` 保证重复调度幂等。

## 4. 持久化契约

`stock_discovery_candidate` 增加：

- `horizon_days`
- `maturity_status`: `NOT_APPLICABLE | PENDING | MATURED | UNAVAILABLE`
- `entry_date`, `exit_date`, `entry_open`, `exit_open`
- `actual_net_return`, `actual_direction`, `prediction_correct`
- `settled_at`, `outcome_source_code`, `outcome_note`

仅 `admitted=true` 的候选进入 `PENDING`。未通过资金、流动性或数据门禁的候选保留原始证据，但不进入结果统计。

新表 `stock_discovery_model_prediction` 保存深度候选每个模型的冻结概率、角色、影子方向、资格状态和到期结果。唯一键为 `(run_id, instrument_code, model_code)`。

## 5. 结算规则

- 信号日：冻结报告的 `as_of_date`。
- 入场：信号日后第一个交易日开盘价。
- 退出：信号日后第 `horizon_days + 1` 个交易日开盘价。
- 净收益：`exit_open / entry_open - 1 - 0.0015`。
- 实际方向：净收益大于零为 `UP`，否则为 `DOWN`。
- 概率方向：概率不低于 0.5 为 `UP`，否则为 `DOWN`。
- 缺少退出日时保持 `PENDING`；历史信号日无法定位时标记 `UNAVAILABLE`，不进入指标分母。

## 6. Python 评测

评测 API 只消费 Java 提供的冻结观察，不自行读取数据库。所有数值字段必须有限，重复 `(run_id, instrument_code)` 请求被拒绝。

### 6.1 概率质量

- Brier Score、Brier Skill Score、Log Loss、方向准确率和 ECE。
- 基准概率只使用评测窗口自身上涨率。
- 仅统计拥有冻结概率且已到期的深度候选。

### 6.2 排名价值

- Top-1、Top-3、Top-5 的样本数、上涨率、平均净收益和中位净收益。
- 同批次全部合格候选作为次级排序对照，计算逐批次 Top-K 超额后再取平均。
- 单股报告原有“同股买入并持有”仍是策略回测主基准；合格池对照只回答股票发现排序是否增值。

### 6.3 模型赛马

- 按模型代码聚合真实 Brier、Log Loss、覆盖率和覆盖后准确率。
- 至少 30 个真实成对样本，挑战者 Brier 至少改善 0.01、Log Loss 不恶化、覆盖率不低于 40%、覆盖后准确率不低于冠军，才标记 `PROMOTION_REVIEW`。
- 系统不自动切换冠军。

### 6.4 健康状态

- `ACCUMULATING`: 已到期概率样本少于 30 或到期批次少于 5。
- `HEALTHY`: Brier Skill 大于零，且最终候选平均净收益不为负。
- `WATCH`: 已有足够样本但概率或最终候选收益没有形成优势。

## 7. 点时因子

股票发现统一读取一份截至业务日的沪深 300 QFQ 历史并对齐到每只股票。市场上下文不可用时按现有中性值降级，不阻断选股。

轻量排名新增：

- `universe_breadth_5`、`universe_breadth_20`
- `sector_breadth_20`
- `relative_momentum_20_sector`
- `sector_flow_rank_quality`
- `cross_activity_rank`

所有截面值只由本批次截至业务日的数据计算。行业资金排名来自本批次同花顺热榜，不用当前值回填历史日期。增强因子首先用于轻量候选排序；由于没有历史同花顺榜单，不把资金排名伪造为历史训练特征。

## 8. 前端

股票发现结果页在现有漏斗和候选可视化之间增加“真实预测能力”区域：

- 状态封印与已到期批次数、候选数、待结算数。
- 30/90/180 日滚动指标卡。
- 概率可靠性图。
- Top-1/3/5 与合格池对照图。
- 冠军/挑战者真实赛马表。
- 板块真实表现与最近结算记录。

当评测 API 暂不可用时，最新选股结果仍正常展示；仪表盘单独降级。

## 9. 性能与恢复

- 每次结算最多扫描 200 个候选，按股票代码复用一次日线请求。
- 评测最多读取最近 2,000 个已到期候选和 8,000 条模型影子记录。
- Python 评测为纯内存线性计算，预计远低于 1 秒。
- 适配 M5、24GB 内存，不增加重型常驻服务。
- 定时任务失败只影响结果结算，不影响热点、单股预测或下一次股票发现。

## 10. 验收

- 重复结算不会覆盖已到期结果。
- 未到期、缺信号日和行情下游失败语义不同。
- Python 指标使用真实冻结概率，不消费后见数据。
- 股票发现使用市场上下文，失败时明确降级。
- 前端准确展示积累中、健康和观察状态。
- Python、Java、前端全量测试与生产构建通过。
