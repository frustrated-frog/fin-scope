# 每日收盘复盘与市场历史设计

## 1. 目标

Market Pulse 从“若干行情卡片”升级为可回溯的每日收盘研究工作台。用户打开页面时应先得到一份有证据、有边界的当日复盘，再按需下钻市场结构和历史演变。

本期解决三个直接问题：

1. 行业 5 日、20 日数据不再依赖页面上线后的自然积累，首次刷新即可使用同花顺行业历史。
2. 市场状态、宽度、行业轮动、事件和候选被组织为一条每日复盘证据链，而不是孤立展示。
3. 每日判断作为不可变业务日期快照持久化，历史页面可以比较状态、宽度和主线变化。

本功能只提供研究优先级和风险提示，不输出买入指令，不承诺收益。

## 2. 产品结构

Market Pulse 保留为一个主导航页，内部增加三个视图：

- `今日复盘`：默认视图。展示一句话结论、指数全景、市场内部、主线/退潮行业、事件确认、风险和次日观察清单。
- `市场结构`：保留并增强现有市场状态、市场宽度、节奏轨、行业轮动、事件与候选明细。
- `历史演变`：展示最近快照的市场阶段、上涨比例、成交额、涨跌中位数、领涨行业和风险信号变化。

日期选择仍控制整个工作台，三个视图共享同一个业务日期快照。

## 3. 数据职责

### 3.1 Python market-data-service

Python 只负责外部结构化行情采集和标准化：

- 同花顺全行业目录与当日资金/涨跌截面；
- 同花顺行业指数历史，默认回看 60 个交易日；
- 对每个行业计算 1/5/20 日收益、近 5 日上涨天数、最近交易日；
- 单个行业失败时保留其余行业并输出 warning；整体无有效历史时返回不可用错误；
- 暴露版本化契约 `sector-history-v1`。

接口：

`GET /v1/sectors/INDUSTRY/history?business_date=YYYY-MM-DD&window=60`

核心字段：

- `business_date`
- `source_code/source_family/retrieved_at`
- `requested_window/covered_trade_dates`
- `entries[]`: `code/name/return_1d/return_5d/return_20d/positive_days_5/last_trade_date`
- `warnings[]`

采集使用有界并发，避免对同花顺形成突发请求。生产默认读取 AkShare 的同花顺行业接口，测试使用注入的固定 DataFrame，不访问网络。

### 3.2 Java RPC 与业务层

Java 通过 `finscope-rpc` 消费版本化行业历史契约，领域层不感知 AkShare 或网页字段。

`MarketPulseSectorService` 将：

- 请求全行业当日截面，而不是只取前后各 10 个；
- 用 Python 历史直接填充 1/5/20 日收益和持续性；
- 当历史接口不可用时，回退到已有 workspace 历史，且明确降低质量；
- 对全部有效行业评分，再截取有研究价值的领先、改善和退潮行业供页面展示。

### 3.3 每日复盘规则引擎

`DailyMarketReviewService` 仅消费冻结后的结构化事实，不执行外部采集。输出 `DailyMarketReview`：

- `headline`：一句话总结市场阶段和量价关系；
- `indexOverview`：指数强弱和风格差异；
- `breadthConclusion`：上涨比例、涨跌中位数、涨跌停和成交额；
- `leadingSectors`：最多 3 个获得历史确认的主线；
- `weakeningSectors`：最多 3 个退潮或弱势行业；
- `confirmedEvents`：事件与行情同向确认摘要；
- `riskSignals`：缩量修复、宽度背离、拥挤、候选缺失等风险；
- `nextSessionWatchlist`：下一交易日需要验证的量能、宽度、主线持续性与失效条件；
- `evidence`：用于解释结论的定量证据；
- `qualityStatus`：数据不足时明确降级，不让文案看起来比事实更确定。

规则引擎负责结论事实，未来 LLM 只能润色这些结构化结论，不能添加没有对应证据的市场原因或股票推荐。

## 4. 持久化与不可变性

现有 `market_opportunity_run.workspace_json` 继续保存完整工作台，新增：

- `daily_market_review_snapshot`：按 `business_date` 唯一保存复盘 JSON、质量状态、事实指纹和生成时间；

同一业务日期刷新允许在数据源更新后覆盖该日期快照，但读取历史日期绝不重新调用外部数据或用当前值重算。`MarketPulseWorkspace` 同时嵌入 `dailyReview`，保证 API 单次返回完整冻结视图。

## 5. 历史演变

Java 在读取 workspace 时加载最近 20 个业务日期的轻量 `MarketPulseHistoryPoint`：

- 日期和市场阶段；
- 置信度；
- 上涨比例、成交额、涨跌中位数；
- 领涨行业名称与轮动分；
- 当日复盘 headline；
- 数据质量。

历史数据来自已保存 workspace，不重新采集，避免未来数据污染。

## 6. 降级策略

- 行业历史部分失败：成功行业正常评分，失败行业不伪造 5/20 日收益，并在 warnings 中列出数量。
- 行业历史整体失败：使用旧 workspace 回退；没有旧数据时保留当日截面并标记 `INSUFFICIENT_DATA`。
- 市场宽度不可用：每日复盘仍可基于指数和行业生成，但宽度结论明确不可用，整体质量至少为 `PARTIAL`。
- 事件或股票候选为空：视为有效研究结果，不影响快照成功；复盘会解释“无确认”或“无候选”的含义。
- 历史不足：历史视图显示已有日期，不补造自然日或未来数据。

## 7. 测试与验收

### Python

- 正确计算 1/5/20 日收益和 5 日上涨天数；
- 截止业务日期，禁止未来数据进入结果；
- 单行业失败时部分成功并产生 warning；
- API 返回 `sector-history-v1`。

### Java

- RPC 拒绝 schema、来源、日期和数值漂移；
- 行业服务使用全行业历史并产生非固定的轮动评分；
- 每日复盘在上涨扩散、缩量修复、宽度背离、行业退潮等场景输出稳定结论；
- Repository 保存并读取复盘和历史点，同日刷新不重复；
- API 日期统一为 ISO 字符串。

### Frontend

- 默认进入今日复盘；
- 三视图切换不会重复请求或丢失所选日期；
- 数据部分缺失时保留结构且明确展示边界；
- 1260px 与移动端不横向溢出；
- 完整前端测试和生产构建通过。

## 8. 本期不做

- 不让 LLM 自由读取新闻后猜测涨跌原因；
- 不自动下单、不输出目标价或确定性买卖建议；
- 不在本期实现周报生成器；周报后续直接聚合每日不可变快照；
- 不复制 Stock Discovery 的完整模型报告到 Market Pulse。
