# Market Pulse 布局宽度约束设计

## 问题

Market Pulse 外层使用单列 CSS Grid，但没有显式声明列宽。顶部三列 Hero 与“行业轮动 + 事件确认”双列区的最小内容宽度会参与隐式列的尺寸计算：在 `1280px` 浏览器窗口中，主工作区只有约 `1020px` 内容宽度，隐式列却被撑到约 `1972px`。AppShell 使用 `overflow: clip`，超出视口的顶部控制区和右侧事件列无法显示。数据边界中的长错误 URL 也不能自然换行，会继续制造内部横向溢出。

## 方案

为 `.market-pulse-page` 显式声明 `grid-template-columns: minmax(0, 1fr)`。`minmax(0, 1fr)` 将唯一内容列限制在父级可用宽度内，同时允许内部 Grid 项缩小；`.market-pulse-warning` 使用 `overflow-wrap: anywhere` 断开长 URL。考虑固定 `224px` 侧栏和工作区内边距后，将 Market Pulse 的单列响应式断点从 `1100px` 提升到 `1260px`，避免 `1101–1260px` 区间的行业与事件双列互相挤压。不修改 AppShell 的全局裁切策略，也不增加横向滚动条。

## 验证

增加样式契约测试，证明 Market Pulse 外层 Grid 使用可收缩的显式单列、警告长文本可换行，并在 `1260px` 及以下切换为单列决策区。随后运行聚焦测试、前端完整测试和生产构建，并在本地真实浏览器中验证页面宽度不超过工作区、顶部控制区和右侧事件列均位于视口内。

## 边界

- 不修改其他工作台的布局或滚动行为。
- 不改变 Market Pulse 各模块的视觉顺序；只修正其响应式断点。
- 不修改市场宽度、行业轮动、事件确认和候选筛选数据。
