# 量化概率收益、横截面排序与过拟合审计设计

## 1. 目标

在现有 V9 方向概率、模型赛马、严格前向切分和真实结果账本之上，补齐三个专业能力：预测未来净收益分布、按横截面相对优势训练股票发现挑战者、量化回测被多次试验放大的风险。系统仍不承诺确定收益；正式结论只采用预测时可见数据和冻结后的未来结果。

## 2. 研究依据与取舍

- 资产收益信噪比较低，优先采用正则线性模型、浅层树模型和受约束集成，不引入常驻大型深度模型。
- A 股更重视流动性、成交活跃度、量价趋势与行业相对强弱，因子必须按日期横截面标准化。
- 股票发现的目标是同日候选之间的排序，因此增加 pairwise ranking 挑战者，但在真实结果积累充分前不替换现有正式排名。
- 原始分位数回归不能直接解释为可靠区间，使用严格时序校准集上的残差进行 conformal 修正。
- 每个候选模型和参数组合都计入试验账本；使用 Deflated Sharpe Ratio 和组合切分近似 PBO 揭示选择偏差。

## 3. 本期范围

### 3.1 实现

1. 使用 `HistGradientBoostingRegressor(loss="quantile")` 分别预测 P10、P50、P90，并使用开发区、校准区、锁定区的前向边界。
2. 使用校准区绝对残差构造时序 conformal 修正，报告锁定区覆盖率、平均区间宽度和当前校准区间。
3. 单股页面同时展示方向概率、预期净收益、下行分位数、上行分位数和区间可靠度。
4. 股票发现增加轻量 pairwise 线性排序挑战者，训练样本仅由同日、已成熟的深度候选构造；候选不足时明确保持规则排序。
5. 最终严格入选仍由现有门禁决定；排序挑战者仅在锁定 Rank IC、Top-K 超额和真实账本满足门槛后进入融合，本期默认影子运行。
6. 回测审计增加试验总数、Probabilistic/Deflated Sharpe、最小可信历史长度、组合切分 PBO 和审计结论。
7. Python、Java、TypeScript 契约同步升级到 V10，双页面增加收益分布和研究可信度可视化。

### 3.2 不实现

- 不引入 Transformer、GAN、图神经网络或 GPU 依赖。
- 不把新闻或 LLM 文本直接作为交易因子。
- 不自动晋升排序挑战者或扩大最终候选数量。
- 不使用当前同花顺榜单回填历史日期。
- 不改变科创板、北交所、整手资金和流动性准入规则。

## 4. Python 组件边界

### 4.1 `forecast/return_distribution.py`

负责收益分位数模型、无泄漏训练/校准/锁定切分、分位数交叉修正、conformal 残差校准和覆盖率审计。输入为现有 `ForecastSample`，不访问数据库和外部网络。

输出包含：

- `p10/p50/p90`：当前扣费净收益分位数；
- `raw_p10/raw_p90`：未经 conformal 修正的模型分位数；
- `locked_coverage`、`mean_interval_width`、`locked_pinball_loss`；
- `sample_count`、`calibration_count`、`locked_count`；
- `status` 与无法计算原因。

### 4.2 `discovery/pairwise_ranker.py`

负责将同一业务日候选转换为收益差的 pairwise 训练样本。使用带 L2 正则的逻辑模型预测 A 优于 B 的概率，再转换为候选排序分数。训练、校准和锁定以日期切分；同一日期不得跨区。输出 Rank IC、Top-K 超额和覆盖审计。

本期没有可靠历史热榜回放时，服务返回 `SHADOW_ACCUMULATING`，使用当前轻量规则排名作为正式路径，并将不可训练原因暴露给页面。

### 4.3 `forecast/selection_bias.py`

负责：

- Probabilistic Sharpe Ratio；
- Deflated Sharpe Ratio；
- 最小可信历史长度；
- 基于候选策略收益序列的组合对称切分 PBO；
- 非正态收益的偏度、峰度修正。

所有输入为已经生成的样本外收益序列和真实试验数量；禁止只把页面上展示的参数数目当作试验数。

## 5. 数据流

```text
QFQ 日线 + 点时市场/行业上下文
  -> 方向分类资格赛与概率校准（现有）
  -> 收益 P10/P50/P90 分位数模型
  -> 校准区 conformal 修正
  -> 当前概率 + 收益分布 + 拒绝门禁
  -> 单股报告 / 股票发现深度证据

股票发现已冻结候选与到期收益
  -> 日期级 pairwise 样本
  -> 排序挑战者锁定评测
  -> SHADOW / PROMOTION_REVIEW

样本外策略收益 + 试验账本
  -> PSR / DSR / PBO
  -> 专业审计结论
```

## 6. 决策规则

方向结论继续受 V9 资格状态和选择性阈值控制。V10 额外要求：

- P50 扣费净收益不高于零时，不得因为上涨概率较高直接标记为强优势；
- P10 显著为负或区间过宽时，降为条件性证据；
- 收益分布不可用时保留 V9 概率结论，但明确显示“收益空间未验证”；
- DSR 不通过或 PBO 偏高时，稳健结论降级为条件有效；
- 任何门禁都不为了凑满五只而放宽。

## 7. 前端设计

沿用现有深色研究终端视觉，新增“概率—收益棱镜”作为签名组件：横向零轴上展示 P10、P50、P90，区间颜色由左侧风险青灰过渡到右侧机会青绿；锁定覆盖率和区间宽度作为刻度说明。避免新增通用大数字卡片。

单股页面展示：

- 收益分布轴及 conformal 覆盖；
- 方向概率与收益中位数是否一致；
- DSR、PBO、试验次数和审计结论。

股票发现页面展示：

- 每只深度候选的 P10/P50/P90 微型区间；
- 排序来源是规则正式路径还是 pairwise 影子挑战者；
- 排序挑战者的 Rank IC、Top-K 超额、样本日期数和晋升状态。

## 8. 性能

- 单股分位数模型限制为三个浅层直方图提升模型，每个最多 50 次迭代。
- 日线样本最多使用最近 1,500 条；锁定评测复用一次拟合，不进行大规模网格搜索。
- pairwise 每个交易日最多确定性抽样 300 对，训练总对数设置上限。
- PBO 组合数设置硬上限并固定随机种子。
- 不增加常驻服务或 GPU 依赖，适配 M5/24GB 单机。

## 9. 验收标准

- 分位数始终满足 `P10 <= P50 <= P90`，所有数值有限。
- conformal 修正只读取校准区残差，锁定区仅用于报告。
- 日期切分满足训练标签退出日早于校准/锁定信号日。
- pairwise 样本只比较同一日期候选，输入顺序不影响结果。
- DSR 随试验数增加不得上升；随机策略的 PBO 不应被错误标记为低风险。
- Python、Java、前端契约测试覆盖新增字段和缺失降级。
- 全量 Python、Maven、前端测试与生产构建通过。
