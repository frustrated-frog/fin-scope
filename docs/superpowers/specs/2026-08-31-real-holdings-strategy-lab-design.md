# 真实持仓策略实验室设计

## 1. 目标与边界

在现有“长期投资地图”中增加一套只管理 A 股股票的真实持仓能力。用户手工录入实际成交与资金流水，系统据此复算持仓成本、已实现/未实现收益、分红收益和账户权益，并把现有单股预测转换为带仓位约束、成本约束和风险预算的影子策略建议。

本期不连接券商、不自动下单、不做组合优化器。系统提供研究与复盘证据，不承诺收益，也不把用户成本价、盈亏状态泄漏进预测模型。

## 2. 核心原则

1. **账本是唯一事实源**：成交、分红、送转和资金变动以不可变事件保存；修改通过冲正原事件并新增更正事件完成。
2. **持仓不能污染预测**：真实数量、成本和历史盈亏不进入涨跌概率模型，只影响可执行数量、集中度、费用和风险预算。
3. **价格语义严格分离**：真实市值使用不复权行情；模型训练与回测继续使用前复权日线。公司行动通过账本事件进入真实账户，禁止用前复权价格估算真实资产。
4. **基准是同股买入持有**：持仓策略验证优先比较“保持当时持仓不动”，再比较用户真实操作，不以沪深 300 代替可执行基准。
5. **先验证后归因**：每次建议冻结输入、模型版本、概率分布、建议动作和数量，待到期后再计算结果；样本不足时明确显示“积累中”。

## 3. 领域模型

### 3.1 股票交易事件

`StockTransaction` 记录以下事件：

- `OPENING_BALANCE`：旧持仓初始化，录入数量与历史总成本；
- `BUY` / `SELL`：买卖成交；
- `CASH_DIVIDEND`：现金分红；
- `BONUS_SHARE`：送股/转增；
- `CASH_DEPOSIT` / `CASH_WITHDRAWAL`：外部资金流；
- `REVERSAL`：冲正指定事件。

所有写入都要求客户端幂等键。证券事件关联 `instrument_id`；资金事件可以没有证券。事件保存实际成交日、数量、单价、佣金、印花税、过户费、其他费用、现金金额、备注、被冲正事件和创建时间。

交易费用优先使用用户实际填写值；未填写时仅在界面提供估算提示，不悄悄写入虚构费用。A 股买入数量按 100 股整数倍校验，卖出允许一次性卖出不足 100 股的零股余量。

### 3.2 成本与收益核算

按证券、成交日、事件 ID 的稳定顺序重放账本，采用移动加权平均法：

- 买入后总成本 = 原总成本 + 成交金额 + 买入费用；
- 平均成本 = 总成本 / 持仓数量；
- 卖出已实现收益 = 卖出金额 - 卖出费用 - 卖出数量 × 卖出前平均成本；
- 卖出后剩余持仓的单位成本不变；
- 现金分红单列为分红收益；
- 送转后总成本不变，单位成本按新数量重算；
- 冲正事件在重放时排除原事件和冲正事件本身。

仓位快照包含数量、平均成本、不复权最新价、行情日期、行情质量、市值、已实现收益、未实现收益、分红收益、总收益、组合权重和集中度风险。

### 3.3 影子策略决策

Java 负责读取账本、行情、最新预测并编排请求；持仓策略计算放在 Python 量化服务的独立端点，避免与预测训练耦合。输出动作状态：

- `HOLD`：优势尚存且风险可控；
- `ALLOW_ADD`：预测优势在费用后仍显著，且资金、手数、集中度和下行预算允许；
- `REDUCE_CONCENTRATION`：预测不一定转空，但单股暴露超出风险预算；
- `EXIT_TRIGGERED`：模型证据明显恶化或触发既定退出规则；
- `ABSTAIN`：行情过期、模型健康不合格、样本不足或优势不足，保持不行动。

策略输入包含最新预测的 P10/P50/P90、上涨概率、校准与稳健性状态、当前原始价、数量、现金、组合权益、交易费率和约束。平均成本、浮盈浮亏仅用于解释真实影响，不参与动作评分。

默认采用小资金约束：买入 100 股一手、保留现金缓冲、限制单股权重、按一手逐步加减仓，并在费用后优势不足时返回 `ABSTAIN`。

## 4. 前瞻验证

每个交易日对有真实持仓且存在可用预测的股票生成至多一条冻结决策。决策保存：

- 证券、决策日、持仓与账户快照；
- 预测运行 ID、模型版本、数据截止日和数据指纹；
- 概率与收益分位数、动作、建议数量、理由和阻断条件；
- 策略版本、成本假设和到期日。

到期后使用不复权实际价格计算策略净收益、同股持有收益、增量收益、最大不利变动和费用。连续多日重复的同类建议折叠为一个决策 episode，避免把同一观点伪装成多个独立样本。

验证面板展示：样本数、胜率、相对持有增量、费用、最大回撤、动作分组表现、概率校准，以及“积累中 / 条件有效 / 无明显优势 / 稳健”的审慎结论。样本量或市场阶段覆盖不足时不得输出“稳健”。

## 5. 服务与数据流

```text
手工交易请求
  -> Web 参数校验
  -> StockTransactionService（幂等、业务校验、事务）
  -> StockTransactionRepository
  -> StockPositionAccountingService 重放账本
  -> strategy_holding 数量/均价兼容投影

持仓策略刷新
  -> 读取最新真实持仓 + 不复权行情 + 最新单股预测
  -> PythonHoldingStrategyClient
  -> Python /v1/quant/holding-strategies/evaluate
  -> 冻结 HoldingStrategyDecision
  -> 到期任务计算 outcome
```

`strategy_holding` 继续承载组合角色、目标权重和旧页面兼容字段，但股票数量与平均成本在启用账本后由账本投影维护，不再允许直接覆盖。

## 6. API

- `GET /api/strategy/stock-account`：账户摘要、股票仓位与行情质量；
- `GET /api/strategy/stock-transactions`：按时间倒序查询交易流水；
- `POST /api/strategy/stock-transactions`：新增幂等账本事件；
- `POST /api/strategy/stock-transactions/{id}/reverse`：冲正错误事件；
- `GET /api/strategy/holding-decisions`：查询冻结建议与验证结果；
- `POST /api/strategy/holding-decisions/refresh`：按最新可用证据生成当天决策，重复请求幂等。

## 7. 前端

在长期投资工作台新增股票专属区域：

- **实盘总览**：总市值、总收益、现金、集中度和行情新鲜度；
- **交易流水**：录入买卖、分红、送转和资金事件，支持冲正；
- **持仓诊断**：每只股票的数量、成本、市值、权重、P10 金额影响和风险门禁；
- **影子策略**：动作、建议数量、主要证据、阻断原因和适用期限；
- **验证账本**：策略相对同股持有的前瞻结果和样本可信度。

单股预测页复用真实仓位快照并展示当前策略建议；股票发现页仅标记“已持有”和当前权重，不改变候选的纯量化排名。

视觉采用现有深色研究工作台风格，强化金额、风险和动作层级；图表保留足够字号、完整坐标和空状态，不以装饰性动画掩盖数据状态。

## 8. 失败与降级

- 行情不可用：保留账本和成本数据，市值标为不可估值，策略返回 `ABSTAIN`；
- 预测不可用或过期：不触发昂贵预测，不报系统错误，返回“等待有效预测”；
- Python 量化服务失败：交易账本写入不受影响，策略刷新失败可重试；
- 重复提交：幂等返回已有事件或已有当日决策；
- 部分股票失败：逐只隔离，不阻断其余持仓；
- 旧持仓迁移：首次打开时可将旧数量与均价转换为一条 `OPENING_BALANCE`，不重复迁移。

## 9. 验收标准

1. 账本重放覆盖买入、部分卖出、清仓、分红、送转、冲正、资金流和非法超卖；
2. 原始价估值与前复权模型数据有测试证明不会混用；
3. 同一幂等键不会生成重复交易，同一股票同一天不会冻结重复策略；
4. 持仓成本不出现在 Python 预测训练请求，只出现在独立持仓策略请求；
5. Python 服务、行情或预测失败不会破坏账本与其他股票；
6. 后端模块测试、Python 测试、前端测试和生产构建通过；
7. 对照《项目开发规范与代码评审清单》完成字段注入、大括号、模块落点和异常边界自检。
