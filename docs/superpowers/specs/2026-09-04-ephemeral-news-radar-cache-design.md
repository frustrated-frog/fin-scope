# 新闻与热点雷达临时缓存设计

## 背景与目标

FinScope 当前已使用 Redis 缓存新闻来源快照和页面视图，但新闻分类结果、雷达信号、雷达事件、事件关系、增强结果及部分交互状态仍写入 SQLite。持续抓取会让这些高时效、低长期价值的数据不断累积。

本次改造建立严格的两层数据模型：

- 实时新闻、热点雷达及首页热点属于临时资讯，只在 Redis 中保存，最长保留 36 小时。
- 只有用户明确执行“记入大事记”后，资讯才以完整快照写入 SQLite，成为长期档案。
- 信源配置、新闻分类字典等非资讯配置继续使用 SQLite。
- Redis 故障或数据丢失不得触发临时资讯回写 SQLite。

## 数据边界

### Redis 临时数据

以下数据统一进入带命名空间的 Redis 缓存：

- 新闻来源抓取结果和新闻条目。
- 单条新闻的自动分类、人工复核分类及复核原因。
- 雷达信号、聚合事件、事件与信号关系。
- 雷达评分、首页金融/科技/政治热点榜单。
- 雷达证据、AI 解读、时间线和通知。
- 已读、忽略、稍后看、临时关注等事件交互状态。
- 雷达生产批次及步骤状态，只保留页面展示和故障定位所需的最近窗口。

这些数据不得再通过现有 `news_item_classification`、`radar_*` 表形成新的 SQLite 记录。

### SQLite 永久数据

以下数据继续持久化：

- `major_event` 中的大事记快照。
- `news_category` 新闻分类字典。
- 信源配置及其他与本次临时资讯无关的业务数据。

大事记必须是反规范化快照，至少包含来源类型、稳定来源键、标题、摘要、来源名称、来源 URL、分类、发生日期和用户备注。读取大事记不得依赖 Redis 中的新闻或雷达事件仍然存在。

## 缓存模型与过期语义

临时数据使用 `finscope:news:*` 和 `finscope:radar:*` 业务前缀。聚合索引和对象内容分开建模，但均由 DAO 模块中的语义化缓存 Repository 封装，Service 不直接拼 Redis Key 或操作 `StringRedisTemplate`。

所有新闻和雷达对象都有 `expiresAt`。其计算规则为：

1. 新闻优先使用可信的 `publishedAt`，否则使用 `firstSeenAt`。
2. 雷达事件以其最早仍有效信号的过期时间为下限、最新有效信号的过期时间为上限；事件中没有有效信号时立即从榜单移除。
3. 单个对象的最长寿命为基准时间后 36 小时。
4. 定时抓取命中同一条内容时只更新 `lastSeenAt` 和排名信息，不延长内容的绝对 `expiresAt`。
5. Redis Key 的 TTL 使用 `expiresAt - 当前时间`，不得每次刷新重置为完整 36 小时。

新闻列表、雷达列表和首页榜单读取时还要按 `expiresAt` 过滤，避免 Redis 惰性删除或索引与对象短暂不一致导致过期内容被展示。

稳定来源键不再依赖 SQLite 自增 ID：

- 新闻沿用 `providerCode:externalId`，无外部 ID 时使用规范化 URL 或内容指纹。
- 雷达事件使用事件指纹作为字符串 `eventKey`。为保持现有 API 兼容，页面仍使用由 `eventKey` 确定性计算出的正数 `Long` 标识；大事记持久化的是原始 `eventKey`，而不是该临时数值投影。
- 大事记的 `originKey` 保存该稳定键并继续承担幂等约束。

## 核心数据流

### 新闻刷新

`ResearchMaterialGateway` 抓取来源后，将标准化新闻写入新闻缓存。分类协调器读取临时新闻并把分类结果写回同一缓存域。`NewsFeedService` 只从新闻缓存读取最近 36 小时的有效条目；缓存为空时返回空列表和明确告警，不查询 SQLite 新闻表。

### 雷达生产与首页热点

雷达生产从新闻缓存读取有效新闻，在内存中完成标准化、去重、聚类和评分，再将一轮结果写入雷达缓存。写入采用“版本化快照后切换活动版本”的方式：先完整写新版本，再原子切换活动版本，避免页面读到半批数据。

研究雷达页面和首页热点都读取同一活动雷达版本。首页不再查询 SQLite `radar_event`，只对活动事件按仪表盘分类生成榜单。

### 记入大事记

创建大事记时，服务根据 `originType + originKey` 从新闻缓存或雷达缓存读取对象，构造完整 `MajorEvent` 快照并写入 SQLite。写入仍以该组合为唯一业务键，重复请求返回既有业务错误。

如果对象已经过期或缓存不可用，接口返回“临时资讯已过期，请重新刷新后再收录”，不得创建字段不完整的大事记。前端继续在成功后提示“已记入大事记”。

### 人工交互

已读、忽略、稍后看、临时关注、AI 解读和通知均跟随雷达事件的 `expiresAt`，不会转成永久数据库记录。

临时雷达上的观察记录入口取消。用户要保留判断时，先将事件记入大事记，再通过大事记备注维护长期内容，避免用户文本随缓存静默消失。

## Redis 故障与并发

- 新闻抓取成功但 Redis 写入失败：本轮刷新标记失败，页面保留上一个仍有效版本；没有旧版本时显示空态和告警。
- 雷达新版本写入不完整：不切换活动版本，继续展示旧版本直到其自然过期。
- 大事记保存失败：Redis 临时对象保持不变，用户可幂等重试。
- Redis 不可用：临时新闻、雷达和首页热点不降级到 SQLite，也不在 JVM 内建立另一套无界缓存。
- 并发刷新通过现有单飞控制及版本切换避免覆盖；过期清理由 Redis TTL 与读取过滤共同保证。

## API 与界面调整

- 新闻、雷达和首页热点接口的响应结构尽量保持不变。
- 雷达事件 ID 从数据库数值 ID 改为稳定字符串键，相关详情、状态和大事记请求同步调整。
- 移除临时雷达的观察记录增删改入口；大事记备注仍保留。
- “关注”文案明确为临时关注，避免用户误认为会永久保存。
- 缓存为空或不可用时展示可理解的空态，不把基础设施异常原文暴露给前端。

## 旧数据退出策略

新增一次性、可幂等执行的数据库迁移：

1. 先验证 `major_event` 已保存完整快照，不依赖雷达外键。
2. 按外键依赖顺序清空 `news_item_classification` 及本次退出使用的 `radar_*` 临时资讯表。
3. 保留 `news_category` 和 `major_event`。
4. 停止创建和访问这些临时表；物理删表放在后续独立迁移中，给本次上线保留回滚窗口。

本次迁移释放的 SQLite 页面可供数据库后续写入复用。为避免启动时长时间锁库，本次不在应用启动过程中自动执行 `VACUUM`；需要缩小现有数据库文件时，提供单独的离线维护命令和操作说明。

## 测试策略

实现遵循测试先行，至少覆盖：

- 新闻 TTL 按发布时间或首次发现时间计算，重复刷新不续期。
- 新闻分类和人工复核只写 Redis，不写 SQLite。
- 雷达版本完整写入后才能切换；部分失败时继续使用旧版本。
- 新闻、雷达和首页接口不会返回超过 36 小时的数据。
- 雷达事件稳定字符串键可用于详情、交互和大事记收录。
- 新闻和雷达收录后，即使删除 Redis 数据，大事记仍完整可读。
- 缓存已过期、Redis 不可用、重复收录和大事记数据库写入失败的行为。
- 一次性迁移只清理临时资讯表，保留分类字典和大事记。
- 前端不再展示雷达观察记录入口，并正确传递字符串事件键。

## 非目标

- 不把文章工作区中用户主动抓取、解读和研究的 `Article` 改成临时数据；它属于主动研究资料，不等同于实时新闻流。
- 不引入新的缓存产品或消息系统，继续复用项目现有 Redis 与版本化视图能力。
- 不改变大事记页面的长期档案定位，也不自动把关注、已读或 AI 解读升级为永久内容。
