# 产品需求：Agent 解读可信与可恢复能力

> 文档状态：已实现；版本：V1.0；日期：2026-07-26；适用范围：文章、资金行为、财报与 Agent Trace

## 一、背景

FinScope 已经具备文章深度解读、资金行为解读、财报解读和量化实验解读等能力，也实现了结构化输出、证据门禁和确定性降级。但当前各链路在安全、任务恢复、状态一致性和结果来源展示上并不统一：部分任务刷新页面后无法找回，瞬时网络错误会让轮询停止，旧标的任务可能写入新标的页面，规则降级也可能在 Trace 中显示为模型成功。

本期不追求增加更多“像 AI 的文字”，而是把 Agent 建设成可证明、可恢复、可审计的研究基础设施。该能力既服务真实使用，也应能在秋招项目展示中回答：模型为什么被调用、使用了什么证据、失败后发生了什么、结果是否来自规则、页面刷新后如何恢复。

## 二、产品定位

Agent 解读是受领域证据约束的异步研究任务，不是一次性聊天接口。

- 事实、数字、因子和财务指标由确定性服务生成。
- 模型负责组织观察、假设、反证和下一步验证条件。
- 每次结果都必须带有生成方式和运行状态。
- 模型不可用时允许规则降级，但必须明确标识，不能伪装成模型成功。
- 用户离开页面、切换标的或重启应用后，任务和结果仍可恢复。
- Agent Trace 必须真实反映模型调用、修复、降级、失败和耗时。

## 三、目标

1. 消除 LLM HTTPS 请求中的全局不安全配置。
2. 让资金行为与财报解读具备可查询、可恢复的任务生命周期。
3. 防止异步结果跨标的、跨报告污染当前页面。
4. 让短暂网络故障不会永久中断任务轮询。
5. 统一 Agent Trace 的成功、降级、失败与模型调用计数语义。
6. 让文章卡片能够说明结果来自 LLM 还是确定性规则。
7. 提高文章解读对外部不可信正文、非法置信度和无依据输出的防护。

## 四、核心用户场景

### 4.1 恢复最近一次资金解读

用户重新打开资金行为页或切换回某个标的时，系统自动读取该标的当前快照对应的最近一次解读。若任务仍在运行，页面继续轮询；若快照已变化，旧结论不得被展示为当前结论。

### 4.2 安全地切换研究对象

用户在 Agent 运行期间切换标的。旧任务可以在后台完成并持久化，但不能更新新标的页面。切回原标的后，可以恢复任务或结果。

### 4.3 识别模型结果与规则降级

所有解读结果显示生成来源：`模型生成`、`模型修复后生成`、`规则解读`或`数据不足`。Agent Runs 中的状态、fallback 标志和调用次数与页面保持一致。

### 4.4 网络波动后继续等待

财报或资金解读轮询发生瞬时失败时，页面显示“连接中断，正在重试”，采用有限退避继续请求。恢复后自动展示结果，不要求用户重新生成。

### 4.5 应用重启后的诚实恢复

应用启动时将上次进程遗留的进行中任务标记为 `FAILED/INTERRUPTED`。用户看到明确原因并可以重新运行，不出现永久 PENDING。

## 五、功能需求

### 5.1 安全 LLM 连接

- 使用 JVM 默认信任链和主机名校验。
- 不修改全局 `HttpsURLConnection` SSL 配置。
- 响应流和连接必须可靠关闭。
- 对外错误信息保留可诊断摘要，不保存或展示 Authorization、API Key 等凭证。

### 5.2 统一任务生命周期

资金行为解读状态：`PENDING -> SUCCEEDED | FALLBACK | INSUFFICIENT_DATA | FAILED`。

财报解读状态：`QUEUED -> RUNNING -> VALIDATING -> SUCCESS | FALLBACK | FAILED`。

共同约束：

- 同一研究对象已有运行中任务时，重复点击复用该任务。
- 非强制请求优先复用当前输入指纹对应的终态结果。
- 强制重跑只在没有运行中任务时创建新版本。
- 任务必须记录创建、开始、完成或更新时间。
- 应用重启将未完成任务标记为中断。

### 5.3 最近结果与恢复接口

- 支持按标的读取最近一次资金行为 Agent 解读。
- 最近结果必须绑定当前资金快照；旧快照结果不冒充当前结果。
- 页面首次加载、切换标的和重新进入页面时自动恢复。
- 运行中结果恢复后继续轮询。

### 5.4 前端竞态与轮询

- 每次加载和 Agent 运行绑定研究对象版本。
- 只有当前对象仍一致时才能写入当前页面状态。
- 网络错误采用按链路配置的短间隔起步、最高 10 秒的退避重试。
- 切换对象或卸载组件必须终止旧轮询的页面写入。
- 超过任务时间预算时提示后台任务仍可恢复，不创建重复任务。

### 5.5 Trace 真实性

- `SUCCESS`：模型输出通过门禁。
- `FALLBACK`：模型未配置、超时、不可用或输出被拒绝后使用规则结果。
- `FAILED`：没有可交付结果。
- `llmCallCount` 只在真正发起模型请求时增加。
- 修复请求计为第二次模型调用。
- Trace 记录研究对象、输入指纹、输出摘要、fallback 原因和生成模式。
- 未进入统一 Trace 的解读型 Agent 分阶段接入，不允许页面宣称“完整运行追踪”。

### 5.6 文章解读可信度

- 外部文章正文按不可信数据处理，Prompt 明确要求忽略正文中的指令。
- 置信度必须限制在 `0–1`。
- 关键输出设置长度和条数上限。
- 模型生成与规则降级来源随情报卡片持久化并返回前端。
- 页面明确标识来源；规则降级仍可用，但不伪装为 Agent 成功。

## 六、非目标

- 不引入多 Agent 辩论或自主工具调用。
- 不引入向量数据库、LangChain 或新的 Python 运行时。
- 不让模型直接读取数据库、执行 SQL 或写入知识库。
- 不在本期实现开放式股票问答。
- 不自动产生交易建议、仓位、目标价或收益预测。

## 七、验收标准

1. LLM 客户端不再包含信任所有证书或跳过主机名校验的代码。
2. 资金行为页刷新后可以恢复当前快照最近一次解读。
3. Agent 运行中切换标的，不会在新标的页面展示旧结果。
4. 资金和财报进行中任务在应用重启后被标记为中断。
5. 财报轮询一次或多次失败后仍会继续，恢复后正常展示结果。
6. LLM 未配置时，Trace 显示 `FALLBACK` 且模型调用次数为 0。
7. 首次输出非法、修复成功时，Trace 显示成功且模型调用次数为 2。
8. 文章解读置信度不会超出 `0–1`，外部正文指令不会改变系统任务边界。
9. 情报卡片能够展示 `LLM` 或 `FALLBACK` 来源。
10. 后端单元/集成测试、前端组件测试、TypeScript 检查与生产构建通过。

## 八、展示价值

本期完成后，项目可以形成一条有区分度的秋招叙事：

> FinScope 没有把大模型当成文本接口，而是构建了证据包、可信门禁、异步状态机、幂等恢复、跨页面竞态保护、确定性降级和可审计 Trace。模型只是候选结论生成器，服务端才是结果可信性的最终裁判。
