# PRD：FinScope 个人投研信息与知识工作台

## 问题背景

当前金融简报依赖临时搜索与模型自由发挥，存在来源不稳定、两天内容重复、缺少可审计采集框架、知识无法长期沉淀的问题。用户希望建立自己的信息获取渠道，并让项目同时服务个人金融学习、秋招展示和未来自媒体素材积累。

项目必须与实习中的热点生产/运营后台项目保持清晰差异：FinScope 不做公共热点榜单、不做运营干预后台、不做企业发布链路、不复用公司代码、接口、数据源、提示词或专有配置。

## 解决方案

FinScope 是一个本地优先、可迁移、可扩展的全栈投研信息工作台，核心链路是：

```text
Sources -> Inbox -> Novelty -> Brief -> Topics -> Content Studio
```

V1/V2 先完成稳定信息源、文章池、跨天去重、新意判断、每日简报和 Web 展示。后续版本逐步补主题知识库、Agent 工作流、自媒体素材和导出恢复。

## 用户故事

1. 作为学习者，我希望配置自己的金融信息源，从而建立稳定的每日信息渠道。
2. 作为学习者，我希望抓取到的文章先进入 Inbox，从而在它们进入简报前检查采集结果。
3. 作为学习者，我希望跨天过滤重复或相似文章，从而避免每日简报重复旧内容。
4. 作为学习者，我希望看到文章被判断为重复、后续进展或新事件的原因，从而信任系统判断。
5. 作为学习者，我希望每日简报拥有稳定栏目，从而持续学习市场信息。
6. 作为学习者，我希望重要主题沉淀为知识卡片，从而把日常信息转化为长期知识。
7. 作为内容创作者，我希望成熟主题可以转化为草稿大纲，从而为后续自媒体输出做准备。
8. 作为求职者，我希望系统暴露流水线 Trace 和 Agent 运行记录，从而展示项目工程深度。
9. 作为公司电脑上的个人用户，我希望采用本地优先存储并支持导出/恢复，从而合规迁移个人学习数据。
10. 作为开发者，我希望信息源适配器、流水线步骤、LLM 客户端和存储模块可替换，从而在想法变化时不需要重写项目。

## 实现决策

- 采用模块化单体：在新的 `fin-scope/` 项目目录中放置一个 Spring Boot 后端和一个 React 前端。
- 本地使用 SQLite 和 Markdown Vault。V1/V2 不依赖云数据库、对象存储、Redis、MQ 或向量数据库。
- 后端拆分为 Maven 模块：`finscope-common`、`finscope-domain`、`finscope-dao`、`finscope-rpc`、`finscope-service` 和 `finscope-web`。
- 业务模块覆盖信息源管理、抓取适配器、文章 Inbox、指纹计算、新意判断、简报生成、Vault 写入、Agent 运行记录和导出/恢复。
- 前端模块包括 Dashboard、Sources、Inbox、Briefs、Topics、Learning、Agent Runs、Settings。
- 对外 API 包括信息源 CRUD/抓取、文章列表/详情、简报生成/列表/详情、主题列表/创建/详情、Agent 运行记录、导出/导入。
- 核心扩展接口包括 `SourceAdapter`、`FingerprintService`、`NoveltyService`、`BriefGenerator`、`VaultWriter`，并为未来 `LlmClient`/工作流预留边界。

## 测试决策

- 后端测试关注服务和 API 的外部行为。
- 当前覆盖指纹计算、标题/正文相似度、Markdown 简报生成、Vault 写入、信息源抓取/Inbox/去重/简报 API 流程、主题沉淀、导出包生成。
- 前端测试覆盖工作台外壳渲染、Inbox 新意原因展示、主题沉淀元数据和 Learning 笔记写入流程。
- 验收场景：
  - 创建信息源 -> 抓取 -> 文章出现在 Inbox。
  - 同一信息源抓取两次 -> 重复计数增加。
  - 生成简报 -> API 返回简报和 Markdown 路径。
  - 文章/简报沉淀主题 -> 主题卡片展示关联数量、术语和学习问题。
  - Learning 页面追加个人理解 -> 写入主题 Markdown。
  - 导出 -> zip 包包含 `manifest.json` 和 Vault 内容。

## 范围外

- 公开金融建议或投资推荐。
- 公司内部数据、代码、接口、提示词、文档或专有信息源名称。
- 公共热点榜单、运营干预后台、企业发布链路。
- 多用户权限、支付、移动 App、实时行情终端。
- 第一阶段不做云同步、向量数据库、Redis、MQ 和完整 Agent 框架。
