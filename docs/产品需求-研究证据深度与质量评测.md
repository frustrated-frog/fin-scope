# 研究证据深度与质量评测产品需求

## 1. 背景

FinScope 已具备持久化 Research Runtime、Observation 驱动决策、动作预算、失败恢复、正反证据和结构化报告。当前主要短板不在 Agent 角色数量，而在证据加工深度：Tavily 命中后通常直接使用搜索摘要，报告校验也只能证明引用编号存在，不能证明引用材料真实支持相邻主张。

本需求借鉴 GPT Researcher 的“发现 URL—读取全文—分块召回—基于证据写作—基准评测”链路，同时保留 FinScope 现有 Java Runtime 和金融研究语义。不引入 LangGraph、向量数据库或通用多 Agent 框架。

## 2. 产品目标

1. 让研究 Agent 在搜索命中后读取 HTML/PDF 原始材料，并把最相关原文片段用于报告。
2. 对报告中的事实主张做 Claim 级引用支持审计，而不只检查 `[E1]` 是否存在。
3. 建立可重复运行的金融研究 Benchmark，用指标证明研究质量变化。
4. 在一手资料意图下优先交易所、监管机构、公司 IR、统计与央行等官方来源。
5. 提供 QUICK 与 DEEP 两种模式，并用统一预算约束研究分支和并发。

## 3. 非目标

- 不把搜索或全文材料写入文章库。
- 不建设通用知识库问答 Agent。
- 不追求接入大量通用搜索引擎。
- 不替换现有 SQLite Runtime、checkpoint、事件和恢复模型。
- 不保存整份网页的无限长度副本；只保存可审计的检索片段和抽取元数据。

## 4. 用户场景

### 4.1 深度证据

用户发起公司、行业或宏观命题研究后，研究页应能区分：

- 已读取原文的证据；
- 仅有搜索摘要的降级证据；
- 抽取失败或不支持的来源；
- 一手来源与新闻补充来源。

报告引用的材料应包含来源 URL、抽取方式、发布时间、原文片段和来源等级。

### 4.2 引用审计

报告完成前，系统应逐条检查带数字、日期、事件和因果判断的事实句。审计结果分为：

- `SUPPORTED`：引用材料完整支持；
- `PARTIAL`：材料只支持部分表述；
- `UNSUPPORTED`：引用不存在或不支持；
- `CONFLICT`：引用材料之间存在冲突。

不支持内容应被删除、降级为待验证判断，或经过一次定向修复。修复后仍不合格则进入结构化保底报告，不得无限重试。

### 4.3 Benchmark

维护带冻结时间、期望关键事实和核验来源的金融问题集，至少输出：

- 引用可访问率；
- Claim 引用覆盖率；
- Claim 支持率；
- 关键事实覆盖率；
- 一手来源占比；
- 正反证据覆盖；
- 信息时效性；
- 总耗时、搜索次数、模型调用次数；
- 重复运行结论稳定性。

### 4.4 研究模式

- `QUICK`：面向快速判断，限制搜索分支、全文读取数和模型调用次数。
- `DEEP`：面向完整研究，最多并行执行支持、反方、一手来源/最新进展三条分支，但仍受统一预算和并发上限约束。

## 5. 功能需求

### FR-1 原文获取与降级

- Tavily 只负责发现 URL。
- HTML 使用现有网页正文抽取能力；PDF 使用受限大小的文本抽取。
- 只允许公网 HTTP/HTTPS URL，拒绝本机、私网和非 Web 协议。
- 抽取超时、页面过大、正文过短或格式不支持时保留搜索摘要，并记录明确状态。

### FR-2 分块与召回

- 按段落与句子边界分块，保留有限重叠。
- 使用研究问题、查询、主体别名和意图进行确定性相关性排序。
- 每个来源只保留少量高相关片段，片段必须能追溯到 URL 和块序号。

### FR-3 Claim 审计

- 识别事实句及其相邻引用。
- 数字、百分比、日期和专有实体必须在引用片段中可核对。
- 审计结果参与报告质量门禁和研究评测。
- 一次受控修复必须保留合法引用白名单，不能创造新证据编号。

### FR-4 官方金融来源

- `PRIMARY` 意图优先官方来源通道。
- 交易所、监管、公司 IR、统计和央行域名映射为 T1。
- 新闻与未知来源继续由 Tavily 补充。
- 来源识别和分级只维护一个事实源。

### FR-5 模式与预算

- 创建研究运行时可选择 `QUICK` 或 `DEEP`，默认 `DEEP` 以兼容现有行为。
- 每种模式明确最大搜索数、全文读取数、并发数、迭代数和报告修复次数。
- 所有分支 Observation 仍进入现有持久化 Runtime，不引入第二套状态真相。

## 6. 验收标准

1. 针对包含 HTML、PDF、抽取失败三类命中的测试，报告上下文分别使用原文片段、PDF 片段和标记清晰的搜索摘要降级。
2. 全文证据 URL 在 `article` 表中的新增数为 0。
3. 无引用数字、引用不支持和冲突证据均能被 Claim 审计识别。
4. 修复 Agent 最多调用一次，修复后不能产生白名单之外的证据编号。
5. Benchmark 能离线运行并输出稳定、可序列化的指标。
6. `PRIMARY` 查询优先官方来源，官方域名统一标记 T1。
7. QUICK 与 DEEP 的预算不同，DEEP 并发不超过配置上限，失败分支不阻塞其他结果提交。
8. 后端全量测试、前端全量测试和生产构建通过，并完成一次真实研究端到端验收。
