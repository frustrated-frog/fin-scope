# PRD：自选研究 Agent Harness

## 1. 背景

当前“深度归因”可以回答标的涨跌的大致方向，但研究问题数量少、证据形态扁平、驱动因素通常只有一到三条，且“产业链分析”没有形成实际数据或推理产物。用户需要的是一份可回溯、内容丰富且诚实表达不确定性的研究报告，而不是搜索摘要的改写。

## 2. 产品定位

自选研究 Agent Harness 是 FinScope 面向股票、基金和板块异动解释的受控研究运行时：模型负责理解与组织证据，系统负责研究计划、工具边界、并行预算、状态恢复、证据门槛和输出验收。

本期不建设通用聊天 Agent，不提供投资建议，也不允许模型执行数据库写入、删除或任意网络访问。

## 3. 用户与核心场景

| 用户 | 场景 | 成功结果 |
| --- | --- | --- |
| 个人投资学习者 | 看到自选标的异动后点击“深度归因” | 得到主因、次级驱动、反证、证据链接和下一观察点 |
| 内容创作者 | 回看某标的历史归因 | 能比较本次与历史驱动，并复用已验证事件 |
| 求职展示者 | 展示 Agent 研究链路 | 能看到计划、并行研究轨道、证据门和降级原因 |

## 4. 目标

1. 每份有充足证据的报告输出 4–6 条结构化驱动，而不是最多三条标题式结论。
2. 每条驱动明确展示“事实、传导链、价格影响、置信度、证据、反证/不确定性”。
3. 将公司/标的、行业产业链、宏观政策、市场资金、反证作为独立研究轨道；轨道可并行但受预算约束。
4. 研究运行可恢复：每个节点有状态、输入输出摘要、预算和失败原因；SSE 中断不影响后端研究完成。
5. 证据必须经过去重、时效、直接性、来源、独立性和立场整理；模型不可用或证据不足时诚实降级。
6. 历史报告形成标的事件记忆，可在后续归因中作为候选背景，但不得替代当日证据。

## 5. 非目标

1. 不做自动交易、买卖建议或收益预测。
2. 不接入付费金融终端、Level-2 或完整基金持仓数据库。
3. 不引入 LangGraph、CrewAI、AutoGen、消息队列、Redis 或向量数据库。
4. 不做开放式多 Agent 自主委派；研究轨道由系统定义，局部查询调整由受限策略完成。
5. 不把长期评测平台作为本期阻塞项；本期只实现运行时质量门和可固化的测试样例。

## 6. 功能需求

### 6.1 研究计划与运行合同

开始归因时创建版本化研究计划，包含目标、研究轨道、每轨查询、最大调用数、依赖、成功条件、重试上限和停止条件。计划必须通过规则校验后才可执行。

### 6.2 多轨证据研究

股票默认覆盖公司、行业、宏观、市场和反证；基金重点覆盖重仓暴露与行业；板块重点覆盖政策、行业、龙头与市场。每轨输出标准化证据，而不是直接输出自然语言结论。

### 6.3 证据门与因果链

高置信度结论需要权威或至少两个独立来源支撑。每个驱动要建立“事件/事实 → 预期变化 → 传导机制 → 行情影响”的链条，并显式记录反证和未确认部分。

### 6.4 报告阅读体验

报告按“市场异动概览、最可能主因、次级驱动、反证与不确定性、下一观察窗口、证据”组织。进度页展示研究轨道及其状态，不暴露模型原始思维链。

### 6.5 标的记忆

保存本次验证过的事件和驱动摘要。后续运行可读取相同标的近期报告作为背景；历史内容必须标记为背景，不能计入当日证据数量。

## 7. 验收标准

1. 有足够证据时报告含 4–6 个驱动，且每项带证据链接与传导说明。
2. 任何没有证据 URL 的驱动不得被标为高置信度。
3. 搜索失败、证据不足、模型输出不合格时，报告必须展示降级原因，不得编造结论。
4. 同一运行中相同规范化 URL 只保留一条证据。
5. 运行计划、步骤状态、预算与错误可持久化查询；服务重启后未完成任务不会伪装为完成。
6. 历史背景不会覆盖当日行情或当日证据。

## 8. 分期

| 阶段 | 范围 | 交付价值 |
| --- | --- | --- |
| 第一阶段 | 研究计划、运行状态、丰富报告契约、五轨检索 | 报告内容明显更丰富且有结构 |
| 第二阶段 | 证据标准化、评分、反证、历史记忆 | 结论更可信、可回溯、可比较 |
| 第三阶段 | 局部重规划、证据充分性门、恢复编排 | 运行时更接近完整 Harness |
