# 产品需求：财报解读 Agent

> 文档状态：待评审；版本：V1.0；日期：2026-07-17；适用范围：A 股非金融企业，公司财报分析工作台第二阶段

## 一、背景

第一阶段已经具备财报抓取、PDF 上传、三张表展示、核心指标、规则发现、数据质量提示与多报告切换能力。下一阶段要解决的不是“再展示更多数字”，而是帮助用户把分散的财务事实组织成一份可核查、可复用的分析结论。

直接让大模型阅读原始报表存在三个风险：口径混用、数字幻觉和结论不可追溯。因此本期产品定位不是自由聊天机器人，而是一个受结构化证据约束的财报解读 Agent。

## 二、产品定位

财报解读 Agent 是“证据组织器和分析助手”，不是财务计算器，也不是投资决策替代者。

- 计算层负责确定性指标、趋势与规则发现。
- Agent 只消费已经保存并校验过的结构化数据。
- 每条实质性判断都必须引用系统证据。
- 页面允许用户沿引用回到指标、三张表项目或规则发现。
- 输出明确区分事实、推断、风险、待验证问题和数据缺口。
- 不生成买入、卖出、目标价或收益承诺。

## 三、目标

1. 一键生成可阅读的完整财报解读，而不是指标罗列。
2. 将增长、盈利、现金、资产、偿债等线索串成一致的经营叙事。
3. 让重要结论具备逐条证据引用和反证意识。
4. 在数据不完整或质量偏低时主动降级，不假装确定。
5. 保留历史解读，使用户能比较不同报告、不同生成版本的判断。

## 四、核心用户场景

### 4.1 首次快速读懂一份财报

用户选择报告后点击“生成 Agent 解读”，在短时间内获得经营概览、六维分析、积极信号、风险、拐点与后续观察项。

### 4.2 核查结论来源

用户点击结论后的证据标签，在证据抽屉中看到指标值、比较期、原始报表项目、规则发现和数据质量说明。

### 4.3 更新数据后重新解读

财报重新抓取或指标算法升级后，系统生成新的分析快照。用户可重新生成解读，同时保留旧版本作为历史记录。

### 4.4 数据不足时获得诚实反馈

如果缺少现金流量表、比较期或关键科目，Agent 必须指出缺口，降低置信度，并避免作出依赖这些数据的强结论。

## 五、一期功能范围

### 5.1 确定性分析能力增强

在现有指标基础上补齐以下指标与趋势：

- 增长：营业收入同比、归母净利润同比、经营活动现金流同比。
- 盈利：毛利率、净利率、期间费用率及其同比变化。
- 现金质量：经营现金流/净利润、自由现金流、资本开支。
- 资产质量：应收账款增速差、存货增速差、合同负债变化。
- 偿债：资产负债率、流动比率、速动比率、有息负债。
- 一致性：资产负债表恒等式校验、收入利润背离、利润现金背离。
- 趋势：最多 8 个可比单季度或 5 个可比年度的同口径序列。

所有指标由服务端确定性计算，Agent 不承担重新计算职责。

### 5.2 一键生成完整解读

固定输出结构如下：

1. 经营状态：改善、稳定、承压或证据不足。
2. 执行摘要：3 至 5 条最重要判断。
3. 六维分析：
   - 成长性
   - 盈利能力
   - 盈利质量
   - 现金质量
   - 资产质量
   - 偿债与资本纪律
4. 积极信号。
5. 风险与反证。
6. 可能的拐点。
7. 后续观察清单。
8. 数据缺口、分析限制与免责声明。

### 5.3 证据引用

每条摘要、维度判断、积极信号、风险和拐点至少引用一个合法证据。引用类型包括：

- `metricRefs`：计算指标。
- `lineItemRefs`：三张表原始科目。
- `findingRefs`：规则引擎发现。
- `trendRefs`：同口径趋势序列。
- `dataGapRefs`：数据缺口与质量限制。

引用标识由服务端生成并校验，模型不能自定义新的引用。

### 5.4 页面交互

- 报告分析页增加“Agent 解读”区域。
- 支持生成、重新生成、查看最新结果和查看历史版本。
- 生成过程显示排队、生成中、校验中等状态。
- 解读卡片中的证据标签可打开统一证据抽屉。
- 新生成失败时保留上一份成功结果，并显示本次失败原因。
- 数据快照变化时提示“当前解读基于旧快照”。

### 5.5 历史记录

每次解读记录报告、分析快照、提示词版本、模型、输入指纹、状态、耗时和失败原因。历史结果不可被后续生成覆盖。

## 六、可信约束

### 6.1 输出门禁

模型输出进入产品前必须通过：

1. JSON 结构校验。
2. 枚举、长度和必填字段校验。
3. 引用存在性与类型校验。
4. 数字白名单校验，禁止出现证据包中没有的精确数字。
5. 置信度上限校验，不能高于输入数据质量允许值。
6. 投资建议与承诺性表达检查。

首次输出不合格时允许一次带错误反馈的修复请求；仍不合格则返回确定性降级解读。

### 6.2 置信度规则

- 高质量且比较期完整：最高可为高置信度。
- 存在重要缺口或对账异常：最高为中置信度。
- 缺少核心报表或多数关键指标不可计算：只能低置信度或证据不足。

### 6.3 事实和推断分离

输出中事实描述必须可直接由证据支持；原因解释和未来影响必须标为推断或待验证，不得冒充管理层原话。

## 七、状态与异常体验

| 状态 | 页面行为 |
| --- | --- |
| 尚未生成 | 展示功能说明与生成按钮 |
| 排队/生成中/校验中 | 展示阶段、开始时间与可刷新状态 |
| 成功 | 展示完整解读、证据和历史入口 |
| 输入过旧 | 继续展示旧结果，同时提示重新生成 |
| 生成失败 | 保留旧成功结果，展示可读错误与重试按钮 |
| 确定性降级 | 明确标识“规则解读”，不伪装成模型输出 |
| 数据不足 | 展示数据缺口与补齐建议 |

## 八、非目标

本期不包含：

- 自由问答和多轮对话。
- 自动下载并解析 PDF 文本作为主要证据。
- 管理层讨论与分析章节的语义抽取。
- 与个人 Strategy/投资命题自动对照。
- 金融企业专用指标体系。
- 行业横向排名、估值与目标价。
- 自动交易或买卖建议。

这些能力将在结构化解读稳定后分阶段建设。

## 九、验收标准

1. 对数据完整的 A 股非金融企业报告，可生成固定结构的解读并保存历史。
2. 所有实质性判断均有合法引用，点击后能回到对应证据。
3. 输出中的精确数字均存在于证据包，构造的非法数字会被门禁拒绝。
4. 年报、累计报告和单季度趋势不会混入同一条比较序列。
5. 缺少比较期或现金流量表时，结果会明确降级并指出限制。
6. 模型超时、输出非法或服务不可用时，页面仍能获得确定性降级结果。
7. 同一快照重复点击不会并发创建重复任务；明确重新生成时可产生新版本。
8. 新任务失败不会覆盖上一份成功解读。
9. Agent Trace 可关联到解读记录，便于排错和成本分析。
10. 后端单元、集成与契约测试通过，前端类型检查、组件测试与生产构建通过。

## 十、成功指标

- 90% 以上的数据完整报告可获得有效解读。
- 100% 的实质性判断具备可解析引用。
- 非证据数字通过门禁后的泄漏率为 0。
- 首次输出加一次修复后的合规成功率达到 95%。
- 降级路径覆盖所有 LLM 失败类型，页面无空白结果。

## 十一、后续路线

1. PDF 自动抓取、公告原文切片与管理层证据 Agent。
2. 与 Strategy 命题对照，输出支持、反证和待验证项。
3. 受限财报问答，只允许在当前报告证据范围内回答。
4. 行业基准、同业对比与金融企业专用分析。
