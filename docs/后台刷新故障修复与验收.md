# 后台刷新故障修复与验收

## 雷达快照与任务状态

2026-11-17 的运行记录表明，按事件拆键后，每个事件的快照数组仍会随着刷新累积并整体重写。现场快照约 502 MB，日志中单次提交达到约 62 MB，触发 1 秒 Redis 超时。

- 新快照存储为 `finscope:radar:v2:<generation>:snapshotHistory:<eventId的Base64>` 有序集合。成员由固定宽度、纳秒精度的时间和单条 JSON 构成，分数统一为 0，使用字典序查找。
- 新增只提交一个时间点；相同事件、相同时间重复提交会替换该时间点。查询只返回截止时间之前的一条，不再传输全部历史。
- 每批最多 100 点且总估算字节不超过 256 KiB，单点不超过 64 KiB。保留七天时间窗口，TTL 跟随父事件续期。
- 已过期父事件的快照由 Lua 原子检查后跳过，其他有效事件继续提交。普通关联写入仍保留原有父记录保护。
- 旧 JSON 在首次访问该事件时逐个迁移，按相同字节上限提交。全部导入后比较原文摘要，再 `UNLINK` 旧键；失败保留旧键，重复迁移不会覆盖新时间点。切换时只运行一个版本的后端。
- 新一轮生产前，将超过 30 分钟的遗留 RUNNING 任务及其未结束步骤转为 FAILED；已有成功、失败记录不改。正常失败也会结束对应的运行步骤。
- 步骤及任务完成时间使用实际时钟，不再复用开始时间；失败流水写入异常作为 suppressed exception 保留，避免覆盖最初的生产异常。

验证使用仅绑定本机 16389 端口的隔离 Redis。测试覆盖两千条旧历史迁移、七天裁剪、同时间幂等、纳秒截止边界、父记录删除、混合批次继续写入、按字节拆批、父事件续期和遗留任务回收。测试不清理、重建实际业务 Redis。

## 扫描公告正文

- 普通 PDF 继续使用 PDFBox；没有文本层时调用 macOS 自带 Vision 识别中文和英文。需要本机 `/usr/bin/swift`，不向外部 OCR 服务发送文件。Linux 环境会明确返回 `PDF_OCR_UNAVAILABLE`。
- 最多识别 20 页，输入沿用 6 MiB 上限，输出最多 1 MiB；默认 45 秒且服从调用链剩余预算。超时、中断会终止本次创建的进程及子进程，清理临时 PDF 与正文。
- OCR 返回的材料仍经过公告编号、证券代码、文件类型和发行人全称核验，识别成功不等于身份核验成功。
- SQLite 的 `announcement_enrichment_retry` 保存失败类型、次数和下一次重试时间。可重试失败从 5 分钟指数退避至 6 小时；不可重试的身份问题间隔 6 小时。列表身份或内容变化立即重试，成功后清除失败记录。
- 用实际失败文件 `AN202611121831662728`（600698）和 `AN202611161831751311`（603337）验证，均可识别出千字以上正文并匹配发行人全称。公开测试文件只放在临时目录，不提交到仓库。

## 板块目录与隔夜数据

- 同花顺板块读取复用既有 HTTP 客户端和 AKShare 附带的公开站点客户端脚本；单请求 8 秒、单项总预算 25 秒，校验目录代码、分页和表格列，最多五页。没有增加依赖。
- 行业资金榜失败时，仍返回已核验的名称目录，资金及排名字段为空并带告警；不会把资金榜失败扩散为整个目录不可用。名称目录也不可用时，HTTP 返回结构化 503，Java 保留最近一次成功数据。Java 适配器显式传递板块接口的超时。
- 账本同步的独立超时从 3 秒调整为可配置的 10 秒，失败日志包含错误类型、耗时和堆栈，不打印持仓请求正文。
- 历史分钟线按整日校验。只有存在其他开收盘锚点或全天成交额校验通过的重叠日期，才允许隔离单个冲突日并导入其余日期；所有重叠日期冲突时继续整批拒绝。原有采集分钟和冻结报告不改。
- 隔离结果保存 `quarantinedDays`、`conflicts`、`verifiedMatchingDays`，后台任务明确记为 PARTIAL。失败保存类型和下次重试时间；暂时不可用至少间隔五分钟，确定没有历史或数据契约不满足至少间隔六小时。
- 导入策略升级时，旧策略已耗尽重试次数的失败任务可以获得一次新的有界重试周期，保存原失败摘要。正常完成任务及正在执行的有效租约不重跑。

现场公开数据回放：301578.SZ 的 2026-10-14 开盘价冲突被隔离，35 个其他重叠日期通过校验，补入一个历史交易日；601091.SH 的 2026-09-17、18、21 三天成交额冲突被隔离，34 个其他重叠日期通过校验。两个标的已采集数据逐行保持一致。此前失败的 603596.SH 公司行为源本次重读成功；外部源今后仍可能暂时不可用，失败继续保留未知并有限重试。

## 真实规模验证

只读复制实际缓存中的 3553 个事件及约 521 MB 旧快照至隔离 Redis，完成全量历史迁移约 32.2 秒。迁移后追加 3553 个新时间点约 127 毫秒，全部事件的最近快照批量查询五轮约 109–132 毫秒。该耗时为本机 DAO 回放，未包含新闻采集、聚类及前端渲染；实际缓存未被测试脚本改写。

IDEA 后端重启后自动使用新存储和任务回收逻辑，首次生产会迁移旧快照。Python 行情服务也需重启加载新适配器和历史导入规则。不要同时运行两个后端版本。
