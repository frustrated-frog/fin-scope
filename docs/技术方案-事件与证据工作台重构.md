# 技术方案：事件与证据工作台重构

## 1. 架构

在既有模块化单体中增加事件论点层，不改变 `EvidenceItem` 的采集职责。项目已有 `ResearchThesis` 用于长期研究问题；本方案不复用它：

```text
ArticleIngestCoordinator
  -> EventClusterService
  -> EvidenceService.capture()
      -> EvidenceItemRepository.save()
      -> EventEvidenceThesisService.syncForEvidence()
          -> EventEvidenceThesisRepository

EvidenceWorkbenchController
  -> EventEvidenceThesisService.workbench()
  -> ThesisWorkbenchResponse
  -> EvidenceView
```

`EvidenceItem` 仍然是“文章中可引用的原子事实”；`EventEvidenceThesis` 是“针对事件的可审查判断”。两者不能混合为单张表，以避免同一条事实在不同判断中的含义被覆盖。

## 2. 数据库

```sql
CREATE TABLE event_evidence_thesis (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  event_id INTEGER NOT NULL,
  statement TEXT NOT NULL,
  kind TEXT NOT NULL,
  status TEXT NOT NULL,
  rationale TEXT,
  evidence_gap TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE(event_id, statement),
  FOREIGN KEY(event_id) REFERENCES event_cluster(id) ON DELETE CASCADE
);

CREATE TABLE event_evidence_thesis_link (
  thesis_id INTEGER NOT NULL,
  evidence_id INTEGER NOT NULL,
  PRIMARY KEY(thesis_id, evidence_id),
  FOREIGN KEY(thesis_id) REFERENCES event_evidence_thesis(id) ON DELETE CASCADE,
  FOREIGN KEY(evidence_id) REFERENCES evidence_item(id) ON DELETE CASCADE
);
```

添加 `event_evidence_thesis(event_id, status)` 和 `event_evidence_thesis_link(evidence_id)` 索引。

## 3. 服务契约

`EventEvidenceThesisService.syncForEvidence(EvidenceItem evidence)`：在同一事件内查找 `statement == evidence.claim` 的论点；没有时依据 evidence type 创建论点，再幂等关联该证据。

`EventEvidenceThesisService.workbench(...)`：加载已筛选的 evidence，取关联论点；返回健康度、论点列表、孤立证据与来源分布。筛选后的 evidence 不会被错误计入没有关联的论点。

`GET /api/evidence/workbench?eventId=&sourceTier=&evidenceType=&minConfidence=` 返回 `EvidenceWorkbenchResponse`。

## 4. 前端契约

`EvidenceView` 首次渲染和筛选变更时请求 workbench endpoint，不再混用 props 局部分页与服务端分页。传入 `events` 只用于事件筛选选择器和跳转。

组件拆分为：

- `EvidenceHealthSummary`：四个计算指标。
- `ThesisCard`：论点状态、陈述、解释、缺口和关联证据。
- `EvidenceClaim`：单条可追溯证据。
- `EvidenceSidebar`：来源构成和孤立证据。

不新增第三方组件库。视觉 token 复用已有 CSS 变量，并新增事件/证据专用布局类；桌面优先，900px 以下折叠为单列。

## 5. 风险控制

- 论点自动生成使用保守规则，且只根据已保存 evidence 生成；不能生成投资建议。
- `PARTIALLY_SUPPORTED` 的文字必须强调不确定性；`CONFIRMED` 只用于可直接从原始证据确认的陈述。
- 所有原文 URL 保持 `target=_blank` 和 `rel=noopener noreferrer`。
- 数据库初始化采用 `CREATE TABLE IF NOT EXISTS` 和 `ensureColumn` 兼容本地现有 SQLite 文件。
