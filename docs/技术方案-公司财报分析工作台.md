# 技术方案：公司财报分析工作台

## 1. 文档信息

- 项目：FinScope
- 对应 PRD：`docs/产品需求-公司财报分析工作台.md`
- 日期：2026-07-17
- 状态：设计已确认，待实施
- 首期运行时：Java 8 + Spring Boot 2.7 + SQLite + React/TypeScript + Python 市场数据服务

## 2. 技术目标

本方案在现有模块化单体和市场数据服务之上新增独立 `financials` 领域，解决以下问题：

1. 如何稳定表示公司、报告期、报告类型和报告版本；
2. 如何将结构化三张表与公开财报 PDF 合并为同一研究对象；
3. 如何保留完整原始科目，同时提供可计算的标准科目；
4. 如何正确处理 A 股季度累计值、单季度推导和不同报表口径；
5. 如何让每个指标、规则和模型结论都能回溯到来源与版本；
6. 如何在外部数据、PDF 解析或 LLM 局部失败时返回可用的部分结果；
7. 如何与 Instrument、Strategy、Events/Evidence 和 Agent Trace 连接而不破坏领域边界。

## 3. 核心技术决策

1. **新增独立 `financials` 领域**：财报不是 Market Intel 的附属 JSON，也不是 Article 的一种类型。
2. **结构化数据与 PDF 双轨并行**：结构化数据负责数字计算，PDF 负责原文阅读、附注和页码证据。
3. **Java 持有领域事实**：报告、科目、版本、计算结果、规则结果和研究快照持久化在主应用 SQLite。
4. **Python 服务负责外部结构化财务数据适配**：在现有 `market-data-service` 增加财报能力；Java 通过稳定规范化 API 消费，不依赖 AkShare 等具体库的数据结构。
5. **Java RPC 负责公告清单与 PDF 文件**：公开公告来源、文件下载、文件指纹和本地文件管理收敛在 `finscope-rpc` 与 `financials` 服务。
6. **值来源是一等字段**：`REPORTED / DERIVED / CALCULATED / AI_EXTRACTED` 不允许通过备注文本表达。
7. **报告版本不可变**：正式报告、更正公告和用户上传版本分别保存；新版本不覆盖旧版本。
8. **BigDecimal 贯穿财务计算**：不使用 `double` 保存或计算财务金额和比率。
9. **规则计算确定性、AI 解读按需运行**：三张表和规则不依赖 LLM；AI 只消费受控证据包。
10. **未经验证的 AI 数字不升级为事实**：`AI_EXTRACTED` 不能自动变为 `REPORTED`。
11. **部分成功是正常状态**：报告清单、结构化报表、PDF 下载、文本解析、规则和 AI 各自记录状态。
12. **首期不做 OCR**：扫描版 PDF 保存并可下载，但解析状态为不支持。

## 4. 现有基础与复用边界

### 4.1 可复用能力

- `Instrument`：公司主数据和股票代码归一化；
- `market-data-service`：Provider Router、质量状态、尝试记录、快照和熔断；
- `FinanceHttpClient`：外部 HTTP 超时、重试、响应大小和负载指纹；
- `LlmChatClient`：OpenAI 兼容模型出口；
- `AgentTraceService`：模型运行、输入输出和失败留痕；
- `StrategyStockThesisService` 与 `strategy_stock_thesis`：读取投资命题；
- `Event/Evidence`：承接重要财报事实和公司事件；
- 统一 `ApiResponse<T>` 和前端 API 客户端；
- SQLite Repository、Service、Controller 分层。

### 4.2 必须保持隔离

- 财务科目不写入 `article`；
- PDF 文件元数据不写入普通文章表；
- Financials 数据不直接写入 `quant_*` 表；
- AI 解释不覆盖结构化科目和规则结果；
- Market Intel 的估值/基本面摘要只引用 Financials 查询服务，不复制财报表；
- Strategy 原命题仍由用户维护，Financials 只追加影响记录。

## 7. 报告身份与版本模型

### 7.1 报告身份

报告逻辑身份由以下字段组成：

```text
instrumentId
periodEnd
reportType
financialScope
```

- `reportType`：`Q1 / HALF_YEAR / Q3 / ANNUAL`；
- `financialScope`：`CONSOLIDATED / PARENT`；
- `periodEnd` 使用会计报告期末日，不使用公告日期替代。

### 7.2 文档种类

`documentKind`：

- `EARNINGS_FORECAST`
- `EARNINGS_FLASH`
- `PERIODIC_REPORT`
- `CORRECTION`
- `USER_UPLOAD`

业绩预告和业绩快报可以作为辅助证据，但不与正式三张表共用唯一键。

### 7.3 版本

每次来源文件或结构化负载变化生成 `FinancialReportVersion`：

```text
id
reportId
versionNo
documentKind
announcementId
publishedAt
supersedesVersionId
isCurrent
qualityStatus
```

`FinancialReportVersion` 表示一次正式披露、更正披露或用户确认的报告版本。结构化数据和 PDF 可能来自不同 Provider，因此来源负载不直接塞入版本记录，而是通过多个 `FinancialReportSource` 关联到同一版本。

`isCurrent` 仅表示当前首选版本，不代表删除旧版本。切换当前版本必须由版本服务执行，并保留替代关系。仅仅重新抓取到相同负载不会生成新版本；正式更正、不同公告标识或用户确认的新文件才生成新版本。

## 9. 公告与 PDF

### 9.1 报告清单

`FinancialReportCatalogProvider` 返回：

- 公告标识；
- 标题；
- 股票代码；
- 报告期；
- 报告类型；
- 文档种类；
- 公告时间；
- PDF URL；
- 来源等级；
- 是否为更正；
- 原始负载指纹。

报告清单为空需要区分“当前没有报告”和“Provider 请求失败”。

### 9.2 文件存储

PDF 保存到：

```text
data/financials/reports/
  {market}-{code}/
    {period-end}/
      {document-hash}.pdf
```

数据库保存相对路径，不保存依赖本机的绝对路径。文件名不直接使用外部标题，避免非法字符和路径穿越。

### 9.3 文件安全

- 仅接受 PDF MIME 和 `%PDF-` 文件签名；
- 配置单文件大小上限；
- 下载和上传都计算 SHA-256；
- 拒绝路径穿越；
- 不执行 PDF 中的脚本、附件或外部动作；
- 解析进程设置页数、文本量和耗时上限；
- 原始文件不进入 Git。

### 9.4 文本提取

首期使用 Apache PDFBox 按页提取文本：

```text
FinancialDocument
  -> page 1 text block
  -> page 2 text block
  -> ...
  -> page N text block
```

保留：

- 页码；
- 文本指纹；
- 字符数量；
- 提取器版本；
- 是否扫描版；
- 解析警告。

PDF 表格抽取不作为结构化数字主来源。首期以页级文本和关键词定位支持原文证据；扫描版标记为 `OCR_REQUIRED`。

### 10.3 流量与存量

- 利润表和现金流量表是期间流量；
- 资产负债表是期末存量；
- 同比、环比和周转指标必须按类型选择正确对比期；
- 禁止用期末资产负债表值直接当作期间平均值，平均余额需要期初与期末数据。

### 11.1 单季度推导

```text
Q2 single = H1 YTD - Q1 YTD
Q3 single = Q3 YTD - H1 YTD
Q4 single = Annual - Q3 YTD
```

`QuarterDerivationEngine` 要求：

1. 输入报告属于同一公司、财务口径和会计年度；
2. 输入值均为可接受质量状态；
3. 科目单位和币种一致；
4. 两个输入科目映射到相同 `conceptCode`；
5. 保存输入行项目 ID、公式、算法版本和输入指纹；
6. 任一条件不满足时返回明确缺口，不生成数值。

## 13. 财务校验

### 13.1 基础校验

- 币种和单位可识别；
- 报告期与报告类型一致；
- 同一表同一期间重复科目检测；
- 数字字符串解析和范围检测；
- 合并/母公司口径不混用；
- 当前报告与前期报告的科目映射版本可追踪。

### 13.2 恒等式

在可用科目足够时验证：

```text
资产总计 = 负债合计 + 所有者权益合计
期初现金 + 现金及现金等价物净增加额 = 期末现金
利润总额 - 所得税费用 ≈ 净利润
合并净利润 = 归母净利润 + 少数股东损益
```

允许来源披露的四舍五入容差。容差按金额单位和规则版本配置，不能硬编码在 UI。

### 13.3 跨来源冲突

同一报告、科目、期间和口径的不同来源数值超出容差时：

1. 保存全部来源；
2. 生成 `CONFLICT`；
3. 不覆盖已有值；
4. 不进入高置信度派生指标；
5. 页面展示差异与来源；
6. 后续更正版本可以解除冲突，但不删除历史记录。

- `CONTRACT_LIABILITY_SIGNAL`

- 现象；

## 17. AI 解释与证据门

### 17.1 不可变证据包

`FinancialEvidencePacket` 包含：

- 报告版本和快照指纹；
- 核心三张表事实；
- 派生值和指标；
- 规则发现；
- 原文片段；
- Strategy 命题；
- 数据质量、冲突和缺口；
- 允许引用的数字与证据 ref。

### 17.2 输出 Schema

```text
summary
facts[]
managementExplanations[]
inferences[]
counterEvidence[]
dataGaps[]
watchPoints[]
thesisImpacts[]
confidence
disclaimer
```

### 17.3 Gate

`FinancialInterpretationGate` 必须：

1. 拒绝输入白名单之外的新精确数字；
2. 校验每项事实的 evidence refs；
3. 将无证据的事实降级为推断或删除；
4. 对 `CONFLICT / UNVERIFIED / PARTIAL` 输入限制最高置信度；
5. 禁止买卖、仓位和收益承诺；
6. 禁止自动更新 Strategy；
7. 非法 JSON 时允许一次结构修复，仍失败则使用规则摘要兜底。

## 18. Strategy 与事件证据桥接

### 18.1 命题影响

`FinancialThesisImpactService` 读取同一 `instrument_id` 的股票研究卡，生成候选影响：

- `SUPPORTS`
- `WEAKENS`
- `UNVERIFIED`
- `CONFLICTING`

影响记录只追加，不修改 `strategy_stock_thesis`。用户可以从 Financials 打开研究卡自行调整。

### 18.2 Events/Evidence

以下财报事实可以由用户确认后桥接：

- 业绩大幅变化；
- 毛利率重大转折；
- 重大减值；
- 资本开支扩张；
- 债务压力显著变化；
- 更正公告；
- 管理层指引变化。

桥接记录必须保留财报报告版本和 evidence ref，避免只有一段脱离来源的摘要。

## 19. API 设计

### 19.1 查询

```text
GET /api/financials/instruments/search?q=
GET /api/financials/instruments/{instrumentId}/reports
GET /api/financials/reports/{reportId}
GET /api/financials/reports/{reportId}/versions
GET /api/financials/report-versions/{versionId}
GET /api/financials/report-versions/{versionId}/statements
GET /api/financials/report-versions/{versionId}/statements/{statementType}
GET /api/financials/report-versions/{versionId}/metrics
GET /api/financials/report-versions/{versionId}/findings
GET /api/financials/report-versions/{versionId}/evidence
GET /api/financials/report-versions/{versionId}/interpretations
GET /api/financials/instruments/{instrumentId}/history
```

`GET /reports/{reportId}` 返回逻辑报告摘要和当前版本；所有三张表、指标、证据与解释查询使用不可变 `versionId`，避免刷新后同一 URL 静默展示不同事实。

三张表接口参数：

```text
scope=CONSOLIDATED|PARENT
periodView=REPORTED|SINGLE_QUARTER
detail=KEY|FULL
unit=YUAN|TEN_THOUSAND|HUNDRED_MILLION
```

后端始终返回原始标准化值和单位；显示单位转换可由前端完成，但导出和引用必须保留原始值。

### 19.2 命令

```text
POST /api/financials/instruments/{instrumentId}/refresh
GET  /api/financials/refresh-runs/{runId}
POST /api/financials/documents/upload
POST /api/financials/documents/{documentId}/confirm-association
POST /api/financials/documents/{documentId}/reparse
POST /api/financials/report-versions/{versionId}/interpret
POST /api/financials/report-versions/{versionId}/thesis-impacts
```

刷新和 AI 解释返回 `202 Accepted` 与运行标识，不在 HTTP 请求中等待完整外部流程。

### 19.3 文件响应

原始 PDF 使用受控文件响应：

```text
GET /api/financials/documents/{documentId}/content
```

校验 document ID 与本地记录，不接受客户端传入任意文件路径。

## 21. 刷新状态机与容错

```text
PENDING
  → RUNNING
      → SUCCEEDED
      → PARTIAL
      → FAILED
      → CANCELLED
```

同一公司相同报告范围的活跃刷新合并，避免重复抓取。单个报告、维度或 Provider 失败不回滚已成功报告。

错误分类至少包括：

- `NETWORK_TIMEOUT`
- `HTTP_ERROR`
- `RATE_LIMITED`
- `PROVIDER_SCHEMA_CHANGED`
- `REPORT_NOT_FOUND`
- `DOCUMENT_DOWNLOAD_FAILED`
- `INVALID_PDF`
- `PDF_PARSE_FAILED`
- `OCR_REQUIRED`
- `REPORT_ASSOCIATION_CONFLICT`
- `LINE_ITEM_MAPPING_FAILED`
- `STATEMENT_VALIDATION_FAILED`
- `SOURCE_CONFLICT`
- `LLM_NOT_CONFIGURED`
- `LLM_TIMEOUT`
- `LLM_INVALID_OUTPUT`

错误信息对用户提供中文摘要，对日志保留 provider、报告期、traceId 和有限技术上下文，不记录完整 PDF 文本或模型密钥。

## 22. 性能与容量

- 报告清单和三张表查询优先读取本地 SQLite；
- 三张表按 `report_version_id + statement_type + period_role` 建索引；
- 历史趋势按 `instrument_id + metric_code + period_end` 建索引；
- PDF 文本按页保存，避免单字段存整份超长文本；
- 综合页面使用聚合查询 DTO，避免前端启动十余个串行请求；
- 首期每家公司只默认预取最近八个季度和五个年度；
- 外部刷新并发有界，按 Provider 限流；
- AI 输入使用快照与证据片段，设置最大字符数和超时。

## 23. 数据安全

- 财报为公开材料，但本地上传文件仍视为用户数据；
- `data/financials/` 默认 Git 忽略；
- 文件上传限制类型、大小和数量；
- 不在日志中打印完整财报文本；
- 不把 PDF 文件内容发送给 LLM，只发送经过筛选的必要片段；
- 模型配置和 API Key 沿用环境变量；
- 导出备份时将财报文件和元数据纳入 manifest，并保留指纹。

## 27. 实施前验证项

正式实施前需对候选外部来源进行一次合同验证：

1. A 股报告清单是否能稳定返回报告期、公告时间和 PDF URL；
