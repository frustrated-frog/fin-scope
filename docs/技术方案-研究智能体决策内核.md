# 研究智能体决策内核技术方案

> 对应 PRD：`docs/产品需求-研究智能体决策内核.md`
> 日期：2026-07-27
> 状态：V1 已实现

## 实现摘要

方案已在 `codex/research-agent-core` 分支落地：新增三张 Agent 轨迹表、严格决策协议、模型决策与确定性降级、类型化工具调度、工作记忆归约、局部 Plan Patch、独立 Finish Verifier、Runtime 循环集成、轨迹离线评测，以及前端“Agent 决策流”。命题研究使用新循环；无命题运行继续走原有固定流程，旧运行详情返回空 `agentCore`。

## 1. 设计结论

采用“外层 Plan-and-Execute Mission Loop + 内层 Observation-driven Decision Loop”的分层结构。现有 `ResearchRuntimeService` 继续负责生命周期、动作预算、幂等、防循环和恢复；新增 Agent Core 负责读取状态、选择工具、消费 Observation、更新工作记忆和局部重规划。

```text
Research Mission / Runtime Checkpoint
              |
              v
      ResearchAgentContextBuilder
              |
              v
       ResearchDecisionAgent
              |
              v
    Schema + Policy Validation
              |
              v
      ResearchToolDispatcher
              |
              v
       ResearchToolObservation
              |
              v
      ResearchAgentStateReducer
              |
       +------+-------+
       |              |
   continue       finish request
       |              |
 local replan   FinishVerifier
       |          |        |
       +----------+     rejected -> gap -> continue
                         accepted -> report synthesis
```

这使 LLM 拥有“选择下一动作”的有限自治权，但外部副作用、预算和完成条件仍由确定性服务控制。

## 2. 模块设计

### 2.1 Domain：决策轨迹模型

新增 `com.finscope.domain.research.agent`：

- `ResearchAgentState`：每个 research run 的当前工作状态；
- `ResearchAgentDecision`：不可变决策记录；
- `ResearchToolObservation`：不可变工具观察记录；
- `ResearchAgentTraceView`：供 API 返回的状态、决策和观察聚合；
- `ResearchAgentTrajectoryMetrics`：过程指标。

关键枚举使用字符串常量兼容 Java 8 和现有代码风格：

```text
decisionType: TOOL_CALL | PLAN_PATCH | FINISH | ABORT
decisionStatus: PROPOSED | REJECTED | EXECUTING | COMPLETED | FAILED
observationStatus: SUCCESS | NO_PROGRESS | RETRYABLE_ERROR | TERMINAL_ERROR
agentStatus: READY | DECIDING | EXECUTING | REPLANNING | VERIFYING | COMPLETED | FAILED
```

### 2.2 DAO：追加式轨迹与可恢复状态

新增 `ResearchAgentRepository`，数据库表由 `DatabaseInitializer` 幂等创建。

```sql
CREATE TABLE IF NOT EXISTS research_agent_state (
  research_run_id INTEGER PRIMARY KEY,
  status TEXT NOT NULL,
  state_version INTEGER NOT NULL DEFAULT 0,
  current_subgoal TEXT,
  plan_summary TEXT,

  evidence_summary TEXT,

  fallback_count INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  FOREIGN KEY(research_run_id) REFERENCES research_run(id) ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS research_agent_decision (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  research_run_id INTEGER NOT NULL,

  validation_error TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE(research_run_id, iteration),
  FOREIGN KEY(research_run_id) REFERENCES research_run(id) ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS research_tool_observation (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  research_run_id INTEGER NOT NULL,
  decision_id INTEGER NOT NULL UNIQUE,
  tool_code TEXT NOT NULL,
  status TEXT NOT NULL,
  observation_summary TEXT NOT NULL,
  new_information TEXT,
  evidence_delta INTEGER NOT NULL DEFAULT 0,
  source_delta INTEGER NOT NULL DEFAULT 0,
  data_refs TEXT,
  error_type TEXT,
  retryable INTEGER NOT NULL DEFAULT 0,
  state_hash TEXT NOT NULL,
  created_at TEXT NOT NULL,
  FOREIGN KEY(research_run_id) REFERENCES research_run(id) ON DELETE CASCADE,
  FOREIGN KEY(decision_id) REFERENCES research_agent_decision(id) ON DELETE CASCADE

```

轨迹表只追加，不覆盖历史。State 使用 `state_version` 乐观锁更新；失败时重新读取后再决定是否恢复，防止异步重复执行器覆盖状态。

### 2.3 Service：Agent Core

新增 `com.finscope.service.research.agent`：

- `ResearchAgentContextBuilder`：构建有界模型上下文；
- `ResearchDecisionAgent`：调用 `LlmChatClient`，严格解析并降级；
- `ResearchDecisionValidator`：校验决策类型、参数、工具权限和完成条件前置约束；
- `ResearchAgentTool`：可执行工具接口；
- `ResearchAgentToolRegistry`：工具描述与执行器映射；
- `ResearchToolDispatcher`：统一执行、超时分类和 Observation 生成；
- `ResearchAgentStateReducer`：基于 Observation 更新工作记忆；
- `ResearchAgentLoopService`：单步循环和终止控制；
- `ResearchFinishVerifier`：独立完成门；
- `ResearchTrajectoryEvaluator`：轨迹指标。

`ResearchService` 保留外层流程，只把当前硬编码的 `public_news_search` 遍历替换为 `ResearchAgentLoopService.run(...)`。

## 3. 决策协议

模型只允许返回单个 JSON 对象：

```json
{
  "decisionType": "TOOL_CALL",
  "currentSubgoal": "补充与命题相反的独立来源",
  "toolCode": "public_news_search",
  "arguments": {
    "query": "光模块 需求下调 风险 2026",
    "intent": "COUNTER"
  },
  "targetGap": "缺少反方证据",
  "expectedObservation": "至少一个独立来源的反方事实",
  "decisionSummary": "现有证据集中支持命题，优先搜索反方材料以降低确认偏误",
  "confidence": 0.78
}
```

约束：

- `decisionSummary` 是可审计结论，不要求模型输出详细推理过程；
- `arguments` 先反序列化为通用 Map，再由工具专属 Validator 转为强类型参数；
- JSON 最长 16,000 字符；摘要、目标和查询均有长度上限；
- `TOOL_CALL` 必须包含工具；其他决策不得携带无关工具参数；
- 模型不接收数据库结构、API Key、类名或内部文件路径。

## 4. 上下文工程与记忆

`ResearchAgentContextBuilder` 按以下顺序构建输入：

1. 不可变研究合同：问题、对象、成功条件、最大预算；
2. 当前状态：活动子目标、计划版本、剩余预算；
3. 最新 Evidence Gap：数量、独立来源、正反分布、告警；
4. 最近 4 条 Decision/Observation 对；
5. 更早轨迹的 `memorySummary`；
6. 已尝试动作指纹和最近错误；
7. 可用工具精简 Schema；
8. Finish Verifier 最近一次拒绝原因。

工作记忆不存整篇文章正文。Observation 的 `dataRefs` 保存文章/证据 ID，必要时由工具按需读取。单次用户 Prompt 目标上限 24,000 字符，超限时先压缩早期轨迹，再截断非关键摘要。

V1 的记忆分层：

- Working Memory：持久化在 `research_agent_state`；
- Episodic Memory：当前命题最近一次运行的成功/失败动作摘要，在新运行首轮注入；
- Semantic Memory：通过已有 research report、evidence 和 Vault 数据引用，不复制数据；
- Procedural Memory：工具描述、完成策略和确定性 fallback 规则，保留在代码中。

## 5. 可执行工具与安全边界

```java
public interface ResearchAgentTool {
    ResearchToolDescriptor descriptor();
    ToolArgumentValidation validate(Map<String, Object> arguments);
    ResearchToolObservation execute(ResearchAgentToolContext context,
                                    Map<String, Object> arguments);
}
```

### 5.1 public_news_search

参数：

```text
query: 2..240 字符的自然语言查询
intent: SUPPORT | COUNTER | PRIMARY | UPDATE
```

执行链路复用 `ResearchSearchSourceFactory -> FetchService`。执行前后比较 run-scoped evidence 和 distinct source 数量，Observation 返回增量及 FetchRun 摘要。查询被规范化后生成动作指纹，重复动作由 Runtime 拒绝。

### 5.2 evidence_assess

无外部副作用，调用 `ResearchMissionService.assess`，将 Evidence Gap 转为 Observation。它允许 Agent 主动确认一次搜索是否改变了完成条件，也为确定性 fallback 提供稳定的状态刷新动作。

### 5.3 外层能力

`source_scan` 和 `report_synthesis` 仍注册在 Mission Tool Registry 用于计划展示，但不暴露给内层 Dispatcher。Agent 不能跳过基线扫描或直接生成报告。

## 6. Agent Loop

```java
while (runtime.canContinue() && !finishAccepted) {
    context = contextBuilder.build(runId);
    decision = decisionAgent.decide(context);
    validator.validate(decision, context);
    repository.appendDecision(decision);

    switch (decision.type) {
        case TOOL_CALL:
            observation = dispatcher.execute(decision);
            repository.appendObservation(observation);
            reducer.reduce(state, decision, observation);
            break;
        case PLAN_PATCH:
            missionService.applyPatch(validatedPatch);
            reducer.recordReplan(state, decision);
            break;
        case FINISH:
            verdict = finishVerifier.verify(runId);
            reducer.recordFinishVerdict(state, verdict);
            finishAccepted = verdict.accepted;
            break;
        case ABORT:
            runtime.terminate(decision.summary);
    }
}
```

每轮最多产生一个外部动作。决策生成本身记录为 Runtime 事件但不消耗外部动作预算；成功进入 Dispatcher 的工具调用消耗动作预算。`PLAN_PATCH` 有独立上限，默认最多 3 次。

## 7. 局部重规划

`PLAN_PATCH` 结构：

```json
{
  "operation": "ADD_OR_REPLACE_PENDING_TASK",
  "taskKey": "adaptive_counter_2",
  "title": "寻找需求下修的一手材料",
  "question": "是否存在订单、指引或资本开支下修？",
  "toolCode": "public_news_search",
  "intent": "COUNTER",
  "queryText": "研究对象 指引 下调 订单 风险",
  "reason": "原查询没有新增独立来源"
}
```

约束：

- 只能增加或替换 `PENDING/FAILED/INTERRUPTED` 任务；
- taskKey 使用 `adaptive_` 前缀并校验唯一性；
- 不允许删除已完成任务、Gap、Decision 或 Observation；
- 每次成功 Patch 将 `plan_version + 1`；
- 相同查询指纹不得通过换 taskKey 绕过重复动作检测；
- 连续两个 Patch 仍无进展时，确定性策略优先请求 Finish Verification 或终止。

## 8. Finish Verifier

独立检查：

1. Evidence Gate 是否满足最低证据、独立来源和正反方向；
2. 是否仍有运行中的工具动作；
3. Runtime 是否已触发硬终止；
4. 是否存在无法解释的状态不一致；
5. 是否已有可用于报告生成的有效证据。

拒绝时生成结构化 `FinishVerdict`，其中 `reasonCode` 和 `missingConditions` 进入下一轮 Context。接受后才由外层调用 `ResearchReportService.generate`。

## 9. 确定性降级策略

模型禁用、超时或输出拒绝时按以下优先级选择：

1. 最新 Gap 缺反方：生成未尝试的 `COUNTER` 查询；
2. 缺支持：生成未尝试的 `SUPPORT` 查询；
3. 独立来源不足：生成 `PRIMARY` 查询；
4. 状态在工具执行后尚未评估：调用 `evidence_assess`；
5. Evidence Gate 满足：请求 `FINISH`；
6. 无安全的新动作或预算不足：`ABORT`。

降级动作同样写入 Decision，`decision_mode=DETERMINISTIC`，并增加 `fallback_count`。

## 10. 防循环与错误分类

- 动作指纹：`toolCode + normalized arguments + target gap`；
- 已执行指纹拒绝再次执行；
- `evidence_delta=0 && source_delta=0` 计为无进展；
- 连续两次无进展要求下一决策不能使用相同工具和意图；
- 连续三次无进展触发 Finish Verification；
- Schema 错误不可重试，网络超时可在不同查询下重试；
- Runtime 的 maxActions、maxRepeatedActions 和 maxStagnantIterations 继续作为硬上限。

## 11. Web API 与前端

`ResearchRunDetailResponse` 增加可空字段：

```text
agentCore:
  state
  decisions[]
  observations[]
  trajectoryMetrics
```

新增前端 `ResearchAgentDecisionFlow.tsx`，放在 `ResearchMissionMap` 之后。组件按 decision id 关联 Observation，不在前端推断状态。

视觉结构：

- 状态条：当前子目标、轮次、计划版本、剩余动作；
- 记忆卡：紧凑工作记忆和 Evidence Gap；
- 决策时间线：Decision -> Observation 成对展示；
- Replan 卡：突出计划变更原因和版本；
- 错误态：拒绝、降级、无进展和终止原因。

遵守 `prefers-reduced-motion`，运行态仅使用低频 opacity/transform 反馈，不使用无限高频闪烁。

## 12. 轨迹评测

`ResearchTrajectoryEvaluator` 从持久化轨迹计算：

```text
decision_validity_rate
observation_followup_rate
duplicate_action_rate
no_progress_rate
replan_success_rate
finish_first_pass_rate
fallback_rate
```

评测为纯函数，不调用 LLM。结果作为现有 `ResearchEvaluation` 的新增 metrics 保存，保持 evaluator version 可追溯。

## 13. 兼容与迁移

- 新表使用 `CREATE TABLE IF NOT EXISTS`，不修改用户现有业务数据；
- 旧运行没有 Agent State 时，详情 API 返回 `agentCore=null`；
- 无命题的探索运行继续使用原有固定流程；
- 有命题的新运行进入 Agent Loop；
- 旧 Mission 任务和 Runtime 事件继续保留并展示；
- SQLite 仍位于项目 `data/finance.db`，不引入第二数据库。

## 14. 测试策略

1. Domain/DAO：状态乐观锁、追加轨迹、唯一轮次、级联删除；
2. Decision Agent：合法 JSON、未知字段、非法工具、模型超时和确定性降级；
3. Tool Dispatcher：参数校验、成功、无进展、可重试和终止错误；
4. Agent Loop：Observation 进入第二轮 Context、动态工具选择、Finish 拒绝、局部 Replan；
5. 恢复：完成动作不重复，State 与 Runtime Checkpoint 对齐；
6. Web：旧运行兼容、聚合轨迹正确；
7. Frontend：状态条、Decision/Observation 配对、Replan 和降级展示；
8. 回归：`mvn test`、`npm test`、`npm run build`。
