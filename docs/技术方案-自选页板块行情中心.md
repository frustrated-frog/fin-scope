# 技术方案：自选页板块行情中心

## 1. 文档信息

- 项目：FinScope
- 对应 PRD：`docs/产品需求-自选页板块行情中心.md`
- 日期：2026-07-14
- 状态：待评审
- 运行时：Java 8 + Spring Boot 2.7 + SQLite + React/TypeScript

## 2. 现有基础与问题

### 2.1 可复用能力

当前代码已经具备：

- `instrument(code,type)` 唯一约束；
- `watchlist_item(instrument_id)` 唯一约束；
- `WatchlistService` 对股票、基金、板块的关注关系与行情组装；
- `EastmoneySectorQuoteAdapter` 对已知 `BKxxxx` 板块的单标的行情查询；
- `QuoteService` 的 30 秒缓存、批量路由和失败兜底；
- 板块归因计划、归因运行和历史报告读取；
- 市场指数与自选行情并行刷新、保留上一次有效行情的前端逻辑；
- 当前分支已有统一财经 HTTP 客户端、请求节流、重试和熔断能力。

### 2.2 当前缺口

现有 `QuoteAdapter` 解决的是“已知代码后查询行情”，不能承担：

- 获取全市场行业/概念目录；
- 对同一快照排序得到领涨、领跌；
- 按名称搜索任意板块；
- 公开市场目录与个人关注关系的语义隔离。

此外，`WatchlistView.tsx` 已同时承担行情加载、刷新协调、分组、添加、归因和渲染。继续直接堆入板块功能会放大组件复杂度，需要做与本需求直接相关的组件边界拆分。

## 3. 核心技术决策

1. **公共目录与个人关注分离**：全市场板块目录只驻留在短期内存缓存；用户关注继续复用 `watchlist_item`。
2. **不新增关注表**：数据库已有唯一约束能保证同一 `Instrument` 只有一条关注关系，现有板块记录可无迁移接管。
3. **API 按产品语义拆分**：普通 `/api/watchlist` 只服务股票和基金；板块排行、搜索和关注使用 `/api/sector-market/*`。
4. **目录快照驱动排行和搜索**：Provider 一次取得一个分类的完整可用目录，服务端在同一快照上排序和搜索，避免逐板块 N+1 请求与时间不一致。
5. **已关注行情继续走 QuoteService**：公共目录快照用于发现；关注卡片使用现有 `EastmoneySectorQuoteAdapter`，保持现有行情与归因合同。
6. **显式数据质量**：排行榜响应使用 `FRESH / STALE / UNAVAILABLE`，过期缓存不伪装成实时数据。
7. **缓存采用 single-flight**：同一分类并发刷新合并为一次上游请求，避免首屏、切换和手动刷新造成请求风暴。
8. **外部访问复用治理设施**：板块 Provider 复用 `FinanceHttpClient` 的超时、响应大小限制、节流、可重试错误和熔断；本期不复制 `HttpURLConnection` 模板。
9. **失败隔离到资源级**：市场指数、行业排行、概念排行、关注板块和股票/基金自选分别保留状态；一块失败不清空其他块。
10. **关注接口幂等**：关注使用 `PUT`，取消使用 `DELETE`；重复操作得到目标状态，不依赖前端防重。
11. **针对性拆分前端**：将市场指数、板块中心、普通自选拆成组件和数据 Hook，`WatchlistView` 只负责编排和归因阅读器切换。

```text

       -> GET /api/sector-market/follows

       -> SectorSearch

  -> InvestmentWatchlistPanel

SectorMarketController
  -> SectorMarketService
       -> SectorMarketProvider
            -> FinanceHttpClient

  -> WatchlistService sector-specific entry points
       -> InstrumentRepository
       -> WatchlistRepository
       -> QuoteService -> EastmoneySectorQuoteAdapter
       -> AttributionRepository
```

模块职责：

- `finscope-domain`：板块分类、目录项、快照和质量状态；
- `finscope-rpc`：第三方板块目录请求与字段解析；
- `finscope-service`：快照缓存、排序、搜索、关注语义和行情组装；
- `finscope-dao`：按标的类型查询关注关系、类型安全删除；
- `finscope-web`：参数校验、DTO 转换和 HTTP 语义；
- `frontend`：独立资源状态、关注交互和响应式渲染。

## 5. 领域模型

### 5.1 板块分类

```java
public enum SectorCategory {
    INDUSTRY,
    CONCEPT
}
```

分类只描述第三方市场目录口径，不写入 `Instrument.type`。所有关注板块仍使用 `type=SECTOR`。

### 5.2 目录项

```java
public class SectorMarketEntry {
    private String code;               // BKxxxx
    private String name;
    private SectorCategory category;
    private Double price;
    private Double changeAmount;
    private Double changePct;
    private Double turnover;
    private String leaderStockCode;
    private String leaderStockName;
    private Double leaderStockChangePct;
    private LocalDateTime quoteTime;
}
```

不使用 `Quote` 承载目录排行，因为领涨股和分类属于板块目录语义，不是通用单标的行情字段。

### 5.3 目录快照

```java
public class SectorMarketSnapshot {
    private SectorCategory category;
    private String providerCode;
    private LocalDateTime retrievedAt;
    private String payloadFingerprint;
    private List<SectorMarketEntry> entries;
    private List<String> warnings;
}
```

快照不可变使用：Provider 解析完成后一次性发布；缓存中的集合不得由 Controller 或前端装配逻辑修改。

### 5.4 数据质量

```java
public enum SectorMarketQualityStatus {
    FRESH,
    STALE,
    UNAVAILABLE
}
```

- `FRESH`：来自 30 秒有效期内的成功快照；
- `STALE`：实时刷新失败，使用不超过 15 分钟的最后成功快照；
- `UNAVAILABLE`：没有可接受的历史快照。

## 6. Provider 设计

### 6.1 接口

```java
public interface SectorMarketProvider {
    String providerCode();
    boolean supports(SectorCategory category);
    SectorMarketSnapshot fetch(SectorCategory category);
}
```

第一期实现 `EastmoneySectorMarketProvider`。外部 URL、查询参数、字段编号和 JSON 结构只存在于 Provider 内部，不泄漏到 service/web/frontend。

### 6.2 解析规则

1. Provider 获取目标分类的完整目录页；上游分页时由 Provider 在受控页数内合并。
2. 必填字段为板块代码、名称；代码必须匹配 `BK\d{4}`。
3. 涨跌幅无效的条目可保留在搜索目录，但不得进入领涨/领跌榜。
4. 缺失领涨股不影响板块进入榜单，对应字段保持空值。
5. 百分比、点位、成交额按数据源缩放规则规范化，禁止使用字符串拼接结果进入领域层。
6. 重复代码按最后一个完整度更高的条目去重，并产生 warning。
7. 空响应、协议字段变化、响应过大和非 2xx 状态区分错误类型。
8. 保存响应 SHA-256 指纹用于日志和问题定位，不在普通接口返回原始负载。

### 6.3 外部访问治理

复用当前分支的 `FinanceHttpClient` 与 `ProviderRequestGuard`：

- 连接超时 5 秒、读取超时 10 秒；
- 响应最大 2 MiB；
- 同 Provider 最小请求间隔；
- 仅对连接错误、429、502、503、504 等可恢复错误重试；
- 连续失败触发短期熔断；
- 非重试协议错误立即失败。

`FinanceHttpClient` 当前位于 `rpc.marketintel` 包。本期允许跨功能复用其接口，不为包名整洁做无关的大规模移动；后续有第三个消费者时再独立重构为 `rpc.finance` 基础设施。

## 7. 排行、搜索与缓存

### 7.1 排行规则

`SectorMarketService` 基于同一 `SectorMarketSnapshot`：

- 过滤 `changePct == null` 的条目；
- 领涨榜按 `changePct DESC, turnover DESC, code ASC`；
- 领跌榜按 `changePct ASC, turnover DESC, code ASC`；
- 同一板块可以在零涨跌极端情况下只进入一侧，服务层用代码集合保证两侧不重复；
- API 的 `limit` 限制为 1–10，页面固定请求 5。

确定性次级排序保证同一快照重复查询结果稳定，便于测试与前端差量渲染。

### 7.2 搜索规则

- 查询文本去除首尾空格；代码转大写；
- 支持名称包含匹配和代码前缀匹配；
- 精确代码、名称前缀、名称包含依次排序；
- 相同匹配级别按绝对涨跌幅、成交额和代码排序；
- `category=ALL` 时并行取得行业和概念目录后合并去重；
- 查询为空返回 400，`limit` 限制为 1–20。

### 7.3 缓存

每个 `SectorCategory` 维护：

```text
lastSuccessfulSnapshot
freshUntil = retrievedAt + 30s
staleUntil = retrievedAt + 15min
inFlightRefresh
```

读取流程：

1. 非强制刷新且快照仍新鲜，直接返回；
2. 需要刷新时，以分类为 key 创建或复用 `CompletableFuture`；
3. 成功后原子替换快照并清除 in-flight；
4. 失败且旧快照仍在 stale 窗口，返回 `STALE` 和错误摘要；
5. 失败且没有可用快照，返回 `UNAVAILABLE`，不伪造空榜单；
6. `refresh=true` 跳过 fresh 判断，但仍复用同一 in-flight，防止并发击穿。

缓存只保存成功解析的不可变快照；失败结果不覆盖最后成功快照。

## 8. REST API

### 8.1 全市场排行

```http
GET /api/sector-market/overview?category=INDUSTRY&limit=5&refresh=false
```

响应：

```json
{
  "category": "INDUSTRY",
  "qualityStatus": "FRESH",
  "retrievedAt": "2026-07-14T10:23:18",
  "warning": null,
  "leaders": [
    {
      "code": "BK1036",
      "name": "半导体",
      "price": 1532.18,
      "changePct": 4.21,
      "turnover": 81230000000,
      "leaderStockCode": "688xxx",
      "leaderStockName": "示例名称",
      "leaderStockChangePct": 12.36
    }
  ],
  "laggards": []
}
```

参数非法返回 400。上游失败属于可展示的数据质量状态，返回 200 + `STALE/UNAVAILABLE`，避免把可预期的数据源故障变成整个页面异常。

### 8.2 搜索

```http
GET /api/sector-market/search?q=半导体&category=ALL&limit=10
```

响应包含 `qualityStatus`、`retrievedAt`、`warning` 和 `items`。每个 item 使用与排行一致的字段，并增加 `category`。

### 8.3 查询关注板块

```http
GET /api/sector-market/follows?refresh=false
```

返回专用 `FollowedSectorResponse[]`：

```json
[
  {
    "code": "BK1036",
    "name": "半导体",
    "price": 1532.18,
    "changeAmount": 61.25,
    "changePct": 4.21,
    "turnover": 81230000000,
    "quoteValid": true,
    "quoteNote": null,
    "quoteDate": "2026-07-14",
    "attributionSummary": "……",
    "attributionReportId": 88,
    "attributionReportDate": "2026-07-14"
  }
]
```

不复用 `WatchlistItemResponse`，避免把基金净值、分组等无关字段变成板块接口合同。

### 8.4 关注与取消

```http
PUT /api/sector-market/follows/BK1036
DELETE /api/sector-market/follows/BK1036
```

- `PUT` 校验代码格式，按需创建 `Instrument(type=SECTOR)`，幂等返回关注资源；
- `DELETE` 只删除 `type=SECTOR` 的关注关系；不存在时仍返回 204；
- 两个接口都不能误删同代码其他类型的 `Instrument` 或关注关系；
- 数据库唯一约束是最终防线，服务层同时处理并发唯一键冲突并回读目标状态。

### 8.5 普通自选合同调整

```http
GET /api/watchlist
POST /api/watchlist
```

- GET 只返回 `STOCK/FUND`；
- POST 只接受 `STOCK/FUND`；
- `SECTOR` 请求返回 400 和“请使用板块关注接口”；
- DELETE/PATCH 在普通自选上下文校验目标不是 `SECTOR`，防止跨区域误操作。

## 9. 持久化与服务边界

### 9.1 数据库

本期不新增表、不修改列：

```text
instrument UNIQUE(code, type)
watchlist_item UNIQUE(instrument_id)
```

既有 `SECTOR` 记录原样保留。`group_name` 和 `sort_order` 继续保留，但板块区域第一期不展示分组；排序沿用 `sort_order ASC, id DESC`。

### 9.2 Repository

`WatchlistRepository` 增加显式类型查询和类型安全操作：

```java
List<WatchlistItem> findByTypes(Collection<String> types);
Optional<WatchlistItem> findByCodeAndType(String code, String type);
boolean existsByCodeAndType(String code, String type);
int deleteByCodeAndType(String code, String type);
```

SQL 参数化；类型列表只由服务层固定枚举构造，不直接拼接用户输入。

### 9.3 WatchlistService

对外暴露语义明确的方法，而不是让 Controller 传任意字符串类型：

```java
listInvestmentItemsWithQuotes(boolean refresh); // STOCK + FUND
addInvestment(String code, String type, String groupName);
removeInvestment(long id);
updateInvestmentGroup(long id, String groupName);

listFollowedSectorsWithQuotes(boolean refresh); // SECTOR
followSector(String code);
unfollowSector(String code);
```

内部可复用创建 Instrument、批量行情和归因摘要组装，但每个公开方法必须执行类型边界校验。现有把未知类型默认成 `STOCK` 的行为改为明确 400，避免错误输入被静默改写。

### 9.4 事务边界

- 外部行情请求不放在数据库事务中；
- 关注命令先尝试解析名称，再用短事务创建/读取 Instrument 和关注关系；
- 取消关注只删除关注关系；
- 唯一键竞争转成幂等成功，不向前端暴露 SQLite 约束异常；
- 归因报告与关注关系生命周期独立。

## 10. 前端设计

### 10.1 文件边界

```text
frontend/src/features/watchlist/
  WatchlistView.tsx
  useWatchlistDashboardData.ts
  MarketIndexOverview.tsx
  SectorMarketPanel.tsx
  SectorRankingBoard.tsx
  SectorSearch.tsx
  FollowedSectorGrid.tsx
  InvestmentWatchlistPanel.tsx
  watchlistFormatters.ts
```

不要求一次性拆尽所有历史逻辑，但新板块功能不得继续全部写入 `WatchlistView.tsx`。格式化、涨跌样式和行情保留策略提取为可测试的纯函数。

### 10.2 类型

新增：

```typescript
type SectorCategory = 'INDUSTRY' | 'CONCEPT';
type SectorMarketQualityStatus = 'FRESH' | 'STALE' | 'UNAVAILABLE';
type SectorMarketEntry = { /* 与接口字段对应 */ };
type SectorOverview = { category; qualityStatus; retrievedAt; warning?; leaders; laggards };
type FollowedSector = { /* 专用关注板块字段 */ };
```

`WatchlistItem` 可继续保留 `SECTOR` 联合类型供归因组件使用，但 `/api/watchlist` 的页面合同只产生 `STOCK/FUND`。

### 10.3 状态管理

`useWatchlistDashboardData` 为每种资源保留独立状态：

```typescript
type ResourceState<T> = {
  data: T;
  phase: 'idle' | 'loading' | 'ready' | 'refreshing' | 'error';
  error?: string;
  warning?: string;
  updatedAt?: string;
};
```

- 首屏使用 `Promise.allSettled`，逐资源提交结果；
- 行业、概念快照在前端分别缓存，切换时优先展示已有数据；
- 刷新使用递增序号丢弃过期响应，延续当前竞态保护；
- 无效新行情不覆盖同代码的上一次有效关注行情；
- 刷新完成提示汇总成功、降级和失败资源数量。

### 10.4 关注交互

- 榜单和搜索结果的关注按钮使用 `aria-pressed`；
- 点击后对该代码设置 pending，防止重复操作；
- `PUT` 成功后以服务端返回结果写入关注列表，并同步所有榜单/搜索按钮状态；
- `DELETE` 成功后按代码移除；
- 请求失败时回滚视觉状态并显示 Toast；
- 关注集合以 `Set<string>` 派生，不在多个组件维护重复布尔状态。

### 10.5 搜索

- 250ms debounce；
- 输入为空时关闭结果层；
- 每次请求附加序号或 AbortController，旧请求不能覆盖新关键词；
- 上下方向键移动结果，Enter 关注，Escape 关闭；
- “无结果”“加载失败”“数据源不可用”使用不同状态。

### 10.6 可访问性与响应式

- 行业/概念、领涨/领跌使用真实 button 和 `aria-selected`；
- 榜单使用有序列表语义，涨跌不只依赖颜色，保留正负号；
- 关注按钮有完整可访问名称，例如“关注半导体板块”；
- 断点下不依赖固定宽度，长板块名和领涨股名称省略但保留 title；
- 键盘焦点样式沿用全局设计令牌。

## 11. 失败处理与可观测性

### 11.1 错误分类

- `INVALID_REQUEST`：分类、limit、代码或搜索词非法；
- `PROVIDER_UNAVAILABLE`：连接、超时或熔断；
- `PROVIDER_CONTRACT_CHANGED`：响应结构不满足最低字段；
- `PARTIAL_PARSE`：部分条目被丢弃；
- `STALE_SNAPSHOT`：实时刷新失败但仍有可用旧快照；
- `FOLLOW_CONFLICT`：唯一约束竞争，转换为幂等成功；
- `TYPE_BOUNDARY_VIOLATION`：普通自选和板块关注跨域操作。

### 11.2 日志

每次目录刷新记录：

- provider、category、refresh 原因；
- 耗时、响应指纹、原始条数、有效条数、丢弃条数；
- 缓存命中、single-flight 复用、stale 回退；
- 错误类型，不记录完整第三方响应。

关注与取消记录代码、结果和目标状态，不记录与功能无关的用户数据。

### 11.3 指标预留

当前项目未统一接入 Metrics 时先使用结构化日志；组件接口保留未来增加以下指标的空间：缓存命中率、刷新成功率、Provider 延迟、解析丢弃率、关注命令成功率。

## 12. 兼容与迁移

1. 无数据库结构迁移。
2. 现有 `SECTOR` 关注记录自动由新接口查询和展示。
3. 下方 `/api/watchlist` 返回数量会减少，这是产品语义变更，不是数据删除。
4. 旧前端若继续发送 `POST /api/watchlist type=SECTOR` 会收到明确 400；新前端改用幂等关注接口。
5. 归因接口、报告表和报告阅读器不变。
6. 市场指数接口与缓存不变，仅加入统一刷新编排。

## 13. 测试策略

### 13.1 RPC 层

- 行业/概念正常响应解析；
- 数值缩放、空字段和无效代码；
- 重复代码与部分损坏条目；
- 空响应、协议变化、HTTP 错误、响应过大；
- 固定 JSON fixture，不在单元测试访问真实网络。

### 13.2 Service 层

- 确定性领涨/领跌排序和两侧去重；
- 名称、代码搜索优先级；
- 30 秒 fresh、15 分钟 stale 和过期不可用；
- force refresh、single-flight 和失败不覆盖成功快照；
- 关注幂等、并发唯一键竞争；
- 普通自选只返回股票/基金；
- 板块关注只返回板块；
- 类型安全删除、取消关注保留 Instrument 与归因报告。

时间相关测试注入 `Clock`，禁止依赖真实等待。

### 13.3 DAO 与 Web 层

- `findByTypes` 和按 code/type 删除；
- 既有板块数据无需迁移即可被关注接口读取；
- API 参数校验、质量状态、专用 DTO；
- `PUT/DELETE` 幂等；
- 普通自选拒绝 `SECTOR`；
- 控制器不直接访问 Provider。

### 13.4 前端

- 行业/概念与领涨/领跌渲染；
- 排行榜关注状态与关注列表同步；
- 搜索防抖、竞态、无结果与错误区分；
- 关注/取消失败回滚；
- 已有板块只在我的关注出现，不在下方重复；
- 添加类型不再出现板块；
- 四类资源失败隔离和刷新状态；
- stale/unavailable 提示；
- 板块归因和报告回看继续工作；
- 响应式关键断点手动检查。

### 13.5 回归门禁

- 后端相关模块测试全部通过；
- 前端 `vitest`、类型检查和构建通过；
- 不降低现有市场指数、自选可靠性和归因测试覆盖；
- 实现完成后使用固定 fixture 做一轮接口集成测试，再进行一次真实数据源手工冒烟验证。

## 14. 安全与性能

- 搜索词、分类、limit 和 BK 代码全部服务端校验；
- 第三方 URL 由 Provider 固定构造，用户输入不能成为任意 URL，避免 SSRF；
- 所有 SQL 参数化；
- 目录缓存和 single-flight 避免每个浏览器请求直击第三方；
- 搜索在缓存目录内执行，不为每个关键词调用第三方接口；
- 完整目录设置条数与响应大小上限，防止异常响应耗尽内存；
- 前端只渲染限制数量的搜索结果和榜单，不将完整目录下发浏览器。

## 15. 实施边界

本期允许的针对性重构：

- 拆分 `WatchlistView` 的数据 Hook 和三个页面区域；
- 为 `WatchlistRepository/Service` 增加类型明确的入口；
- 复用统一财经 HTTP 客户端和请求保护设施；
- 提取行情格式化与保留旧值的纯函数。

本期不做：

- 全局状态管理框架迁移；
- 整仓库 HTTP 基础设施改包；
- 板块数据持久化历史库；
- 与 Market Intel、量化策略或事件系统的大范围整合。

这些边界保证本需求具有清晰的领域模型、可靠性和测试深度，同时避免为了“技术含量”引入无业务价值的复杂度。
