# 财报研报联动分析技术方案

## 1. 总体架构

能力归属 `financials` 限界上下文，新增外部券商研报子域。保留现有内部 `research_report` 不变，避免将系统生成报告与外部版权材料混为一谈。

```text
公开来源自动同步 / PDF 补充上传
  -> 来源适配、目录去重与公开 PDF 下载
  -> 文件校验与 SHA-256 去重
  -> PDF 文本/页码提取
  -> 研报元数据与原文入库
  -> 详细结构化解析（LLM / deterministic fallback）
  -> 预测和观点标准化
  -> 与选定财报的指标、科目匹配
  -> 验证状态与差异计算
  -> REST API
  -> 研报分析 Tab
```

## 2. 数据模型

### 2.1 `broker_research_report`

保存外部研报身份、文件信息、完整提取文本及结构化解读 JSON：

- `instrument_id`：公司标的。
- `linked_report_id`：上传时选中的财报，可为空。
- `title`、`institution`、`analyst`、`published_date`、`report_type`。
- `rating`、`target_price`、`target_price_currency`。
- `source_type`、`source_url`、`original_file_name`、`relative_path`、`file_hash`。
- `page_count`、`parse_status`、`analysis_status`、`quality_level`。
- `extracted_text`：供学习和重新解析使用的原始文本。
- `analysis_json`：详细解读快照。
- `error_message`、`created_at`、`updated_at`。

### 2.2 `broker_research_forecast`

结构化保存预测数据，支持后续跨研报聚合：

- `research_report_id`、`metric_code`、`metric_label`。
- `forecast_period`、`forecast_value`、`unit`。
- `source_quote`、`source_page`。

实际值、偏差和验证状态在查询时根据当前财报计算，避免财报更新后保存过期结果。

### 2.3 `broker_research_claim`

保存核心观点与可追溯证据：

- `research_report_id`、`category`、`title`、`detail`。
- `claim_type`：`OPINION`、`FORECAST`、`RISK`。
- `source_quote`、`source_page`。
- `financial_metric_code`、`financial_concept_code`。

## 3. 领域对象与 API

领域对象使用 `BrokerResearchReport`、`BrokerResearchForecast`、`BrokerResearchClaim` 和聚合响应 `BrokerResearchReportView`。

REST API：

- `GET /api/financials/instruments/{instrumentId}/research-reports`
- `POST /api/financials/instruments/{instrumentId}/research-reports/sync`
- `GET /api/financials/instruments/{instrumentId}/research-reports/candidates`
- `POST /api/financials/instruments/{instrumentId}/research-reports/import`
- `GET /api/financials/research-reports/{id}?financialReportId={reportId}`
- `POST /api/financials/research-reports/upload`（multipart）
- `POST /api/financials/research-reports/{id}/reanalyze`
- `GET /api/financials/research-reports/{id}/content`

自动同步按标的六位代码查询最近 365 天公开目录，最多返回 20 篇，并自动导入最新 5 篇尚未入库的 PDF。上传参数包括 `instrumentId`、可选 `financialReportId`、可选元数据和 `file`。第一期使用同步解析以保持接口简单；同一标的并发同步复用进行中的任务，LLM 调用设置独立超时，失败时自动回退。

### 3.1 来源适配器

`BrokerResearchSource` 只暴露目录查询和 PDF 下载，业务服务不依赖来源字段。第一期实现 `EastmoneyBrokerResearchSource`，访问无需登录的东方财富个股研报目录与公开 PDF；固定超时、响应大小上限、User-Agent、Referer 和 HTTPS 主机白名单。后续增加来源只需新增适配器。

## 4. PDF 解析与详细解读

使用 Apache PDFBox 3.0.7 提取页面文本，替换现有仅适用于简单 PDF 指令的正则方案。单份 PDF 最多 500 页，落库文本最多 2,000,000 字符；超过文本上限时标记 `PARSED_TRUNCATED`。Agent 输入最多使用 60,000 字符；超长研报保留前 45,000 与末尾 15,000 字符，以兼顾核心观点、正文和尾部风险章节。

Agent 必须返回单个 JSON：

- `executiveSummary`
- `investmentThesis`
- `businessAnalysis`
- `industryAnalysis`
- `keyAssumptions`
- `catalysts`
- `risks`
- `learningNotes`
- `glossary`
- `forecasts`
- `claims`
- `limitations`
- `disclaimer`

七个实质分析章节中的每一项必须同时包含 `text`、`sourceQuote` 和可选 `sourcePage`。输出门禁检查字段类型、文本长度、预测指标白名单，并反查每段引用是否真实存在于 PDF 提取文本；无法定位的结论、预测和观点拒绝入库。页码超出 PDF 范围时移除页码并记录限制。输出失败时生成确定性基础解读：保留可识别元数据、章节文本、风险段落和限制说明，不生成虚构数字。

## 5. 财报联动算法

支持以下标准映射：

| 研报指标 | 财报映射 |
|---|---|
| `REVENUE` | 利润表营业总收入/营业收入 concept code |
| `NET_PROFIT_PARENT` | 归母净利润 concept code |
| `EPS` | EPS financial metric 或对应科目 |
| `GROSS_MARGIN` | 毛利率 financial metric |

查询详情时由 `BrokerResearchFinancialLinker` 获取选定财报的标准值：

- 预测期晚于财报期：`PENDING`。
- 无映射值：`INSUFFICIENT_EVIDENCE`。
- 可比较值：计算 `(actual - forecast) / abs(forecast)`。
- 百分比指标使用百分点差异。
- 默认误差阈值为 10%；阈值只用于研究标记，不代表投资判断。

观点验证只在 claim 声明了指标或科目映射时执行。其他定性观点标记为 `INSUFFICIENT_EVIDENCE`，防止无证据推断。

## 6. 前端设计

新增 `ResearchReportAnalysisPanel`，由 `FinancialsView` 传入当前 `instrumentId` 和 `financialReportId`。面板自行管理列表、选中详情、上传状态和错误状态，避免继续扩大主页面的数据请求职责。

页面采用“研报导航 + 详细阅读”结构：

- 顶部：自动同步状态、公开候选列表、研报选择器、补充上传与元数据。
- 第一屏：核心结论、评级、目标价和质量标记。
- 中部：投资逻辑、业务、行业、假设、催化和风险。
- 对照区：预测值、实际值、偏差、验证状态和财报报告期。
- 观点验证区：研报原文摘录与财报事实并列。
- 底部：学习提示、术语、限制和可折叠完整原文。

## 7. 安全、性能与演进

- Spring multipart 与业务层均限制文件最大 30MB，请求最大 32MB；校验 PDF 魔数、文件结构，净化文件名，存储路径必须位于 data root。
- 远程下载只允许配置的 HTTPS 主机，校验最终重定向地址、Content-Type、PDF 魔数和 30MB 响应上限。
- SHA-256 唯一索引实现去重，同一进程内使用哈希粒度锁消除重复上传竞态；跨公司复用同一文件时拒绝并提示核对股票。
- PDF 解析设置页数与文本上限，扫描件、损坏文件和超限文件返回明确状态或参数错误。
- 不记录 API key，不在日志输出研报全文。
- 数据库迁移 `303` 创建研报表，`304` 增加来源 URL 唯一索引；启动可重复执行。
- 列表接口不返回全文和 analysis JSON；详情接口按需返回。
- 后续可将同步解析替换成异步任务，而不改变详情对象和前端呈现协议。
- 自动来源只处理无需登录、无需付费且无需绕过访问控制的公开材料。
