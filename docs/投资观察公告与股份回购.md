# 投资观察：公司公告与股份回购

## 数据流程

投资观察的后台同步和“立即同步”增加独立的公司公告入口：

`东方财富公告列表 → 分页采集 → 回购公告 PDF 原文 → news_report → 回购阶段识别 → 公司身份核验 → 观察样本`

- 定时同步沿用投资观察原有的五分钟调度；页面查询不触发外部抓取或模型。
- 每轮回看最近七天，按每页 100 条遍历全市场 A 股公告，单轮最多 200 页、60 秒。已经落库且原文完整的公告不重复下载，不改写阅读状态。
- 单个 PDF 失败时仍保存标题、链接和时间，下一轮重试原文；部分失败、超时或分页未完成会保留已有结果，并在同步状态中报告未完成。
- 原文使用现有统一采集和 PDF 文本提取，不依赖 Sidecar 或 LLM。扫描件可能只有公告元数据，不能据此自动推断事项关联。
- 公告日期与来源上架时间分别保留。公开时间采用来源 `display_time`，不把未来落款日期当成未来发布；没有可解析公开时间的记录不会创建自动观察。
- 公告以“文章”进入新闻库；资讯窗口仍展示最近 36 小时，投资观察可以补录七天内公告。历史补录保留真实公开时间和捕获时间。

## 回购分类与事项关联

新增 `REPURCHASE`，细分为预案、融资支持、股东披露、实施进展、结束和终止。标题必须直接描述公司自身的回购行为；排除国债逆回购、债券、限制性股票回购注销和另一家公司行为。

不同阶段各自保留原文、公开时间和行情基线。只有原文明示同一家公司同一天召开的董事会审议通过回购方案，才用“公司代码 + 董事会审议日期”建立共同事项；不按公司和年份猜测合并。审批日期缺失或矛盾时不关联。原文迟到时可补齐关联，不重写已有观察快照或行情。

详情默认展开“同一回购事项的进展”，按时间列出其他阶段；重复的实施进展也能列出。同一回购事项的其他进展不作为独立历史案例加入收益对照。
