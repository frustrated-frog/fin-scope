# 新闻 AI 统一理解与成本控制

## 使用方式

新闻整理使用独立的 `gpt-6-luna` Responses 客户端。全局 DeepSeek、Agent 问答、研究报告和人工点选的长文解读保持原配置。

`backend/finscope-web/src/main/resources/application.yml` 中唯一的新闻 AI 总开关为：

```yaml
finscope:
  news-ai:
    enabled: true
```

设为 `false` 后重启后端，不再发出新闻 AI 请求。抓取、原文持久化、本地分类、聚类、评分、筛选、分页和浏览继续运行。已保存的 AI 结果仍可复用，不会因为停用模型重新花钱或拆散已有事件。

Key 保存在 `~/.config/finscope/llm.local.properties`，配置项为 `finscope.news-ai.provider.api-key`。仓库只保留空值，不能填写其他供应商的 Key。缺少 Key 时等同未激活，不会调用 OpenAI，也不会触碰全局 LLM 的密钥。

2026-11-17 已完成真实 Luna 小样本验收：从现有新闻库选择六条历史报道，包含两组跨来源重复、另一项技术合作和一条业绩消息。v2 协议单次调用接受六条结果，得到四个事件；重复处理没有新增调用。样本运行使用独立临时数据库，生产新闻库只读；这六条不能代表整体准确率。

## 从逐篇重复调用改为增量事件编辑

```text
新闻抓取 → 原文与版本落库 → 本地规则立即可用
                           ↓ 独立后台队列
          内容身份去重 → 已理解内容复用 → 本地候选召回
                           ↓
                  Luna 批量统一理解与归属
                           ↓
            保存事实卡、事件版本、报道关系与调用用量
                           ↓
               新闻列表 / 雷达生产只读取持久化结果
```

每批最多六份新内容，一次输出业务分类、展示分类、事件类型、主题、主体、关键事实、短标题、摘要和事件关系。请求内使用 n/e 短编号，原始内容身份和候选版本留在服务端；输出 Schema 固定为内容编号、内容理解、关系判断的顺序，避免在理解原文前先生成关系结论。不会在分类、合并、摘要之间再次读取同一篇全文。正文最多1,600字符，保留开头及后续数字、否定和进展句；截断标识也发送给模型，信息不足时要求保守分开。

内容键保留数字、小数点、正负号、标点和否定词，仅规范 Unicode 与连续空白，避免把“1.2亿/12亿”“+5%/-5%”误当成相同内容。相同标题及原文跨来源共用理解。内容理解可跨日复用；事件归属包含发生日期，避免每天同一句行情描述被永久归为同一事件。

候选用本地字符二元组倒排索引召回，不以证券代码、公司词典或分类相等作为门槛。每份内容最多六个候选；没有词面交集时仍补充近期候选。候选只发送有界事实卡，不携带整篇旧报道。词面召回可能漏掉完全不同表达的同事件，这一版不宣称可以消除所有重复。

同批较早输入可直接成为后续输入的候选，不需要先付费调用一次。模型返回的目标必须在本条候选白名单内，不能生成任意事件 ID。后台处理最多八批后让出队列，不占页面请求线程。

## 关系与输出

| 关系 | 保存行为 | 是否更新实质进展 |
| --- | --- | --- |
| NEW_EVENT | 新事件 | 是 |
| DUPLICATE | 转载改写，关联已有事件 | 否；新增事实必须为空 |
| SAME_EVENT | 同事实的独立报道，关联已有事件 | 只有明确新增事实时才更新 |
| PROGRESS | 同事件的新阶段或新事实 | 是；必须给出新增事实 |
| RELATED | 关联主题，单独事件 | 单独保存 |
| CONFLICT | 事实冲突，单独事件 | 单独保存 |

模型输出逐项校验，编号必须来自本次请求的枚举，并进一步校验目标是否属于该条自己的候选；未知分类、未知目标、多次返回同一内容键、超长字段和矛盾关系均不落库。尾部截断时已完整输出的项目照常保存，仅缺失或无效项目进入有限重试。

同一事件的新进展以语义版本 CAS 保存。若模型读取的候选已被其他任务更新，保留本次内容理解，只重做归属，不重新发送原文。旧原文版本的结果不能覆盖修订后的报道或人工分类。

新闻列表默认合并同事件报道，并显示“合并 n 条报道”。“更多筛选”可以取消合并，所有原文仍存在；详情中的关联报道可查看同事件的其他来源。筛选和到达序号快照先于聚合，分页总数按事件计算。阅读状态仍按原文版本记录，不将其他未读报道自动设为已读。

雷达使用同一份事件归属和展示分类。已明确分开的 AI 事件不会再被本地相似规则合并；模型选择原有本地事件时保留原有身份及尚未理解的报道。转载不增加独立确认，也不刷新实质进展时间。热度、公共价值与个人排序继续由本地评分体系计算，避免让模型随意打出不可比较的分数。

## 启用范围与停用

`backfill-existing: false` 为默认值。第一次配置好 Key 后，从后台观察到激活的时间开始处理新到达或原文有变化的新闻，旧闻继续使用本地结果，不会突然全量补跑。关闭并被后台观察到后再次启用，会重新建立增量起点。

如果明确需要处理当前已有的36小时窗口，可临时设置 `backfill-existing: true`，完成后改回 `false`。默认不设置每日金额或调用次数配额，单批大小、并发和重试次数仍有边界。模型、规则或分类目录变化不会自动触发全部已成功归属内容重新计费。

没有 AI 结果的报道始终走完整本地路径；AI 缓存无法读取时继续保存原文和本地生产。后台成功后通过视图版本提示更新，阅读中的列表不会被强行刷新。

## 费用、失败与排查

| 配置 | 当前值 | 含义 |
| --- | --- | --- |
| daily-budget-micros | 未配置 | 默认不设每日金额上限；只有显式配置时才执行限额 |
| daily-max-calls | 未配置 | 默认不设每日调用次数上限 |
| batch-size | 6 | 每次请求的最大内容数 |
| max-attempts | 2 | 无效输出/归属冲突最多领取两次 |
| input-dollars-per-million | 0.10 | 本地配置的输入计价基线，$/百万tokens |
| output-dollars-per-million | 0.50 | 本地配置的输出计价基线，$/百万tokens |

用量按北京时间自然日汇总，只包含新闻 AI。按用户要求，默认不设置每日金额与调用次数硬上限。每次发送前，仍按完整请求 UTF-8 字节数加协议余量和最大输出预算记录保守估算；不把中文字符数直接当 tokens，也不依赖供应商缓存折扣。收到 usage 后，按实际输入/输出 tokens结算，释放未使用预留。更换模型或供应商价格变化时须同步修改计价配置，最终账单仍以供应商为准。

进程重启不会清空内容缓存或调用账本。租约、owner、调用 ID、候选版本与费用预留都在 SQLite 中保存。网络错误、超时、请求发出后的崩溃无法确认处理结果时，标为 UNKNOWN，保留完整预留且不自动重发。HTTP错误也采用这一保守策略，未决预留用于记录可能发生的费用，不能误认为已实际消费；默认不会因此阻断当天其他新闻。只有显式配置每日金额限额时，未决预留才会占用该限额。

默认不会因当天累计金额或调用数暂停新闻整理。如以后显式配置可选每日限额，达到限额时才暂停至次日；配置值为0表示暂停发送，未配置表示不限制。结构化输出错误冷却一小时，归属版本冲突冷却五分钟，均受最多两次领取限制。客户端没有 SDK 隐藏重试。

只读状态接口 `GET /api/news/ai/status` 提供：总开关、Key是否配置、模型、当天请求数、输入输出tokens、已知费用、未决预留、剩余额度及内容任务状态计数。返回金额单位均为百万分之一美元；`dailyBudgetMicros`、`dailyMaxCalls` 和 `remainingMicros` 为 null 时表示未设置每日上限，不表示额度耗尽。不返回 Key 或供应商错误正文。

理解缓存保留30天；仍被现存报道引用的内容与事件保留。已结算调用明细保留90天，未决费用明细不自动删除。原始新闻继续遵循原来的七天缓冲与投资观察/大事记引用保留规则。

`finscope.news-workbench.automatic-model-enabled` 保持 `false`，旧的自动模型解读不与统一新闻整理并行启用。人工点选解读的费用属于全局模型，不计入此新闻预算。


## 2026-11-17 真实调用记录

初版真实调用出现两条未通过校验，以及 Snowflake 同事件被判为 RELATED 的漏合并；其中关系理由串用了另一条 TPU 新闻的内容。v2 因此引入请求内短编号、编号 Schema 枚举、先理解后判断的固定输出顺序，并明确重复报道也要返回完整的单条理解。

| 协议 | 完成本组处理的调用数 | 输入 / 输出 tokens | 按配置估算费用 | 聚合结果 |
| --- | --- | --- | --- | --- |
| v1（含两条重试） | 2 | 9,052 / 2,153 | $0.001982 | 5个事件，存在一组漏合并 |
| v2 | 1 | 5,244 / 1,359 | $0.001204 | 4个事件，符合本组预期 |

三次验收调用合计约 $0.003186，均收到了 usage，无未决预留。以上仅是这组六条历史样本的结果，不能直接推算全量新闻准确率或日均费用。后端仍由 IDEA 启动，配置文件在下一次启动时读取。


## 2026-11-17 当天新闻扩展抽查

从 IDEA 进程实际打开的新闻库只读抽取18条当日消息，在独立数据库中运行相同生产处理器。样本包含八组跨来源同事件，以及京东工业和京东物流两家公司的独立财报，共预期十个事件。该样本是人工挑选的检查集，不能用来宣称全量准确率。

结果：18条全部通过校验，八组同事件均合并，得到十个事件；未观察到跨预期事件的误合并。南京新百“人民币约9亿元”与“4.1亿新谢克尔”的不同币种表述归到同一交易，京东工业与京东物流财报分开。产品发布归科技，融资、股东回报、公司财报与企业合作归财经，宏观数据保留宏观业务分类。

共调用三次，输入25,597 / 输出4,488 tokens，按配置单价估算费用$0.004806；再次处理同批数据，调用次数与费用均未增加，未决预留为0。此记录只验证独立回放；验收时8080进程尚未提供新的AI状态接口，实际页面需在IDEA重启后端后加载新链路。
