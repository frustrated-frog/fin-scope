# 模型服务接入与配置说明

## 1. 配置约定

FinScope 通过 `OpenAiCompatibleLlmClient` 调用 OpenAI 兼容的 Chat Completions 接口。所有运行参数直接固定在 `backend/finscope-web/src/main/resources/application.yml`，不使用环境变量占位符。

API Key 只允许保存在该配置文件的既有位置。本文档不记录、复制或展示任何凭据；复制仓库、截图、提交到公开远端前必须先轮换凭据。

客户端使用非流式请求，并将 `base-url` 规范化为最终的 `/chat/completions` 地址：

- `base-url` 已以 `/chat/completions` 结尾时直接使用；
- 否则自动追加 `/chat/completions`；
- 请求使用 `Authorization: Bearer <api-key>`；
- 请求体包含 `model`、`temperature`、`stream: false` 和 system/user messages；
- 调用方提供输出预算时，额外发送 `max_tokens`。

## 2. 当前默认配置：GPT-5.5

| 配置项 | 固定值 | 注意事项 |
| --- | --- | --- |
| `enabled` | `true` | 关闭后所有模型节点使用确定性降级路径。 |
| `base-url` | `http://llm-gw.jd.local/v1` | 仅公司内网可达；客户端会自动追加 `/chat/completions`。 |
| `api-key` | 仅配置文件保存 | 不得写入本文档、README、日志或测试输出。 |
| `model` | `GPT-5.5-joybuilder` | 网关模型标识；实际响应模型版本可能显示为具体日期版本。 |
| `timeout-ms` | `300000` | 作为全局上限；单次 Agent 可以申请更短的超时。 |
| `temperature` | `1` | GPT-5.5 只接受默认值 `1`；发送 `0.2` 会返回 `unsupported_value`。 |
| 网关 `max_tokens` | `256` | 当前由网关保留；过低的值可能只消耗推理预算而没有正文。 |

已验证以下能力：

- 流式请求返回 HTTP 200、正文分片与 `[DONE]`；
- 非流式请求返回 HTTP 200，项目客户端能读取 `choices[0].message.content`；
- system message、`temperature: 1` 和 `max_tokens: 256` 可以组合使用；
- `temperature: 0.2` 会被上游拒绝，不能用于该模型。

## 3. 历史配置：GLM-5

切换 GPT-5.5 前，项目使用以下非敏感配置：

| 配置项 | 历史值 | 注意事项 |
| --- | --- | --- |
| `enabled` | `true` | 与当前配置相同。 |
| `base-url` | `https://modelservice.jdcloud.com/v1` | HTTPS 模型服务地址。 |
| `model` | `GLM-5` | 历史默认模型名。 |
| `timeout-ms` | `300000` | 长报告生成需要较长读取超时。 |
| `temperature` | `0.2` | GLM-5 可使用该采样温度。 |
| `response_format` | 默认关闭 | 该模型使用 `json_object` 时可能提前终止并返回残缺 JSON，因此由上层从纯文本提取 JSON。 |

历史 API Key 未复制到本文档。若要切回 GLM-5，需要从受控位置恢复对应凭据，不能从 Git 历史、日志或聊天记录复制未知状态的旧凭据。

## 4. 接入其他 OpenAI 兼容模型

1. 使用最小请求验证网关、鉴权、模型标识和消息格式。
2. 分别验证非流式与流式响应；FinScope 当前实际消费非流式响应。
3. 单独测试 `temperature`。部分推理模型只接受默认值，不能沿用其他模型的温度。
4. 使用至少 256 的输出预算测试短回答，再使用真实 Agent 的预算测试结构化 JSON。
5. 将 `base-url`、`api-key`、`model`、`timeout-ms` 和 `temperature` 写入 `application.yml`。
6. 重启后端，检查 Agent Runs 中的模型名、状态、耗时和降级原因。
7. 运行 `OpenAiCompatibleLlmClientTest`，并至少执行一次真实文章解读或研究 Agent 调用。

## 5. 常见故障

| 现象 | 排查方向 |
| --- | --- |
| HTTP 400 且提示 `temperature` 不支持 | 删除网关注入的温度，或把项目温度改为模型支持的默认值。 |
| HTTP 200 但正文为空 | 检查 `finish_reason`、推理 token 消耗和 `max_tokens` 是否过低。 |
| 文档示例成功但项目失败 | 对比 system message、`temperature`、`max_tokens` 和 `response_format`。 |
| 请求地址出现重复路径 | `base-url` 推荐写到 `/v1`；客户端负责追加 `/chat/completions`。 |
| 模型失败但文章仍入库 | 这是预期降级行为；从 Agent Runs 查看模型错误和 fallback 记录。 |

## 6. 修改检查清单

- `application.yml` 中不存在 `${...}` 环境变量占位符；
- 文档、测试输出和 Git diff 不展示 API Key；
- 模型温度符合上游限制；
- 网关输出预算足够返回正文；
- LLM 客户端单测通过；
- 真实非流式请求返回非空正文；
- 修改配置后重启后端。
