# 模型服务接入与配置说明

## 1. 配置约定

FinScope 通过 `OpenAiCompatibleLlmClient` 调用 OpenAI 兼容的 Chat Completions 接口。所有运行参数直接固定在 `backend/finscope-web/src/main/resources/application.yml`，不使用环境变量占位符。

API Key 只允许保存在该配置文件的既有位置。本文档不记录、复制或展示任何凭据；复制仓库、截图、提交到公开远端前必须先轮换凭据。

客户端使用非流式请求，并将 `base-url` 规范化为最终的 `/chat/completions` 地址：

- `base-url` 已以 `/chat/completions` 结尾时直接使用；
- 否则自动追加 `/chat/completions`；
- 请求使用 `Authorization: Bearer <api-key>`；
- 请求体包含 `model`、`temperature`、`stream: false` 和 system/user messages；
- 调用方提供输出预算时，额外发送 `max_tokens`。
- 对 HTTP 408、429、全部 5xx 以及连接类瞬时错误，在调用方总超时预算内自动重试一次；429/5xx 会优先遵循 `Retry-After`，没有该响应头时使用短暂退避；
- 兼容字符串、文本分片数组和旧式 `choices[].text` 正文形态；空正文、仅推理正文和残缺 JSON 会触发一次扩展输出预算重试。
- 供应商错误正文不会写入异常、Agent 轨迹或 UI，只保留 HTTP 状态码和脱敏后的 request ID。

研究规划与逐轮决策采用“服务端受控编排 + 模型辅助”协议：

- 服务端生成任务图、依赖、方法选择、工具和参数合同；模型不能新增或替换这些字段；
- 规划模型只增强研究范围、成功条件和已有任务的检索表述；
- 决策模型只从服务端给出的可执行任务键中选择一个，工具参数由服务端重建；
- 只有“请求成功但结构化输出无效”时才进行一次修复请求；网络或供应商失败不会被误判为格式错误后重复调用；
- 模型辅助仍不可用时继续执行已经验证的受控计划，不记为“规则降级”，但会以“模型辅助状态”保留脱敏原因，便于排查供应商兼容性。

因此，切换 GLM、DeepSeek 或其他 OpenAI 兼容模型时，供应商对数组、对象、空字符串或多余字段的表达差异不会进入研究任务和工具 DTO 的反序列化链路。

## 2. 当前默认配置：DeepSeek V4 Flash

| 配置项 | 固定值 | 注意事项 |
| --- | --- | --- |
| `enabled` | `true` | 关闭后所有模型节点使用确定性降级路径。 |
| `base-url` | `https://api.deepseek.com` | DeepSeek OpenAI 兼容 HTTPS 服务地址；客户端会自动追加 `/chat/completions`。 |
| `api-key` | 仅配置文件保存 | 不得写入本文档、README、日志或测试输出。 |
| `model` | `deepseek-v4-flash` | DeepSeek V4 Flash 的固定模型标识。 |
| `timeout-ms` | `300000` | 作为全局上限；单次 Agent 可以申请更短的超时。 |
| `temperature` | `0.2` | 当前默认采样温度。 |
| `response_format` | 默认关闭 | 使用 `json_object` 可能提前终止并返回残缺 JSON，因此由上层从纯文本提取 JSON。 |

当前接入约束：

- 项目客户端使用非流式 Chat Completions 请求；
- 上层 Agent 继续负责从纯文本中提取结构化 JSON；
- 2026-08-02 已切换至 DeepSeek V4 Flash（`deepseek-v4-flash`），使用 `https://api.deepseek.com` 的 OpenAI 兼容接口；凭据本身不进入文档和测试。
- 2026-08-01 已恢复 GLM-5 固定配置及其对应凭据，凭据本身不进入文档和测试。

## 3. 可选模型：GLM-5.2

`GLM-5.2-joybuilder` 使用 JoyBuilder 内网网关及其对应凭据，与当前 GLM-5 模型服务不是同一套接入配置。凭据只允许保存在 `application.yml`，文档示例使用占位符：

```bash
curl -X POST "http://llm-gw.jd.local/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <API_KEY>" \
  -d '{
    "model": "GLM-5.2-joybuilder",
    "messages": [
      {
        "role": "user",
        "content": "Hello!"
      }
    ],
    "stream": true
  }'
```

| 配置项 | 建议值 | 注意事项 |
| --- | --- | --- |
| `base-url` | `http://llm-gw.jd.local/v1` | 与 GPT-5.5 共用网关。 |
| `api-key` | 使用 JoyBuilder 网关凭据 | 不得复制到文档、日志或测试输出。 |
| `model` | `GLM-5.2-joybuilder` | 实际响应中的模型名为 `glm-5.2` 或 `GLM-5.2`。 |
| `timeout-ms` | `300000` | 推理过程可能较长，应保留当前全局超时。 |
| `temperature` | `0.2` | `0.2` 与 `1` 均已通过协议测试；切换时建议使用 `0.2`。 |
| `max_tokens` | 至少 `4096` | 网关默认 256 只适合最小对话，不足以稳定承载带 system message 的 Agent 请求。 |

2026-07-30 实测结果：

- 流式最小请求：HTTP 200，收到正文分片、`finish_reason=stop` 和 `[DONE]`；
- 非流式最小请求：HTTP 200，返回正文；
- 非流式 system/user 请求在 `max_tokens=256` 时无正文，`finish_reason=length`；
- 同一请求在 `max_tokens=1024` 时仍无正文，大部分预算被推理 token 消耗；
- 同一请求在 `max_tokens=4096` 时返回正文，`finish_reason=stop`；
- 因此目前只确认协议兼容，尚不建议在网关默认 256 预算下直接替换 FinScope 默认模型。

## 4. 可选回退模型：GPT-5.5

切回 GPT-5.5 时使用以下非敏感配置：

| 配置项 | 建议值 | 注意事项 |
| --- | --- | --- |
| `enabled` | `true` | 与当前配置相同。 |
| `base-url` | `http://llm-gw.jd.local/v1` | JoyBuilder 公司内网网关。 |
| `model` | `GPT-5.5-joybuilder` | 网关模型标识。 |
| `timeout-ms` | `300000` | 长报告生成需要较长读取超时。 |
| `temperature` | `1` | 该模型只接受默认值 `1`，发送 `0.2` 会返回 `unsupported_value`。 |
| 网关 `max_tokens` | `256` | 网关默认值只适合短回答，真实 Agent 请求需要核对输出预算。 |

GPT-5.5 的 API Key 未复制到本文档。若要切换，需要从受控位置恢复对应凭据，不能复用当前 GLM-5 凭据。

## 5. 接入其他 OpenAI 兼容模型

1. 使用最小请求验证网关、鉴权、模型标识和消息格式。
2. 分别验证非流式与流式响应；FinScope 当前实际消费非流式响应。
3. 单独测试 `temperature`。部分推理模型只接受默认值，不能沿用其他模型的温度。
4. 使用至少 256 的输出预算测试短回答，再使用真实 Agent 的预算测试结构化 JSON。
5. 将 `base-url`、`api-key`、`model`、`timeout-ms` 和 `temperature` 写入 `application.yml`。
6. 重启后端，检查 Agent Runs 中的模型名、状态、耗时，以及研究页中的“模型辅助/受控编排”状态。
7. 运行 `OpenAiCompatibleLlmClientTest`，并至少执行一次真实文章解读或研究 Agent 调用。

## 6. 多源公开搜索配置

研究智能体和归因智能体共同使用 `SearchEvidenceGateway`。搜索供应商配置同样固定在 `application.yml`，凭据不写入本文档：

- Tavily 是主搜索来源；QUICK 模式只调用 Tavily。
- DEEP 模式和归因研究同时调用 Tavily 与 AnySearch，任一供应商失败时保留另一方结果。
- AnySearch 第一阶段固定使用 `general.general`，不启用需要额外参数的 `finance.*` 标签。
- AnySearch 官方接口允许不带 Bearer 的匿名请求，因此默认可以用空 `api-key` 运行；从控制台申请 Key 后直接填写既有配置项即可提升可管理性。
- 融合层按规范 URL 去重，使用 Provider 内排名做倒数排名融合，并限制单域名结果数；AnySearch 没有相关性分数时不会被过滤。
- `rrf-constant` 默认 60，`max-per-domain` 默认 2，`concurrency` 默认 2。修改并发数时应同时考虑研究分支数和外部调用预算。

搜索 HTTP 错误只记录 Provider、状态分类和耗时，不记录 Authorization、API Key 或供应商完整错误响应。

## 7. 常见故障

| 现象 | 排查方向 |
| --- | --- |
| HTTP 400 且提示 `temperature` 不支持 | 删除网关注入的温度，或把项目温度改为模型支持的默认值。 |
| HTTP 200 但正文为空 | 客户端会先扩展输出预算重试；若仍为空，再检查 `finish_reason`、推理 token 消耗和上游输出限制。 |
| 研究决策字段类型随模型变化 | 研究控制面只消费 `missionTaskKey`，工具、参数、缺口和计划补丁不再由模型反序列化。 |
| 文档示例成功但项目失败 | 对比 system message、`temperature`、`max_tokens` 和 `response_format`。 |
| 请求地址出现重复路径 | `base-url` 推荐写到 `/v1`；客户端负责追加 `/chat/completions`。 |
| 模型失败但文章仍入库 | 这是预期降级行为；从 Agent Runs 查看模型错误和 fallback 记录。 |
| QUICK 搜索提示无可用 Provider | QUICK 只使用 Tavily，检查 `finscope.search.enabled` 和既有 Tavily Key。 |
| DEEP 只有 Tavily 结果 | 检查 `finscope.search.any-search.enabled`、AnySearch 配额和运行轨迹中的 Provider 诊断。 |

## 8. 修改检查清单

- `application.yml` 中不存在 `${...}` 环境变量占位符；
- 文档、测试输出和 Git diff 不展示 API Key；
- 模型温度符合上游限制；
- 网关输出预算足够返回正文；
- LLM 客户端单测通过；
- 真实非流式请求返回非空正文；
- 修改配置后重启后端。
