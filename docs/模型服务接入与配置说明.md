# 模型服务接入与配置说明

## 1. 配置约定

FinScope 的全局模型通过 `OpenAiCompatibleLlmClient` 调用 OpenAI 兼容的 Chat Completions 接口。新闻自动整理另用独立的 `NewsAiLunaClient` 调用 Responses 接口，详见[新闻 AI 统一理解与成本控制](新闻AI统一理解与成本控制.md)。所有运行参数直接固定在 `backend/finscope-web/src/main/resources/application.yml`，不使用环境变量占位符。

LLM API Key 只保存在用户主目录 `.config/finscope/llm.local.properties`，由 `spring.config.import` 加载；仓库 `application.yml` 中的 LLM `api-key` 保持为空。本文档不记录、复制或展示任何凭据。

客户端使用非流式请求，并将 `base-url` 规范化为最终的 `/chat/completions` 地址：

- `base-url` 已以 `/chat/completions` 结尾时直接使用；
- 否则自动追加 `/chat/completions`；
- 请求使用 `Authorization: Bearer <api-key>`；
- 请求体包含 `model`、`temperature`、`stream: false` 和 system/user messages；
- 调用方提供输出预算时，额外发送 `max_tokens`。
- 对 HTTP 408、429、全部 5xx 以及连接类瞬时错误，在调用方总超时预算内自动重试一次；429/5xx 会优先遵循 `Retry-After`，没有该响应头时使用短暂退避；
- 兼容字符串、文本分片数组和旧式 `choices[].text` 正文形态；空正文、仅推理正文和残缺 JSON 会触发一次扩展输出预算重试。
- 供应商错误正文不会写入异常、Agent 轨迹或 UI，只保留 HTTP 状态码和脱敏后的 request ID。

研究规划与逐轮决策采用“服务端受控编排 + 模型辅助”协议：

- 服务端生成任务图、依赖、方法选择、工具和参数合同；模型不能新增或替换这些字段；
- 规划模型只增强研究范围、成功条件和已有任务的检索表述；
- 决策模型只从服务端给出的可执行任务键中选择一个，工具参数由服务端重建；
- 只有“请求成功但结构化输出无效”时才进行一次修复请求；网络或供应商失败不会被误判为格式错误后重复调用；
- 模型辅助仍不可用时继续执行已经验证的受控计划，不记为“规则降级”，但会以“模型辅助状态”保留脱敏原因，便于排查供应商兼容性。

因此，切换 GLM、DeepSeek 或其他 OpenAI 兼容模型时，供应商对数组、对象、空字符串或多余字段的表达差异不会进入研究任务和工具 DTO 的反序列化链路。

深度研究报告另采用“Java 完整基线 + 命名文本槽位增强”协议：

- Java 先生成包含证据表、子问题、论证链、反方解释、三种情景、监测项和证据附录的完整报告结构；
- 模型仅返回 `<<<SLOT_NAME>>>...<<<END>>>` 命名文本段，不再负责巨大嵌套 JSON、数组长度、证据编号或 Markdown 章节；
- 长正文阶段使用 240 秒调用预算，给推理型模型保留稳定完成空间，同时仍受全局 300 秒上限约束；
- 已解析段落会被逐段保留，缺失段落只修复缺失槽位，不会因为尾部截断丢弃前面已经完成的正文；
- 模型返回 JSON、空正文、仅推理正文、错误字段类型或不完整输出时，服务端仍保留完整结构，并在模型恢复后继续增强可识别段落；
- 事实、数字、日期、URL 和证据引用由 Java 白名单控制，模型不能自行创建证据。

股票学习卡采用“固定一级维度 + 维度专属栏目 Schema”协议：

- 空间、盈利模式、竞争格局、治理结构、市场定价和反方验证六个一级维度由服务端固定；
- 每个维度拥有独立的必答栏目、可选栏目、评级名称、搜索模板和输出校验，不再共同返回“为什么、反方、未知”；
- 模型只能返回服务端白名单中的栏目代码与标题，必答栏目不可缺失，可选栏目只在证据足够时出现；
- 每个栏目分别返回证据编号和 `SUPPORTED`、`PARTIALLY_SUPPORTED`、`UNVERIFIED`、`CONTRADICTED` 验证状态，证据编号必须来自本次输入；
- 前五维相互隔离生成，反方验证在第二阶段读取前五维结论与自身风险证据，形成核心假设、反证和证伪条件；
- 任一维度输出不合法、资料不足或模型不可用时，只降级该维度，并生成包含全部核心栏目的保守结果。

## 3. 可选模型：GLM-5.2

`GLM-5.2-joybuilder` 使用 JoyBuilder 内网网关及其对应凭据，与当前 GLM-5 模型服务不是同一套接入配置。凭据只允许保存在仓库外的 `~/.config/finscope/llm.local.properties`，文档示例使用占位符：

```bash
curl -X POST "http://llm-gw.jd.local/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <API_KEY>" \
  -d '{
    "model": "GLM-5.2-joybuilder",
    "messages": [
      {
        "role": "user",
        "content": "Hello!"
      }
    ],
    "stream": true
  }'
```

| 配置项 | 建议值 | 注意事项 |
| --- | --- | --- |
| `base-url` | `http://llm-gw.jd.local/v1` | 与 GPT-5.5 共用网关。 |
| `api-key` | 使用 JoyBuilder 网关凭据 | 不得复制到文档、日志或测试输出。 |
| `model` | `GLM-5.2-joybuilder` | 实际响应中的模型名为 `glm-5.2` 或 `GLM-5.2`。 |
| `timeout-ms` | `300000` | 推理过程可能较长，应保留当前全局超时。 |
| `temperature` | `0.2` | `0.2` 与 `1` 均已通过协议测试；切换时建议使用 `0.2`。 |
| `max_tokens` | 至少 `4096` | 网关默认 256 只适合最小对话，不足以稳定承载带 system message 的 Agent 请求。 |

2026-07-30 实测结果：

- 流式最小请求：HTTP 200，收到正文分片、`finish_reason=stop` 和 `[DONE]`；
- 非流式最小请求：HTTP 200，返回正文；
- 非流式 system/user 请求在 `max_tokens=256` 时无正文，`finish_reason=length`；
- 同一请求在 `max_tokens=1024` 时仍无正文，大部分预算被推理 token 消耗；
- 同一请求在 `max_tokens=4096` 时返回正文，`finish_reason=stop`；
- 因此目前只确认协议兼容，尚不建议在网关默认 256 预算下直接替换 FinScope 默认模型。

## 5. 接入其他 OpenAI 兼容模型

1. 使用最小请求验证网关、鉴权、模型标识和消息格式。
2. 分别验证非流式与流式响应；FinScope 当前实际消费非流式响应。
3. 单独测试 `temperature`。部分推理模型只接受默认值，不能沿用其他模型的温度。
4. 使用至少 256 的输出预算测试短回答，再使用真实 Agent 的预算测试规划最小 JSON 和报告命名文本槽位。
5. 将 `base-url`、`api-key`、`model`、`timeout-ms` 和 `temperature` 写入 `application.yml`。
6. 重启后端，检查 Agent Runs 中的模型名、状态、耗时，以及研究页中的“模型辅助/受控编排”状态。
7. 运行 `OpenAiCompatibleLlmClientTest`，并显式执行一次 `ResearchReportModelSmokeTest`；该测试不启动应用、不连接数据库，只验证真实模型和报告协议。

真实报告协议烟测命令：

```bash
cd backend
mvn -pl finscope-web -am -Dsurefire.failIfNoSpecifiedTests=false \
  -Dfinscope.real-model-smoke=true -Dtest=ResearchReportModelSmokeTest test
```

烟测默认由 JUnit assumption 跳过，只有显式设置开关才调用模型。测试使用窄范围配置读取器，不经过会打印完整 YAML 的调试加载器，任何断言和诊断都不得包含凭据。

## 6. 多源公开搜索配置

研究智能体和归因智能体共同使用 `SearchEvidenceGateway`。搜索供应商配置同样固定在 `application.yml`，凭据不写入本文档：

- Tavily 是主搜索来源；QUICK 模式只调用 Tavily。
- DEEP 模式、归因研究与产业链图谱同时调用 Tavily、AnySearch 与 Firecrawl，任一供应商失败时保留其他来源结果。
- AnySearch 第一阶段固定使用 `general.general`，不启用需要额外参数的 `finance.*` 标签。
- AnySearch 官方接口允许不带 Bearer 的匿名请求，因此默认可以用空 `api-key` 运行；从控制台申请 Key 后直接填写既有配置项即可提升可管理性。
- Firecrawl 使用 Search v2 并请求 Markdown 正文，用于补充可直接归纳的网页资料；启用状态、Key、基础地址、超时和响应大小上限位于 `finscope.search.firecrawl`。
- 融合层按规范 URL 去重，使用 Provider 内排名做倒数排名融合，并限制单域名结果数；AnySearch 没有相关性分数时不会被过滤。
- `rrf-constant` 默认 60，`max-per-domain` 默认 2，三路搜索的 `concurrency` 默认 3。修改并发数时应同时考虑研究分支数和外部调用预算。

搜索 HTTP 错误只记录 Provider、状态分类和耗时，不记录 Authorization、API Key 或供应商完整错误响应。

## 7. 常见故障

| 现象 | 排查方向 |
| --- | --- |
| HTTP 400 且提示 `temperature` 不支持 | 删除网关注入的温度，或把项目温度改为模型支持的默认值。 |
| HTTP 200 但正文为空 | 客户端会先扩展输出预算重试；若仍为空，再检查 `finish_reason`、推理 token 消耗和上游输出限制。 |
| 研究决策字段类型随模型变化 | 研究控制面只消费 `missionTaskKey`，工具、参数、缺口和计划补丁不再由模型反序列化。 |
| 报告模型返回截断 JSON 或数组/对象类型漂移 | 报告链路不再消费模型生成的巨大 JSON；检查命名槽位覆盖率和脱敏诊断，已完成段落会被保留。 |
| 文档示例成功但项目失败 | 对比 system message、`temperature`、`max_tokens` 和 `response_format`。 |
| 请求地址出现重复路径 | `base-url` 推荐写到 `/v1`；客户端负责追加 `/chat/completions`。 |
| 模型失败但文章仍入库 | 这是预期降级行为；从 Agent Runs 查看模型错误和 fallback 记录。 |
| QUICK 搜索提示无可用 Provider | QUICK 只使用 Tavily，检查 `finscope.search.enabled` 和既有 Tavily Key。 |
| DEEP 只有 Tavily 结果 | 检查 `finscope.search.any-search.enabled`、`finscope.search.firecrawl.enabled`、各供应商配额和运行轨迹中的 Provider 诊断。 |

## 8. 修改检查清单

- `application.yml` 中不存在 `${...}` 环境变量占位符；
- 文档、测试输出和 Git diff 不展示 API Key；
- 模型温度符合上游限制；
- 网关输出预算足够返回正文；
- LLM 客户端单测通过；
- 真实非流式请求返回非空正文；
- 修改配置后重启后端。


## 资讯与雷达的手动解读

`application.yml` 中的 `finscope.news-workbench.model-enabled: true` 开放实时资讯和研究雷达的手动解读，两处共用新闻专用的 `finscope.news-ai.provider` 配置和仓库外的新闻密钥。

在报道原文或雷达事件详情点击「生成 AI 解读」才提交任务。报道按正文版本复用结果，雷达按事件证据版本复用结果。`finscope.news-workbench.automatic-model-enabled` 保持为 `false`，后台自动模型任务继续关闭。

新生成的解读通过 OpenAI Responses API 调用 `gpt-6-luna`，推理强度为 `none`。报道与雷达共用七个解读维度，包括白话首句、关键概念、事件变化、背后机制、为什么重要、影响传导和条件情景。重要性单独生成判断和理由；其余分析按需展开，简单通知可只保留首句。单次生成最多输出 3,200 个 token，雷达另校验引用的证据。每次生成只发送一次模型请求。概念和问答随结果缓存，在原有解读布局中直接显示。旧版解读可继续查看，手动生成新版后，后续点击复用同一版本。若遇到输出截断、空正文、超时或 HTTP 错误，事件详情会显示对应原因。可在该事件的 Agent 调用记录中查看模型返回的结束原因和 token 用量，缺失的计数保留为空。

## 后台自动调用开关

以下开关在 `application.yml` 中默认均为 `false`，与 `finscope.llm.enabled` 独立。保留模型 Key 不会自动启用这些后台调用；修改开关后需重启 Java 服务。

| 配置项 | 关闭时的行为 |
| --- | --- |
| `finscope.intake.scheduled-review-model-enabled` | 定时信息源采集仍抓取候选，逐条预审改用确定性规则；手动抓取的模型预审不受影响。 |
| `finscope.stock-supply-chain.automatic-model-enabled` | 打开股票产业链页签只读取快照；无快照时显示手动生成按钮，默认不提交生成任务。 |
| `finscope.news-workbench.automatic-model-enabled` | 关闭新闻分类、雷达配对、标题与证据增强、Kafka 预解读投递与消费中的模型任务。 |
| `finscope.industry-chain.recovery-model-enabled` | 启动后不自动恢复并执行遗留的产业链图谱生成任务；用户新建或手动刷新图谱仍可触发生成。 |
| `finscope.industry-chain.kafka.enabled` | 关闭产业链 Kafka 消费与发布，避免启动后消费旧消息；用户新建或手动刷新图谱时改由本地执行器生成。 |

这些开关控制后台自动发起的模型工作，不关闭由用户明确发起的研究、文章入库、财务解读等模型功能。重新开启产业链 Kafka 消费前，应注意旧消息可能在启动后被继续处理。


### 页面触发与接口兼容（2026-09-27）

股票产业链和雷达详情响应分别返回 `automaticModelEnabled`、`automaticInterpretationEnabled`。只有服务器明确返回 `true` 时前端才允许自动提交；字段缺失也按关闭处理。

这两个生成接口增加 `automatic` 参数，默认 `true`。旧页面不带参数的请求按自动请求处理，后端开关关闭时不会排队或调用模型。用户点击生成按钮时前端显式传 `automatic=false`。这是业务触发来源约定，不是身份认证机制。

雷达 Kafka 消费继续运行，自动开关关闭时跳过模型预解读。它不会关闭新闻数据采集。产业图谱的恢复扫描和 Kafka 消费仍按原有独立开关关闭。

## 股票自动整理调用预算修复（2026-11-15）

自选基本面页面的“自动整理经营”复用六维股票学习卡。此前该 Agent 硬编码每维 20 秒、1800 输出 token，覆盖了配置中的全局 300 秒上限。实际失败记录已经采集到公开资料，随后在生成阶段失败；使用先导基电失败资料重放，旧参数在约 20 秒发生 `SocketTimeoutException`。华天科技盈利维度在扩展预算后约 27 秒完成，说明固定 20 秒会中断有效请求。

当前运行参数在 `application.yml` 的 `finscope.stock-learning-card` 中维护，不改变全局模型或 API Key：

| 参数 | 默认值 | 契约 |
| --- | --- | --- |
| `synthesis-timeout-ms` | `120000` | 每维首次请求与格式修复共用的总预算；代码限制最大 120 秒，仍受全局客户端上限约束。 |
| `max-output-tokens` | `6000` | 留出结构化正文与推理预算；代码接受 1800–12000。 |

- 栏目正文要求简洁，输入区分完整正文与检索摘要，不将摘要当作已核对原文。
- 仅 JSON、栏目、引用等输出校验失败时，允许一次受控格式修复；网络超时和供应商失败继续交由 RPC 层处理，不额外作为格式问题重复请求。
- 格式修复必须使用原始证据，再次执行同样校验；未知证据、缺失栏目、交易语言仍拒绝，有支持或反向判断的栏目必须带有效引用。
- 每个失败维度保存可区分的超时、输出校验或处理失败原因。整次生成失败时，基本面页面读取该原因；已有可用认识和用户手工笔记继续保留。
- 修复不批量改写历史研究记录，也不自动触发所有自选的付费模型请求。重启后端后，用户重新整理时使用新参数。

回归覆盖六维生成、单维失败保留其他结果、格式修复预算、未知引用及无引用判断拦截、超时不触发格式重试、失败原因透传及旧认识保留。

修复后使用先导基电原失败运行已保存的公开资料进行真实模型重放：六个维度均通过生成与引用校验，单次约 14–32 秒，投影出 2 项带来源的经营认识；没有写入用户数据库。华天科技盈利、长鑫科技竞争维度的单独重放同样通过。已有资料仍不足的栏目保持未知，生成完成不代表所有经营问题都已有充分证据。相关学习卡、基本面、LLM 客户端和配置测试共 111 项通过。

澳弘电子后续暴露了“六维生成完成但经营投影为零”的资料相关性问题，补充了目标公司筛选、公司资料与财报基线及未知状态校验。实现与验收见《自选经营资料整理的标的校验.md》；不通过放松引用校验来增加展示条目。

## 盘中实验的 Codex 编程模式

在「实验室 → 新建实验」选择「Codex · Python 策略」，填写虚拟本金和股票池即可提交。研究方向可以留空。行情服务以当前系统用户运行本机已登录的 Codex CLI，沿用 Codex 登录凭据及其默认模型。Luna 继续负责因子规则模式和每日收益复盘。

- 运行行情服务的环境需要能找到 `codex` 和 `docker`。可用 `codex login status` 检查登录，运行 `docker pull python:3.12-slim` 准备策略镜像。Python 依赖由行情服务的锁文件安装。
- Codex 可以查询完整开发段的逐股覆盖，按日期翻阅五分钟行情，试跑策略或单独计算因子。每次编写最多试跑四次。每个任务最多正式评议三个候选，每份候选遇到执行错误最多修正两次。开发收益、等权基准、回撤、成交、费用和因子结果一起参与评议。Codex 可以要求修订、选定任一候选或结束研究。结束的任务仍可在「查看研究证据」中展开。
- 新策略用 Python 3.12 标准库实现 `factors(bars)` 和 `decide(ctx)`。前者返回一至四个命名因子的截面值，后者用最近 49 根已结束的五分钟行情、虚拟账户和上次决策的状态生成目标仓位。开发段按 5 分钟、30 分钟、1 日、3 日和 5 日对齐未来收益，计算 IC、Rank IC、日 Rank ICIR、正相关占比、近 20 日表现、因子间相关性和控制其他单个因子后的偏秩相关。股票池涨跌分组使用当时可见的过去一个交易日等权收益。五组收益按截面从低分到高分排列。缺失目标价格或跨越已知除权日的标的不参与该条收益配对。相关性至少需要三只股票，五组比较至少需要五只。不同周期的观测数和缺失值可在详情中核对。
- 每只股票最多保存最近 12,000 根行情。初次研究按交易日期切分，前约 80% 用于开发，最后一段从初始现金开始验证。选定源码和镜像会在验证前持久化。重试和复验沿用冻结输入。验证结果仅在选定候选后产生。固定当前股票池回看过去仍有选样偏差。
- 撮合先处理减仓，再以实际可用现金增仓。档案缺少真实成交量时仍可计算因子和估值，该根行情的订单记为未成交。新 Python 实验同时冻结公司行为数据，已核验分红计应收、送股计权益。当前数据源仅提供除权日，缺少到账日、上市日时不释放可交易资金或股份。股息按税前计，配股按不认购处理，未分类事件和来源缺失在逐股覆盖中显示。旧版快照沿用原有复验口径。
- 勾选自动衍生后，至少观察五个模拟交易日。符合任一条件即可唤醒评议：跨两个交易日累计成交三笔、有成交且最大回撤达到 5%、费用达到本金的 0.5%、有成交且与基准相差至少五个百分点、累计十笔未成交，或可比较的收盘因子样本中近五日平均 Rank IC 比正向开发基线下降至少 0.10。它们是当前实现的研究触发参数。Codex 可以选择继续观察，至少再积累五个观察日后才会重复评议。决定研究时，以触发复盘之后的新行情做留出验证。未收齐新行情时任务等待。手动对照仍沿用父版本快照。冻结并启动后，父子策略以相同本金和起点分别模拟。


### 行情档案、因子版本与次日收益

「实验室 → 研究行情档案」按股票列出完整交易日、真实股数覆盖和行情截至日期。后台同步自选股和最新股票发现池各自前 24 只，并维护已有实验使用的股票。行情服务保存原始分钟股数，分钟成交额缺失时保持空值。单只股票补数失败会进入自己的重试队列。价格或成交额口径冲突的分钟线保留已有行情，只有相同证券、相同时点且价格与金额相容的档案才补入股数。
