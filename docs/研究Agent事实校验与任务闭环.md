# 研究 Agent：任务契约、事实校验与质量反馈

本次增强保留长报告。原有正文目标仍为 8,000–16,000 字符、正文硬上限 24,000 字符；新增审计附录单独追加，不截短正文。相同引文的多个指标合并到一行，保留全部数字、单位和原文位置。

## 执行链路

1. 创建研究任务时冻结契约：原始问题、主体与别名、证券代码、事件、研究截止日、事件时间窗、必需事实和完成条件。恢复任务沿用同一契约；问题中的数字只作为待验证描述。
2. 每次采集后审计本次运行留存的正文。规则提取候选事实，记录主体、维度、原始数值/单位、事件日期、口径、连续原文和字符位置。
3. 生成报告时，配置了 LLM 才允许额外提出候选事实。数据库为每个运行最多预留一次提取尝试，超时 20 秒、输出最多 1,800 tokens，失败回到规则。候选不得自行确定主体、事件日期或统计口径，必须通过相同的服务端校验。
4. 校验拒绝跨主体/跨事件、时间窗不符、无法定位的引句、不匹配的数值单位、预测性表述及仅有搜索摘要的候选。网页发布时间不替代事件日期。正文清洗后仍无法在原文连续定位的片段不作为核验事实。
5. 来源按同站点、正文显式转载、相同或高度重合正文合并为可解释的来源组。来源相同不会因为域名不同而自动视为独立。
6. 同主体、同日期、同指标、同口径的数值统一万/亿/千单位后比较；不同交易日、单笔和当日总量、均价和单笔价格分开。冲突保留双方引用并要求回查原始披露。
7. 校验反馈进入真实工具 Observation 和工作记忆；针对缺口创建受动作预算和指纹去重约束的检索任务，优先执行。主体问题带名称/代码，日期问题带时间窗，正文/来源问题寻找原始披露，冲突要求核对更正公告。
8. Finish Verifier 同时检查原有方法完成条件及任务契约。事实未覆盖、来源不足或有数值冲突时不能主动完成。预算耗尽保留缺口，报告使用低置信度和显式限制；没有任何候选证据时阻止生成结论报告，质量审计仍保留。

报告正文的事实材料来自校验通过的引文，避免同一篇原始网页中的其他公司、旧日期和导航文字被重新拼进报告。缺口报告不使用模型把不充分的证据扩写成确定结论。

## 持久化与查询

启动时增量创建三个表：`research_task_contract`、`research_quality_assessment`、`research_fact_extraction_attempt`。契约和证据指纹具有唯一约束，重复评估复用快照，恢复运行不会重复消耗模型提取额度。现有原始文章和搜索证据保持不变。

`GET /api/research/runs/{id}/quality` 返回最近一次审计，包括契约、候选/核验事实、引用位置、逐来源拒绝原因、谱系分组、事实覆盖、数值冲突和后续检索建议。报告追加“任务契约与事实校验”章节，现有 Markdown 阅读器可直接阅读。

旧运行在下一次评估/重新生成时建立审计，升级不会批量重写历史报告。新代码需重启后端生效。

## 离线评测

评测版本升级为 `deep-research-rules-v5`，增加任务事实覆盖、原文引句可定位率、被拒候选数量、转载合并后的来源组、未解决冲突和反馈后的证据改善率。诊断指标不与原有百分制总分直接相加；任务契约未满足会阻断评测通过。

`ResearchQualityBenchmark` 使用有独立预期标签的冻结资料，不访问网络。测试资源 `task-quality-benchmark.json` 包含正常事实、错误公司、旧事件重新发布、缺失日期、导航、摘要、跨域转载、数值冲突、等价单位、拒绝后恢复和模型伪造数字共 11 个场景，分别核对错误事实接受率、引文支持率、任务覆盖、来源组、冲突和恢复结果。

## 当前能力边界

这是可执行的规则与模型候选协同校验，不是对现实真假的全面证明。主体别名、事件类型和事实维度有明确规则范围；复杂指代、多主体长句、未覆盖的别名或统计口径可能需要人工复核。隐蔽转载也不能只凭正文完全识别。测试集上的错误接受率不能代表所有开放问题的错误率。

没有可核实日期时保留日期缺口；没有足够信息区分统计口径时，不把数值一致当成交叉验证成功。保守拒绝的材料仍可在审计中追溯和用于后续检索。
