# 研究报告证据质量修复（2026-11-06）

## 修复边界

- 网页抽取不再因正文容器包含“责任编辑”等页尾文字而删除整个容器；忽略空链接。
- 全文分块前与摘要降级路径统一清理确定的导航、分享工具栏、空链接和 PDF 目录页码。清理保留数字、百分比及正文段落。
- 纯数字但不命中研究词的分块不再因数字多而成为证据。
- 已入库文章和搜索结果适用相同的公司相关性门禁；另一家公司文章中提及研究对象的关联事实可保留，但不再带入其余经营数据。
- 明确问“大宗交易、财资中心、股东减持、股份回购”的公司问题要求相应事件证据。确定性检索计划、规则决策和动态查询保留原研究问题，避免只搜公司名称和通用行业词。
- 事实摘录不在小数点处分句；结构化报告对完全重复的认识去重。清理发生在证据档案组装前，不再把原始导航追加回正文。
- 研究问题若采用“围绕‘完整事件标题’，哪些事实已经确认，后续应重点观察什么？”形式，可以精确复用运行开始前已归档的唯一大事记快照。相似标题、同公司其他新闻、重复归档或运行之后的归档均不会自动补入。引用保留事件实际发生日期，仅作为一个来源，不把归档快讯当作已获多源确认。

原始文章、搜索内容、快讯快照保持不变。报告可用原始材料重新生成；没有有效证据时拒绝生成结论。

## 旧报告离线修复

`ResearchReportRepairPreview` 是仅注册所需仓储和确定性生成器的维护入口，不启动 Spring Boot、调度、消息队列，不读取本地 LLM Key，也不调用搜索或模型。数据库以只读模式打开，默认预览仅输出受污染报告的修复计划；显式指定运行 ID 时可以重建指定报告。扫描采用主键游标、每批 100 条。

先以 JDK 21 构建维护入口并解析依赖（这里跳过测试仅用于本地构建；代码回归应另行执行）：

```bash
mvn -f backend/pom.xml -pl finscope-web -am install -DskipTests
mvn -f backend/finscope-web/pom.xml dependency:build-classpath -Dmdep.outputFile=target/repair-classpath.txt
```

默认只预览：

```bash
python scripts/repair-research-reports.py \
  --database /绝对路径/data/finance.db \
  --classpath-file backend/finscope-web/target/repair-classpath.txt
```

核对输出目录的 `preview.json` 后，同样命令加 `--apply` 才会回写。可用 `--run-id 46` 限制单次修复范围，也可重复指定多个运行 ID。

每次执行在数据库同级 `exports/research-report-repair-时间戳/` 保存预览和日志。实际回写前保存 `originals.json`，包含旧报告完整行、命题结论、运行认识和旧 Markdown 文件。报告一旦被并发修改或运行仍在执行，脚本会拒绝回写；写入失败会回滚数据库并恢复 Markdown 文件。

修复会同步报告、其 Markdown 投影、该运行的认识记录，以及当前最新运行所属命题的结论。不会修改旧运行的 Decision/Observation、搜索证据或文章，不会用旧报告覆盖同一命题的更新运行结论。修复报告明确标记为确定性生成及证据缺口；无可引用材料的旧报告标记 `INVALIDATED`，原结论失效，要求重新运行研究。

## 验证

```bash
python -m unittest discover -s scripts/tests -p 'test_repair_research_reports.py'
cd backend
mvn -pl finscope-web -am test -Dtest='Research*Test,Deterministic*Test,MajorEventRepositoryTest,WebContentTextTest,WebArticleExtractorTest,DefaultResearchSourceReaderTest' -Dsurefire.failIfNoSpecifiedTests=false
```

服务代码更新后需重启后端以使后续采集/生成使用新规则；离线修复后的旧报告直接从 SQLite 读取，原始证据仍可追溯。
