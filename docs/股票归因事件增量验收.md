# 股票归因：事件脉络与本次增量

本批只增加事件研究章节，不重排、删除或重写已有报告区域。当前分支：`codex/align-attribution-story-arrows`。

## 实现边界

- 新章节挂在 `AttributionReaderView` 原有 `attribution-report-layout` 之后，仍位于报告主内容列，历史侧栏不变。
- 使用独立的 `AttributionEventContextSection` 和限定在 `.attribution-event-context` 下的样式。旧报告无扩展字段时不产生任何额外 DOM。
- `assessment.eventContext` 为可选快照，通过既有 assessment JSON 保存，无数据库结构变更，不改变已有字段语义。
- 原报告生成后再做事件追溯。扩展流程独立容错，模型、搜索和正文读取失败均不能抹掉原摘要、故事线或原因卡片。

## 研究流程

1. 从原始材料及原报告主解释选择最多两个需要追溯的事件。原报告结论只用于提出核验对象，不作为事实来源。
2. 按业绩、订单、产品价格、治理、行业等框架组织专项问题，追溯原始披露和实质进展。最多四次定向搜索、四个不同网页全文读取、两次模型调用，无新增独立 Agent。
3. 整理事项关系、事实时间线、此前状态、本次市场信息增量、影响方向与机制、改变/未改变的判断和后续条件。
4. 历史查询不受三天窗口截断，但以目标日为信息截止。新近增量与研究新查到的旧事实必须区分；资料缺失不能等同此前未披露。
5. 时间线日期未知时留空，前端标注“日期待确认”；未来节点与不在材料中的引用不能进入事实时间线。机制推演仍保留并明确其性质。来源筛选不替代利好利空判断。

## 验收要求

- 同一份固定报告数据：新增前后原区域 DOM 不变，截图尺寸、顺序、宽度一致；仅新增末尾章节。
- 历史报告、无明确事件、部分数据、模型失败、搜索失败、非法链接、日期未知、未来消息、长文本和窄屏均有明确表现。
- 真实模型案例检查：是否取得原报告没有展开的条款/进展；是否区分真实市场新增信息与本次研究新增认识；是否把同公司不同事项误连成因果；是否给出有依据的方向判断。
- 公司业务尺度、行业同业对照和价格反应诊断不在本批，不以增加事件章节宣称已完成整个系统的专业化。

## 本批验证记录

自动化测试覆盖专项查询、历史保留、未来日期、来源匹配、无事件与失败容错；DAO 覆盖可选快照往返持久化，前端覆盖原区域 DOM 保持不变以及新章节各状态。

真实检查使用本地已生成的华脉科技、超声电子、杭电股份公开材料，并通过配置的模型及搜索接口追溯原始披露。运行输出与截图保留在本地 `/tmp/finscope-event-context/`，不提交用户数据库或配置密钥。具体结果以该目录实际输出为准，不把测试通过等同于研究内容质量合格。

### 实测结果与边界

- 华脉科技：定向补查取得股份转让比例、价格、锁定期及控制权条款；区分较早披露的转让与目标日前的工商登记进展，不将两者拼成控制权变更。
- 超声电子：保留英伟达认证与供货澄清的负面影响分析，并把较早澄清标作背景；杭电股份保留龙虎榜的多空解释和股东会议线索，不凭材料缺失断言不存在催化。
- 原报告区域 DOM 完全一致；固定报告截图尺寸均为 1064 × 11560，前后仅有少量边缘抗锯齿像素差异。新区域已检查深浅主题、390px 窄屏和扩展失败状态。
- 定向搜索结果受搜索索引与模型输出影响；页面摘要不足时仍可能缺少原文条款。结果不是确定因果证明，不能承诺每次都有新增事实。新增流程最多两次模型调用，会增加报告耗时。
- 历史快照不回写，新生成报告才包含本章节；仅本地读取公开材料验证，未重启用户的 Java/Python 服务。
