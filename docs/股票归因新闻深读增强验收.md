# 股票归因新闻深读增强

## 目标与展示位置

保持现有报告顺序、故事线、四块 AI 解读及底部业务/预期补充研究。对已有新闻增加专业分析方法，不新增证据准入规则，也不恢复独立证据列表。

- **每个驱动的 AI 解读下方**追加“新闻深读”：事件类型、影响方向、关键变化、2～4个适用的业务分析维度、短中长期影响、产业链传导。
- **故事线及既有放大/反方因素之后**追加“多条消息如何共同作用”“消息与股价对照”。
- **原有字段**继续生成，要求吸收专项解读结论；业务关联和预期变化补充研究接收专项分析作为研究线索，依据资料核对，不将模型推演当作新的事实来源。
- 新字段可选，旧报告及不适用内容不会生成空卡片。历史快照不自动重新生成；重新生成报告后才可能出现新增内容。

## 分析方法

| 新闻类型 | 重点解读 |
| --- | --- |
| 业绩 | 量价结构、毛利费用、扣非与一次性收益、现金流、基数和持续性 |
| 订单 | 协议阶段、相对收入规模、交付与验收、利润结构、回款 |
| 价格变化 | 需求或成本驱动、报价与成交、成本转嫁、库存及上下游利润分配 |
| 政策 | 落地阶段、适用对象、采购补贴或准入等业务传导 |
| 技术产品 | 研发到量产阶段、客户导入、良率产能、商业化周期 |
| 资本事项 | 交易对价、融资支付、稀释、控制权、整合与财务影响 |
| 澄清 | 精确识别确认和否认范围，分析原有题材假设的变化 |
| 交易 | 资金披露、成交与筹码、板块联动及持续条件 |
| 其他 | 根据事件选择具体经营、财务或交易变量 |

同一事件可采用最多3种方法，重复转载不计为多个催化。方向判断独立于当日因果置信度，旧消息不自动变成中性。多消息分析关注强化、抵消、先后条件；股价背离分析依据已有行情及具体机制，不直接套用“利好兑现”。观察项需对应业务机制、时间窗口及增强/削弱解释的具体变化。

分析仍使用截至目标日公开的信息；后续事项只能作为观察条件。数字带期间和口径，没有数字时保留有条件的定性分析。上述维度用于深化解读，不要求新闻具备全部字段才能进入报告。

## 实现与兼容性

- 复用候选解释、归因综合、业务与预期研究的已有模型调用，不增加逐条新闻模型请求。
- 股票综合调用通过现有客户端四参接口设置8192输出 token 预算，超时继续沿用客户端配置；提示词要求总文本控制在4000汉字以内并输出完整 JSON。基金和板块的综合调用方式保持原样。
- `AttributionNewsAnalysis` 挂在 `AttributionDriver.newsAnalysis`，使用原有 `drivers_json`；两项综合分析使用 `narrative_json`，无新增表或数据库迁移。
- `NewsInterpretationType` 表示驱动深读采用的方法，可多选；原有事件脉络 `EventResearchFramework` 的单值契约保持不变。
- 可选对象解析容忍缺失、错误类型和未知枚举值，丢弃无实质内容的对象，不将未知方向强制设为中性。数组及文本长度受控，局部无效不使主报告失败。
- 展示使用独立 `attribution-news-*` 样式和现有主题变量，避免与通用卡片选择器冲突。保持带背景的小框和14～16px卡片间隔，窄屏改为单列。

## 已完成验证

- 后端归因相关测试通过，覆盖旧字段保留、新字段解析容错、混合类型、长度上限、JSON数据库往返、综合调用预算与次数、专项分析向业务/预期研究传递。
- 前端自选模块99项测试通过；验证原有 AI 四卡与故事线 DOM 保持一致、可选内容不会产生空卡、适用周期按需展示。生产构建通过（保留项目已有的大包提示）。
- 使用浏览器临时注入明确标注的演示数据检查1600px桌面、390px手机及深浅主题。页面宽度分别为1600和390，无横向溢出；未将演示数据写入业务数据库。
- 按项目规范检查字段注入、完整大括号、模块依赖方向及改动范围，无新增框架、无服务重启。
