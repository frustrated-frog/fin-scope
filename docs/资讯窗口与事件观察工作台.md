# 资讯窗口与事件观察工作台

## 本次交付

从 `main` 的 `7fb8e07a` 创建隔离分支 `codex/news-event-workbench`，复用已提交的无模型模式与雷达可靠性修复，不包含原工作目录的未提交改动。

- 后台每轮采集先累积保存报道，再通知页面和雷达生产；新闻查询不发起外部抓取或模型请求。
- 在已采集的 36 小时窗口内按关键词、排除词、来源、分类、类型、未读和时间范围检索。筛选、计数、分页在服务端完成，不受首页 100 条限制。
- 原始报道使用来源代码与外部 ID 标识；缺少外部 ID 时优先用来源 URL 构建稳定身份。不同来源引用相同链接仍保留各自报道。
- 重复采集只更新采集时间；标题或正文变化才增加内容版本。人工分类、阅读进度、排名和股价变化不增加正文版本。
- 人工确认可以处理未分类报道；人工分类保存在 SQLite 中，后续规则重算不覆盖。
- 新闻详情包含原文、同一来源的版本对照、同一事件其他报道和股票反应。股票关联与价格计算复用投资观察模块，不建立第二套行情口径。
- 保存筛选条件并显示未读数量。阅读确认携带实际展示的正文版本；后台新增内容先提示，用户主动载入后才替换列表。
- 雷达按半小时保存全局排名、报道数和独立来源数，保留七天。首次记录没有比较基线，断档不连接成连续走势。
- 来源的时间排序不再参与热度排名评分。补录的旧报道不能仅因刚被采集，就计入当前发布速度。

## 数据与职责

| 数据 | 落点 | 保留与更新方式 |
| --- | --- | --- |
| 已采集报道、原文版本 | `news_report`、`news_report_version` | 默认保留七天，常规浏览窗口为 36 小时 |
| 已读正文版本 | `news_report_read` | 与原文版本分离；旧版本确认不吞掉后续更新 |
| 保存的筛选 | `news_saved_filter` | 本地持久化，最多 50 个 |
| 事件身份和证券关联 | 既有 `investment_reaction_source`、`investment_reaction_sample` | 沿用稳定来源映射和股票观察流程 |
| 股价与每日变化 | 既有投资观察计算和变化表 | 原有交易日、复权、基准和缺失状态口径 |
| 全局排名历史 | `radar_rank_history` | 半小时一条，每个区间保存最近一次生产记录，保留七天 |

进入投资观察或大事记的新闻及正文版本不随普通新闻保留期清理。首次有效公开时刻与首次收录时刻分别保存；重抓不重置首次公开时刻。分页同时固定时间窗口和到达序号，避免新新闻插入导致翻页重复。

领域对象位于 `finscope-domain`，持久化位于 `finscope-dao`，采集编排与规则位于 `finscope-service`，HTTP 入口位于 `finscope-web`。新增 Bean 使用字段注入，复用 SQLite、统一响应、规则分类、来源网关、页面版本通知和价格计算，无新增运行时依赖。

## 接口

- `GET /api/news/window`：查询参数包括 `query`、`exclude`、`source`、`category`、`kind`、`hours`、`unreadOnly`、`page`、`size`、`asOfSequence`、`asOfTime`。
- `GET /api/news/window/detail?id=...`：原文、版本、已关联报道、股票反应。
- `POST /api/news/window/read?id=...&version=...`：确认指定版本已读。
- `POST /api/news/window/review?id=...&category=...`：人工确认分类。
- `GET/POST /api/news/window/filters`：读取或保存筛选。
- `DELETE /api/news/window/filters/{id}`：删除筛选。
- `GET /api/research-radar/events/{id}/rank-history`：最近七天的排名记录。

旧新闻接口保留兼容既有调用者；后台雷达和投资观察消费完整窗口。大事记优先按持久化报道 ID 查找来源，兼容旧快照来源。

## 能力边界

“完整窗口”指本应用实际采集到的新闻，不承诺抓取外部网站的全部历史内容。来源停机或上游只提供少量最新内容时，仍需遵循现有适配器的可获取范围。

当前分类继续采用可解释的确定性规则；未匹配内容保留未分类。证券自动观察沿用已支持的业绩、合同等事件与可靠主体关联，不猜测受益公司。

版本对照记录原文变化，不把跨来源数字差异自动判定为事实修正，也不将相同主题自动合并为同一事件。同一事件其他报道的入口只使用已经持久化的事件关联。更广泛的结构化财务事实抽取仍需独立规则与样本验证。

保存筛选提供站内未读提示，未增加外部消息推送。雷达排名反映本工作台当时的研究排序，不代表外部市场热度，也不作为收益预测。

```sh
mvn -f backend/pom.xml -pl finscope-web -am test -Dtest='*News*,*Radar*,*Reaction*,MajorEventServiceTest,ResearchMaterialGateway*Test' -Dsurefire.failIfNoSpecifiedTests=false
npm --prefix frontend test
npm --prefix frontend run build
```
