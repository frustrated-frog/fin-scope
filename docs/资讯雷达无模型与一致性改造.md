# 资讯雷达无模型与一致性改造

第一批落实无模型可用与正确性修复；第二批实现窗口资讯库与分页检索。可命名的保存筛选、统一实体字典、事件内容版本和榜单订阅仍属于后续批次。

## 无模型运行

`application.yml` 的 `finscope.news-workbench.model-enabled` 默认 `false`。既有 Key 保持原样，开关仅作用于资讯与雷达。规则分类、来源读取、聚类、榜单和原文阅读照常运行；模型分类、配对判断、标题增强、证据搜索、预解读消息投递和详情解读任务不提交。启用时还需模型客户端已配置。

规则 v1 仅覆盖明确词表，按宏观、全球、市场异动、公司、行业的顺序处理。央行逆回购优先归为宏观，不与股份回购混淆。结果保留命中词和位置，不将规则匹配展示成概率。未匹配结果记为 UNCLASSIFIED，不因未归类反复重试；人工已确认结果优先。

分类任务执行器拒绝时将已领取批次标为失败，超时 PENDING 可回收。分类保存后发布 news 视图失效；通知失败不会反向覆盖已经保存的分类。

## API 与缓存契约

- `/api/research-radar` 及其子路径、`/api/dashboard/hotspots` 的数字标识符在 HTTP 边界转为字符串。后端存储与内部 Long 不变；旧 JsonNode 快照同样转换，防止 JavaScript 解析阶段丢精度。前端兼容字符串与旧的小整数数据，标识符不参与数值计算。
- 雷达查询先取得当前 TTL 窗口的事件，再应用用户状态、统计 `stateCounts`，最后截断返回列表。默认快照使用相同状态语义，忽略事件不占展示名额。快照查询版本升级为 2，旧版本快照不再命中。
- 命中雷达内容快照时仍单独读取生产状态，避免旧快照隐藏运行中或失败状态。
- 来源健康信息与成功内容分开缓存。失败更新最近尝试及告警，不修改成功内容、最近成功时间或成功内容 TTL；恢复成功后清除失败状态。`sourceHealth` 包含来源、状态、最近尝试和最近成功时间。
- 新闻 `refreshedAt` 仍表示页面快照生成时间，前端明确标为“页面快照”。资讯发生时间继续使用 `publishedAt`，来源成功同步时间从 `sourceHealth` 读取。

## 页面行为

隐藏页面收到 revision 时保存待刷新范围，恢复可见后补拉并对账。通知按事件 ID 加载详情，不依赖当前列表；详情打开成功才将通知标已读，失败保留未读并展示原因。无模型详情默认展示证据与来源，直接显示已采集正文，不触发解读或持续轮询。首次详情失败展示错误和重试入口。

## 验证与边界

回归覆盖：关闭模型后无任务提交、规则优先级与未归类、分类拒绝与 PENDING 回收、隐藏页恢复、通知打开失败、大整数 JSON 缓存精度、生产状态覆盖、排名 50 之后的状态筛选、忽略事件计数、来源失败后的告警与原成功时间。

当前规则不承担通用财经语义理解。资讯仍读取来源最近一次快照，保留原有 Top 100 和时间窗口；本批没有宣称已实现窗口内完整新闻检索。雷达事件 ID 的业务身份、正文历史与内容版本也未在本批重建。

## 启动后页面阻塞修复（2026-09-20）

实际启动后发现雷达请求超过 12 秒未返回。线程采样显示后台逐条信号摄取反复读写整份 Redis 状态，并持有更新锁；列表逐事件查询解读又造成全量缓存读取放大。首页同时等待全部初始化接口，进一步使独立页面一起延迟。

- 一批信号在一次缓存更新中摄取，保留稳定 ID、首次发现时间和上一轮排名。
- 解读批量查询只读取一次快照；无模型模式直接跳过解读查询。
- Redis 读取反序列化独立的最近完整快照，不等待更新锁；写入仍串行，避免丢失更新。
- 列表读取不再创建通知；关注变化通知仍由生产快照流程生成。
- 前端每个请求完成后立即发布数据，不等待其余初始化接口。

新增回归覆盖并发读取、100 条信号批量更新、500 个事件一次查询，以及无关接口持续等待时首页仍显示数据。相关后端 161 项测试、前端 App 37 项测试和生产构建通过。本地实际数据、启动后台任务运行期间，雷达接口约 1.3 秒，首页/文章/信源/知识库约 70–220 毫秒；该结果是本机抽样，不是性能上限承诺。


## 窗口资讯库与分页检索（2026-09-21）

后台来源刷新后，将已获取的资讯增量合并到 SQLite 的 `news_window_item`，主键为来源代码和原始编号；同一来源修订正文时更新原条目，保留首次采集时间。按现有 `finscope.ephemeral-content.ttl-hours` 保留（默认 36 小时），写入时清理过期记录，查询也强制应用保留边界。来源失败不会清空已采集条目。这不是全网历史补录：首次启用前已被来源快照挤出的资讯无法恢复；本批仅保证已实际采集入库的窗口数据可查。

新接口 `GET /api/news/paged` 支持 `category/source/query/hours/page/pageSize/asOf`。页码从 0 开始，每页最多 100 条，默认 50；返回 `totalCount/totalPages/page/pageSize/asOf/sourceOptions/windowHours`。时间和来源索引先缩小候选范围，关键词对标题与正文做字面匹配；分类以现有 Redis 结果和人工复核为准，按每 500 个 ID 批量读取，再筛选、计数，最后只从 SQLite 读取当前页正文。分类计数受时间、来源和关键词影响，未归类条目进入“全部”并单独计数。

翻页沿用首次查询的 `asOf`，排除之后新采集的资讯；新查询重新设置时间锚点。该锚点不是历史版本快照：过期清理、来源修订和人工分类调整仍可能改变结果。旧 `/api/news` 保留原契约供雷达等现有生产流程使用。大事记改为按窗口资讯 ID 读取，不再受最新 100 条限制。

验证覆盖：151 条数据的增量保留、重复更新、来源/关键词过滤、字面通配符、延迟到达排除、过期清理；分类发生在第 100 条之后仍能筛选分页，人工分类优先，超大页码回落；1001 个分类 ID 只发起 3 次批量缓存读取；HTTP 筛选参数和分页元数据契约。


页面提供 6/12/24/36 小时时间范围、来源渠道、关键词提交搜索与前后翻页。分类切换保留来源和关键词；筛选条件保存于当前浏览器标签页的 sessionStorage，重新进入或刷新后恢复；新筛选重置到第一页。请求序号屏蔽迟到的旧结果，失败显示重试入口。第一页仍以新资讯提示接收更新，后续页保持查询时间锚点。

第二批验证：后端相关 37 项、前端 NewsView/App 共 59 项测试通过，前端生产构建通过。运行中的真实数据已采集 146 条，前两页无重复；第 100 条之后的资讯可通过标题检索。后台刷新期间抽样查询第一页约 149 毫秒、第二页约 108 毫秒，关键词/来源/空结果约 9–16 毫秒。浏览器验证分页、关键词提交和筛选保留；这些数字仅代表当前本机数据规模。
