# 资讯雷达无模型与一致性改造

本批落实无模型可用与正确性修复。窗口资讯库、保存筛选、统一实体字典、事件内容版本和榜单订阅属于后续批次。

## 无模型运行

`application.yml` 的 `finscope.news-workbench.model-enabled` 默认 `false`。既有 Key 保持原样，开关仅作用于资讯与雷达。规则分类、来源读取、聚类、榜单和原文阅读照常运行；模型分类、配对判断、标题增强、证据搜索、预解读消息投递和详情解读任务不提交。启用时还需模型客户端已配置。

规则 v1 仅覆盖明确词表，按宏观、全球、市场异动、公司、行业的顺序处理。央行逆回购优先归为宏观，不与股份回购混淆。结果保留命中词和位置，不将规则匹配展示成概率。未匹配结果记为 UNCLASSIFIED，不因未归类反复重试；人工已确认结果优先。

分类任务执行器拒绝时将已领取批次标为失败，超时 PENDING 可回收。分类保存后发布 news 视图失效；通知失败不会反向覆盖已经保存的分类。

## API 与缓存契约

- `/api/research-radar` 及其子路径、`/api/dashboard/hotspots` 的数字标识符在 HTTP 边界转为字符串。后端存储与内部 Long 不变；旧 JsonNode 快照同样转换，防止 JavaScript 解析阶段丢精度。前端兼容字符串与旧的小整数数据，标识符不参与数值计算。
- 雷达查询先取得当前 TTL 窗口的事件，再应用用户状态、统计 `stateCounts`，最后截断返回列表。默认快照使用相同状态语义，忽略事件不占展示名额。快照查询版本升级为 2，旧版本快照不再命中。
- 命中雷达内容快照时仍单独读取生产状态，避免旧快照隐藏运行中或失败状态。
- 来源健康信息与成功内容分开缓存。失败更新最近尝试及告警，不修改成功内容、最近成功时间或成功内容 TTL；恢复成功后清除失败状态。`sourceHealth` 包含来源、状态、最近尝试和最近成功时间。
- 新闻 `refreshedAt` 仍表示页面快照生成时间，前端明确标为“页面快照”。资讯发生时间继续使用 `publishedAt`，来源成功同步时间从 `sourceHealth` 读取。

## 页面行为

隐藏页面收到 revision 时保存待刷新范围，恢复可见后补拉并对账。通知按事件 ID 加载详情，不依赖当前列表；详情打开成功才将通知标已读，失败保留未读并展示原因。无模型详情默认展示证据与来源，直接显示已采集正文，不触发解读或持续轮询。首次详情失败展示错误和重试入口。

## 验证与边界

回归覆盖：关闭模型后无任务提交、规则优先级与未归类、分类拒绝与 PENDING 回收、隐藏页恢复、通知打开失败、大整数 JSON 缓存精度、生产状态覆盖、排名 50 之后的状态筛选、忽略事件计数、来源失败后的告警与原成功时间。

当前规则不承担通用财经语义理解。资讯仍读取来源最近一次快照，保留原有 Top 100 和时间窗口；本批没有宣称已实现窗口内完整新闻检索。雷达事件 ID 的业务身份、正文历史与内容版本也未在本批重建。
