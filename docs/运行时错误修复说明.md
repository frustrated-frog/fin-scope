# 运行时错误修复说明

本次修复基于 main，未处理东方财富代理连接和历史 HTTP 402；不修改本地密钥，也不直接更改正在运行服务的业务数据。

## 可选新闻分类

新闻分类沿用 `NewsWorkbenchCapabilities` 判断：仅当资讯模型开关开启且 LLM 客户端配置完整（包括非空 API Key、模型与地址）时调用模型。全局 LLM 开关关闭时也不会调用。

未配置或关闭模型时，直接执行确定性规则分类，不提交模型线程池，不创建失败 Agent Run。空、null、空白密钥均有回归测试。主分支原本已经存在配置判断，此次补齐真实客户端配置测试，并让规则分类独立于模型队列。

## SSE 生命周期

页面版本订阅到期时移除订阅并完成响应，客户端可重新连接。全局异常处理器对已经采用 `text/event-stream` 的超时和 I/O 断开不再写 JSON；普通异步接口仍保留原有错误响应。

## 次日预测结算

历史问题来自同一批行情中不参与本次结算的早期前复权负价格。结算按同一股票所有待结算记录的最早基准日确定所需范围，在 RPC 适配层跳过更早记录的价格校验。所需范围内仍严格校验价格、成交量、成交额与 OHLC；不补零、不改变复权方式、不用其他日期替代目标日。完整历史研究接口仍维持原校验要求。

同一轮同一股票只取数一次；失败后默认冷却 15 分钟，保留待结算状态，冷却后重试。配置为 `finscope.next-session-prediction.retry-delay-minutes`。错误信息带股票、日期及异常行情值。冷却状态为进程内状态，重启后允许重新尝试。

## 股票发现执行恢复

- 新增 `stock_discovery_run.attempt_count`，兼容旧库时默认 0，历史实际尝试次数无法回溯。
- 每个批次默认最多执行 3 次，由 `finscope.stock-discovery.max-attempts` 控制；数据库条件更新约束并发领取，避免只在 Service 中判断。
- RUNNING 不再直接被新消费者抢占。恢复扫描先将超过时限的运行记录转为 FAILED，再对最新业务日期决定是否重试。历史批次只回收状态，不自动批量补算。
- 回收时限取 30 分钟与 Python RPC 配置超时加 1 分钟中的较大值。每次至多回收 100 条，并兼容旧记录缺少 started_at 的情形。
- 回收清除执行令牌；迟到完成或失败不能覆盖新执行。完整报告和明细在同一事务中写入，先检查执行令牌再修改明细。
- 状态接口新增 attemptCount；次数耗尽后 retryPending 为 false，保留最后错误和上一份成功报告。

Python 在单个进程内按完整请求参数合并在途任务，HTTP 调用方取消不会取消共享计算；重试等待同一份计算。成功结果最多缓存 8 份、30 分钟，失败不缓存；最多允许 4 个不同请求在途。不同日期、预算或策略的请求不会共享结果。

Java 超时/回收表示停止等待，不等于远端计算被强制取消。Python 合并仅在同一进程有效，不承诺跨进程或重启后复用；现有线程中的模型训练无法安全强制终止。本次不引入独立任务服务或强制杀进程。

上线时需要重新构建并重启 Java/Python 服务，数据库字段由现有初始化机制自动增加。恢复扫描随既有调度器启动执行，受其调度负载影响；不承诺精确到秒的回收时刻。
