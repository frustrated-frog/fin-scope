# 雷达缓存按对象存储改造

2026-11-14 的只读检查中，`finscope:radar:state` 为 24,038,097 字节：历史快照约 11.3 MB、事件约 6.3 MB、信号约 4.0 MB、关联约 1.8 MB。此前批量摄取与解除读锁降低了调用次数，但查询运行状态仍须读取全包。

## 存储与查询

新布局使用 `finscope:radar:v2:<generation>:<collection>:<id>`，业务 ID 以 URL-safe Base64 编码。事件、信号、每个事件的关联/快照/工作台状态、每个批次的运行记录分别存储。通知及通知去重指纹同样按条存储。

每个集合的 ZSET 只保存 ID 与绝对过期时间。单条查询使用 MGET 读取所需对象；遍历某个集合时只加载该集合，MGET 每批最多 100 条，不加载无关正文和历史。多记录详情使用版本前后校验，遇到并发提交重新读取。

修改后的对象与本次读取的原始 JSON 比较，只提交变化记录。版本检查、父记录存在性检查、对象及索引更新由同一个 Lua 脚本执行。跨后端实例发生版本冲突时重新读取并重试，最多四次。序号改用独立 INCR，重试允许出现空号，不会复用已经分配的序号。

## 有效期与关联

信号按发布时间（缺失时取首次发现时间），事件按最近出现时间（缺失时取首次发现时间），运行记录按开始时间计算有效期。无关写入不会延长它们的有效期。事件更新时仅续期已有子记录和身份索引，不重新传输它们的内容。子记录写入必须有有效父记录。

迁移清理所有找不到父事件的子集合，而非仅清理本轮刚过期事件的子数据；同时清理已经失效的信号关联。对象自行过期，集合查询排除已到期 ID，写入时回收该集合的过期索引。

## 首次迁移

首次访问使用 WATCH 保护旧键与活动代号。旧 JSON 按 256 KiB 的字节段读取，拼接后解码，避免一次传输大包以及截断中文字符。清理后分批 pipeline 写入独立暂存代；每条暂存记录和集合索引都有有效期。全部写入成功才通过事务发布活动代号。旧键或活动代号在迁移期间变化会放弃发布并重试；解析、网络等失败均不发布部分数据。

旧键保留原有 TTL 供核对，原本没有 TTL 的遗留键补上缓存窗口 TTL。新后端切换后不再读写旧键，旧后端应在 IDEA 重启时停止。该改造不改 Redis 全局超时，不写入用户 SQLite 数据库。

## 验证

普通雷达回归测试不需要 Redis。真实 Redis 契约测试只允许显式指定的隔离端口 16389，不加载应用 Redis 配置：

```bash
JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home \
mvn -f backend/pom.xml -pl finscope-web -am test \
  '-Dtest=*Radar*Test,IndustryChainEventImpactRepositoryTest,*Ephemeral*Test' \
  -Dsurefire.failIfNoSpecifiedTests=false -Dfinscope.test.redis-port=16389
```

覆盖中文分段迁移、悬空关联、按需状态读取、嵌套对象更新、无关 TTL 不续期、关注状态随事件续期、跨实例并发更新、详情一致性重读、父记录过期拦截、Lua 写入前类型校验、失败迁移重试、并发冷启动及有界批量读取。

## 生产链路批量化

信号摄取、事件及关联保存、历史快照保存、分类更新均限制为每批最多 100 个对象。事件与它的信号关系在同一脚本内提交。历史身份候选、上一轮评分快照按事件键批量读取；同标题候选在本次保存前加载一次，避免逐事件扫描整个事件集合。跨批次仍执行同标题去重，批次开始写入前先校验全部事件身份。

历史评分快照在所属事件有效的前提下最多保留七天，每次追加时清理自身旧记录，不再每轮读取所有事件的历史来清理。独立的七天排名历史保持既有实现。页面继续使用现有的雷达与首页版本联合发布，完整生产成功后才发布新页面版本。

## 实际数据副本验证

将当时 23,914,695 字节的旧缓存只读复制到隔离 Redis，以 1 秒 Redis 命令超时运行真实 DAO；没有启动 Web 后端、触发外部抓取或修改实际运行缓存。

- 首次迁移约 1670 ms，保留 3017 个有效事件、3867 条有效信号。
- 20 次热读取：最新运行记录 P50 1 ms、P95 2 ms，只读取 runs，记录内容约 13.5 KB。
- 单事件详情选择信号数最多的有效事件：P50 5 ms、P95 13 ms，相关记录约 33.3 KB。
- 全窗口事件列表 P50 65 ms、P95 84 ms，只读取 events，约 6.18 MB；其仍需完成全窗口筛选和状态计数，没有宣称只读取最终展示的 20 条。
- 新建运行记录约 6 ms，不读取任何已有事件、信号或历史记录。

这是本机 Redis/DAO 的抽样，字节数只统计业务记录，时延不包括 HTTP、前端渲染和外部采集。旧大键作为临时核对副本仍保留原有效期，新请求不再使用它。
